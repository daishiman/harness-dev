# 背景の調査（別の LLM が行う）

あなたは、分析の背景を確かめる外部の数字と出来事を、公的な資料から集める調査担当です。仮説の良し悪しは判断しません。**確かめた観測事実だけを、出典つきで表にする**ことが仕事です。公表資料の記述や時期の一致も因果の証明ではなく、反事実効果は推定しません。

この調査は `brief.json` の `plan.背景分析` が `true` の場合だけ行います。`false` なら外部調査を始めず、依頼元へ契約の不一致を返します。

調査は2人で並列に行います。依頼文で指定された `役割` だけを行います。

| 役割 | 集めるもの | 書くファイル |
|---|---|---|
| 裏づけ | 主な背景の仮説（`対立` が false）の系列と、仮説の出来事・時代背景 | `背景データ.csv`（系列で分けたときは依頼文のファイル名） |
| 反証 | 対立仮説（`対立` が true）の系列、主な仮説の反証条件に当たる数字、**比較の相手**（業界全体・他の地域・国全体の同じ系列）、`brief.候補` に無い別の説明 | `背景データ-反証.csv` |

反証役は、主な仮説が**間違っている**と仮定して資料を探します（悪魔の代弁者）。`causes.md` §2 の型と3つの軸（時間の長さ・立場・範囲）のうち、`brief.候補` に無い欄を優先して探します。

## 読むもの（フォルダ `<dir>` の中）

- `brief.json` の `plan`（問い・範囲・基準・焦点）と `候補`、`層` が `背景` の仮説（`主張`・`反証条件`・`列`・`対立`）
- スキルの `references/causes.md` §2（型と3つの軸）と §5（資料の優先順位と、時点のそろえ方）

WebSearch と WebFetch を使います（読み込まれていなければ ToolSearch で `select:WebSearch,WebFetch` を読み込む）。

## 集めるもの

- 自分の役割の仮説の `列` に書かれた**系列名ごと**に、基準と範囲を含む各期間の値。系列名は `列` の文字列をそのまま使う。比較の相手の系列は `<系列名>（業界全体）` のように相手を括弧で付ける。
- 仮説の `主張` に出てくる制度・出来事の日付（施行・開始・終了）。系列名は `出来事` にする。
- **時代背景**: `plan.範囲` の期間から調査日までに起きた、焦点の筋に関わる制度の変更・出来事・公表された見通し。直近のものほど優先し、系列名は `出来事` にする。

## 探し方

- 系列・出来事ごとの検索は互いに独立です。**WebSearch と WebFetch は、1つのメッセージに複数並べて同時に**行います（1件ずつ順に検索しない）。
- 依頼文で担当の系列とファイル名が指定されたら、その系列だけを調べ、そのファイルに書きます（裏づけ役を分けたとき）。

1. 仮説ごとに、系列名・期間・発行元の候補（官公庁・統計の名前）で検索し、統計の表か公表資料のページにたどり着く。
2. 主な仮説だけでなく、**反証条件に当たる数字と、対立仮説を支える資料も同じだけ探す**（都合の良い資料だけを集めない）。
3. 最新の公表（確定値・改定）があれば、古い版より優先する。版の日付を `基準` に書く。

## 守ること

- 数字は、出典のページや表で**実際に見た値だけ**を書く。記憶や推測で埋めない。見つからない系列は書かず、報告に回す。
- 資料の因果解釈や調査担当の推測は CSV に保存せず、数値・日付・定義・出典という観測事実だけを保存する。
- 出典は `references/causes.md` §5 の順に選ぶ。URL は、その数字が載っているページ（表のファイルなら、そのファイルの URL）にする。
- 1つの系列の中で、`単位` と `基準`（定義・時点・速報/確定）を混ぜない。混ざるなら系列名を分ける。
- 同じ `系列` と `期間` の行は1件だけにする。複数資料がある場合は、基準に合う最新の値を1つ選ぶ。
- 手元のデータと期間の区切り（暦年・年度・月末など）が違えば、そのまま書き、`基準` に明記する（勝手に換算しない）。

## 出力: `<dir>/背景データ.csv`（裏づけ）か `<dir>/背景データ-反証.csv`（反証）

UTF-8、1行目は見出し。列は次の8つで、この順にします。

| 列 | 内容 |
|---|---|
| 系列 | 仮説の `列` と同じ名前。出来事は `出来事` |
| 期間 | `2024`、`2024-10`、`2024-10-01` のどれか |
| 値 | 数値（桁区切りなし）。出来事は空 |
| 単位 | 人、件、%、円 など。出来事は空 |
| 基準 | 暦年・年度・何月何日時点・速報/確定 など |
| 出典 | 資料の名前（発行元と表の名前） |
| URL | `https://` で始まる出典の URL |
| 注記 | 出来事の名前（出来事の行は必須）。ほかは任意 |

既にファイルがあれば、残す行を確かめたうえで上書きします。自分の役割のファイル以外は書き換えず、一時ファイルは scratchpad に置きます。

## 最後の報告

1. 集まった系列と期間
2. 集まらなかった系列と理由（分析者が仮説を直すのに使う）
3. 定義や時点が手元のデータとずれている点
4. 仮説に無いが、資料に出てきた別の説明（1行ずつ。型・出典つき。分析者が `brief.候補` に足すか判断する）。反証役は、主な仮説を弱める資料があったかを最初に書く

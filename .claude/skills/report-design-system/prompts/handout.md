# 実行部隊向け資料の進め方

経営者向けレポートの結論と打ち手を、実際に動く人 (配車担当・ドライバー・事務など) に渡す資料にする。資料に載せるのは **目的・ゴール・やること** (と、あれば困ったときの相談先・振り返り) だけ。数字の根拠、統計、要因の分析は載せない。

中身はユーザーとの往復で決める。往復の正本は、フォルダの `hearing.md` (ヒアリングシート)。**AI が下書きをほぼ全部書き、ユーザーには決めてほしいことだけを聞く。** 資料の HTML は、このシートから `report.mjs handout` が組み立てる。HTML を手で直さない。

```bash
R=<スキルの場所>/scripts/report.mjs
node $R hearing <フォルダ>   # シートを作る / 「AI が直すこと」と「ユーザーに聞くこと」を出す (回答待ちなら終了コード 3)
node $R handout <フォルダ>   # 了承済みのシートから資料 <フォルダ名>-handout.html を作る
```

フォルダは経営者向けレポートのフォルダでよい。レポートがあれば打ち手 (担当・期限つき) を「やること」に写し、前の月のシートがあれば相手・相談先・見せない情報を引き継ぐ。新しいフォルダでも始められる。

## 往復の進め方

1. `hearing` を実行する。
2. 「AI が直す」の項目は、ユーザーに聞かずにシートを直す (表紙・目的の下書き、現場の言葉への言い換え、字数、件数の絞り込み)。直したら `hearing` をもう一度実行する。
3. 「ユーザーに聞く」の項目を、**1回に多くても4問**でチャットで聞く (`hearing` がまとまりごとに束ねて出す)。1問ごとに次を添える。
   - 何のための質問か (1行)
   - AI の案。「この案でよければ OK、違えば直してください」と書く。「誰が」は渡す相手、「いつまでに」はゴールの期限を案にしてよい
4. 聞くことに「確認」が出たら、下書き全体を短く見せて「この内容で資料にしてよいか」を聞く。ほかの質問と同じ回に聞いてよい。
5. ここで止まり、返事を待つ。答えを推測して埋めない。返し方は、チャットで答えるか `hearing.md` を直接直すかのどちらでもよいと伝える。
6. 答えはそのままの意味でシートに書き写し、1. に戻る。すでに答えてもらったことを聞き直さない。「聞き直し」(わからない・未定) の項目は、聞き方を変え、選べる案を2〜3個出す。

往復は **3回まで** を目安にする。3回で決まらない項目は AI の案で埋め、最後の確認で「ここは AI の案です」と示して了承だけをもらう。

## 了承の印

- 「OK」「それでいい」など**明示の了承があったときだけ**、`- [ ] この内容で資料にする` を `- [x]` にする。
- ユーザーの答えを書き写しただけなら、印はそのままでよい。AI が言い換えたり足したりしたら `[ ]` に戻し、変えた点を示してもう一度了承をもらう。

## 仕上げ

1. `hearing` が終了コード 0 (ヒアリング完了) になったら `handout` を実行する。検査が不合格なら、指摘された文をシートで直して再実行する。
2. 生成された `<フォルダ名>-handout.html` を渡し、次の2点をユーザーに伝える。
   - 印刷ボタンで紙にできること
   - 直したいときは `hearing.md` を直して `handout` を再実行すること

## 書き方の決まり

- 読み手は数字や統計に慣れていない人。1文1つのことを、ふだん話す言葉で書く。
- 使わないもの: 統計・分析の言葉 (中央値、相関、指標、仮説など)、「▲」、小数、絵文字、社内の分析資料だけで通じる言葉。使いたくなったら、何が起きているかを言葉で書く (例: 「km単価が低い」→「距離のわりに運賃が安い」)。言い換えの例は `hearing.mjs` の `FRONTLINE_WORDS`。
- やること1件に、担当は1つ (人か役割)、動作は1つ。「〜を確認し、〜を依頼する」のように2つの動作が入るなら2件に分ける (`hearing` の「分ける」。後の件の担当・期限・目安も案を書き、了承のときに見せる)。
- 「渡す相手」に書いた人は、全員がやることを1件以上持つようにする。持たない人がいれば、相手から外すか、その人のやることの案を作り、同じ回の質問 (4問の中) で確かめる。
- 「赤字の車」「値上げを頼む荷主」のように絞り込んだ相手は、現場で見分けられる形にする。見せてよい範囲で車番や荷主を書くか、「対象の一覧を渡す」をやることに足す。
- 「できたかの目安」は、終わったと誰が見ても分かる形にする (例: 「一覧を社長に渡した」「週1回続けられた」)。「意識する」「徹底する」は目安にならない。
- 期限はシートに `2026-10-31` `2026-10末` のように書いてよい。資料では「10月31日」「10月末」と読む形で出る (年は作成日と違うときだけ付く)。
- 各欄は60字まで、題名は40字まで。
- 見せない情報 (荷主の社名、車両ごとの赤字額など) は、シートの「見せない情報」に語句で書いてもらい、資料に出さない。無ければ「なし」と書いてもらう。

## してはいけないこと

- ゴール・担当・期限・見せない情報を AI だけで決めること。案は出してよいが、決めるのはユーザー。
- ユーザーの了承なしに `[x]` を付けること。
- 見せない情報を、言い換えて資料に残すこと (「大手の荷主A社」なども避ける)。
- 資料の HTML を手で直すこと。

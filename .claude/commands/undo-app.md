公開済みアプリを**1つ前の状態に戻して**ください。

## 状況

$ARGUMENTS

## 実行ルール

- 取り消しは必ず `git revert` で行う。**`git reset --hard` と `push --force` は使用禁止**(履歴を消すと二度と戻せなくなるため)。詳細は Skill `solo-git-flow` §7。
- 手順: (1) `git log --oneline` とタグで戻す対象を特定 → (2) 直近の変更を既定の推奨対象として、戻る内容・影響・復元方法を日本語で示す → (3) 対象コミットを revert → (4) `pnpm run preview` で戻った状態を確認 → (5) `.github/workflows/deploy.yml`があれば main へ反映し(v1 到達済みならPR経由、未達なら main へ直接コミットして push)、mainのCI成功後に起動したDeployを監視 → (6) 本番URLを時間を空けて2回確認。自動Deployがある環境で手元の`wrangler deploy`へ迂回しない。CI/CD未導入の初回公開または記録を残す緊急対応だけ、cleanな確定コミットから公開する。
- どこまで戻すか曖昧でも候補一覧を質問として返さない。履歴・リリース時刻・依頼文から最有力の対象を1つ選び、まず非破壊の差分プレビューを作る。異なる対象を望む場合だけユーザーから差分指定を受ける。
- DBのスキーマを変えた変更を戻す場合: まずバックアップ、影響行、コードだけ戻した場合の挙動を調べ、推奨する復旧計画を1つ作る。データ復元は不可逆になり得るため、実行直前に「この復旧計画でデータも戻す」の一点だけ承認を得る。
- 完了報告は「1つ前の状態に戻しました + 確認用URL + 戻した内容(業務の言葉で)」の形式。git 用語は使わない。

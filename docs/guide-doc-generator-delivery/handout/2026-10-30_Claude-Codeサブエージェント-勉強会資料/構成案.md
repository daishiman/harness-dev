## 2. 資料の芯

### 題

**Claude Code サブエージェント編**（前回の「スキル応用編」とそろえる。2026-10-13 確定）

### 全体を通すたとえ: 「別の机で働くサブエージェント」

前回は「机の広さ」（一度に載せられる量には限りがある）を使いました。今回はその続きとして、サブエージェントを**自分の机を別に持つ働き手**として説明します。資料では、いま話している Claude（いまの会話）を「メイン」と呼びます。

- メインの机には、本題の紙だけを置いておきたい
- 調べものの途中の紙は、サブエージェントの机に広げてもらう
- メインに戻ってくるのは、結果をまとめた紙1枚だけ

スキルとの違いも同じたとえで言えます。**スキルは「何をどの順でするか」を書いた手順書で、サブエージェントは別の机で作業して結果を返します**。手順書は今の机で開くのが基本で、サブエージェントに持たせることもできます（8節）。役割が違うので、どちらか一方を選ぶものではありません。

### 冒頭（表紙）に置く文

| 欄 | 文（案） |
|---|---|
| 1行目（lead） | サブエージェントは、別の机で作業して、結果だけを返す。調べものは任せて、メイン（いま話している Claude）の机を空けておく。 |
| ゴール | 最初からいるサブエージェントに調べものを任せ、自分用を作って呼び出すまで扱う。 |
| 目的 | 何でも一つの会話に頼んで机が埋まる形から、作業を分けて任せる形へ移す回。 |
| 背景 | 前回は、スキル（Claude に持たせる手順書）を作った。今回は、別の机で調べものを引き受けるサブエージェントを扱う。前回の手順書は、サブエージェントに持たせることもできる。 |

- 表紙の文は、資料の字数の上限（表紙全体で 640 字）に収まるよう短くしています（5回目・634 字）

### 覚えて帰ること（2つまで）

1. サブエージェントは別の机で作業し、メインには結果だけを返す
2. 机は別でも、使用量は同じ財布から出る。たくさん読む調べものは任せ、小さな頼みはそのまま頼む

- 2つ目は、前の版の「いつ呼ばれるかは description で決まる。スキルと同じ」から替えました。「同じなら、どちらが先に動くのか」という迷いを生むためです。呼び分けの答えは8節に置きます

### 覚えなくてよいこと

- 設定ファイルの細かい項目（使える道具の範囲、使うAIの種類など）。直したいときは Claude に頼めば足りる
- 最初からいるサブエージェントの全部の名前。調べるものと何でもするものが分かれば足りる
- 同じ名前が何か所かにあるときの細かい決まり（答えは Q&A にある。構成案の10節）
- 手順書（スキル）を持たせる設定の書き方。「持たせて」と Claude に頼めば足りる

### この回で扱う作業

| id | 作業 |
|---|---|
| t-ask | 最初からいるサブエージェントに調べものを任せる |
| t-parallel | いくつかの調べものを、同時に別々に任せる |
| t-call | 4つの呼び方で呼ぶ（必ず動かすなら @） |
| t-judge | 任せるか、そのまま頼むかを、得と損で決める |
| t-choose | 作業を、手順書（スキル）にするかサブエージェントにするかを決める |
| t-make | 自分のサブエージェントを作ってもらい、名前で呼ぶ |

### 3. サブエージェントとは（18:40・10分）

- 言いたいこと: サブエージェントは、別の机で作業して、結果だけを返す。
- 判断軸: 途中の経過を見なくてよい作業なら、サブエージェントに任せられる。戻ってきた結果には、メインで目を通す。
- 呼び方: いま話している Claude（いまの会話）を「メイン」と呼ぶ。資料の最後までこの呼び方で通す
- 図解（左右の対比・題「机に何が残るか」）: 「一人で全部やると」と「サブエージェントに任せると」

| 一人で全部やると | サブエージェントに任せると |
|---|---|
| 調べた途中の紙が、全部メインの机に積まれる | 途中の紙は、サブエージェントの机に広げてもらう |
| 本題に使える場所が減っていく | メインに届くのは、結果の紙1枚 |
| 長くなると、前のほうが要約されて細かい所が抜ける | メインの机は、本題のために空いている |

- カード3枚: サブエージェントが持っている3つ
  - 自分の机（別の作業場所で動く）
  - 専用の指示（何をするサブエージェントかが書いてある）
  - 使える道具の範囲（読むだけ、などと絞れる）
- 一言の補足: サブエージェントは、ふつうはメインの会話を見ていない。必要なことは頼むときに書く。例外は、次の節の最後に折りたたんである「会話ごと引き継ぐサブエージェント」（構成案の4節）
- 図解（流れ・題「頼んでから、結果が届くまで」）: メインがサブエージェントに頼む（必要なことは頼む文に書く）→ サブエージェントが白紙から読む（途中の紙はサブエージェントの机に残る）→ 結果の紙1枚を返す → メインに結果が届く
- 講師の画面で、サブエージェントが動いた表示と、戻ってきた結果を見る（届くのは結果だけ）

### 4. サブエージェントにできること（18:50・10分）

- 言いたいこと: サブエージェントは、まとまった作業を引き受ける。最初からいるものを、Claude が頼み方に合わせて呼ぶ。
- 判断軸: 読むだけで済む頼みごとは、調べるサブエージェントに任せる。
- 番号つきの行4つ: サブエージェントにできること

| できること | たとえば |
|---|---|
| 別の机で、たくさん読む | フォルダ全体を読んでも、メインに届くのは要約だけ |
| 同時にいくつも動く | 3本の資料を、3つのサブエージェントが同時に読む |
| 使える道具を絞る | 「読むだけ」のサブエージェントは、ファイルを書き換えない |
| サブエージェントごとに軽いAIで動かせる | 「このサブエージェントは軽いAIで動かして」と頼む。速く、使用量も少ない |

- 前の版の5枚目「手順書を持って動く」は外しました。スキルとの違いを話す前に出すと「サブエージェントとスキルは同じもの？」の迷いを生むため、8節でまとめて扱います
- 表: 最初からいるサブエージェント

| サブエージェント | すること | ファイルの書き換え |
|---|---|---|
| Explore（調べる） | フォルダの中を探して読む。速い | しない |
| Plan（計画を立てる） | 計画を立てる前の下調べ | しない |
| general-purpose | 何でもする。調べて、書き換えまでする | する |

- 補足: 覚えるのは Explore（調べる）と general-purpose（何でもする）の2つで足りる。Plan（計画を立てる）は、Claude が計画を立てるときに自分で使う。

**サブエージェントには、こんなこともできる**（手を動かさず紹介する）

- 資料では、下の8行のうち3行（裏で動く・続きを頼む・会話ごと引き継ぐサブエージェント）を、節の最後の折りたたみにしています（5回目の時点）。文は次のとおり
  - サブエージェントは、ふだん裏で動く: 動いている間も、メインで別の話を進められる。Background tasks（動いている作業の一覧）に出る。
  - 続きを頼む: サブエージェントは呼ぶたびに白紙から始まる。同じ会話の中なら「さっきのサブエージェントに続きを頼んで」と頼める。Explore（調べる）と Plan（計画を立てる）は続きを頼めないので、頼み直す。
  - 会話ごと引き継ぐサブエージェント: いまの会話を持って始まるサブエージェント。Claude が自分から使うこともある。ターミナル版では、入力欄で /subtask に続けて頼む。

| こんなこともできる | どう頼むか・どう見えるか |
|---|---|
| 頼まなくても、サブエージェントは裏で動く | サブエージェントはふつう裏で動く。動いている間も別の話を進められ、動いている作業の一覧（Background tasks）に出る。ターミナル版では Ctrl+B で裏に回せる |
| 続きを頼む | サブエージェントは呼ぶたびに白紙から始まる。前の続きをしてほしいときは「さっきのサブエージェントに続きを頼んで」と頼む。Explore と Plan は1回きりで、続きは頼めない |
| サブエージェントに記憶を持たせる | サブエージェントごとにメモを残させ、次に呼ばれたときに読み返させられる |
| サブエージェントがさらにサブエージェントを呼ぶ | サブエージェントの中から、別のサブエージェントを呼べる（メインから数えて3段まで） |
| 会話ごと引き継ぐサブエージェント | ふつうのサブエージェントと違い、いまの会話の流れをそのまま持って始まる。Claude が自分から使うこともある（2026-10-30 追記。公式では既定でオン）。自分で使うときは、入力欄で `/subtask` に続けて頼みごとを書く（`/` で始まるが、スキルではなく、Claude Code に最初から入っている命令） |
| 写しの上で作業させる | 元のファイルとは別の写しで作業させ、元に触れないようにできる（フォルダを git で管理しているとき） |
| 動く回数に上限を付ける | サブエージェントが長引かないよう、作業の回数に上限を付けられる |
| 会話全体をサブエージェントとして始める | ターミナル版では `claude --agent サブエージェントの名前` で、最初から作ったサブエージェントとして話せる |

- 要確認（当日前の実機確認）: この表のうち、Code タブで動くと公式に書かれているのは「動いている作業の一覧にサブエージェントが出る」ことだけです。ほかは公式のターミナル版の説明によります。資料では各行に「ターミナル版で確認」と添えるか、実機で確かめてから添え書きを決めます

### 5. 調べものを任せる（19:00・30分・手を動かす）

- 言いたいこと: 調べものをサブエージェントに任せると、メインには一覧だけが届く。
- 判断軸: 結果が返ってくれば、サブエージェントの動いた表示を見逃しても先へ進んでよい。
- 練習の題材: 架空の会社の会議メモ3本、商品一覧1つ、お客様向けの案内文の下書き1本を、その場で Claude に作らせる（配布物なし。社名・人名はすべて架空。案内文の下書きは9節で作るサブエージェントに見せる）

**貼り付ける依頼文（準備）**

```
このフォルダに、練習用の架空の資料を作ってください。
会議メモを3本（それぞれ別の日付と議題）と、商品一覧を1つ、
お客様向けの案内文の下書きを1本。
会社名と人名は、すべて架空にしてください。
```

**貼り付ける依頼文（調べるサブエージェントに任せる）**

```
調べるサブエージェント（Explore）を使って、このフォルダの会議メモから、
まだ終わっていない宿題を探して一覧にしてください。
```

**貼り付ける依頼文（同時に任せる）**

```
3本の会議メモを、それぞれ別のサブエージェントで同時に要約してください。
最後に、3本の要約を1つの表にまとめてください。
```

**手順**

| # | すること | こうなれば進む | 止まったとき |
|---|---|---|---|
| 1 | Code タブで Local と練習フォルダを選ぶ | 「サブエージェント練習」が画面に出る | フォルダは先にデスクトップに作っておく。Local は、自分のパソコンで動かす設定 |
| 2 | 準備の依頼文を貼る | 会議メモ3本、商品一覧、案内文の下書きができる | 書き込みの許可を聞かれたら許可する |
| 3 | 調べるサブエージェントの依頼文を貼る | サブエージェントが動いた表示が出て、宿題の一覧が返る | 表示を見逃しても、一覧が返れば進めてよい |
| 4 | 同時に任せる依頼文を貼る | サブエージェントがいくつか並んで動き、最後に表が返る | 表が返る前に、次の手順で一覧を開く |
| 5 | Background tasks で動いている作業を選ぶ | サブエージェントの出力が見え、そこから止めることもできる | 一覧は、画面上の帯の「⋮」メニューから開く。もう終わっていたら、講師の画面で見る。止めたサブエージェントは、Claude に頼んでも続きからは動かない。要るときは、同じ依頼文をもう一度貼る |

- 練習用のフォルダの名前は「サブエージェント練習」（2026-10-30・5回目で、資料に合わせて名前を替えた）。9節の手順でも同じ名前を使う
- 同時に任せる依頼文のあとに、流れの図（題「3本を同時に任せると」）を置く: 依頼文を1回貼る → サブエージェントが同時に読む（1本ずつ、別の机で）→ 要約が3つ届く → メインが表にまとめる
- 要確認（当日前の実機確認）: 手順4・5は公式のデスクトップ版の説明（2026-10-13 確認）に沿っています。実際の画面で、同時に任せたサブエージェントが一覧に並ぶか、一覧から止められるかを一度確かめてください
- 要確認（当日前の実機確認）: Esc や停止ボタンでサブエージェントも止まるかは、公式に書かれていません（停止ボタンは Claude の応答を止める、とだけある）。止まると確かめられたら、手順5の「止まったとき」に足します

### 6. サブエージェントの呼び出し方（19:40・10分・手を動かす）

- 言いたいこと: 呼び方は4つ。迷ったら、サブエージェントの名前を書いて頼む。
- 判断軸: 狙ったサブエージェントが呼ばれないときは、名前を書いて頼み直す。必ず動かしたいときは @ で名指しする。まだ作っていない作業を任せたいときは、その場で任せる。
- 並び: 挿絵 → 順の図 → 手順 → 依頼文
- 順の図（狙ったサブエージェントを動かしたいときの順）: 普通に頼む（Claude が選ぶ）→ 名前を書いて頼む（書いた名前が選ばれやすくなる）→ @ で名指しする（その1回は必ず動く）
- 手順は4段で、この4段がそのまま4つの呼び方になる

| # | すること | こうなれば進む | 止まったとき |
|---|---|---|---|
| 1 | 「このフォルダの宿題を探して」と頼む | サブエージェントが動くか、メインがそのまま答える | どちらになっても間違いではない |
| 2 | 「Explore サブエージェントで宿題を探して」と頼む | 書いたサブエージェントが動いた表示が出る | 動かなくても間違いではない。次の @ で確かめる |
| 3 | @ を打ち、Explore を選んで頼む | 選んだサブエージェントが、その1回は必ず動く | 頼む文は「宿題を探して」でよい。一覧にサブエージェントが出なければ、名前を書いて頼む形で進める |
| 4 | 下の依頼文（4つ目・その場で任せる）を貼る | サブエージェントが動いた表示が出て、結果が返る。サブエージェントのファイルは残らない | どのサブエージェントに任せるかは Claude が決める。動かずに、メインがそのまま答えても間違いではない |

**貼り付ける依頼文（4つ目・その場で任せる）**（手順のすぐ下に置く）

```
サブエージェントを使って、案内文と商品一覧の食い違いを確かめてください。
```

- 呼び方の表（4行）、「残る／残らない」の表、前回のスキルとの呼び方の違いの文は外しました（2026-10-30・3回目）
- 2026-10-30 の見直し: 「呼び方は @・自動・その場で作って実行の3つ」という整理を公式（docs/en/sub-agents、07:14 取得）と突き合わせました
  - @ で名指し: 合っている。公式は「選ぶのを Claude に任せず、そのサブエージェントが動く」（ensures that specific subagent runs rather than leaving the choice to Claude）。サブエージェントへの指示文は、@ のときも Claude が書く
  - 自動（普通に頼む）: 合っている。Claude が頼みごと・description・いまの会話の流れを見て決める。使わないこともある
  - その場で作って実行: 半分だけ合っている。サブエージェントが新しく作られるのではなく、Claude がその場で指示を書いて、最初からいるサブエージェントか「会話ごと引き継ぐサブエージェント」（4節）に任せる。サブエージェントのファイルは残らない。ファイルに残したいときは「サブエージェントを作って」と頼む（9節）
  - 公式には、もう1つ「名前を書いて頼む」がある。選ばれやすくなるが、最後に決めるのは Claude。そのため呼び方は4つにした（3回目の更新で、表は手順4段に置き換えた）
- 要確認（当日前の実機確認）: @ での名指しは、公式のデスクトップ版の説明にはファイルの指定しか書かれていません（2026-10-30 07:27 に再確認。サブエージェントそのものは Code タブでも動き、Background tasks に並ぶと書かれている）。Code タブでサブエージェントを選べるか確かめ、選べなければこの行は「ターミナル版で使える呼び方」として紹介だけにします。そのときは、8・9・10・11節の「@」も同じ扱いに直します

### 7. 任せる得と損（19:50・10分）

- 言いたいこと: サブエージェントに任せるとメインの机は空くが、使用量はその分かかる。机は別でも、財布は同じ。
- 判断軸: たくさん読んで結果だけほしい作業はサブエージェントへ、すぐ終わる頼みごとはそのまま頼む。
- 対比の表: 得（良い所）と損（かかるもの）を、机・使用量・時間・道具の4つの観点で並べる

| 観点 | 得（良い所） | 損（かかるもの） |
|---|---|---|
| 机 | メインの机が埋まらない。途中の紙はサブエージェントの机に残り、要約だけ届く | 何人も使って詳しく返させると、メインの机がかえって埋まる |
| 使用量 | 簡単な作業は軽いAIで動かせば、使用量を抑えられる | サブエージェントも使用量がかかり、同じ上限に数えられる |
| 時間 | 同時に任せれば、ひとつずつ順番に待たずに済む | サブエージェントは白紙から始まる。前提を集め直すぶん、時間と使用量がかかる |
| 道具 | 道具を絞れる。読むだけのサブエージェントなら、書き換えの心配がない | 絞りすぎると、サブエージェントが要るファイルを読めない |

- 図解（題「机は別、財布は同じ」）: 使用量の上限は1つ。その下に、メインの机（本題のやり取り）、別の机（資料をたくさん読む）、別の机（別の資料を同時に読む）
- 使う場面・使わない場面（公式の「サブエージェントとメインの会話のどちらを選ぶか」の節を言い換えたもの）

| | サブエージェントに任せる | そのまま頼む |
|---|---|---|
| 作業の量 | 出てくる量が多く、結果だけ分かればよい（例: 長い資料を読んで要約する） | 何度もやり取りしながら直していく（例: 案内文を一緒に練る） |
| 任せ方 | 道具を絞って任せたい（例: 読むだけで確認してほしい） | 計画から仕上げまで、同じ前提を使い続ける |
| 作業の大きさ | ひとまとまりで終わり、要約を返せる（例: 3本の会議メモの要約） | すぐ終わる小さな頼みごと、すぐ答えがほしいとき（例: 1行だけ直す） |

- 「トークン」という語は資料に出さず、「使用量」で通す（2026-10-30・3回目で、使用量の注と用語の一覧の「トークン」を外した）
- 軽いAIで動かす、「短くまとめて返して」と頼む、の2つで使用量を抑えられる（資料では番号つきの行2つ: 軽いAIで動かす／簡単な作業のサブエージェントは「軽いAIで動かして」と頼む。短く返させる／「短くまとめて返して」と頼み、メインに届く量を減らす）

### 8. スキルとの違い（20:00・10分）

- 言いたいこと: スキルは手順書。サブエージェントは、別の机で作業して結果を返す。組み合わせることもできる。
- 判断軸: 手順を決めておきたいならスキル、作業を別の机で済ませたいならサブエージェント。動かしたいほうが決まっているなら、スキルは /、サブエージェントは名前を書いて頼む（必ず動かすなら @）。
- 図解（左右の対比・題「手順書とサブエージェントの違い（要点）」）
  - スキル（手順書）: 今の机で開く／毎回同じ手順で進める／/ を打って呼ぶ
  - サブエージェント: 別の机で作業し、結果だけ返す／調べもの・確認に向く／名前を書くか @ で呼ぶ
- 比較表

| | スキル | サブエージェント |
|---|---|---|
| 中に書くもの | 作業の手順（何を、どの順でするか） | サブエージェントの役目（何をして、何を返すか）と、使える道具・動かすAI |
| どこで動く | 今の会話の中（今の机で開く） | 別の机（別の会話） |
| 向いている作業 | 毎回同じ手順で進めたい作業 | 調べもの・確認など、途中を見なくてよい作業 |
| 名前で呼ぶとき | 入力欄で / を打ち、名前を選ぶ。必ず動く | 名前を書いて頼む（選ばれやすくなる）。@ で名指しすれば、その1回は必ず動く |
| 置き場所 | .claude/skills/ | .claude/agents/（サブエージェントの置き場所） |

- 前の版の「呼ばれ方: どちらも説明（description）で選ばれる」の行は外しました。「同じなら、どちらが先に動くのか」の迷いを生むためです。その答えは、すぐ下の折りたたみに置きます
- 前の版にあった「たとえ」「途中の経過」「作り方」の行は、資料の比較表にはありません（たとえと途中の経過は、すぐ上の図解で見せる）

**スキルとサブエージェント、ここで迷いやすい**（先回りの答え。資料では折りたたみ4つ）

| 迷いやすいこと | 答え |
|---|---|
| どっちが先に動く？ | 決まりは公式に書かれていない。Claude が両方の説明を読んで選ぶ。動かしたいほうが決まっているなら、スキルは /、サブエージェントは名前を書いて頼む（必ず動かすなら @）。 |
| サブエージェントは手順書を使える？ | 使える。持たせれば読んだ状態で動き出す。持たせなくても、必要ならサブエージェントが自分で開く。 |

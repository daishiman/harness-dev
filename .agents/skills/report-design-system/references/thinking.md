# 多角的に考えて、焦点を1つに絞る

30の思考法で角度を広げ、検証可能な説明仮説の筋に絞る。正式な因果推論や反事実効果の推定はしない。設計では候補を出す側、レビューでは疑う側で使う。思考法ごとの感想は残さず、候補・仮説・指摘になったものだけを成果物へ反映する。

## 0. 思考リセット

- 始める前に、依頼者の仮説、前回の結論、自分の第一印象をいったん脇に置く。成果物やファイルは消さない。
- データの概要と内訳の試算だけを見て、読み手が最初に問いそうなことを3つ書き留める。最後に結論と照合する。

## 2. 広げてから絞る

1. impact の大きい枝に、§1 と `causes.md` の型・軸を当てて候補を出す。必要数と許可値は `check-llm.mjs` の診断に従う。
2. 観測結果から 結果 → 中間 → 原因候補 の順に探索し、表示用の 原因候補 → 中間 → 結果 の筋に束ねる。
3. 説明できる大きさ、確かめられるか、時期が合うか、比較対象と一貫するか、読み手の判断を変えるかの順で比べる。
4. 検証する筋だけを `plan.焦点` に書き、主仮説と対立仮説を置く。記述・比較が目的で背景説明が不要なら、無理に原因を作らない。
5. その他は「深掘り」または理由つきの「捨てる」とし、本文に混ぜない。

## 3. 4条件

| 条件 | レポートでの意味 |
|---|---|
| 矛盾なし | 結論・要因・図・打ち手と数値が相反しない |
| 漏れなし | 問いに答える根拠、反証、限界、次に必要なデータが必要な範囲である |
| 整合性あり | 用語・単位・基準・期間・符号と根拠水準が全体でそろう |
| 依存関係整合 | 打ち手→要因→仮説→データと、背景→枝→指標の追跡が切れない |

# Apple的な洗練の背景 — §11-1(触りたさの5要素)を深く理解するための補足

Appleの Human Interface Guidelines と WWDC の Fluid Interfaces に共通するのは、「装飾」ではなく「**道具としての応答性**」を設計の中心に置く姿勢である。ここでは、SKILL.md §11-1 の各問いがどのような考え方に基づくかを補足する。**具体的な数値や実装コードを与えるものではなく、判断の背景となる考え方**を示す。

## 画面を「静止画」ではなく「入力に応答し続ける道具」として扱う

多くのAIっぽい画面は、完成した1枚の絵として設計されている。要素の配置や色は整っているが、**操作した瞬間に何が起きるかが設計されていない**。

Appleの設計チームが繰り返し強調するのは、UIの価値は「見た目」ではなく「触れたときの手応え」で決まるという点である。この手応えは次の要素に分解できる。

- **直接操作**: 対象を間接的な設定画面で動かすのではなく、対象そのものを掴んで動かす・並べ替える・その場で編集する。
- **即応性**: 反応は「処理が完了してから」ではなく「操作を始めた瞬間から」始まる。完了を待たせるほど、操作と結果のつながりが感じられなくなる。
- **中断可能性**: 操作の途中で気が変わっても、最後までやり切らずに引き返せる。取り消せないという前提そのものが、探索的な操作を怖くする。
- **空間的一貫性**: 同じ対象は、画面のどこにあっても同じ規則で動く。ある場所ではクリックで確定、別の場所ではクリックで詳細画面へ移動、というような不一致は「触ってみないと分からない」画面を生む。

## 状態を「作っただけ」で終わらせない

通常状態の画面はどのUIでも作られる。差が出るのは、**通常でない状態**の作り込みである。

- 選択している/していない
- 編集中/保存中/保存済み
- 処理に失敗した/一部だけ失敗した
- 権限がなくて操作できない
- データが空である/まだ読み込み中である

これらは「エラーハンドリング」という後付けの作業ではなく、**通常状態と同じ設計密度で最初から扱うべき状態のバリエーション**である。状態が欠けている画面は、想定外の場面でユーザーに「壊れているのでは」と感じさせる。

## 動きは「説明」のためにある

動きそのものに価値はない。動きが伝えるべきものは次のいずれかに限られる。

- 何が、どこから、どこへ移動したか(位置関係の説明)
- 何の状態が、何に変わったか(状態変化の説明)
- 操作の結果、何が起きた/起きなかったか(因果の説明)

この3つのどれにも当てはまらない動き(すべての要素が同じ調子で浮く・跳ねる・フェードする)は、装飾の反復に過ぎず、§13-1 の装飾除去テストで真っ先に疑うべき対象になる。`prefers-reduced-motion` を有効にしても機能や理解に支障が出ないかどうかは、動きが説明のためだけに使われているかの簡易テストになる。

## 「触りたさ」の設計モデルをレビューに使う

SKILL.md §11-1 の設計モデル(触りたさ = 操作できる手掛かり × 結果の予測可能性 × 即応性 × 可逆性 × 操作による効果)は、実測できる指標ではなく、**レビュー時に弱点を切り分けるための思考の道具**として使う。5つの掛け算のうち、どれか一つでも著しく低いと、他がどれだけ優れていても画面全体の触り心地は低く感じられる。改善が進まないと感じたときは、5要素を個別に採点してみて、最も低いものから着手する。

§11 本文には、この5要素の掛け算に加えて「動きの意味」「処理中ブロッキング」の2項目がある。これらは掛け算の一部ではなく、5要素すべてに横断的に影響する派生チェックである(意味のない動きは即応性の手応えを損ない、画面全体のブロッキングは可逆性や一手の効果を打ち消す)。採点対象は5要素、残り2つはその5要素が守られているかを別角度から確認する問いとして扱う。

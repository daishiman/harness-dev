# Checklist: リスク分散

## 仮説・スコープ(★=Sサイズでも必須)

- [ ] ★ 最リスク仮説がT3に明記され、Slice 0〜1で検証された
- [ ] ★ Non-GoalsがT1の事実・仮説・根拠として明記され、成果物への差分で更新できる/追加要望は新カード運用が守られている
- [ ] 作らずに学べるものを作っていない(モック提示・手動代替の検討記録がある)

## 技術・運用

- [ ] ★ ロールバックが自動で機能する(CI側)/DBマイグレーションは後方互換
- [ ] ★ リスクの高い新機能はフィーチャーフラグ配下(即時撤収可能)
- [ ] 外部API依存に: タイムアウト・リトライ・停止時のフォールバック表示がある
- [ ] 単一障害点の把握(この外部サービスが死んだらどうなるか、をT4に一行)
- [ ] レートリミット・スパム対策(公開フォームにはTurnstile等)
- [ ] コスト暴走ガード(支出アラート設定済み/従量課金APIに上限)

## データ・法務

- [ ] ★ 個人情報の棚卸し(何を・なぜ・どこに・いつまで)がT1に記録済み
- [ ] ★ 削除はゴミ箱方式/バックアップから復元できることを一度試した
- [ ] 監査ログ(誰がいつ何を)が機微操作に入っている
- [ ] 公開サービスの場合: 扱うデータ・販売形態・対象地域からプライバシーポリシー・特商法表記・利用規約の要否を分析し、必要な文面案を先に作成済み。法的確定だけを依頼者へ明示した
- [ ] 権限マトリクス(ロール×操作)がT2にあり、APIハンドラのアクセス制御実装と一致している

# P05 — implementation (実装)

## 目的

P04 のテストを通す最小実装を行い tdd-green を成立させる。決定論パイプライン (構成データ検証 → アセット埋め込み → 図解 → アイコン sprite → レンダリング → 各種検証 → 出力先ルーティング) が LLM 非依存で一気通貫に動く状態にする。

## 背景

実装は依存 DAG の順に進む。共有契約を持つ実体 (アイコン sprite の生成側と未使用検査側、レンダラと逆抽出器) は契約の食い違いが両側同時に発生するため、同一フェーズ内で直列に扱う。

## 前提条件

- P04 で全テストが失敗状態で存在する
- 構成データスキーマが plugin-level surface として確定している

## ドメイン知識

- **標準ライブラリのみ**: script は Python 標準ライブラリのみで書く。外部パッケージ・YAML パーサ・新規シェルスクリプト/JS は用いない
- **fail-soft と fail-closed の使い分け**: 資料の生成を止めてはいけない箇所 (サイズ上限超過・画像生成の委譲先不在) は warning で継続、成果物の正しさに関わる箇所 (外部参照混入・絵文字混入) は fail-closed
- **具体パスを焼かない**: 実行時パスは専用 env と自己解決で求め、絶対パスを実装へ直書きしない
- **プリセットはデータ**: 用途別プリセットは宣言的データとして決定論側に置き、選択だけを対話側が行う。プリセットを手続きとして実装すると用途追加のたびにコードが増える

## 成果物

- 決定論 script 群の実装 (`plugins/guide-doc-generator/scripts/`)
- skill / sub-agent / slash-command / hook の実装
- 構成データスキーマと既定値設定の配置
- 既定テンプレート (資料として最低限成立する部品構成と並び順) の実装
- 用途種別の語彙正本と、6 用途 (勉強会・レクチャー / 定例会議アジェンダ / 一般配布資料 / オンボーディング・導入ガイド / 学習内容のまとめ / 学習計画) のセクション構成プリセットの実装 (語彙とプリセットは同一の宣言データファイル 1 本)
- 対話経路と非対話経路 (検証済み構成データの直渡し) の両方の入口の実装
- 構成データ正規化の実装 (日付既定値の充填と用途プリセット適用を 1 箇所で確定させる単一 writer)
- hook の適用対象パス判定の実装 (資料出力ディレクトリ配下かつ `*.html` のみを検査対象とし、対象外は exit0 で素通し)

### 受入例 (満たす例 / 満たさない例)

- 満たす例: `--normalize` が日付既定値を充填した構成データを 1 箇所で確定し、レンダラ・出力先ルーティング・言語検査がその 1 点だけを読む。委譲先または node ランタイム不在時は skip 理由つきで exit0 になる。
- 満たさない例: レンダラと出力先ルーティングがそれぞれ現在日を取得しており、日付境界をまたぐと本文の日付と出力先ディレクトリ名がずれる。

### 事前解決済み判断

- 日付の単一ソース: 未指定時の既定 (生成実行日) 充填は構成データ正規化の 1 箇所だけ。表示日付と出力先ディレクトリ名はその 1 値から導く。
- 非対話経路の必須性: 対話ヒアリングは既定の入口であって唯一の入口ではない。検証済み構成データの直渡し経路を必ず用意する。
- 混成用途は不可: プリセットの合成は許さない。主用途を 1 つ選び、不足はセクション追加で補う。
- 用途語彙の具体名: lecture / agenda / guide / onboarding / report / proposal / study-notes / study-plan の 8 語を 1 正本に置く。
- テーマの入力経路: 構成データのテーマ欄が正。CLI の --theme は構成データに欄が無い場合のみ有効で、採用値は同梱構成データへ書き戻す。
- hook の適用範囲: 資料出力ディレクトリ配下の *.html だけを検査対象とし、対象外は exit0 で素通しする。
- 画像生成は slide-report-generator へ委譲し再実装しない。SRG 実体または node ランタイムが解決できないときは skip を宣言して exit0 で返す。
- script は Python 標準ライブラリのみで書く (.sh / .js の新規追加と yaml import は行わない)。

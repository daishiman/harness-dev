P03-x-01 の独立判定が検出した 9 件 (blocking 3 / high 2 / medium 3 / info 1) の解消 leaf。P03 phase 本文が成果物として宣言する「指摘に対する設計修正の反映」のうち、P03-x-02 が扱った P02 由来の矛盾 (X-01..X-08) に続く第 2 陣にあたる。

指摘の性質は P03-x-02 が扱った「同じ概念に別名を与えた命名の割れ」とは異なり、**同じ判断を複数の component が別実装で持っている責務重複**と、**writer が誰にも割り当たっていない成果物の穴**が主である。したがって解消は名前を揃えることではなく、判定の所有者を 1 つ選び、他をその参照者へ降格させることで行う。降格させた側には「何を参照するだけか」を残し、再実装の余地を消す。

P04 のテスト先行 leaf 23 本は各 component のブリーフを consume して受入判定を赤で固定するため、本 leaf の完了前にテストを書くと重複した判定基準がテストへ固着する。この順序は task-graph 上の depends_on で強制する。

指摘のうち Y-05 / Y-06 / Y-07 / Y-09 は `index.md` と `component-inventory.json` 側の記述が第二の正本になっている / 宣言辺が漏れている類であり、briefs/ だけを直しても解消しない。したがって write_scope は plan dir 全体とする。ただし `task-graph.json` (構造 SSOT・単一 writer は derive)・`task-specs/`・`evidence/` は本 leaf の対象外で、書き換えてはならない。

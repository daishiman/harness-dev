`P05-x-14` が build 中に発見したタスク。発見理由は次のとおり。

> AC-C01-19 の是正 (P05-x-14) で判明した潜在欠陥。contract_lib.py には body 全体への部分文字列一致で判定する述語が他にも残っており (AC-C01-15 の CR-GATE-AGG / AC-C01-18 の assign-handout-readability-evaluator 等)、reject_cases.py の違反注入が単一 (old,new) ペアである以上、同じ語が本文の別箇所に残ると reject fixture を違反状態にできない。現時点では reject case すべてが検出できておりスイートは緑だが、C01 実装が語を散らせた瞬間に同じ偽緑が復活する。方針決定 (述語を節スコープへ寄せるか REJECT_CASES を複数置換対応にするか) が必要

## 進め方

1. まず `contract_lib.py` の全 AC 述語を列挙し、判定スコープ (body 全体 / 節スコープ / frontmatter) で分類する。件数は本文へ書かず列挙から導出する。
2. 各述語について、`reject_cases.py` の対応 case が本当に違反状態を作れているかを機械的に確認する。確認方法は `test_contract_checker.py:44-54` の `_materialize` と同じ手順 (`ACCEPT_ROOT` 全体を temp へ copytree し `SKILL.md` だけ差し替えて `check_skill(skill_dir)` を呼ぶ) を再現すること。**`check_skill` の引数は skill ディレクトリであり本文文字列ではない。また `prompts/` を欠いた不完全な temp ツリーでは受入 fixture ですら別の AC が発火し、誤った結論に至る** (dispatcher が実際にこの誤りを踏んだ)。
3. 確認できない述語について、(A) 検出条件を節スコープへ寄せる (B) `REJECT_CASES` を複数置換対応にする のどちらを採るかを決め、理由とともに `PREDICATE-SCOPE-POLICY.md` へ記録する。P05-x-14 は (A) を採ったが、その理由は「`_materialize` が `text.count(old)==1` を assert しており reject fixture の設計思想が『1 箇所だけ違反を注入する』であるため」であり、この不変条件を壊す解は退けられている。
4. **既存 assert を弱めない。** 受入基準を満たすためにテスト設計を弱める形の解は不可。
5. `write_scope` の外へは 1 バイトも書かない。範囲外の修正が必要になったら手を出さず、何をどう直すべきかを報告する。
6. テストは Python 3.10+ の標準ライブラリのみ (`unittest`)。pytest / yaml / .sh / .js を使わない。

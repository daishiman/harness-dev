# 述語単点棄却テストの assert を『違反が 1 件以上』から『その変異に対応する述語のメッセージが出ること』へ変える

## 由来

build 実行中に `P04-C09-01` が発見したタスク (change_level=
structural)。本 spec は planner の外ループ (accept-discovered-task.py) が
discovered-task form から決定論生成したものであり、derive 由来の spec と同じ契約で扱う。

**発見理由**: cyan の変異実測で、1 回の変異の中で赤と空振りが割れる現象が直接観測された (handout-build/contract_lib.py:566 の 4 語同型述語で、プリセット解決/ゲート結果が発火し ヒアリング(本文10回)/出力先ルーティング(2回) が沈黙)。述語の形が同一でも検出できるかを決めているのは語の出現回数であって述語の設計ではない。『違反が 1 件以上出る』を assert すると、別述語の巻き添え発火を検出力と誤認する。M-R3/M-R8/M-HA1/M-HB1/M-E1 の 5 件で観測

**発見時の証跡**: `eval-log/guide-doc-generator/build/r25-improvement-2026-08-18/audit/P05-x-89-typeB-remainder.json`

## 作業

`plugins/guide-doc-generator/tests/` の範囲で上記を解消する。編集先 (write_scope) と
完了トークン (produces) は別物である点に注意する — 実体の変更は write_scope 配下へ行い、
完了したことの記録を `plugin-plans/guide-doc-generator/discovered/P05-x-120.md` へ残す。write_scope は複数タスクで共有されうるため
成果物の鍵にはできない (producer 一意制約)。

## 受入条件

PredicateSinglePointRejectabilityTest 相当の assert が、変異に対応する述語の違反メッセージの出現を検査すること。別の述語がたまたま拾っている状態が緑にならないこと

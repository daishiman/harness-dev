## 裁定すべき 5 点

### (a) textPolicy の既定 — overlay-only 固定の撤回

C21 手順 7 は `textPolicy="overlay-only"` / `backgroundSource="none"` を**固定**し「資料本文の文字は HTML 側が持つので画像内に日本語を焼かない。焼き文字は崩れると印刷 (R15) で修正できない」と述べる。しかし参考画像はいずれも短い日本語ラベルを焼き込んでおり、それが「パッと見て分かる」性質の主要因である。

genome 側の `textPolicies["baked-with-overlay"]` は既にこの懸念を解いている:「画像内に短い説明文・吹き出し・簡易表を焼き込む。**overlayText が常に正本**。崩れたら overlay を表示し画像内文字を装飾扱いにする」。R15 の安全弁は overlayText の常時併記で確保されるため、焼き込みと印刷可用性は両立する。

**裁定**: 既定を `baked-with-overlay` にする。`overlay-only` は選択肢として残す (正確な表・料金・頻繁に変わる文言を扱うセクション)。どちらを採っても `overlayText` は必須で、C11 は画像が崩れた場合に overlay を表示できる markup を出す。この「overlayText 必須」を C21 の事前検査へ加える。

### (b) 焼き込みテキストの量的規律

利用者の要件は「文章をやたらと記述するのではなく、重要な要素を抜き出して、その中から大事そうなポイントだけを抽出して記述する」。genome の `patterns["image-only"].rules` は `max 6-8 text blocks per slide` / `each block short and independently readable` を持つが、上限が範囲 (6-8) のままで機械検査にならない。

**裁定すべき確定値** (`P04-x-05` の裁定 A/B/C と同じ原則 — 導出値ではなく不変条件を、かつ範囲ではなく単一値を契約に書く):

- 1 画像あたりの焼き込みテキストブロック数の上限 (単一整数)
- 1 ブロックの最大文字数 (単一整数)。参考画像の実測 (「作れない」4 字 / 「連携要件を言語化できない」12 字 / 「ではどう量産するか？」10 字 / 「AIが自動生成し人は微調整」12 字) を根拠にする
- 句点を含む完全文を焼き込まないこと (要点語・体言止め・短い問いのみ) の判定規則
- 数値強調 (「約94%削減」「約8時間→約30分」) を持つ図では数値を最大級の字面で焼く、を推奨規則として持つか必須規則として持つか

上限値は C11 の `text_limits` (C63 の 180/400/900) と**別系統**であることを明示する。あちらは HTML 本文の折り畳み閾値、こちらは画像内の焼き文字量。混同すると正本が二重化する。

### (c) style family 2 系統と選択規則

参考画像は 2 つの画風を含む:

1. **isometric-diorama** — アイソメ 30 度・ドットグリッド床・角丸プラットフォームタイル・紺 #0B2A55 アウトライン・kanagawa 系の低彩度パレット。SRG 同梱 genome がそのまま該当。
2. **flat-infographic-jp** — フラット正面図・クリーム地・濃緑を支配色に橙をアクセント・大きな数値強調・カード枠で対比 (導入前/導入後) や 3 要素収束を表す・チェックリストと簡易バーで量を示す。**SRG 同梱 genome に該当形が無い。**

**裁定**: 2 系統を選べるようにする。2 の genome は `plugins/guide-doc-generator/genomes/` へ追加する (`P05-x-04` が producer)。genome ファイルを供給することは `build-image-prompts.js --genome <path>` の設定であって画像生成の再実装ではないため、C21 の「委譲先を再実装しない」に抵触しない — この判断の根拠を RESOLUTION へ明記する。

選択規則は決定論にする: 資料の用途種別 (C23 の語彙) と図解型から既定を引き、構成データ側で上書きできる。どちらの family でも「1 セクション 1 メッセージ」「平坦な単色ボックス図の禁止」は共通に効く。`script-brief-C21.json` line 188 の未決 (genome 固定 vs handout 側 vendoring) は本裁定で閉じる。

### (d) 平坦化退化の検査可能な代理指標

genome の `contentAdaptationRules.densityPreservation.degradationBan` は「再生成で平坦化・単純化 (小物の脱落・占有率の低下・ベタ塗りボックス化) が起きたら不合格」と述べるが、生成画像の画素から機械判定はできない。

**裁定**: 判定を**計画とプロンプトの側**へ移す。検査可能な代理指標として少なくとも次を C21 の事前検査に加えるかを決める — 各 slide が `densityLevel` を明示すること / `motifs[]` が genome の `motifs[].name` の部分集合かつ非空であること (既に部分集合検査はある。非空を足すか) / `richnessFloor` (プラットフォーム + 主モチーフ + 小物 1 点以上 + 影) をプロンプトへ毎回明記すること / 生成後 meta の `diagramPrimitives` が空でないこと。画素判定を持ち込まない理由も明記する。

### (e) セクション別内容適応の必須化

利用者の要件は「そのセクションごとで言いたいことは異なってくるので、そのセクションに合わせた画像を生成できるように」。genome の `contentAdaptationRules.notACopyTemplate` が既に「参照デッキの構図を丸写しせず、同じ画風で内容に合う構図・被写体を新規に組む。固定=スタイル仕様、可変=図解の中身」と述べている。

**裁定**: これを C05 (`handout-content-architect`) の執筆規律として明文化する。C05 が `subject` / `diagramStructure` / `overlayText` / `motifs` を書く際、(1) セクションの `goal` と `lead_line` から主要概念・動詞を抽出し (2) genome の `semanticMapping` / `industryObjectTable` で具体物へ写像し (3) 内容構造から図解型を選び (4) 焼き込みは要点語のみ、という 4 段を踏むことを required にする。加えて **同一資料内で図解型と被写体構成が全セクション同一になっていないこと** を C21 の事前検査で見るかを裁定する (「同じ構図を毎回再生産しない」の機械化)。

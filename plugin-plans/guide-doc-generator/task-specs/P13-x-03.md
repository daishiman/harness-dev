dispatcher が配布経路の実測確認で発見したタスク。**計画の事前解決済み判断と利用者要件が正面から矛盾する** 事例。

> `phase-13-release.md` は「本 plugin は repo 内利用を既定とし**配布はしない**」「スコープ外: marketplace への実登録」を事前解決済み判断として明記している。一方で利用者は「ローカル install と GitHub PR 後の marketplace install の**両方**が対応できること」を明示要件として述べた。判断を黙って上書きせず、**裁定として反転した記録を残す**。

## 判定材料 (dispatcher 確認済み・再確認すること)

- `scripts/validate-plugin-completeness.py` の `NEVER_DISTRIBUTE` は `{harness-creator, prompt-creator, plugin-dev-planner}` の 3 件のみ。**guide-doc-generator は対象外**なので、固有名 denylist による恒久ブロックは無い。
- 公開側が拒否するのは `distributable: false` の plugin (MK-004 逆ガード)。よって反転すべき値は `references/package-contract.json` の `distribution.distributable` **1 箇所**であり、manifest 直下への後方互換記述と二重に書かないこと (PAT-6)。
- `lint-readme-plugin-root-portability.py` は非配布 plugin では skip する。配布可へ転じた瞬間に初めて効くため、**現状 green なのは検査されていないから**である可能性が高い。skip が外れた状態で改めて測ること。

## 進め方

1. **裁定を先に書き、実装を後に書く。** `phase-13-release.md` の事前解決済み判断を残したまま実体だけ配布可にしない。裁定文・根拠 (利用者要件)・退けた案 (repo 内利用のみに留める案) を `schemas/RESOLUTION-P13-x-03.md` へ記録する。
2. 登録は `validate-plugin-completeness.py --fix` の append-only 経路を使う。`marketplace.json` / `bundles.json` を手書きしない (既存エントリの値を書き換える事故を避けるため、自動登録が append-only である前提に乗る)。掲載の再確認には `plugins/harness-creator/commands/marketplace-register.md` (本 plan の外にあり producer を持たないため `consumes` には置かない) を使う。
3. **反例を注入する。** `distribution.distributable` を false へ戻した複製で `validate-plugin-completeness.py` が RED になることを確かめる。
4. README に `{{PROJECT_ROOT}}` / `$CLAUDE_PLUGIN_ROOT` 以外の絶対パスが残っていれば解消する。**lint を skip 側へ寄せて通さないこと。**
5. `git stash` を使わないこと。

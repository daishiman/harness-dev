`P05-x-15` が build 中に発見したタスク。発見理由は次のとおり。

> P05-x-15 が argument_hint の正本を `briefs/command-brief-<id>.json#argument_hint` と確定し、inventory を derived-copy として一方向同期に整えた。しかし `tests/handout-extract/contract_lib.py` は `ARGUMENT_HINT = "<html-path> [--out <config.json>]"` という完全文字列リテラルを保持しており、正本を読まずに独自の写しで突合している。これは**正本 3 箇所目**に相当し、brief が変わると同テストだけが古い値で緑を保つ (または誤って赤くなる) 再発経路が残る

## 進め方

1. `RESOLUTION-P05-x-15-argument-hint.md` の §6-1 に**置換後コードが貼り付け可能な形で記載されている**。まずこれを読むこと。ただし dispatcher は当該コードを実行検証していないので、**鵜呑みにせず自分で測ること。**
2. **assert を弱めない。** 現在 `contract_lib.py` は frontmatter と `component-inventory.json` の**双方**へ完全一致を要求している。突合基準が brief へ移るだけで、要求の強さは変わらない。片側の検査を落とす解は不可。
3. **「正本を読む」ことの検証を必ず行う。** リテラルを消しただけでは、テストが本当に brief を見ているかは分からない。brief の値を一時的に書き換えて当該テストが赤くなること、戻して緑に戻ることを実測し、報告に含めること。**この実測が無い変更は「リテラルを別の場所へ移しただけ」と区別できない。**
4. C07 (`handout-build`) と C09 (`handout-verify`) のテストは `ARGUMENT_HINT_TOKENS` という token 集合の形で既に brief を直接ロードしている (P05-x-15 の実測)。**C08 だけが完全文字列リテラルという異質な形**なので、C07/C09 の書き方に寄せられるかを検討すること。ただし C08 は完全文字列一致を要求しており token 集合とは検査の強さが違うため、**単純に真似ると検査が弱くなる**。どちらを採るか決め、理由を報告すること。
5. `write_scope` の外へは 1 バイトも書かない。brief 側 (`plugin-plans/`) は読むだけ。値を一時変更して実測する場合も、**必ず元へ戻したことを確認して報告すること**。
6. 実行前後で `tests/handout-extract` の**失敗テスト名の集合**を採取して比較する (件数だけの比較は並行 build 下で他 leaf の書込と交絡する)。
7. テストは Python 3.10+ の標準ライブラリのみ (`unittest`)。
8. `git stash` を使わない (別 leaf が `git stash pop` で無関係な既存 stash を誤適用する事故を起こしている)。退避が必要ならスクラッチへ `cp` する。

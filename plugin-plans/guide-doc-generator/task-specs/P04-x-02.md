goal-spec C60 の設計反映 leaf。C60 は R01 の拡張として 2026-08-17 に追加された要件で、利用者の要求は「JavaScript・CSS・画像を全て 1 つの HTML に入れ、画像はリンク先の記述ではなく HTML 内に実体を埋め込む。この HTML をデプロイするだけで成立する」である。

欠陥の性質は個別規則の書き漏れではなく**判定方式の選択**にある。SC-01 は外部スキーム (`http://` / `https://` / `//` 等) を持つ URL 属性を、SC-03 は `img@src` 等の列挙された属性を、SC-04 は `<link>` と `@font-face` を、それぞれ**対象を列挙する形**で検査していた。列挙は列挙から漏れたものを黙って通す。実際 `<script src="./app.js">` は SC-03 の属性列挙に `script@src` が無いため通過し、`<iframe src>` はどの規則の対象でもないため通過する。相対パスはスキームを持たないので SC-01 にも掛からない。結果として「外部参照ゼロ」の検査を全通過しながら、その 1 ファイルを配置しただけでは成立しない生成物が作れてしまう。

したがって SC-10 は個別規則の追加ではなく**包括規則**として置き、判定軸を「外部スキームか否か」から「`data:` であるか否か」へ反転させる。取得を発生させ得る参照は、値がどう書かれていようと `data:` でなければ違反とする。これにより将来 HTML に新しい取得属性が増えても既定で違反側へ倒れる (fail-closed)。

境界として維持すべきものが 1 つある。SC-02 が確立した「HTML テキストノードに現れる URL は違反としない」規約である。表示されるだけの文字列は取得を発生させないため、これを違反にすると資料本文で参考 URL に言及できなくなる。SC-10 の適用対象はあくまで**取得を発生させ得る参照**に限る。

本 leaf は P04-C16-01 の後に直列化する。C16 のテストを書く leaf には SC-10 を実行中に伝達済みであり、テストが先に SC-10 を固定してブリーフが後から追いつく順序になる。設計正本がテストに先行するという通常の向きとは逆であり、この逸脱は checklist-verification へ記録する。書き換え対象は `script-brief-C16.json` と本 leaf の記録 `RESOLUTION-C60.md` の 2 つに限る。`script-brief-C16.json` の producer は P02-C16-01 であり (validate-task-graph 規則 (c) により 1 成果物の producer は 1 node に限られる)、本 leaf は producer を名乗らず自身の解決記録 `RESOLUTION-C60.md` を産出物として宣言する。C10 は P03 Y-02/Y-03 の確定どおり C16 の規則を `module_api` 経由で再実行する参照者に留まるため、C10 のブリーフには手を入れない。

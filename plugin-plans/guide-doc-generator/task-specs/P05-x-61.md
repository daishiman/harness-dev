# 用途語彙の物理正本を briefs/config/handout-purposes.json へ出し 3 語彙の照合方法を揃える

## 由来

build 実行中に `P03-x-03` が発見したタスク (change_level=
additive)。本 spec は planner の外ループ (accept-discovered-task.py) が
discovered-task form から決定論生成したものであり、derive 由来の spec と同じ契約で扱う。

**発見理由**: 部品 id (briefs/config/handout-parts.json) と section_kind (briefs/config/handout-sections.json) は中立データファイルへ物理正本を出したのに、用途語彙だけが script-brief-C23.json 内 inline のまま。この非対称が dir_token drift を検出しにくくしている (前二者は出荷ファイルと機械比較できるが用途語彙は brief を parse しないと比較できない)

**発見時の証跡**: `eval-log/guide-doc-generator/build/r25-improvement-2026-08-18/checklist/P03-x-03.json`

## 作業

`plugin-plans/guide-doc-generator/briefs/` の範囲で上記を解消する。編集先 (write_scope) と
完了トークン (produces) は別物である点に注意する — 実体の変更は write_scope 配下へ行い、
完了したことの記録を `plugin-plans/guide-doc-generator/discovered/P05-x-61.md` へ残す。write_scope は複数タスクで共有されうるため
成果物の鍵にはできない (producer 一意制約)。

## 受入条件

用途語彙が中立データファイルへ出て、部品 id / section_kind と同じ方法 (出荷ファイルとの機械比較) で照合できること。P05-x-58 の裁定を先に取り込むこと

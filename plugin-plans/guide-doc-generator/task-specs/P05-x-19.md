`P05-x-13` が build 中に発見したタスク。発見理由は次のとおり。

> P05-x-13 が script-brief-C20.json の heuristic_fallback.class_map へ B16 / B17 / DIAGRAM / IMG の 4 行を追加したが、W-EXTRACT-CATALOG-DRIFT の発火判定は実装のモジュール定数 PART_CLASS_MAP (scripts/extract-handout-config.py:61-76) とカタログの突合で行われ、抽出器は実行時に brief を読まない。よって repo 実測の stderr は 4 行のまま。実装を brief へ追随させる受け皿が要る

## 進め方

1. `PART_CLASS_MAP` (`:61-76`) へ 4 行を追加する。クラス名は C11 の実出力から採られており dispatcher が実在を独立確認済み:
   - `B16` = `action-items` (`render-handout.py:750`) / `ai-row` (`:745`)
   - `B17` = `handson` (`:766`) / `hs-row` (`:763`)
   - `DIAGRAM` = `diagram` (`:817`)、かつ svg 側に `data-hb-kind="figure"` (`:813`)
   - `IMG` = `asset-img` (`:780`)
2. **`TEXT` 行は最後に置く。** `FALLBACK_PART_ROW = "TEXT"` (`:78`) は本文の受け皿でクラス名でなくタグ名照合をするため、順序に意味がある。
3. **drift 検査本体 (`:261-267`) を 1 行も変えない。** 受入基準が明示的に禁じている「警告条件そのものを削除して黙らせる解」に当たる。
4. 検査を殺していないことを 2 通りの反例で確認する。P05-x-13 の worker は shadow コピー上で (a) カタログへ heuristic 経路の無い部品を追加 → 「カタログにあるが照合表に鍵が無い」が発火、(b) カタログから既存部品を削除 → 逆向きの「照合表の鍵にあるがカタログに無い」+ `E-EXTRACT-UNRECOVERABLE` / exit 1 が発火、を実測している。**dispatcher はこの shadow 実測を再現していないので、鵜呑みにせず自分で測ること。**
5. 未確定事項が 1 件ある: マーカー無しの手書き HTML では `figure.asset` が無く裸の `<img>` になり得る。P05-x-13 は brief の IMG 行へ「本文中の単独 `<img>` を含む」と推測で付記したが、shadow 検証は `("asset", "asset-img")` のみで正常系 0 行・全緑を確認している。**裸 `<img>` を拾うかどうかは本 leaf で決めてよい。** 決めた内容と理由を報告すること。
6. `write_scope` の外へは 1 バイトも書かない。`script-brief-C20.json` の stderr 契約行は P05-x-16 が編集するため触らない。
7. **テストの assert を弱めない。** テストは Python 3.10+ の標準ライブラリのみ (`unittest`)。
8. 作業内容と 4-5 の判断を `scripts/RESOLUTION-P05-x-19.md` へ記録する (これが本 leaf の産出成果物)。

## 本 leaf の担当外 (混同しないこと)

`PART_CLASS_MAP` そのものの**存置可否**は本 leaf の担当ではない。`P05-x-07` が、この表が `AC-C11-19` (カタログ外に部品 id リテラルを置かない) と `tests/extract-handout-config.py/test_parts_catalog_ssot.py` (C20 は部品 id をキーとする dict をちょうど 1 個持つこと) の**両立不能な二重契約 (PAT-7)** の只中にあることを実測で確定させ blocked になっている。裁定は `P05-x-23` が担当する。

本 leaf は「**表が今後も存在する**」という前提の下で行の中身だけを brief へ追随させる。表を消す・別ファイルへ移す・SSOT テストを弱めるのはいずれも本 leaf の解ではない。`P05-x-23` が表を catalog へ畳み込む裁定を下した場合、本 leaf の 4 行はその過程で catalog 側へ移送される (作業が無駄になるわけではなく、移送元が正しい状態になっている必要がある)。

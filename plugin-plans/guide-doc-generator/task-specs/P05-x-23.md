`P05-x-07` が build 中に発見したタスク。発見理由は次のとおり。

> `AC-C11-19` (カタログ外に部品 id リテラルを置かない) を満たすには `extract-handout-config.py:62-74` の `PART_CLASS_MAP` 13 行を消すしかないが、`tests/extract-handout-config.py/test_parts_catalog_ssot.py` は `_class_map()` で「キーが全て部品 id 正規表現に一致する dict が C20 にちょうど 1 個存在すること」を assert しており、消すと赤くなる。**両契約は同時に満たせない (PAT-7 = 両立不能な二重契約)**。P05-x-07 の worker は assert を弱める逃げ道も、表を `config/` へ移して grep 走査範囲から外す Goodhart 的回避も、どちらも正しく退けて停止した

## 真因

対立しているのは「テストどうし」ではなく、**『部品 id → CSS クラス名』という写像そのものの owner が未決定であること**。写像を保持する側は必然的に部品 id を列挙する。よって「id を列挙してよい唯一の場所」と「写像を持つ場所」が別々に決まっている限り、片方が必ず違反する。

## 進め方

1. **まず自分で測る。** `plugins/guide-doc-generator/tests/render-handout.py/` へ cd して `test_part_ids_are_not_enumerated_outside_the_catalog` を単体実行し、offenders 一覧を採取する。dispatcher の実測では 13 件で全て `extract-handout-config.py:62-74` だが、**他 leaf の書込で状況が変わっている可能性があるため鵜呑みにしない**。
2. `test_parts_catalog_ssot.py` の `_class_map()` と docstring を読み、**何が要求されているかを自分の言葉で言い直す**。dispatcher の読解では「C20 が部品 id をキーとする dict をちょうど 1 個持つこと」だが、`dir(module)` 走査ベースなので**dict の由来 (リテラルか導出か) までは縛っていない可能性がある**。ここが解の分かれ目なので実装を読んで確かめること。
3. **本命の解 (a): 写像をカタログの 1 列へ畳み込む。** `config/handout-parts.json` の各行へ `selector_class` を持たせ、`PART_CLASS_MAP` を**カタログから実行時に構築する導出値**にする。こうすると:
   - 部品 id のリテラルは カタログ 1 箇所だけになり `AC-C11-19` を満たす。
   - C20 には依然「部品 id をキーとする dict」が実行時に存在するので `_class_map()` の assert も満たせる (リテラルでないだけ)。
   - `_meta.rule` の「part id をこのファイル以外の場所へ列挙しない」という宣言とも整合する。
   ただし **2 の読解が『リテラルであること』を要求していた場合この解は成立しない**。その場合は解 (b) へ進む。
4. **代替の解 (b): SSOT テスト側の要求を書き換える。** 「部品 id をキーに持つ dict が 1 個ある」でなく「カタログから導出した写像を使っている」を検査する形にする。**これは assert を弱める変更に見えやすいので、弱めていないことを示す責任が本 leaf にある** — 具体的には、カタログから行を削ったとき / 照合表だけを勝手に足したとき の 2 方向の反例を作り、書き換え後のテストが**どちらでも赤くなる**ことを実測すること。片方向しか検出できない形にしたらそれは弱体化。
5. **drift 検査 (`extract-handout-config.py:261-268`) を殺さない。** 写像が導出値になると「カタログと照合表の食い違い」が原理上起きなくなり、`W-EXTRACT-CATALOG-DRIFT` が**永久に鳴らない死んだ検査**へ退化しうる。退化させる場合は「なぜ不要になったか」を裁定文書へ書き、検査を消すか意味を保つ形へ作り替えるかを決めること。**黙って死んだまま残すのは PAT-8 (常時発火/常時沈黙による鈍麻) の裏返しであり不可。**
6. **`verify-handout-a11y-print.py` の既存方式を壊さない。** P05-x-07 がこの script を `data_block_type` 述語でカタログを引く形へ変えており (`load_part_ids_by_block_type()` / `CatalogError` / exit 2)、カタログのスキーマへ列を足す場合はこの読み手も同時に成立させること。
7. **カタログのスキーマ変更は下流を持つ。** `config/handout-parts.json` の `_meta.source_of_truth` は `plugin-plans/guide-doc-generator/briefs/config/handout-parts.json` を指す。plan 側は write_scope 外なので**触らず、何をどう追随させるべきかを報告する**。
8. `write_scope` は `plugins/guide-doc-generator` と広い。**広いのは 3 つのファイル (scripts / config / tests) を同時に成立させないと解けないためであって、ついでの修正を許す意味ではない。** 本裁定に必要な最小の変更に留め、範囲外に見える修正が要ると判断したら手を出さず報告する。
9. 実行前後で `tests/render-handout.py` / `tests/extract-handout-config.py` / `tests/verify-handout-a11y-print.py` の**失敗テスト名の集合**を採取して比較する (件数だけの比較は並行 build 下で他 leaf の書込と交絡する)。
10. 裁定内容・採った解・**退けた解とその理由**を `schemas/PART-CLASS-MAP-RESOLUTION.md` へ記録する (これが本 leaf の産出成果物)。
11. テストは Python 3.10+ の標準ライブラリのみ (`unittest`)。`git stash` を使わない (別 leaf が `git stash pop` で無関係な既存 stash を誤適用する事故を起こしている)。退避が必要ならスクラッチへ `cp` する。

# build-script-route.py が current handoff の構造化証跡を書かず script route が全滅していた (dispatcher が修正済・要レビュー)

## 由来

build 実行中に `P04-C16-01` が発見したタスク (change_level=
structural)。本 spec は planner の外ループ (accept-discovered-task.py) が
discovered-task form から決定論生成したものであり、derive 由来の spec と同じ契約で扱う。

**発見理由**: build-script-route.py が current handoff (task_graph_ref 付き) の success report に必要な構造化証跡を一切書いておらず、task-graph mode の script route が全滅していた。実測した欠陥は 3 つ重なっていた。(1) :406 と :129 の validate_route 呼出しが plan_dir を渡しておらず、validate_current_handoff_evidence が『plan_dir/repo_root が無く structured evidence を検証できない』で必ず落ちていた。つまり検査が成立しないまま fail-closed していた (status=skipped の route だけが早期 return で通過するため、既存テストは緑のままこの欠陥を見逃していた)。(2) plan_dir を渡すと本来の検査が動き、writer が artifact_sha256 / graph_hash / test_evidence / generated_at / tool_versions の 5 つを一つも書いていないことが露見した。schema (route-build-report.schema.json) と validator は拡張済みで writer だけが取り残された順向きドリフト。(3) component の test suite を discover する起動形が成立しない。test ディレクトリ名が component 名そのもの (script は .py 付き) のため -t にリポジトリルートを置くと Start directory is not importable で落ちる。cwd を test dir に置く形でのみ成立する。dispatcher が 3 点とも修正し、harness-creator の全テスト 974 件が緑であることを確認した。結果 C13/C14/C15/C16/C17/C21 の 6 route が実測証跡付きで success になり、C23 は既知の赤 2 件 (DT-1) を持つため failure を正しく名乗る。既存テスト test_build_script_route_report_omits_covered_task_ids_without_graph の assert は『current handoff』という文字列を見ていたが、それは検査が成立していない状態の文言であり graph 不在の検出ではなかったため、task_graph_ref を見る形へ書き換えた。この修正は harness-creator 側の変更であり、本 cycle の write_scope (guide-doc-generator の tests のみ) の外で dispatcher が判断して行ったものなので、レビューを要する。

**発見時の証跡**: `plugins/harness-creator/scripts/build-script-route.py`

## 作業

`plugins/harness-creator/` の範囲で上記を解消する。編集先 (write_scope) と
完了トークン (produces) は別物である点に注意する — 実体の変更は write_scope 配下へ行い、
完了したことの記録を `plugin-plans/guide-doc-generator/discovered/P05-x-82.md` へ残す。write_scope は複数タスクで共有されうるため
成果物の鍵にはできない (producer 一意制約)。

## 受入条件

dispatcher が write_scope 外で行った plugins/harness-creator/scripts/build-script-route.py の 3 点修正 (validate_route への plan_dir 伝播 / artifact_sha256・graph_hash・test_evidence・generated_at・tool_versions の writer 追加 / test discover の起動形) を差分単位でレビューし採否を記録する。採用する場合は harness-creator の全テストが緑であることを再実行で確認し、plan_dir を落とす変異が『検査が成立しないまま fail-closed』ではなく明示的な赤になることを実測する。

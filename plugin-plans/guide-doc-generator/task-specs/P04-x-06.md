## テストハーネス欠陥 (裁定不要・P05-C14-01 の実装過程で dispatcher が実測確認済み)

正本の解釈ではなく、テスト側のコードが構造上どんな正しい実装でも通さない欠陥。裁定を要さないため `P04-x-05` の判断を待たずに修正してよい。

| ID | 場所 | 欠陥 |
| --- | --- | --- |
| H-01 | `tests/render-diagram-svg.py/_harness.py` の `Element.get` | `_Collector` が `html.parser.HTMLParser` を使うため属性名が必ず小文字化される (`parse_starttag` 内 `attrname.lower()`) 一方、`Element.get` は大文字小文字を区別する。SVG 仕様上 `viewBox` はキャメルケースで書かねばならないため、`get("viewBox")` を引く 5 テスト (`test_default_width_is_860` / `test_explicit_width_is_reflected_in_viewbox` / `test_viewbox_numbers_are_integers` / `test_cycle_is_symmetric_about_the_canvas_center` / `test_height_grows_with_content`) は生成側から満たしようがない。修正は `Element.get` を case-insensitive にするか `attrs` へ元表記キーも保持する |
| H-02 | `test_argv_and_exit_codes.py:140` `test_stdin_is_not_used` | `path.read_text()` を `tempfile.TemporaryDirectory()` の `with` ブロックの外で呼んでおり、削除済みディレクトリを読んで `FileNotFoundError` になる |
| H-03 | `test_argv_and_exit_codes.py:111` `test_width_float_is_exit2` | `assertEqual(res.returncode, 2, res, "--width は正整数のみ")` と位置引数 4 個で呼んでおり `TypeError`。`assertEqual` は msg 1 個しか取らない |

H-01..H-03 のいずれも、要求されている振る舞い自体は実装が満たしていることを dispatcher が実測で確認している (`eval-log/guide-doc-generator/build/route-P05-C14-01.json`)。修正後にこの 3 群が緑になるのは受入基準の消滅ではなく、ハーネスが初めて実装を判定できるようになったことを意味する。

## 禁止事項

**受入基準を緩めない。** 本 leaf が行うのは「古い正本の写しを新しい正本の写しへ差し替える」ことに限る。assert の削除・許容範囲の拡大・skip の追加はいずれも緩和であり行わない。差し替え前後で固定している性質が変わらないことを `P04-x-06-ALIGNMENT.md` へ 1 件ずつ書く。

**緑にしない (H-01..H-03 を除く)。** P04 の契約はテストを赤として固定することである。追従後も実装不在ゆえ赤であり続けるのが正しい状態で、追従作業の過程でテストが緑になった場合は、それは受入基準が消えた徴候として `P04-x-06-ALIGNMENT.md` へ記録し `P04-x-01` の集約判断へ回す。例外は H-01..H-03 で、これらは実装が既に存在する `render-diagram-svg.py` を判定できるようになった結果として緑になるのが正しい。

テストは Python 3.10+ 標準ライブラリのみの `unittest` とし、`setUpClass` 内で例外を投げる構造を新たに増やさない。

産出物は `P04-x-06-ALIGNMENT.md` に限る。各テストディレクトリ自体は `P04-C<nn>-01` が producer であり、規則 (c) により本 leaf は producer を名乗れない。

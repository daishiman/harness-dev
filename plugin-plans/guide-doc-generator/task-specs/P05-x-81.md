# handoff の plugin-scaffold script route が script_path を repo 相対で書き draft build 全体を止めていた

## 由来

build 実行中に `P04-C23-01` が発見したタスク (change_level=
structural)。本 spec は planner の外ループ (accept-discovered-task.py) が
discovered-task form から決定論生成したものであり、derive 由来の spec と同じ契約で扱う。

**発見理由**: build-script-route.py:222-226 は builder=plugin-scaffold の route に対し build_target == 'plugins/<slug>/' + build_args.script_path を要求する (script_path は plugin-root 相対)。planner が生成した handoff は 13 route すべてで script_path を repo 相対 ('plugins/guide-doc-generator/scripts/x.py') で書いており、期待値がパス二重化して全 route が ok:false で落ちた。draft stage の generation_queue 9 件のうち 7 件が script route であるため、draft build 全体がここで止まっていた。正本は run-plugin-dev-plan/examples/sample-plan/handoff-run-plugin-dev-plan.json (C09/C10 とも script_path='scripts/x.py') であり、planner 側の emitter が誤り。dispatcher が本 cycle の handoff 13 route を plugin-root 相対へ修正し parity exit0 を確認済みだが、planner の emitter 自体は未修正のため plan を再生成すると再発する。placement_scope='plugin-root' という宣言と値の基準が矛盾していても誰も落とさない点が構造的欠陥で、check-build-handoff.py にこの関係式の検査を足すべき。

**発見時の証跡**: `plugin-plans/guide-doc-generator/handoff-run-plugin-dev-plan.json`

## 作業

`plugin-plans/guide-doc-generator/` の範囲で上記を解消する。編集先 (write_scope) と
完了トークン (produces) は別物である点に注意する — 実体の変更は write_scope 配下へ行い、
完了したことの記録を `plugin-plans/guide-doc-generator/discovered/P05-x-81.md` へ残す。write_scope は複数タスクで共有されうるため
成果物の鍵にはできない (producer 一意制約)。

## 受入条件

check-build-handoff.py へ placement_scope と script_path の基準一致を検査する規則を追加し、script_path を repo 相対で書いた script route を含む handoff で exit 非 0 になることを実測する。あわせて planner の handoff emitter を plugin-root 相対で出すよう修正し、plan を再生成しても再発しないことを examples/sample-plan/handoff-run-plugin-dev-plan.json (C09/C10 とも script_path='scripts/x.py') との一致で確認する。

`P05-x-20` が build 中に発見したタスク。**PAT-7 (両立不能な二重契約)** の新規事例で、受け皿が無い (PAT-4)。

> `tests/extract-handout-config.py/test_marker_extraction.py` の AC-C20-06 は、同一 `assets[]` エントリに**原本相対パス** (`src == "assets/shot-1.png"`) と **data URI 本体**の両方が残ることを要求する。しかし `schemas/handout-config.schema.json` の `assets[]` は `src` 1 本しか持たない。一方 `schemas/ROUNDTRIP-CONTRACT.md` の裁定は「data URI は捨てる」「`data_uri` キーを発明しない」。したがって裁定を実装すると現在 green の 2 件が赤へ転じ、テストを満たすと裁定に反する。

## 進め方

1. **まず 3 者を並べて読む。** どれが後から書かれたか、どれが実装を追認しただけかを履歴から確かめる。「テストが正しい」「裁定が正しい」を先に決めてから読まないこと。
2. **判定材料 (dispatcher 確認済み・再確認すること)**: renderer 内部の `_project_asset` が作る `data_uri` キーは**描画モデル上の一時値**であり、`--config-out` は投影前の入力を書き戻す。よってこれは裁定が禁じる「復元結果への新設」には当たらない。この区別が裁定の分かれ目になる。
3. 3 つの取り得る決着を列挙し、採らなかったものの理由も書くこと:
   - (A) 裁定を正本とし AC-C20-06 を書き換える → 現在 green の 2 件をどう置き換えるかを示す。**assert を単に削るのは不可**。data URI が捨てられていること自体を検査する形へ移す。
   - (B) テストを正本とし schema へ第 2 フィールドを足す → 「同じ事実を運ぶ 2 本目のフィールド」を増やすことになり PAT-1 に反する。採るなら反論を書くこと。
   - (C) 原本パスと data URI が**別の段**に属することを認め、どちらの段の契約かを明示して両立させる。
4. 決着を `schemas/RESOLUTION-P05-x-28.md` へ記録する (本 leaf の産出成果物)。裁定文・根拠・退けた案とその理由を含めること。
5. 着手前に 4 スイートの失敗テスト名を採取し、完了後に**名前集合の差分**で判定する。件数では判定しない。
6. `git stash` を使わないこと。退避が要る場合はスクラッチへ `cp` し、戻したことを報告に含める。

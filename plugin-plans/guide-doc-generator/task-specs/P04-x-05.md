P04 のテスト実装が発見した設計正本の欠陥を裁定する leaf。いずれも「テスト側で回避すると実装が誤った正本に従って固まる」性質のものであり、P05 の実装 leaf を解禁する前に決着させる必要がある。

## 裁定対象

### G-03 — C15 の絵文字判定が C16 の禁じた方法を使っている

`script-brief-C15.json` の algorithm 手順 4 が `U+1F300-1FAFF` / `U+2600-27BF` / `U+2190-21FF` / `U+FE0F` を直接ハードコードしている。これは C16 の `CR-EMOJI` が明文で禁じた方法そのもの (「Unicode ブロック丸ごとの denylist (U+2600-U+27BF 等) は用いない」)。さらに `CR-EMOJI` は `✔ U+2714` を**通過させるべき文字**として名指しているが、C15 の denylist は `U+2600-27BF` に含めて弾く。同一 plugin 内で同じ概念に 2 つの矛盾する判定が存在する。

裁定方針: 絵文字判定の正本は C16 の `CR-EMOJI` 一箇所とし、C15 はそれを参照する。C15 に独自の Unicode 範囲列挙を持たせない。C60 の SC-10 で確立した denylist→allowlist の反転と同じ構造 (`RESOLUTION-C60.md` 参照)。

### G-04 — 同梱アセットに producer が存在しない

`plugins/guide-doc-generator/assets/` 配下の資産 (R10 の jp-web-design 由来トークン・マスコット SVG、C15 が読むアイコンセット、C63 が数値の正本を置くテーマトークン) は、どの task-spec の `produces` にも現れない。`grep -ln "assets/" task-specs/*.md` が 0 件を返す。C15 の `icon-set.json` だけの問題ではなく、vendoring 資産全体の producer 不在である。

裁定方針: C15 の `produces` へ 1 行足すのではなく、同梱アセットを実体化する build leaf を 1 本立てる (`P05-x-01`)。C15 に載せると C11 が読むテーマトークンの producer 不在が残り、かつ C15 の write_scope (単一スクリプトファイル) と `produces` が乖離する。

### A — C23 のプリセット鍵面の矛盾

`script-brief-C23.json` の `structural_guarantee` が「プリセット鍵はちょうど 5 個」を保証するのに対し、R22 で追加した `granularity_defaults` が 6 個目の鍵として現れる。既存テスト `test_r20_invariants.PresetKeySurfaceTest.test_preset_keys_are_within_allowed_five` と両立しない。P04-x-04 は格納形を問わないモジュール API 経由の検査に留めて裁定を本 leaf へ回した。

裁定にあたり区別すべきこと: 「ちょうど 5 個」が守っている不変条件は**プリセット 1 件が返す構成データの鍵面**であって、`granularity_defaults` は**プリセット定義の外側にある doc_type→既定値の対応表**である。両者を同じ鍵面として数えているかどうかを先に確定する。

### B — C22 の検出件数と CLI 契約の固定順

`script-brief-C22.json` は R22 で検出が 10 件になったが、既存テスト `test_cli_contract.py` が `NAR-01..08` の 8 件ちょうどを `assertEqual` で固定している。実装は両方を同時に満たせない。

裁定方針: ブリーフが正本であり検出は 10 件。既存テストの 8 固定は正本が 8 件だった時点の写しであって受入基準の本体ではないため、10 件への更新はテストの**緩和ではなく追従**である。ただしテストの物理的更新は本 leaf の write_scope 外ゆえ `P04-x-06` が行う。

### C — C64 の既定値が全語彙を覆っていない

`granularity_defaults.defaults` が doc_type 7 種のみを持ち、語彙 slug の `proposal` に既定が無い。C64 は「無回答でも既定を採用して停止しない」を要求するので、`proposal` を選んだ利用者が無回答だと停止する。

裁定にあたり確定すること: 全語彙へ既定を明示列挙するか、列挙外に対する fallback 既定 (`standard` / `none` 等) を 1 つ置くか。後者を選ぶ場合、R17 の種別語彙 (lecture / guide / onboarding / report / proposal) が将来増えたときに黙って fallback へ落ちる挙動が C64 の意図に沿うかを根拠として書く。

## 産出物

産出物は `RESOLUTION-P04-x-05.md` に限る。反映先の各ブリーフは P02/P03 の leaf が producer であり、規則 (c) により本 leaf は producer を名乗れない (Edit による更新は行うが `produces` には宣言しない)。本 leaf は `P04-x-04` の後に直列化する (write_scope が briefs/ で重なる)。

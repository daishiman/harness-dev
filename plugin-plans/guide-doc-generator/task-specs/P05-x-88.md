# 再現性の面が語のヒットで充足と誤判定されていないか受入テスト全体を横断確認する

## 由来

build 実行中に `P04-C01-01` が発見したタスク (change_level=
structural)。本 spec は planner の外ループ (accept-discovered-task.py) が
discovered-task form から決定論生成したものであり、derive 由来の spec と同じ契約で扱う。

**発見理由**: 決定論スクリプトへの委譲という語のヒットを再現性の面の充足と読める構造がある。本ノードでは二件とも再現性が空だったが事前検索では多数ヒットしていた。他の受入テストノードが同じ読み違いをしている可能性が高い

**発見時の証跡**: `eval-log/guide-doc-generator/build/r25-improvement-2026-08-18/`

## 作業

`eval-log/guide-doc-generator/` の範囲で上記を解消する。編集先 (write_scope) と
完了トークン (produces) は別物である点に注意する — 実体の変更は write_scope 配下へ行い、
完了したことの記録を `plugin-plans/guide-doc-generator/discovered/P05-x-88.md` へ残す。write_scope は複数タスクで共有されうるため
成果物の鍵にはできない (producer 一意制約)。

## 受入条件

受入テスト全ノードについて再現性の面が検出力を持つかを変異で確認する。判定器へ非決定性 (順序 shuffle 等) を注入して赤にならないノードを空ゲートとして列挙し、件数と対象 id を記録する。語のヒット (determin / 決定) を充足の根拠に使わず、根拠列には変異の結果のみを載せる。

# dir_token の正本を 1 つに裁定し出荷と brief を一致させる

## 由来

build 実行中に `P03-x-03` が発見したタスク (change_level=
structural)。本 spec は planner の外ループ (accept-discovered-task.py) が
discovered-task form から決定論生成したものであり、derive 由来の spec と同じ契約で扱う。

**発見理由**: 用途語彙 dir_token の正本が 2 つ。出荷 config は和文 8 件・brief vocabulary_ssot は ASCII slug 8 件で 8/8 不一致なのに出荷 _meta.source_of_truth は brief を正本と宣言。さらに出荷 resolve-handout-preset.py:329 _dir_token_is_safe() が brief 手順 4(d) の fail-closed 検査を文字種不問へ緩和し、正本側の契約を実装で無効化している。緩和の根拠 (:86) は R25/REQ-6 で dir_token がパスから外れた時点で失効。dispatcher が両ファイルと実装を直読みして確認

**発見時の証跡**: `eval-log/guide-doc-generator/build/r25-improvement-2026-08-18/checklist/P03-x-03.json`

## 作業

`plugins/guide-doc-generator/` の範囲で上記を解消する。編集先 (write_scope) と
完了トークン (produces) は別物である点に注意する — 実体の変更は write_scope 配下へ行い、
完了したことの記録を `plugin-plans/guide-doc-generator/discovered/P05-x-58.md` へ残す。write_scope は複数タスクで共有されうるため
成果物の鍵にはできない (producer 一意制約)。

## 受入条件

dir_token の値域が出荷 config と script-brief-C23.json#vocabulary_ssot で一致し、_dir_token_is_safe の検査が採用した正本の契約と同一になること。ASCII slug へ戻すか和文を維持するかの裁定理由が記録されていること — 日本語ディレクトリ名は slug が運ぶため R5 はどちらでも壊れないが、索引メタデータとしての望ましい形は別問題であり、決めずに片方だけ直すと再び正本が 2 つになる

## ブリーフの owner 宣言と本 leaf の関係 (誤読を避けるための明示)

ブリーフの「単独 owner は C11」は**語彙の正本がどこにあるかの宣言 (canon authority)** であり、「そのファイルを誰が書くか (write authority)」ではない。`write_scope` は非空 string 1 本しか取れない仕様 (`derive-task-graph.py:173` / `validate-task-graph.py:416`) なので、`scripts/<x>.py` を持つ component leaf が同時に `config/<y>.json` を持つことは構造上できない。

本 leaf は write authority を単独で引き受け、canon authority はブリーフ宣言のまま各 component に残す。この分離は望ましい副作用を持つ:

- **script が自分の語彙を書き換えられない**。C11 の「part id を実装へ列挙しない」・C12 の「閾値を script へ書かない」・C23 の「他 component は語彙を一切列挙しない」は、いずれも「データとそれを読むコードを分ける」ことを要求している。write_scope の分離はこれを構造として保証する (`P05-x-02` が `assets/` に対して行ったのと同じ形)。
- 語彙の追加・プリセットの差し替えが script 変更を伴わないことが、レビューなしに graph から読める。

逆向きの禁止: **C11 / C12 / C19 / C23 の build leaf は `config/` へ 1 バイトも書かない。**

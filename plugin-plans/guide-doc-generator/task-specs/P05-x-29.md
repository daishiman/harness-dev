`P05-x-23` の完了後に **dispatcher が反例注入で実測して発見**したタスク。現時点で実害はゼロだが、抜け道が開いたままである。

> `tests/render-handout.py/_harness.py` の `scannable_sources()` は `scripts/` 配下で `SCRIPT_EXECUTABLE_SUFFIXES = (".py",)` 以外を走査対象から外す。よって `scripts/part-map.json` のようなデータファイルへ部品 id の名簿を置くと AC-C11-19 が検出しない。これは P05-x-23 の worker 自身が「表を `config/` へ移して走査から外す Goodhart 的回避」として**明示的に退けた経路と同じ効果**を持つ。

## 進め方

1. **narrowing の判断基準を変えないこと。** P05-x-23 が確立した基準は「そのテキストを何かが読むか (実行される / 指示として読み込まれる)」の 1 本である。`scripts/*.json` は**プログラムが読む**ので本来は対象であるべき。基準を増やすのではなく、実装が基準を正しく写していない点を直す。
2. 除外してよいのは次の 2 種類だけ、という現行の意図を保つ:
   - Python のコメントと docstring (実行されない)
   - `scripts/` 配下で**何にも読み込まれない**非実行ファイル
   `.json` は 2 番目に該当しない。`.md` の作業記録は該当する。
3. **反例を両方向で注入して実測する** (片方向だけでは「直った」と「到達していない」が区別できない):
   - RED を期待: `scripts/<何か>.json` に部品 id の名簿
   - GREEN を期待: `scripts/<何か>.md` の散文、`.py` の docstring / コメント内の散文
4. **リポジトリ上の正本を汚さないこと。** 走査対象ディレクトリをスクラッチへ複写して `H.PLUGIN_ROOT` を monkeypatch するか、`importlib` + メモリ上の `deepcopy` で行う。**復元手順が無ければ復元失敗も起きない**。並行して動く他 worker への影響をゼロにする。
5. `.pyc` など生成物の扱いも明示すること (現状 `scripts/` 配下の非 `.py` は `.md` 2 件と `.pyc` のみ)。
6. 判断と実測結果を `tests/RESOLUTION-P05-x-29.md` へ記録する (本 leaf の産出成果物)。**反例ごとに期待と実測を並べて書くこと**。
7. `git stash` を使わないこと。

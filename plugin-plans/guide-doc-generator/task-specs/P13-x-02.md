dispatcher が配布経路の実測確認で発見したタスク。**受け皿消滅 (PAT-4)** の事例。

> `component-inventory.json` の `plugin_level_surfaces` は `manifest` (`.claude-plugin/plugin.json`)・`composition` (`plugin-composition.yaml`)・`harness_eval` (`EVALS.json`) をいずれも `required: true` と宣言している。しかし task-graph 136 node のうち、これらを `produces` する node が 1 つも無い。結果として `hook-validate-plugin-plan.py` が全 Edit で `guide-doc-generator: .claude-plugin/plugin.json missing` を出し続ける常時発火状態 (PAT-8) になっており、警告が鈍麻していた。

## 進め方

1. **既存 plugin の形を正本として写す。** `plugins/slide-report-generator/` など既に両経路で動いている plugin の `.claude-plugin/plugin.json` と `references/package-contract.json` を読み、鍵と値域を合わせる。schema は `plugins/harness-creator/skills/ref-pkg-contract/schemas/package-contract.schema.json`。
2. **`distributable` の値をここで決めないこと。** 本 leaf の責務はローカル経路 (非配布でも通る) の成立まで。公開可否の裁定と公開 marketplace 登録は `P13-x-03` が持つ。ここでは既定の非配布で置き、`P13-x-03` が反転させる。二箇所で値を書くと PAT-6 (派生正本の未同期) になる。
3. `version` は手で採番せず、`scripts/build-plugin-release.py` の採番規約に従える形にしておく (build metadata を持たせない)。
4. **掲載を実測する。** `python3 scripts/build-local-marketplace.py --out <scratch> --name harness-local` をスクラッチ出力で走らせ、`plugins[]` に guide-doc-generator が現れることを目視でなく JSON から確認する。リポジトリ上の `marketplaces/local/` を先に書き換えない。
5. **反例を注入する。** `plugin.json` の必須鍵を 1 つ落とした複製で `--check` が RED になることを確かめる。緑になっただけでは検査が働いているか区別が付かない。
6. `git stash` を使わないこと。退避はスクラッチへ `cp`。

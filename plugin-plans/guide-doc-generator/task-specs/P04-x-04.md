R22 の遅延到着に対するテスト側の追補 leaf。P04 の 23 テスト leaf は component 単位でテスト実体を赤として固定する契約だが、R22 は C12 / C23 / C11 / C22 の各 leaf が `done` へ遷移した後に到着した。`sync-task-state.py` の `ALLOWED_TRANSITIONS` において `done` は終端であり、閉じた leaf を再オープンすると `reconcile_done_dependency_closure()` が下流の done も巻き戻すため、追補は別 leaf として置く。

追補の割り当ては P04-x-03 が確定させた責務割当てに従う。

| checklist | 追補先 | 固定する赤 |
| --- | --- | --- |
| C61 | C12 / C23 | `detail_level` 必須・enum 外を reject・プリセット既定値の解決・provenance (default / explicit) の記録 |
| C62 | C12 | `evidence_depth` 必須・enum 外を reject・detail_level との独立性 (9 通りの組み合わせが全て valid) |
| C63 | C11 | 本文文字数上限が detail_level ごとにテーマトークンから引かれること・スクリプト側に数値リテラルが無いこと |
| C64 | C01 | ヒアリングが両フィールドを提示し、無回答時に既定を採用して停止しないこと |
| C65 | C11 | detail_level だけを変えた 3 生成物で C44 の共有の型が全て保持され、差分が記述量と任意詳細部の展開状態に限定されること |
| C66 | C22 / C09 | 宣言と実態の乖離 (detailed 宣言で記述量が overview 相当 / sourced 宣言で出典ゼロ) を不合格にすること・4 面集約への反映 |

**禁止事項**: 既存テストの受入基準を緩める書き換えを行わない。R22 は既存の型に軸を足す要件であり、既存の型を弱める要件ではない。既存テストが R22 の追補と矛盾する場合は書き換えず、矛盾自体を `R22-AMENDMENT.md` へ記録して P04-x-01 の集約判断へ回す。

テストは Python 3.10+ 標準ライブラリのみの `unittest` とし、`setUpClass` 内で例外を投げる構造を避ける (unittest が failures ではなく errors へ分類し、赤の性質が実装不在によるものか構造不備によるものか区別できなくなるため)。

産出物は `R22-AMENDMENT.md` に限る。各テストディレクトリ自体は P04-C<nn>-01 が producer であり、規則 (c) により本 leaf は producer を名乗れない。

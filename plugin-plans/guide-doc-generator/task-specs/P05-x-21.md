`P05-x-11` が build 中に発見したタスク。発見理由は次のとおり。

> P05-x-11 の裁定で 12 項目すべてが `decision: marker` と決まり、そのうち `data-hb-field="heading"` と `data-hb-notes-enabled` は**新設マーカー**である。また真因が「マーカー不在」ではなく「`data-hb-generated` による読み飛ばしでマーカーへ到達できない」ことだったため、**chrome 境界 (どこまでを生成物として読み飛ばすか) の規定が宣言正本に無い**ことが判明した。抽出器の実装 (P05-x-19) と renderer の実装 (P05-x-18) が参照する宣言正本を先に整える必要がある

## 進め方

1. `ROUNDTRIP-CONTRACT.md` の fenced JSON を `json.loads` し、`adjudications` から `marker` フィールドを機械的に列挙する。**本文へ件数を直書きせず列挙から導出する** (導出値を契約へ書き下す PAT-1 の再発を作らない)。
2. brief の `required_markers` 相当の節へ、列挙されたマーカーを反映する。`data-hb-notes-enabled` は P05-x-11 の worker が命名した新語であり既存 brief に無い — **命名を追認するか別名を採るかは本 leaf で決めてよい**。別名を採る場合は裁定文書との不整合になるため、その旨を報告すること (裁定文書は write_scope 外)。
3. **chrome 境界を明文化する。** 現状 `data-hb-generated="true"` は hero 枠 (`render-handout.py:1386-1391`) と header (`:1411`) の両方に付いており、抽出器 (`extract-handout-config.py:422`) は部分木を丸ごと読み飛ばす。「何を生成物として読み飛ばすか」「マーカー付きの著者データを内包する枠をどう扱うか」を規定する。実装をどう直すかは P05-x-18 / P05-x-19 の担当なので、**brief は規定だけを書き実装を指示しない**。
4. **既存の記述を壊さない。** P05-x-13 が追加した `heuristic_fallback.class_map` の 18 行 (TEXT を最後に置く順序制約つき)、`class_map_completeness`、`recovery_limits` はそのまま保つ。
5. **stderr キーは `P05-x-16` が既に整えた (done)。** 現在の stderr 契約は `E-EXTRACT-UNRECOVERABLE` / `W-EXTRACT-OPTIONAL` / `W-EXTRACT-HEURISTIC` / `W-EXTRACT-CATALOG-DRIFT` / `E-ROUNDTRIP-DIFF` / `E-HTML-MALFORMED` の 6 件を列挙し、E-/W- の失敗意味論と exit code への影響差まで書いている。**この内容を壊さないこと。**
6. **`exit_codes` の相互参照を揃える。** P05-x-16 が scope 外として残した課題で、`exit_codes["1"]` は「`--strict-fidelity` 下での任意フィールドの復元不能」と書くだけでコード名 `W-EXTRACT-OPTIONAL` を挙げていない。他の事由には `(E-EXTRACT-UNRECOVERABLE)` 等が併記されているため、**この 1 件だけ書式が揃っていない**。他にも同種の不揃いがないか全 exit code を確認すること。
7. **診断コードの棚卸しに `grep -oE '\b<pattern>'` を使わないこと。** macOS の BSD grep は日本語を含む長い UTF-8 行で語境界判定が壊れ、`E-EXTRACT-UNRECOVERABLE` の行から `E-EXTRACT-UN` という**存在しない一致**を出す。`\b` を外すか Python の `re.findall` を使う。dispatcher が実際にこれで誤った前提を作った。
8. `write_scope` の外へは 1 バイトも書かない。範囲外の修正が必要になったら手を出さず、何をどう直すべきかを報告する。
9. 編集後に `python3 -c "import json; json.load(open(...))"` で妥当性を確認し、トップレベルキーの集合が編集前後で保存されていることを実測する。

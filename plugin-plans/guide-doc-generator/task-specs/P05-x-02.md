`P04-x-05` の裁定 G-04 に対応する build leaf。`plugins/guide-doc-generator/assets/` 配下の資産は R10 (デザイン言語の vendoring)・C63 (文字数上限の数値の正本)・R08 (アイコン規約) が前提とするにもかかわらず、どの task-spec の `produces` にも現れず producer が存在しなかった。本 leaf がその唯一の producer になる。

## 産出内容

### テーマトークン (`assets/tokens/<theme>.json`)

C11 が `theme_token_schema_ownership` で定義したスキーマに従う。`text_limits.block_body_max_chars_by_detail_level` の値は当初 `RESOLUTION-R22.md`「確定した数値 (C63)」の表 (overview=180 / standard=400 / detailed=900) を正本としていたが、**R25 (改善 2026-08-18・goal-spec C73・最優先) により `improvement/text-length-gate-decision.json` (+ `briefs/RESOLUTION-R25-improvement-2026-08-18.md` D8) が正本を上書きした**。現在の正本値は overview=60 / standard=100 / detailed=160 であり、`block_body_max_chars` (既定) も 100 へ揃える。R22 の 180/400/900 は「R25 で改定された旧値」として経緯にのみ残し、本 leaf が実体化する値には使わない。**スクリプト側に同じ数値を書かないための正本がここである**ため、値の再解釈や丸めを行わない。

アクセント 1 色 + 明度 4 段階・CSS 変数駆動・`font-feature-settings:"palt"`・数値の `tabular-nums` を含む (R10)。テーマ差し替え可能性のため、既定テーマ 1 件に加えて差し替え例が 1 件あることが望ましい。

**2026-08-18 追補 (team-lead 訂正)**: R25/REQ-8 (goal-spec C74) の hero フィールド文字数/文数上限は本 leaf の産出物へ追加しない。正本は `config/handout-visual-policy.json#opening.hero_fields` (既存値のまま、変更しない) の 1 箇所に一本化されており、テーマトークン側へ並行フィールドを新設すると二重定義になる (詳細は `task-specs/P05-x-03.md` の同節)。

### アイコンセット (`assets/icons/icon-set.json`)

C15 (`build-icon-sprite.py`) が読む入力。R08 の統一様式を全アイコンが満たす。

**判定は属性様式でなく幾何規約で行う (P05-x-02-geometry-acceptance)**。属性の綴りが揃っていることは、アイコンが規約どおり描かれていることを意味しない — 綴りを満たしたまま座標系の外へはみ出す図形も、線幅が規約外の図形も、綴り一致では素通りする。よって受入は次の 3 点を実測で見る。

1. **座標系**: 全図形の座標値が 0-24 の範囲に収まる。外形寸法の宣言ではなく座標値そのものを見るため、宣言と中身が食い違っているアイコンを検出できる。
2. **線幅**: 2.2-2.6 の範囲。参照 v2 の実測レンジであり、ここを外れると他アイコンと並べたときに線の太さが揃わない。
3. **線表現**: 面塗りを持つ図形が 0 件。塗りで描かれたアイコンは `currentColor` による配色追従が効かず、テーマ差し替えで色が取り残される。

この 3 点が空ゲートでないことは、(a) 座標を 25 へ 1 つずらす (b) 線幅を 2.0 にする (c) 図形 1 つを塗りに変える の 3 変異でそれぞれ赤になることで示す。

参照 HTML v2 で実際に使われているアイコンを最小集合として含める (`analysis/guide-doc-generator/reference-analysis.md` §10 が規約の正本)。

**絵文字を 1 文字も含めない。** 判定は C16 の `CR-EMOJI` に委ねる (`P04-x-05` の G-04 と同時に裁定される G-03 により、Unicode ブロック denylist は用いない)。

### マスコット SVG (`assets/mascot/`)

参照 v2 の SVG マスコット。inline SVG として HTML へ埋め込まれるため、外部参照・`xmlns` 依存を持たない形にする。

## 境界

本 leaf は資産を置くだけで、資産を読む側のロジック (C11 のトークン適用・C15 のスプライト生成) は書かない。逆に C11 / C15 の build leaf は `assets/` へ書かない。この分離により、テーマ差し替えがスクリプト変更を伴わないことが構造として保証される。

jp-web-design はユーザーグローバル資産 (`~/.claude/skills` 配下) で本リポジトリに同梱されていないため、参照できない環境では `analysis/guide-doc-generator/reference-guide-v2.html` から抽出した値を用いる (R10 の「vendoring して自己完結させる」がそもそもこの不在を前提とした要件である)。

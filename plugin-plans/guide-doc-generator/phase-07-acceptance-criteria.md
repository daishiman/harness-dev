# P07 — acceptance-criteria (判定)

## 目的

テストの green ではなく「目的を満たしたか」を判定する。生成された資料が初心者に伝わり、外部依存ゼロで開き、テンプレートとして反復配布できる状態になっているかを受入基準で確認する。

## 背景

機械ゲートを全部通しても資料が読みにくければ目的は未達である。決定論ゲートで測れる面と、独立 context のレビュアーでしか測れない面を分けて判定する二段構えが要る。

## 前提条件

- P06 で全テストが green である
- 実題材で 1 本の資料を生成済みである

## ドメイン知識

- **purpose-acceptance**: 受入基準はゲートの言い換えではなく、当該 component の目的語彙から導く
- **proposer ≠ approver**: 生成した本人が読みやすさを採点しない。独立 context のレビュアーが verdict を返す
- **二段判定**: 一段目は決定論 (文長・言い換え宣言の被覆・日付書式)、二段目は意味判断 (初心者に伝わるか)

## 成果物

- 実題材での生成物 1 式 (資料 HTML / 構成データ / 素材 / README)
- 決定論ゲートの判定結果
- 独立 context の読みやすさ verdict
- 受入判定 (合否と未達項目)

## スコープ外

- 品質面の網羅的検査 (P09)
- 文書化 (P12)

## 完了チェックリスト

- [ ] 生成資料が外部依存ゼロで開く
- [ ] 目次から各セクションへ移動でき見出しが隠れない
- [ ] 初心者向け読みやすさの verdict が PASS である
- [ ] 同梱物 4 種が揃い出力先の命名規則に沿っている
- [ ] 出力先へ同梱された構成データからの再生成がバイト一致する (起動引数ではなく同梱構成データが再現の単位である)
- [ ] 冒頭に目的・背景・ゴールが揃い、各セクションのゴールが目次から追える
- [ ] 8 用途のプリセットいずれで生成しても共有の型が保たれ、差分が宣言済みの 4 軸 (セクションの並び・推奨部品・粒度既定値・用途固有の必須項目) に限定される

### 受入例 (満たす例 / 満たさない例)

- 満たす例: 生成資料をネットワーク遮断下で開いて全機能が動き、同梱構成データからの再生成がバイト一致し、8 用途いずれのプリセットでも共有の型が保たれている。
- 満たさない例: 起動引数を変えると出力が変わるため、同梱構成データだけでは同じ資料を再現できない。

### 事前解決済み判断

- 日付の単一ソース: 未指定時の既定 (生成実行日) 充填は構成データ正規化の 1 箇所だけ。表示日付と出力先ディレクトリ名はその 1 値から導く。
- 非対話経路の必須性: 対話ヒアリングは既定の入口であって唯一の入口ではない。検証済み構成データの直渡し経路を必ず用意する。
- 混成用途は不可: プリセットの合成は許さない。主用途を 1 つ選び、不足はセクション追加で補う。
- 用途語彙の具体名: lecture / agenda / guide / onboarding / report / proposal / study-notes / study-plan の 8 語を 1 正本に置く。
- テーマの入力経路: 構成データのテーマ欄が正。CLI の --theme は構成データに欄が無い場合のみ有効で、採用値は同梱構成データへ書き戻す。
- 読みやすさの受入は決定論ゲート (文長・言い換え被覆・日付) と独立 context の意味判定の二段構えで行い、生成した本人が採点しない。
- 導入一文と判断軸の検査と、目的・背景・ゴールの検査は独立の受入面として扱い、一方の PASS を他方の代替にしない。
- **2026-08-18 にプリセットの受入基準を訂正した (裁定の履歴を消さず追記で残す)。** 元の文言は「6 用途」「差分はセクションの並びと推奨部品の 2 軸」だったが、同じフェーズの用途語彙は当初から 8 語であり、R21 (用途固有の必須項目) と R22 (粒度既定値) が軸を 2 本増やしていた。基準文だけが古いまま残っていたため、実測 (`preset-matrix.json`: doc_type 8 種・共有鍵 10 個・変動 4 軸) に合わせて 8 用途 / 4 軸へ改めた。**基準を実測に合わせて緩めたのではなく、実装より古い基準文を実装の宣言済み仕様へ追随させた訂正である。**

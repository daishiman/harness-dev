# P12 — documentation (文書)

## 目的

利用者が自力で資料を作れる状態にする文書を揃える。何ができるか・どう起動するか・構成データをどう書くか・生成物をどう配るか、が読めば分かる状態にする。

## 背景

本 plugin の利用者は非エンジニアを含む。構成データを手で書く場面があるため、スキーマの機械可読性だけでなく、記入例と判断の指針が要る。plugin 自身が「初心者に伝わる資料」を作る道具である以上、その文書が伝わらないのは矛盾する。

## 前提条件

- P11 で証跡が揃っている

## ドメイン知識

- **文書の読み手**: 非エンジニアを含む。専門用語には初出時に言い換えを添える (本 plugin が資料に課す規約を自身の文書にも適用する)
- **記入例**: 抽象的なスキーマ説明ではなく、実題材の構成データを例として示す
- **既定と上書き**: 出力先やサイズ上限などの既定値と、その上書き方法を明記する

## 成果物

- plugin の README (できること / 起動方法 / 出力物)
- 構成データの書き方 (必須項目と記入例)
- 部品カタログの参照導線
- 委譲先不在時の挙動と対処
- 環境変数の設定方法 (専用 env と未設定時のフォールバック)

## スコープ外

- 配布判断と marketplace 登録 (P13)
- 資料の題材別テンプレート集の作成 (初版のスコープ外)

## 完了チェックリスト

- [ ] README が起動から出力物までを通しで説明している
- [ ] 構成データの必須項目と記入例が揃っている
- [ ] 専門用語に初出言い換えがある
- [ ] 既定値と上書き方法が明記されている

### 受入例 (満たす例 / 満たさない例)

- 満たす例: README だけを読んだ初見の利用者が、起動から出力物の受け取りまでを追加質問なしで実行でき、専門用語に初出言い換えが付いている。
- 満たさない例: 構成データの必須項目が列挙されているだけで記入例が無く、何を書けばよいか読者が推測することになる。

### 事前解決済み判断

- 文書は初心者・非エンジニアを読者に固定する。専門用語は初出で言い換えを併記し、既定値と上書き方法を必ず併記する。

# 分析・提案の独立評価契約

目的は現物診断と提案の妥当性を、提案者とは別の担当が検証すること。提案の修正と制作は所有しない。元画像を見てから提案を読む。共通規則は[stage-common](../../../references/stage-common.md)。

## 入力・出力の正本

呼出側が生成した評価テンプレート、元画像と最新要求、analysis.json の同一版を受け取る。評価者は台帳を記入し、読取検査を行う。再発行に伴う cycle 記録・旧評価退避は呼出側の準備責務に限り、評価者は行わない。型は[analysis-review schema](../../../schemas/analysis-review.schema.json)。analysis/source/policyのhashが変われば旧評価は無効。

## 評価する4条件

- evidenceAlignment: 元画像の具体領域と分析所見が一致し、主従/対象認知を説明だけで捏造していない。
- completeness: 最新必須要望、保持点、全案の適用範囲、未確定情報が追跡できる。
- changeDiscipline: 必須と候補を区別し、採用/維持/見送りに理由がある。良い構図を一律処方で崩さない。
- feasibility: 書体/描画経路/素材権限/顔・QR・中心軸を踏まえ、提案を実際に実装・再検証できる。executionPlanがあれば、pilotの案が変更の効果と副作用を確かめるのに代表的か、propagationが案ごとの保持点を壊さない展開になっているかも見る。

この4条件は分析・提案を評価する物差し。数値の自動算出や「妥当」の一言でPASSにしない。読んだ指針IDを根拠へ対応させ、専門レンズを使うときはstage-commonの「専門レンズの共通規則」に従う（stage=analysis-review）。

## 未達診断と戻り

問題が元画像未確認なら該当領域を確認し、要求漏れ/採否の弱さ/実現不能を具体化してFIXを返す。必須要望をdeclineした案、未確定の肩書き/成果の創作、保持点を壊す無根拠な処方、不明事実や素材権限の暗黙補完はPASSにしない。4 条件すべて根拠付き PASS、必須修正 0、独立性と鮮度が成立すれば「制作へ渡せる提案」の PASS を呼出側へ返す。制作への進行は workflow の実行範囲に従う。FIX は常に run-analyze-flyer へ返す。

必須修正は mandatoryFixes の text に案 ID・画像領域・元要求・観察事実と未達理由を書き、serves に本質条項 E1〜E5 を対応させる。本質未達に結べない好みは preferenceNotes の text へ記録する。提案 FIX に画像評価用の fixClass や画像用戻り先を補わない。

FIX は 4 条件すべての判定が完了し、少なくとも 1 条件が FIX、必須修正が 1 件以上あるとき。好みしかなければ 4 条件は根拠どおり PASS にし、好みを理由に FIX や cycle 消費を作らない。PASS は 4 条件がすべて PASS、必須修正 0 件の場合だけ。

必要情報の追加確認と、ユーザーへの毎回の承認質問は別である。実行許可済みの改善について、各案・各サイクルで許可を取り直すことを要求しない。

完成評価の premise（前提の崩れ）の FIX から作り直した analysis も同じ4条件で評価し、cycle は stage-common の「戻り先と改善上限」に従う。

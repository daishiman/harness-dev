# 完成画像の評価の物差し

完成画像の独立評価で、全案に同じ物差しを当てるための基準。評価を始める前に固定し、評価の途中で合格に合わせて書き換えない。判定はPASS/FIXの2値で、点数・平均・合計から自動で決めない。見る順序の正本はこの文書で、他の文書はここへリンクするだけにする。データ形は[visual-review schema](../schemas/visual-review.schema.json)、独立性と統合は[review-contract](../skills/assign-flyer-review/references/review-contract.md)、FIXの戻り先は[workflow](workflow.md#改善と納品)、様式で崩れやすい点は[style-profiles](style-profiles.md)を正本とする。

## 評価コストの原則

- 実見する評価対象は、最新の評価台帳で reusedFrom の無い案。初回は全案を対象にする。再評価時は画像の SHA・その案の入力・規範の照合が通る前の PASS だけを reusedFrom 付きで引き継ぎ、その項目を書き換えない。変わった案は再実見し、共通入力や規範が変われば全案を失効させる（E5）。
- 専門レンズは、design-contract.jsonのexpertEscalation（昇格条件）に当たった案だけで呼ぶ（R3）。
- 読む知識は[design-knowledge-index](design-knowledge-index.json)のusedByで、担当する観点のDDに絞る。

## 見る順序

縮小 → 全体 → 拡大の順に見る。設計意図を読む前の観察と、読んだ後の照合を分ける。順序を入れ替えると、意図の説明に引っ張られた所見になる。

1. **縮小で初見を記録する（viewedThumbnail）**: 評価対象の案を同じ縮小サイズで1案ずつ見る。最初に読めた文言と意味群（firstRead/firstGroup）、次に読めた文言と意味群（nextRead/nextGroup）、誰に向けた案内と分かった手掛かり（audienceCue）を記録する。文言は紙面に見えた語をそのまま書く。掲載文に無い語は機械検査で落ちる。
2. **全体を見る（viewedFull）**: 紙面全体の重さ、上下左右の濃さ、視線の移動、写真・画像と文字の関係を見る。
3. **拡大で細部を見る（viewedDetails）**: 主題、対象者の言葉、条件群（日時・会場・料金・注意）、顔・手元、ロゴ、QRと静寂域、写真/画像の境界、白い外縁を拡大して見る。
4. **設計意図と照合する**: 初見の読み順が意図の最初と違えば、構図か意図のどちらかを直す。2番目が違えば、その理由・迷いをhesitationへ書く。
5. **5観点を判定する**: 下の物差しで各観点をPASS/FIXにし、画像領域・所見・対応する意図を結ぶ。
6. **保持点を確かめる（preservationChecks）**: 分析で「保持する」と決めた良い点が、新しい画像でも残っているかを1点ずつ確認する。

## 5観点の物差し

各観点の「PASS」は満たすべき状態、「FIXの典型」はその状態が崩れた例。典型に当てはまらなくても、読取りや目的に具体的な支障があればFIXにする。好み・褒め言葉・変更量はPASSの理由にしない。

### hierarchy（主従・読む順序）

- **PASS**: 意図した主題が縮小で最初に読め、次に読ませたい群へ自然に進める。強い誘導語がある場合も主題と同じ強さで競合しない。文字の大小・太さ・向きの差が、意味の重要度の差と一致する。
- **FIXの典型**: 誘導語や内容名が主題より先に読める。主題を上げるために導入語を極小化する。複数の語を同時に巨大化して競合する。縦組と横組の混在が読み順を分岐させる。
- **縮小で見ること**: 最初と次に読めた語、対象者が分かった語。
- **拡大で見ること**: 改行位置、字間・行間、文字切れ、画像への重なり。

### balance（均衡・重さ）

- **PASS**: 写真/画像・主題・条件群・QRの重さが紙面全体で釣り合い、意図的な非対称は理由を説明できる。案件方針で中心軸を指定した意味群は紙面全幅の中心にまとまり、字面でも中心に見える。
- **FIXの典型**: QRや写真を避けて意味群全体を左右へ逃がす。数値の中心だけ合って字面や意味群がばらつく。片側に重さが偏り、反対側に理由の無い空洞がある。
- **縮小で見ること**: 上下左右の濃さ、視線の移動。
- **拡大で見ること**: 意味群の整列線、字面の中心と枠の中心の差。

### spacing（余白・まとまり）

- **PASS**: 同じ意味の情報が近く、違う意味の群の間は群内より広い。余白が主題の認識や群の切替に役立つ。注記はどの情報に属するかが近接で分かる。
- **FIXの典型**: 注記が孤立する。料金と条件、日時と受付、QRと申込案内が離れる。空きを埋めるために文・枠・装飾を足す。左寄せ・右寄せ・中央が理由なく混じる。
- **縮小で見ること**: 群のまとまりと切替。
- **拡大で見ること**: 群内/群間の距離、注記の帰属、QRとの間隔。

### color（配色・可読性）

- **PASS**: 色が主題・誘導・条件・行動の役割を補助し、写真/画像/背景の上でも必要な文字が局所的に読める。アクセントが重要度を平坦にしない。支給ロゴの色を保つ。
- **FIXの典型**: 主題や対象者の言葉が画像の明暗に埋まる。金額だけ強く条件が細字で沈む。色を増やして全てが同じ強さに見える。可読性のために硬い帯や黒面を足し、全体の調和を壊す。
- **縮小で見ること**: 主題と誘導の強さ、アクセントの競合。
- **拡大で見ること**: 小さな文字の直下の明暗差、模様・滲み・ハイライトとの重なり。

### integration（画像・ブランドの統合）

- **PASS**: 写真/画像と主題の言葉が一つの紙面として結び付き、境界が自然か意図的かを説明できる。ロゴと内容名の主従が意図どおりで、顔や重要な画面を文字で隠さない。各案の良い点（保持点）が残っている。
- **FIXの典型**: 画像の端が硬く浮く。ロゴが内容名や主題を圧倒する。主題を大きくして顔を隠す。全案を一つの構図へ均して、案ごとの長所を失う。読者の判断に役立たない肩書き・制作ラベルを足す。
- **縮小で見ること**: ロゴ・内容名・主題・画像の役割と競合。
- **拡大で見ること**: ロゴの歪み、顔/手元との重なり、境界の硬さ、白い外縁の接続。

## 合否の決め方

- **案ごと**: 5観点がすべてPASS、適用する要望がすべて充足、mandatoryFixesが0、保持点がすべてPASS、所見が今回の画像（同じSHA）に対応する場合だけPASS。
- **全体**: 全案が案ごとのPASSを満たす場合だけ全体PASS。他案の出来や平均で不足を相殺しない。
- **未実見はPASSにしない**: 一覧表示だけ、古い画像のSHA、制作者の修正説明だけで判定しない。
- **FIXの返し方**: 案ID・画像領域・観点・理由・必要な再確認を返す。必須修正にはfixClass（修正の分類）・serves（満たす本質条項 E1〜E5）・returnTo（戻り先）を付け、分類は[workflow の表](workflow.md#改善と納品)に従う。どの本質条項にも結べない所見はpreferenceNotesへ残す。評価者は修正しない。

## 案件ごとの点数表との併用

案件やpresetが独自の点数表（例: 段階評価）を指定した場合は、その表で手動評価した記録も残し、案件の合格線と本書のPASSの両方を満たす。点数表の観点と5観点の対応は選択した preset の preset.json の knowledgeFiles が指す案件知見に書き、弱点を消すための丸め込みに使わない。

## 確認できないこと

画像評価は、印刷物の実物の色、来場や申込の効果、実環境でのQR読取の代わりにならない。これらは実施した検査と未実施を分けて報告する。

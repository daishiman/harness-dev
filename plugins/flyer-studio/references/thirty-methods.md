# 30法を使う詳細レビュー

通常の制作検査に加えて、ユーザーが詳細レビューを指定した場合に適用する制作側唯一の30法手順。工程やagentはこの文書へ参照する。

思考リセットは成果物を削除することではありません。従来の修正を正しいと決めつけず、目的・主題・実画像を改めて確認します。

|担当|適用する方法|
|---|---|
|論理・構造9法|批判的思考、演繹思考、帰納的思考、アブダクション、垂直思考、要素分解、MECE、2軸思考、プロセス思考|
|メタ・発想9法|メタ思考、抽象化思考、ダブル・ループ思考、ブレインストーミング、水平思考、逆説思考、類推思考、if思考、素人思考|
|システム・価値12法|システム思考、因果関係分析、因果ループ、トレードオン思考、プラスサム思考、価値提案思考、戦略的思考、why思考、改善思考、仮説思考、論点思考、KJ法|

**リセット完了 → 3群の全分析完了 → 統合・改善 → 再検証**の順を守る。最初に俯瞰を完了してから3担当を並列にし、全結果が揃ってから改善へ進みます。ホストにSubAgentが無ければ直列で実施し、並列だったとは報告しません。各方法について画像ID・位置・観察事実・課題・改善案・変更後の証拠を記録し、名前を列挙しただけで適用済みにしません。why思考は根拠と仮説を区別して段階を掘り下げます。

改善→再描画→再検証の回数は、工程全体の改善 cycle の予算（[workflow の改善と納品](workflow.md#改善と納品)）を共有し、別枠を作りません。各所見に変更箇所と解決状態を結び付け、未達をPASSへ書き換えません。プラグイン自身への改善要望は報告に書き、外部サービスへ自動送信しません。

統合時に改善案が競合すれば、同じ事実・素材・出力条件の画像で比較する。方向性が変わる重要な分岐だけ具体的な候補を示して確認し、既に認められた通常の構図改善で不要な再承認を求めない。同じ改善へ複数方法が結び付いてよいが、30個の方法名だけでは完了にしない。

検証は次の4条件で行い、全4条件の根拠を示す。

|条件|証拠|
|---|---|
|矛盾なし|今回の回答・事実正本・プレビュー・PDF・公開範囲が相反しない。最新規則を古い見本より優先する。|
|漏れなし|必須情報、全案、brief.policy.requiredTones の配色、公開条件、住所、申込、印刷とQRの検査、5観点と、昇格した場合は専門レンズの所見が揃う。|
|整合性あり|用語・氏名・時刻・料金・書体役割・軸・親子関係・版・ハッシュが一致する。|
|依存関係整合|入力→素材と公開処理→生成と仮配置→文字→PDF→最新画像/規範への独立レビュー→納品の順を守り、各段のSHAがつながる。|

4条件の根拠と、画像比較による美観の採否、実際の来場効果の実測を混同しない。

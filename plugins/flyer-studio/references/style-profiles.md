# 表現様式の判断基準

表現様式（以下、様式）を提案し、作り、評価するときの判断基準。様式は名前の決まった選択肢ではなく、目的と素材から選ぶ手段である。下の「既知の様式の例」に無い様式でも、「様式の記述軸」で書けば同じ判断点で設計・評価できる。どの様式にも固定の構図・書体・pt・配色を当てはめない。様式に依らない制約（公開範囲・QR・印刷・情報量、様式と配色を別に決めること、事実を判読できる書体で組むこと）は[design-rules](design-rules.md)（§4）、評価の物差しは[review-rubric](review-rubric.md)を正本とし、ここでは様式によって判断が変わる点だけを書く。

## 様式の記述軸

どの様式も次の8軸で言葉にする。軸は網羅のためでなく、判断に要るものに絞ってある（[R3](essence.json)）。

| 軸 | 書くこと |
|---|---|
| medium | 媒体・技法（実写、切り絵、水彩、3DCG など） |
| lineAndPlane | 線と面（輪郭線の有無と太さ、色面の分け方） |
| texture | 質感（紙・インク・粒子・光沢） |
| colorTemperament | 色の気質（にじみ・平塗り・彩度の傾向）。白系・黒系などの配色（tone）とは別に決める |
| density | 密度と余白（装飾の量、文字を置く静かな領域） |
| typeCharacter | 文字の性格（主題の書体の印象。本文と条件は判読できる書体で組む） |
| culturalRef | 参照する時代・文化。実在の作家名・作品名は使わない |
| people | 人物・実在物の扱い（実写・架空の人物・描かない） |

軸から次の判断点を書く: **伝わるもの**・**構図と余白**・**背景生成**・**起きやすい失敗**・**レビューの重点**（5観点のうち、その様式で崩れやすいもの）・**権利**（公開範囲と許諾）。文字の扱いが様式で変わるときは**文字**も書く。

「既知の様式の例」は、この型で書いた例であり、選べる様式の上限ではない。切り絵・版画・水彩・ピクセル・3DCG・コラージュなど例に無い様式は、8軸と判断点を書いた臨時のプロファイル（その案件だけで使う判断点の一式）を作り、その案のdesignIntent.imageRelationshipへ短く残す。以後の設計・背景生成・評価は、例と同じ判断点で行う。

## 提案時の使い方

利用者が様式を言葉にしにくいときやおまかせのときは、利用者の情報（雰囲気の言葉・参考にしたい画像や物・避けたい雰囲気・purpose・使える素材）を根拠に、8軸で書き分けた2〜3案を出す。各案には使った根拠と、目的（[E1](essence.json)の読者・価値・行動）への効き方を書く。提案と選ばれた案（chosen）の記録先は`<project>/style-proposals.json`（型は[style-proposals schema](../schemas/style-proposals.schema.json)、工程上の位置は[workflow](workflow.md#全体の流れ)の「様式提案」）。

## 案ごとの使い分け

- 決まった様式（brief.stylePreferences）の範囲で、案ごとに様式を変えて比較できる。様式を変えたことは構図の違いの証拠にならないため、構図・主従・余白の違いも別に説明する。
- 公開できる写真が無いのに写真案を作らない。
- 実在の作家名・作品名を名指しして模倣させない（[E3](essence.json)）。参考画像は根拠として読むが、その構図や図像を写さない。

## 既知の様式の例

各項目は、設計（design.md）・背景生成（background.md）・最終評価（visual-review.md）で読む。

### 写真（実写）

- **伝わるもの**: 実在の人・場の空気・催しの信頼。
- **構図と余白**: 顔・視線・手元・マイクなど意味のある部分を主役語と競合させない。写真の占有率と文字領域を先に決め、写真内の静かな部分を文字の置き場に使う。
- **背景生成**: 写真と背景の境界を段階的になじませ、光の向き・色温度を写真に合わせる。写真の人物を生成で描き足さない。
- **起きやすい失敗**: 四角い写真の端が浮く、文字が顔やハイライトに重なる、第三者の顔・画面・催事名が残る。
- **レビューの重点**: integration（写真と文字/背景の接続）、color（写真上の局所可読性）。
- **権利**: [design-rules §6](design-rules.md#6-写真の公開範囲と差し替え)のprivacy 5項目を全て確認する。

### イラスト・生成画像

- **伝わるもの**: 撮影していない場面、概念、世界観の統一。
- **構図と余白**: 画像の主対象と主題の言葉の関係（説明する／象徴する／余白を作る）を案ごとに決める。装飾が増えるほど文字の静かな領域が減るため、先に文字領域を決める。
- **背景生成**: 画風（線の有無・塗り・質感）、主対象、文字を置く静かな領域、外縁の扱い、描かない物（文字・ロゴ・実在人物の似顔）を具体化する。
- **起きやすい失敗**: 画像内の偽の文字・偽ロゴ、指や顔の破綻、案ごとに画風がばらついて同じ催しに見えない。
- **レビューの重点**: integration（画風と文字の世界観の一致）、balance（装飾の重さの偏り）。
- **権利**: 生成ツールとプロンプトを記録する。

### 漫画調

- **伝わるもの**: 物語・会話・悩みへの共感を入口にする。
- **構図と余白**: コマ・フキダシ・人物の役割を1〜2個に絞る。フキダシには主題か問いを担わせ、説明文の追加に使わない。硬いコマ枠を既定にしない。コマ割り・視線誘導・フキダシの読む順番・読む向きを見る問いと出典は[漫画調の見る観点](designer-knowledge.md#漫画調--コマ割り視線誘導フキダシ読む向き)。
- **文字**: フキダシ内の言葉もbriefのcopyから組み、生成画像内の手描き文字で代用しない。
- **背景生成**: 線の太さ・トーン（網点など）・人物の数と感情・フキダシを置く余白を指定する。フキダシを絵に描かせず後から置く案も比べる。
- **起きやすい失敗**: 情報が会話文に分散して条件が探しにくい、架空の人物が実在の登壇者に見える、コマ割りで読み順が分岐する。
- **レビューの重点**: hierarchy（会話と主題・条件の主従）、spacing（コマ/フキダシと意味群の帰属）。
- **権利**: 実在人物の漫画化は本人の許可を記録する。

### 墨絵・水墨・書

- **伝わるもの**: 静けさ・格式・季節・余韻。余白そのものが表現の一部になる。
- **構図と余白**: 墨の濃淡と滲みが作る重さで均衡を取る。余白を「間」として機能させ、意味群をその間へ置く。濃墨の筆致の近くに小さな文字を重ねない。濃淡・にじみとかすれ・余白と間・落款と印章を見る問いと出典は[墨絵の見る観点](designer-knowledge.md#墨絵--濃淡にじみとかすれ余白と間落款と印章)。
- **文字**: 主題を書・筆文字にする場合は、brief.fontsとbrief.fontFilesで日本語グリフと利用許諾を確認した書体を使う（[runtime](runtime.md)）。縦組みはsceneのwritingModeで扱う。文字の回転は案に必要なときだけsceneの文字のrotationで書き、縦組み・中心軸の意味群・文字以外の回転は未対応として報告する。
- **背景生成**: 墨の濃淡・滲み・かすれ、和紙の質感、朱（落款風の差し色）を使うか、文字を置く白い間の位置を指定する。偽の落款や判読できない書は描かせない。
- **起きやすい失敗**: 淡墨の上で細字が沈む、滲みの縁が文字に触れる、朱が主題や行動と競合する、伝統表現を貼っただけで催しの目的と関係しない。
- **レビューの重点**: color（淡墨・和紙上の局所可読性と朱の役割）、balance（墨の重さと間）。
- **権利**: 既存作品を素材にする場合は使用許諾を記録する。

### 手書き

- **伝わるもの**: 親しみ・手作り感・話しかける温度。
- **構図と余白**: 手書きは主題や短い見出しに限り、揺らぎが読み順を乱さない位置に置く。整列する要素と揺らぐ要素を混ぜる理由を残す。
- **文字**: 手書き風書体はbrief.fonts/fontFilesで実在を確かめる。手書き画像を素材にする場合は、誤字を拡大で確かめる。
- **背景生成**: 紙・鉛筆・マーカーなどの質感と、手書き要素を置く静かな領域を指定する。
- **起きやすい失敗**: 本文まで手書きにして判読性が落ちる、子供向けの印象が対象読者と合わない。
- **レビューの重点**: hierarchy（揺らぐ見出しでも最初に読めるか）、color（線の細さと背景の差）。
- **権利**: 個人の筆跡を使う場合は本人の許可を記録する。

### 文字主体（タイポグラフィ）

- **伝わるもの**: 言葉そのもの・問い・宣言。
- **構図と余白**: 文字の大小・太さ・向き・字間が構図そのものになる。写真が無いぶん、群間の距離で意味の切替を見せる。
- **文字**: 書体の対比は役割で付け、役割の無い書体を増やさない。大きな文字の字面・字間・約物（句読点・括弧）の位置を拡大で確かめる。
- **背景生成**: 生成画像を使わない選択も比べる。現行の描画には背景の画像資産が必要なので、非生成案は支給された無地・色面等の背景を、公開・再利用の明示確認（reuse-approved）付きで使う。生成する場合は質感・色面だけにし、文字と競合する図像を入れない。
- **起きやすい失敗**: 全ての言葉が大きく競合する、装飾的な書体で条件が読みにくい。
- **レビューの重点**: hierarchy（大小差が意味の差と一致するか）、spacing（群内/群間）。
- **権利**: 写真固有の検査は対象外の理由付きで記録し、書体の利用許諾を確かめる。

### 混合

- 2つ以上の様式を組み合わせる場合は、どれが主でどれが従かと、境界の処理（なじませる／意図的に切る）の理由をdesignIntent.imageRelationshipに書く。
- 組み合わせた様式すべての「起きやすい失敗」と「権利」を適用する。様式の数を表現の豊かさの証拠にしない。

## 評価への接続

評価者は[review-rubric](review-rubric.md)の共通の物差しを使い、「レビューの重点」を、その様式で崩れやすい観点として重く見る。様式に合っていること自体を合格理由にせず、読者が最初に何を読み、誰向けと分かり、行動へ進めるかを実画像で確かめる。

# UBM目標設定 Phase 4 出力フォーマットエージェント

ヒアリング結果を目標設定フォーマットに整形し、バリデーション後に一時下書きを親へ返すサブエージェント。

---

## Layer 1: 基本定義層

### プロジェクト概要

- **目的**: ヒアリング結果を既存の目標設定ファイルと完全同一のフォーマットで出力し、品質チェック→バリデーション→検証済み一時下書きの返却を実行する。
- **成功基準**:
  - `skills/run-ubm-goal-setting/references/output-formats.md`（統一ハイブリッド）とフォーマット（公式セクション順・見出しレベル）が完全一致している（週報・月報・期報・1年とも公式21ブロックを公式順に保持し、深掘りは公式の後）
  - 全ての数値が半角で記載されている
  - 差分に+/-が付いている
  - 必須セクションが全て埋まっている
  - 決定論ゲート（validation-gates.md の表）の、回す条件に当たる各行が rc=0 になっている
- **スコープ**:
  - 含む: フォーマット整形、品質チェック、下書きのバリデーション
  - 含まない: ユーザーとの対話、情報収集、目標設定

### 実行仕様

Step 1〜4 の詳しい手順（読むファイル・データ整形・品質チェックとバリデーション・下書きの返却）は `${PLUGIN_ROOT}/references/agent-output-formatter-steps.md` にある。Step 1 の前に Read し、その順で実行する。各 Step の内容と完了条件は Layer 6「実行フロー」の表のとおり。`yearly` の到達点の取り方（interview_data → 挑戦宣言 → 現行の1年目標の順。親が渡したパスだけを読む）もこのファイルにある。

- **target_period**: start_date〜end_dateの形式
- **interview_data**: Phase 3のヒアリングで収集した全データ（構造化テキスト）。基本情報、前回実績、目標値、行動目標（`actions[]`。組み立ては `${PLUGIN_ROOT}/references/agent-output-formatter-steps.md` の Step 2）、やらないこと、判断基準、文脈フィールド（今期売上目標/累計実績・事業/グリッドパートナー数・アカデミー/壁打ちのスナップショット・前期間行動レビュー・前回のやらないことの守れた／守れなかった（`prev_not_doing_check`、週報・月報））、`projects`（プロジェクト別タスク 2階層まで。要否は `output-formats.md` の「共通部品F 層別差分表」）、`habit_check`（`weekly` のみ: 3原則のチェック項目）、`principles`（`monthly` のみ: 北原さんの原則で今月特に守ること。data-contract #38）を含む

- **peer_paths**: info-collector が対象期間と同じ期から選んだ yearly/quarterly/monthly/weekly の絶対パスと期間。欠けた層は null と理由。入力解決の正本は validation-gates.md。1年層の引数への渡し方は `skills/run-ubm-goal-setting/references/validation-gates.md` の「IN3 の1年層の引数」

#### 出力

下書き結果レポート:
- 下書きの絶対パスとSHA256、正式保存予定先（どの種別も1件）
- バリデーション結果: 決定論ゲート（validation-gates.md の表）の各行の **rc の値そのもの**＋実行した引数（「合格（PASS）」の語だけでは返さない。回さなかった行は、表の「回す条件」に書いた記録の値を返す）
- 生成した目標のサマリー（3行以内）

## Layer 5: エージェント定義層

### 5.1 担当エージェント

output-formatter — 書き込みと検査を担当する役。親が許可した出力先と入力の契約を守り、下書きの検証結果を親へ返す。

### 5.2 ゴール定義

- 目的: 確定した聞き取りを目標4階層の出力契約へ整形し一時下書きを検証する。
- 背景: 親が値と文脈を確定し、この役が検証ゲートを持つ書き手として出力する。
- 達成ゴール: 作成中の出力と利用した上位層が validation-gates の決定論ゲートを満たし、一時下書きのSHA256・検査結果と保存予定先が親へ返る状態になっている。

### 5.3 完了チェックリスト

- [ ] 入力データと peer_paths・plugin_root/vault_root の出所を確認した。
- [ ] 作成中の層を一時下書きとして検査した。
- [ ] 正本が要求する連動・層・形式の検査結果が合格である。
- [ ] 下書きのSHA256・検査結果・正式保存予定先を親へ返せる。正式先へ直接書いていない。

### 5.4 実行方式

目的とチェックリストを読み、未達を解消する操作をLayer3の入力・参照・検証制約から選ぶ。実行後にチェックリストを再確認する。親が定めた反復上限で未達なら、理由と根拠を親へ返す。反復時は original_goal（不変）/ current_goal_snapshot / delta_from_original / merged_directive_for_next / drift_signal を親へ渡す。

## Layer 6: オーケストレーション層

### 実行原則

Step 1 内のファイル読み込みは並列で実行する:
- output-formats.md の読み込み
- `quarterly` の場合: 既存期報ファイルの読み込み（output-formats.md と並列。旧名の期報ファイルも対象）
- `yearly` の場合: past_data の出所にある挑戦宣言と、peer_paths の `yearly`（既存の1年目標）の読み込み（output-formats.md と並列。ディレクトリを探して選ばない）
- `quarterly` / `monthly` の場合: peer_paths の `yearly` があれば、その読み込み（到達点2件を注記行へ写すため。output-formats.md と並列）

Step 2〜4 は前のステップの結果に依存するため順次実行する。
ただし Step 3 のバリデーション失敗→修正→再バリデーションは品質チェック（手動確認）とバリデーション（スクリプト実行）を連続で行う。

# output-formatter の用語と規則表

`agents/output-formatter.md` が使う用語の定義、OUTPUT_007 以降の対応表、ファイル命名規則、出力評価基準の正本。output-formatter は Step 1 の前にこのファイルを Read し、整形（Step 2）と確認（Step 3）に当てる。内容規則の正本は `skills/run-ubm-goal-setting/references/output-formats.md` で、ここと矛盾した場合は正本が勝つ。

## 用語集

| 用語 | 定義 |
|------|------|
| 半角数字ルール | 全ての数値は半角数字のみ。「万円」「千円」不可（600000と記載） |
| 差分記号ルール | 差分は必ず「+」または「-」を付ける（-300000, +2） |
| 行動目標基準 | 期日と数値を含む。「頑張る」「意識する」は不可 |
| 動的学習 | `quarterly`（期報・3ヶ月）の場合、直近の既存期報を読んでスタイル・語彙の参照のみを行う。見出し集合・セクション順・A1規則は `skills/run-ubm-goal-setting/references/output-formats.md` を正本とし、旧期報で上書きしない |
| 統一ハイブリッド | 週報・月報・期報・1年を貫く共通構造。公式セクション（公式21ブロック）を公式順に並べ、深掘り（差分・前期間行動レビュー・やらないこと・末振り返り等）を公式の後に置く。週報も公式ブロックを保持し、後段に週報固有の実行チェックリスト（最重要数字・日別到達ライン・成果グループ別の行動目標・習慣目標・判断基準・週末振り返り）を持つ。**週報では【今週送る個別メッセージ】と【今週やらないこと】を独立セクションとして出力しない（廃止）。いずれも該当する日の【今週の大きな到達ライン】の子タスクへ組み込む。廃止は週報に閉じた措置で、月報・期報・1年の【今月/今期/今年やらないこと】独立セクションは必須のまま。** 正本は `skills/run-ubm-goal-setting/references/output-formats.md` |
| 公式21ブロック | 出力テンプレート側の**固定**の見出し集合（今期売上目標/累計実績・前期間売上/成果/行動レビュー・今期間計画・事業/グリッドパートナー数・アカデミー/壁打ちのスナップショット文脈）。21 はこの集合の件数で、北原さん提出フォーマット由来のため**不変**。正本は `skills/run-ubm-goal-setting/references/output-formats.md` |
| 品質チェックリスト | `agents/output-formatter.md` の Layer 4 が持つ**保存前の確認観点**の列挙。公式21ブロックとは別物で、**観点が増減すれば件数も変わる**ため件数で呼ばない（「品質チェックリストの全項目」と呼ぶ）。「21項目」の語をこちらに使ってはいけない |

## ファイル命名規則

| 種別 | パターン | セクション構成 |
|------|----------|----------------|
| `weekly` | `UBM - 1-週報 - {{start_date}}〜{{end_date}}.md` | 詳細のみ |
| `monthly` | `UBM - 2-月報（１ヶ月） - {{start_date}}〜{{end_date}}.md` | 1ファイル内で提出用セクション＋管理用セクション |
| `quarterly` | `UBM - 3-月報（３ヶ月） - {{start_date}}〜{{end_date}}.md` | 詳細のみ |
| `yearly` | `UBM - 4-年報（１年） - {{start_date}}〜{{end_date}}.md` | 詳細のみ |

保存先のディレクトリは4層とも `{vault_root}/05_Project/UBM/目標設定/`（vault_root は親が検証した `$UBM_VAULT_ROOT` の絶対パス）。`archive/` はその下の旧ファイルの置き場で、新規の保存先にしない。

**ファイルは4層で各1本。`（提出）` 付きの別ファイルを作らない**（**理由: 複数ファイルにまたがると改善・修正のときに反映漏れが起きる**。片方だけ直して他方が古いまま残る形を作らない。見やすさを理由に2本へ戻さない）。月報だけ1ファイルの中を `# 北原さん提出用（シンプル）` → `# 管理用（詳細）` の順に分け、**提出用セクションの `## 【…】` には閉じ括弧の内側に「（提出）」を付ける**（例 `## 【今月の売上目標（提出）】`）。**管理用セクションの見出しには文字を足さない**（必須見出しの完全一致検査を満たすのは管理用側）。両セクションは公式21ブロックの見出しを**どちらも全件**持ち、違うのは粒度だけで**数字は同じ値**（正本: `skills/run-ubm-goal-setting/references/output-formats.md`「月報は1ファイルの中で提出用セクションと管理用セクションに分ける」）。

新規作成は上表のみ。読み取り・過去参照では旧名 `UBM - 3-月報（２ヶ月） - …` と `UBM - 3-期報 - …` も受理する。期報の期間は3ヶ月分の月報期間の連結（開始=1ヶ月目の月報開始日／終了=3ヶ月目の月報終了日。月の最終月曜日起点。例 `2026-06-29〜2026-09-27`）。

**`yearly`（1年・4層の最上位）の扱い**: 期間は**暦の1年**で切る（下位3層の最終月曜日起点とは別。例 `2026-10-01〜2027-09-30`）。サマリー見出しは `## 【1年の目標】{{start_date}}〜{{end_date}}`。骨格は期報と同じで、期間語を「今年 / 前年」に置き換える（`## 【今年の売上目標】` `## 【前年の売上実績】` 等）。**1年層の正本は挑戦宣言**（`05_Project/UBM/挑戦宣言/`）で、`## 【今年の最重要数字】`（1年層では必須）に到達点を置き、注記行に `月間売上到達点：<数値>` / `継続コンサル人数：<数値>` を書く（期報・月報が同値で継承する4層アンカー。`validate-cross-level.py` が `--yearly` を渡されたときだけ照合する）。本文で `（１年）` を含むファイル名を引用しても、全角数字チェックでは FAIL にならない（`validate-goal-output.py` は `１年` を含む行を、`１ヶ月`・`２ヶ月`・`３ヶ月` を含む行と同じく行ごと検査から外す）。その代わり、その行にあるほかの全角数字も検出されないので、数値はその行に書かない。

## 出力評価基準（フォーマット実装検証）

評価優先度: フォーマット準拠 > 数値ルール > 行動の具体性

| 項目 | 観点 | 合格条件 | 不合格時アクション |
|------|------|----------|-------------------|
| フォーマット一致 | 既存ファイルとセクション構造・見出しレベルが一致か | `skills/run-ubm-goal-setting/references/output-formats.md`（統一ハイブリッド）のテンプレートとセクション順・見出しレベルが完全一致（週報も公式21ブロックを保持） | テンプレートを再読み込みして修正 |
| 数値ルール準拠 | 半角数字ルール・差分記号ルールが守られているか | 決定論ゲート（validation-gates.md の表）の `validate-goal-output.py` の行が rc=0 | エラー箇所を特定して修正後、再バリデーション |
| 一本筋の参照整合 | 行動目標のグループ見出し `### → 成果目標名：…` の成果目標名が成果目標の項目名と一致し、どの成果目標にも支える行動があるか | 決定論ゲート（validation-gates.md の表）の `validate-goal-output.py` と `validate-goal-linkage.py` の行が rc=0 | 見出しの成果目標名を成果目標の項目名へ揃える、支える行動を足す、または支える行動が無い成果目標を外す |
| 必須セクション充足 | 全ての必須セクションが埋まっているか | 空欄・プレースホルダーが残っていない | interview_dataから該当データを再抽出 |

**最大改善回数**: 3回

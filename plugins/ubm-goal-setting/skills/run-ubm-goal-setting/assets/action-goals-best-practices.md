# 行動目標 ベストプラクティス

過去の目標設定ファイルから抽出した「良い行動目標」のパターン集。
目標設定時にこの基準で具体性を担保する。

**三層分離（売上目標＝金額／成果目標＝相手の側に起きた事実の数／行動目標＝自分が手を動かした回数）と行動目標の採否基準の正本は `references/output-formats.md`。** 本ファイルは正本に従う書き方の実例集で、判定基準そのものは持たない。

本ファイルの実例はすべて次を満たす。

- 行動目標に金額を書かない（金額は売上目標の層）。使う動詞・書かない語の一覧は正本の「行動目標の動詞（この語で書く／この語で書かない）」にあり、本ファイルは一覧を写さない
- 一人で完結し相手の側に何も起きない行（資料を仕上げる・名簿を作る・書き出す等）は行動目標に置かない。判定は正本の「行動目標に何を載せるかの採否基準」で行う
- 成果目標に自分の開催回数・作業回数を書かない（それは行動目標の層）
- 成果目標1件につき、それを支える行動目標を最低1つ置く

## 売上以外の成果目標のフォーマット（1年・期報・月報・週報 共通）

成果目標は **売上目標から逆算して置く**。各項目に「この成果が売上をいくら動かすか」を数値で持たせ、売上と成果を線でつなぐ。

### フォーマット定義

**1項目=2行**（正本は `output-formats.md` の「共通部品B 成果目標と売上貢献の根拠」）。

```
- [項目名]：[先方判断・結果の状態]　期日[M/D]
  → 売上貢献：[単価] × [件数] = [貢献額]
```

貢献額には **式** または **括弧の根拠** のいずれかが必ず随伴する。`150000` という数字だけでは、それが正しいかを後から誰も検算できないため、単価と件数を分けて残す。単価×件数の形にできないもの（値引き後の一括見積など）は式を省いてよいが、その場合も `→ 売上貢献：150000（値引き後の一括見積）` と根拠を括弧で添える。

### 実例

```
- 研修の継続合意：Aさんの合意1件　期日4/15
  → 売上貢献：75000 × 1 = 75000

- 単価合意：Bさんの合意1件　期日4/2
  → 売上貢献：80000 × 1 = 80000

- 月額顧問の成約：Cさんの成約1件　期日4/2
  → 売上貢献：50000 × 1 = 50000

- 提案の受諾：Dさんの受諾1件　期日4/10
  → 売上貢献：150000（値引き後の一括見積）

- 追加ライセンスの発注：Eさんの発注3件　期日4/15
  → 売上貢献：40000 × 3 = 120000

- AI質問会勉強会：参加者5名以上　期日4/18
  → 売上貢献：0（5月の月額顧問の成約を支える）
```

月額顧問の成約（Cさん）が `50000 × 1` なのは、**その期間に実際に売上として立つ分だけを計上する**ため。月額5万円の顧問契約で今週の売上に立つのは初月の 50000 であって、3ヶ月分の 150000 ではない。式の件数に期間単位（`ヶ月`／`年`）を掛けない。期間をまたぐ分は次の期間の成果目標として立て直すか、翌期に計上する直接成果として `→ 売上貢献：0（8月計上・顧問の2ヶ月目以降）` の形で書く（`output-formats.md` の「共通部品B 成果目標と売上貢献の根拠」）。

### この層に書かないもの

| 書かない | なぜ | どこへ書くか |
|---------|------|-------------|
| `売上75,000円` | 金額は売上目標の層 | 【今月の売上目標】 |
| `自主開催1回` | 自分が手を動かした回数 | 【今月の行動目標】 |
| `参加・実績報告1回` | 自分が手を動かした回数 | 【今月の行動目標】 |
| `パイプライン構築1件` | 1人で完結し相手側で何も起きない | 行動目標にも置かない（作業は目標にしない） |

### 記述ルール

| ルール | OK例 | NG例 |
|--------|------|------|
| 貢献額は式か括弧の根拠つき | `→ 売上貢献：80000 × 1 = 80000` ／ `→ 売上貢献：150000（値引き後の一括見積）` | `→ 売上貢献：150000`（裸の数字） |
| その期間に立つ分だけ計上 | 月額5万の顧問の今週分 `→ 売上貢献：50000 × 1 = 50000` | `→ 売上貢献：50000 × 3 = 150000`（3ヶ月分を今週に計上） |
| 式の左辺の積と右辺は一致 | `40000 × 3 = 120000` | `40000 × 3 = 150000` |
| 売上に乗らないものは0＋括弧の根拠（3つの形だけ。`output-formats.md` の「共通部品B 成果目標と売上貢献の根拠」） | 同じ文書の直接成果を支える `→ 売上貢献：0（月額顧問の成約を支える）` ／ 来期以降を支える `→ 売上貢献：0（8月の研修の受注を支える）` ／ 翌期に計上する `→ 売上貢献：0（8月計上・8月実施の研修で請求）` | `→ 売上貢献：0`（裸の0）／ `→ 売上貢献：0（体験診断後の成約を支える）`（支える先が同じ文書の直接成果に無いのに月を書いていない） |
| 数値化必須 | 成約数12件　期日6/30 | 前月の成約数を上回ります |
| 期日必須 | 単価合意1件　期日4/2 | 単価合意を目指す |
| 項目名（「：」より前）に個人名を入れず、相手は「：」の後に固有名詞で書く（`output-formats.md` の「共通部品A 行動行」） | 提案の受諾：Bさんの受諾1件 | Bさん：提案の受諾1件 ／ 提案の受諾：クライアントの受諾1件 |
| 実行完了型は置かない | 研修の継続合意：Aさんの合意1件 | 研修の実施：Aさんの研修1回 |
| 合計が売上目標に届く | 貢献合計 = 売上目標 | 貢献合計 < 売上目標のまま放置 |
| 1項目1成果（`・` 禁止） | 業務委託の開始：Bさんの開始1件　期日4/2 | 単価合意：Bさんの合意1件・業務委託開始1件　期日4/2 |
| 短く書く（期間別件数・共通文字数は正本参照） | 提案の受諾：Bさんの受諾1件　期日7/3 | 提案の受諾：Bさんの体験診断を経たうえでの提案内容への受諾1件　期日7/3 |

※ 表内の例は紙幅の都合で1行に畳んである。実際の出力は上の「フォーマット定義」どおり **1項目=2行**（`→ 売上貢献：` は2行目）。

### 実行完了型を置かない（最重要）

**実行した時点で達成になってしまうもの**は成果目標ではない。それは行動であり、やって当たり前のこととして扱う。

北原さん:「実行したら完了する目標は、もう置きません。実行したら成果につながって、売上につながる。そこまで降りてくる目標だけにします」

| ✗ 成果目標に書いてはいけない | ✓ 成果目標として置き直す |
|---|---|
| 勉強会を月4回開催する | 勉強会からの体験診断の申込3件　→ 売上貢献：0（8月の月額顧問の成約を支える） |
| 研修実施1回 | 研修後の継続合意1件　→ 売上貢献：75000 × 1 = 75000 |
| アカデミーに参加する | （目標に置かない。当たり前の土台として行動目標の `### → （土台）` グループへ） |
| 自主開催1回 | 参加者5名以上　→ 売上貢献：0（8月の研修の受注を支える） |
| 提案書を1件提出する | 提案の受諾1件　→ 売上貢献：150000（値引き後の一括見積） |

### シンプルに書く（1項目=1つのこと）

複雑な目標・長い文の目標は、自分で自分の目標を複雑にし、結局動けなくなる。**短くまとめるのではなく、置き場所を変える**のが原則。

| 上限 | 対象 |
|---|---|
| 成果目標 | `references/output-formats.md`「シンプルさの上限」の期間別件数・共通文字数 |
| 行動目標 | 同上。必要な主要行動を件数のために削らない |

- 2つのことが入ったら **2件に割る**
  - ✗ 「火曜にBさんの体験診断1件を実施し、当日中に提案ドラフト1件を共有する」
  - ✓ 「体験診断：実施する　期日6/30」＋「提案ドラフト：診断当日に共有する　期日6/30」
- 対象リスト・理由・注意点は行に書かない（判定に必要な対象・数量だけ残す。注記は依頼されたときだけ。`output-formats.md` の「共通部品A 行動行」）
  - ✗ 「個別メッセージを平日は毎日4件送る（対象: 過去接点のある製造業の経営者。朝9時の最初のタスクに固定）」
  - ✓ 「個別メッセージ：平日に4件ずつ送る　期日毎日」
- 上限は逸脱の検出線であり、狙う長さではない。長さの手本は `assets/golden-sample-weekly.md`

### 注記

> 上の【今月の売上目標】から逆算し、前月の未達に対する行動変化を踏まえた上で、あなたが約束する売上以外の成果目標（先方判断・期日・売上貢献額）を **1項目=2行** で数値化して記載すること。貢献額は式（`単価 × 件数 = 貢献額`）または括弧の根拠つきで、その月に実際に立つ分だけを計上すること

## 週報の行動目標パターン

週報の行動目標は、それが支える成果目標ごとに `### → {成果目標の項目名}：{要約}（{貢献額}円）` の見出しでグループ化し、配下に `- [ ]` を並べる。見出しの金額は成果目標の貢献額と一致させる。貢献額の大きいグループを上に置く並び順は推奨（優先順位がそのまま見える）。以下は1行1行の書き方の例で、実際はこのグループ見出しの配下に置く。

### 良い例（過去ファイルの行を共通部品A の書式に直したもの）

```
- [ ] 対面候補日：Aさんとの打ち合わせで4月の関東出張時の候補日を打診する　期日今週
- [ ] 価値提供の案：Bさん・Cさんとの打ち合わせでヒアリング内容をもとに共有する　期日2026-03-24
- [ ] 日程候補：Dさん経由案件の次回候補を2件提示する　期日今週
- [ ] 顔合わせ候補日：Eさんへ打診する　期日今週
```

いずれも「相手が応じなくても自分だけで回数を数えられる」形で終わっている。`日程確定` `次回化を進める` は相手が応じないと達成にならないため、行動目標ではなく成果目標の層（例: `次回の打ち合わせ設定1件`）へ置く。

### パターン分析

行の書式・合格基準・期日トークンは `output-formats.md` の「共通部品A 行動行」。支える成果目標は、グループ見出しの `：` より前を成果目標セクションの項目名と一致させて示す（記法の正本は `references/output-formats.md`「分離の実装ルール」）。

## 月報の行動目標パターン

### 構成要素

月報の行動目標は以下の3層構造。各行の書式と期日トークンは `output-formats.md` の「共通部品A 行動行」。

1. **日次行動**（毎日やること）
   - 例: 「個別メッセージ：1日3件送る　期日毎日」
   - 例: 「近況の連絡：既存顧客1名へ出す　期日毎朝」（投稿と相手の反応は分け、主要行動の採否は正本を参照）

2. **週次行動**（毎週やること）
   - 例: 「勉強会：週1回開催する　期日毎週」
   - 例: 「面談：週2件実施する　期日毎週」

3. **期限付きタスク**（期日を M/D で決めてやること）
   - 例: 「見積：A社へ提示する　期日3/15」
   - 例: 「契約条件：A社へ打診する　期日3/31」
   - 「資料を完成させる」は1人で完結し相手側で何も起きないため、行動目標に置かない

### 数字の入れ方

| パターン | 例 |
|----------|-----|
| 件数/日 | 個別メッセージ：1日3件送る　期日毎日 |
| 件数/週 | 面談：週2件実施する　期日毎週 |
| 件数/月 | 勉強会：月4回開催する　期日3/31 |
| 累計 | 個別メッセージ：月内に累計60件送る　期日3/31 |
| 期日 | 見積：A社へ提示する　期日3/15 |

金額は行動目標に書かない（売上目標の層）。「契約を確定させる」「成約する」は相手が応じないと達成にならないため成果目標の層（例: `新規成約3件`）に置き、行動目標はそれを支える回数（例: `契約条件：8件打診する　期日3/31`）で書く。

## 期報の行動目標パターン

月報の3層構造 + 以下を追加:

4. **マイルストーン**（3ヶ月の各月の到達点・成果目標の層で書く）
   - 例: 「1ヶ月目: 新規成約1件 + 新規接点2社」
   - 例: 「2ヶ月目: 月額顧問の継続合意2件」
   - 例: 「3ヶ月目: 有料コンサル3件」
   - 月商などの金額は売上目標の層へ置き、マイルストーンには件数で書く

5. **戦略的行動**（フェーズ進行に関わる行動・自分だけで回数を数えられる形で書く）
   - 例: 「連携の打診：商工会議所へ2回行う　期日8/31」
   - 例: 「助成金の要件確認：窓口へ1回問い合わせる　期日7/31」
   - 「体制を構築する」は相手が応じないと達成にならないため成果目標の層へ置く
   - 「申請書を提出する」「資料を仕上げる」は一人で完結し相手の側に何も起きないため、採否基準で行動目標から外れる

## 「やらないこと」の書き方パターン

出力先と件数は層で違う（`output-formats.md` の「共通部品F 層別差分表」の「やらないことの出力先」）。下は1項目の書き方の例。

### 良い例（過去ファイルから抽出）

```
* 売上や案件前進に直結しない新規開発
* 細部を詰めすぎて全体の前進が止まること
* 資料を完璧にすること自体を目的にすること
* 面談や登壇を、その場限りで終わらせること
```

### パターン: 「〜すること」で統一

- 動詞の名詞化で終わる
- 具体的な行動を否定する（抽象的な「ダメなこと」ではない）
- 北原さんの「選択と集中」に基づく

## 判断基準の書き方パターン

### 良い例（過去ファイルから抽出）

```
今週の終わりに見るべきものは、頑張った感ではない。

* 次回の約束が増えたか
* 前回 YES をくれた人から、次の YES を取れたか
```

### パターン: 「〜したか？」の疑問形

- はい／いいえで判断できる基準
- 数値で測定可能
- 「頑張った感」を排除する視点

## 合宿アドバイスとの整合性チェック

### チェック項目

目標設定時に、直近の合宿フィードバックと以下の点で整合性を確認:

1. **方向性の一致**: 合宿で決めた事業方針と目標がズレていないか
2. **フェーズの一致**: 合宿で確認したフェーズに合った目標か
3. **具体的アドバイスの反映**: 合宿で受けたアドバイスが行動目標に落とし込まれているか
4. **前提の更新**: 合宿で覆された前提が目標に反映されているか

### チェック方法

```
直近の合宿（{{camp_date}}）で受けたアドバイス:
[合宿ファイルから抽出]

今回の目標と整合性を確認:
- 方向性: OK / 要修正
- フェーズ: OK / 要修正
- アドバイス反映: 反映済み / 未反映（具体的に何が未反映か）
```

## 品質チェックリスト

目標設定完了前に以下を確認:

- [ ] 成果目標が1項目=2行で書かれ、項目名（「：」より前）に個人名が無く、貢献額に式（`単価 × 件数 = 貢献額`）または括弧の根拠（貢献0は共通部品B の3つの形）が付いている（裸の数字が無い）
- [ ] 貢献額が、その期間に実際に売上として立つ分だけになっている（式の件数に `ヶ月`／`年` を掛けていない）
- [ ] 行動目標に精神論の NG 語（正本はプラグイン直下の `references/action-language-policy.json` の `goal_exact_phrases`）が含まれていない
- [ ] 全ての行動目標が `output-formats.md` の「共通部品A 行動行」の合格基準（何をする＋行末の期日トークン）を満たしている
- [ ] 行動目標の並び順と期日が、正本 `references/output-formats.md`「行動目標の並び順と期日の逆算」に照らして合格している（判定条件は本ファイルに写さない）
- [ ] 三層分離: 売上目標＝金額／成果目標＝相手の側に起きた事実の数／行動目標＝自分が手を動かした回数に分かれている
- [ ] 行動目標に金額が無く、正本「行動目標の動詞（この語で書く／この語で書かない）」の書かない語が1件も無い
- [ ] 行動目標の各行が正本「行動目標に何を載せるかの採否基準」の残す側に入っている（一人で完結する作業が残っていない）
- [ ] 成果目標1件につき、それを支える行動目標が最低1つある
- [ ] 未達を踏まえて上げたのは行動の基準値であり、その成果につながる行動に限っている（挽回の行は `output-formats.md` の「共通部品D 前回ブロック」の対応行で、今回の行動目標の項目名を指す）
- [ ] 「やらないこと」が `output-formats.md` の「共通部品F 層別差分表」の出力先と件数どおりに置かれている
- [ ] 判断基準がはい／いいえで判定できる
- [ ] 直近の合宿アドバイスと方向性が一致している
- [ ] 売上目標から逆算した行動量が明記されている
- [ ] 北原さんの原則との整合性がある

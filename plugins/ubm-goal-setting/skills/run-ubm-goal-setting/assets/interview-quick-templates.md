# UBM目標設定 高速ヒアリングテンプレート

目標種別ごとの質問文の**言い回し集**。過去データから自動取得できる項目はスキップし、最短ルートで情報収集する。

> **位置づけ（重要）**: 対話の**ターン構成・設計順序・完了条件の正本は `prompts/R1-〜R5-` の各責務プロンプト**であり、本ファイルではない。本ファイルのターン番号は R 側のターン記号（3A・4B 等）と 1:1 対応しない。両者が食い違う場合は必ず R 側に従う。本ファイルは「同じことをどう聞くか」の言い回しだけを提供する。
>
> **設計順序は売上 → 成果 → 行動の逆算で固定**（`references/output-formats.md`「逆算の設計手順」）。行動目標から先に聞かない。

---

## 設計原則

- **1ターン1〜3問**: ユーザーが答えやすい分量
- **自動取得優先**: 過去ファイルから取れる情報は聞かない
- **バッチ質問**: 関連する質問はまとめて聞く
- **段階的深掘り**: 浅い回答には1回だけ深掘り、それ以上は次へ進む
- **所要時間目安**: 週報5〜8分 / 月報10〜15分 / 期報15〜20分
- **並列Read活用**: Phase 3開始時の参照ファイル4本は並列Readする

## 週報（1週間目標）フロー

### ターン1: 先週の振り返り確認
```
先週の週報を確認しました。

[自動表示: 先週の目標サマリー]

先週の目標について、実績はどうでしたか？
1. 売上実績（数字）
2. 行動目標の達成状況（何件やったか）

困ったことや想定外だったことがあれば教えてください。
```

### ターン2: 差分分析 + 原因
```
[差分を自動計算して表示]

この差分について、一番大きな原因は何だと思いますか？
（1つだけ挙げてください）
```

### ターン3: 今週の売上目標（逆算の起点）
```
[前回の原因分析を踏まえて]
[アカデミーアドバイスがある場合: アカデミーで決めた方向性を提示]

まず起点を1つだけ決めます。
1. 今週の売上目標はいくらですか？（数値1つ・半角）

※ 内訳（誰から・いくら）はここで一緒に聞きますが、ファイルには数値1つだけ書きます
※ 北原さんの言葉:「売上目標は追わない。人との関係を育むことが一番大事」
→ 数字は追う対象ではなく、「誰との関係が動けばこの数字になるか」を映す鏡として使う
```

### ターン4: 今週の成果目標（売上目標から割り付ける）
```
[ターン3で決めた売上目標を提示して]

この売上が立つには、誰の・どの判断が必要ですか？

1. 相手ごとに「先方が下す判断・受諾・合意・継続」を挙げてください
2. それぞれに売上貢献額を割り当ててください（今週の売上に乗らないものは 0 ＋ いつ・いくらになるか）

形式: 1項目=2行
  1行目 `- 相手：先方判断・結果の状態　期日M/D`
  2行目 `  → 売上貢献：単価 × 件数 = 貢献額`

※ 単価と件数を分けて書いてください。`150000` という数字だけでは、それが正しいかを後から誰も検算できません
※ 式に分解できないもの（値引き後の一括見積など）は `→ 売上貢献：150000（値引き後の一括見積）` と括弧で根拠を添えます
※ 計上するのは **今週の売上に実際に立つ分だけ** です。月額5万円の顧問なら初月の `50000 × 1 = 50000` で、3ヶ月分の 150000 ではありません。先の分は `→ 売上貢献：0（8月に 100000 の見込み）` として見通しに回します

※ 「実施する／開催する」等の実行完了型は成果目標に置きません（それは次のターンの行動目標）
※ 貢献額の合計が今週の売上目標に届くまで出し切ってください。届かないなら成果の抜けを疑います
   （行動を足してごまかさない）
※ 1項目1成果・50字以内。長くなったら短縮せず2件に割ってください
```

### ターン4.5: 今週の行動目標（各成果目標から逆算する）
```
[確定した成果目標を1件ずつ提示して]

この判断を引き出すために、自分は何を・何件・いつまでにやりますか？
北原さん:「何を考えて、どう思って、どう行動するかを考える」

1件の成果につき「準備 → 資料作成 → 実施 → フォロー」の粒度で2〜4件を紐付けます。

  NG:「個別メッセージを3件送る」（行動だけ・誰の成果を支えるか不明）
  OK:「Bさんはセミナー集客で困っている→AI集客の事例をまとめて送る」
  →「誰が」「何を求めているか」「だから何をするか」の3点で設計

行動は、それが支える成果目標ごとにまとめてください（形式: `### → 相手名：{成果の要約}（{貢献額}円）` の見出し＋配下に `- [ ]`）。
習慣・土台の行動だけは `（土台）` と書いて構いません。

※ 8件以内・1件60字以内。行動を足して不安を埋めない
```

### ターン5: やらないこと + 判断基準
```
2つだけ:
1. 今週「やらない」と決めること（迷いを減らすため・3つ以上）
2. 迷ったときの判断基準（1文で）

例: 「売上に直結しないことはやらない」
例: 「人との接点が増えることか？ Yes→やる / No→やらない」

※ 週報では「やらないこと」を独立セクションにせず、制約が効く日の【今週の大きな到達ライン】の
   子タスクとして書きます（独立セクションは月報・期報のみ）
```

### ターン5.5: プロジェクト別タスク（粗い棚卸し・週報では既定で省略）
```
[週報は方式2（成果グループ＋日別到達ライン）で実行管理するため、このターンは既定で飛ばす。
 ユーザーがプロジェクト別タスクを望んだ場合のみ聞く。月報では必須・期報では出力しない]

抱えているプロジェクトを2階層まで（プロジェクト→必要ならサブ）で粗く出してください。
各プロジェクトには先方担当者を入れてください。各タスクは「期日」「提出先・宛先」「対象物・行動」だけでOK。

形式:
### ▼ プロジェクトA：{{name}}（目的：{{why}}）
- 先方担当者: {{client_owner}}
- [ ] [{{YYYY-MM-DD}}] [{{提出先・宛先}}] {{対象物・行動}}

1. プロジェクト名と目的（1文）を全て
2. 各プロジェクトの先方担当者（未確認なら未確認）
3. 各プロジェクトの今週分のタスクを期日・提出先付きで（粗くてOK）

※ 自主開催AI勉強会・外部AI勉強会登壇は毎回同じ定型チェックリストで生成します。全項目が完了したら、翌月分として新規作成します。
```

### ターン5.7: 習慣目標の運用パラメータ（週報のみ）
```
毎日の運用を支える習慣目標を確定します。
1. 1日に回す30分ブロックは最低何本？
2. 今週分散させる「大物タスク」と、何日に分けるか？

※ 30分切替・分散・粗い粒度の3原則は固定。週末にチェックボックスで振り返ります。
```

### ターン6: アカデミー整合性 + 関係構築チェック → 確認 → 出力
```
[完成した週報を表示する前に以下をチェック]

【アカデミーアドバイスとの整合性】
※ アカデミーデータが[自動取得]の場合のみ実行。[要ヒアリング]の場合はスキップ
※ [鮮度注意]（3ヶ月超）の場合は参考情報扱い
直近のアカデミー（{{camp_date}}）で決めた方向性と照らし合わせます:
- 方向性: OK / 要修正
- 具体的アクションの反映: OK / 未反映

【関係構築チェック】
- 行動目標に「人の名前」が入っていますか？
- 「売上を追う」ではなく「関係を育む」行動になっていますか？
- 「相談をもらう」「接点を増やす」が軸になっていますか？

[整合性チェック後、完成した週報を表示]

この内容で保存してよいですか？
修正したい箇所があれば教えてください。
```

## 期報（3ヶ月目標）フロー

月報フローをベースに、3ヶ月スパンの戦略的要素を追加した全ステップフロー。対象期間は3ヶ月分の月報期間の連結（開始=1ヶ月目の月報開始日／終了=3ヶ月目の月報終了日。月の最終月曜日起点）。

### ターン1: 自動取得データの確認
```
過去のデータから以下を確認しました:

[自動表示: ユーザー基本情報 + 前回期報サマリー + 対象期間内の全週報・月報3件]

この情報に変更はありますか？
```

### ターン2: 前回実績のヒアリング
```
前回の3ヶ月（{{期間}}）について:

4. 3ヶ月間で一番変化があったことは？
```

### ターン3: 差分分析 + 原因深掘り
```
[差分を自動計算して表示]
```

## スマートスキップルール

過去データから自動取得できる場合にスキップする項目:

| 項目 | スキップ条件 |
|------|-------------|
| 名前 | 前回ファイルに記載あり |
| 事業内容 | 前回ファイルに記載あり（変更確認のみ） |
| フェーズ | 前回ファイルから推定可能 |
| 形態 | 前回ファイルに記載あり |
| 顧問参加前月商 | 前回ファイルに記載あり |
| 前回の目標値 | 前回ファイルから自動取得 |
| 合宿日程 | 合宿ディレクトリから推定可能 |

## 回答パターン別の対応

詳細は `agents/phase3-coordinator.md` の「回答パターン対応」セクションを参照。

基本方針:
- 具体的数字 → 次へ
- 曖昧 → 数字で再質問
- 精神論 → 仕組みに転換
- 沈黙 → 3択提示
- 長文 → 1文要約確認

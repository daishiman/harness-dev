## Layer 1: 基本定義層 (不変原則)

### 1.1 不変ルール
- 目的: 前回目標と実績の差分を可視化し、根本原因を 1 つ特定する。
- 背景: 差分の根本原因を特定しなければ次の目標設定が場当たり的になる。表層的な原因ではなく構造的な原因に到達することで、再現性のある改善が可能になる。
- 改善は「仕組み・構造・手順の変更」で捉え、精神論に帰着させない。

### 1.2 倫理ガード
- 深掘りは「追い詰める」のではなく「一緒に根っこを見つけましょう」のスタンスで行う (心理的安全性を保ち、正直な回答を引き出すため)。

## Layer 2: ドメイン層 (本質ロジック)

### 2.1 責務 (単一責務)
- 担当: 差分の数値化、ボトルネック箇所の特定、根本原因の interview_data への記録。
- 非担当: 基本情報収集 (R1)、目標設定 (R3)、行動計画 (R4)、最終確認 (R5)。

### 2.2 ドメインルール (適用思考法)
- **なぜ思考 (No.35/56)**: 「なぜ？」を 3〜5 回繰り返し、表層→根本原因に到達する。
- **ボトルネック分析 (No.51)**: 「商品作り→外交→商談→成約→フォロー」のどこが詰まっているか特定する。北原原則「商品があるなら届けて届けて届けていく」。
- **仮説思考 (No.48)**: 「もし外交を毎日 1 件やったら、月に何件の商談が生まれるか？」の仮説構築。
- **論点思考 (No.49)**: 対象期間 (今週 / 今月 / 今期 / 今年) で解くべき問題を 1 つに絞る。北原原則「迷う＝止まる。迷う状況を作らない」。
- **差分の対象期間 (種別で 4 分岐)**: 差分を見る相手は 1 つ前の同じ層。1年 (`yearly`) は「前年」の 1年目標、期報 (`quarterly`) は「前期」、月報 (`monthly`) は「前月」、週報 (`weekly`) は「前週」。期間語は正本 (`references/data-contract.md` §1.0 の 4層の種別定義) に従い、1年層では「今年 / 前年」を使う (「今期」「今月」に置き換えない)。1年層の期間だけは暦の 1年で切るため、前年との比較も暦年どうしの比較になる (下位 3層の最終月曜起点とは別規則)。
- **1年層のギャップは到達点アンカー 2 件に対する差で見る (1年のみ)**: 1年層が下へ降ろすのは到達点アンカー 2 件 (`月間売上到達点` / `継続コンサル人数`) だけなので、1年のギャップ分析は売上の月次差分ではなく**この 2 件に対する現在地との差**として見る。① 到達点の月間売上に対して、直近の月商はいくらか (差分) ② 継続コンサル人数の到達点に対して、現在の継続人数は何人か (差分)。追う対象は金額でなく人数・回数であるため、②の差を主、①の差を結果指標として扱う。アンカーのラベル文字列・置き場の正本は `references/data-contract.md` §3.1.3 の 4層ロールアップ契約。
- **1年層の初回 (前年の 1年目標が存在しない) の扱い (1年のみ)**: 1年目標は 4層化で新設された層であり、**初回は比較対象となる前年の 1年目標ファイルが存在しない**。このとき本 Step をスキップせず、比較対象を次の 2 つに差し替えて実施する。① 直近の期報・月報の積み上げ (すでに在る期報・月報の売上実績と最重要数字を足し上げ、現在地として扱う) ② 挑戦宣言 (`05_Project/UBM/挑戦宣言/UBM - 挑戦宣言 - YYYY-MM-DD.md`。1年層の到達点の正本) の到達点 2 件。差分は「挑戦宣言の到達点」−「①で測った現在地」として取る。前年目標が無いことは隠さない。`prev_sales_diff` は `+`/`-` 付きか `null` のいずれかしか取れないため**初回は `null`** とし (正本: `references/data-contract.md` #7)、到達点との差は `root_cause` / `bottleneck` の対話の中で現在地の出所 (直近の期報・月報の積み上げ) とあわせて言葉で確定させる。成果物の本文に書くときは、比較対象が存在しない旨を `（前年の1年目標が無いため差分は定義できない）` のように理由だけで書き、符号の付けられない裸の数字を置かない (正本: `references/output-formats.md` の数値ルール)。

### 2.3 入力契約
| フィールド | 型 | 必須 | 説明 |
|---|---|---|---|
| prev_sales_target | number | はい | 前回売上目標 (Step 1 から) |
| prev_sales_actual | number | はい | 前回売上実績 (Step 1 から) |
| prev_other_target | string | はい | 前回成果目標 (Step 1 から) |
| prev_other_actual | string | はい | 前回成果実績 (Step 1 から) |

| yearly_continuous_consult_count | number | 1年のみ | 1年後の月額継続コンサル人数 (Step 1 で挑戦宣言から提示・確認済みの値。アンカー #0b) |

| prev_sales_diff | string | 売上差分 (+/-付き)。1年の初回 (前年の 1年目標なし) は差分が定義できないため `null` にする (`prev_sales_diff` は `+`/`-` 付きか `null` のいずれか。正本: `references/data-contract.md` #7 とそのバリデーション。理由文を入れるフィールドではない) |

## Layer 5: エージェント層 (ゴール駆動の実行主体)

### 5.1 担当エージェント
- `run-ubm-goal-setting` の親コンテキストが本プロンプトを Read して対話を進行する。`phase3-coordinator` は必要時に次問案を返す読み取り専用の助言役であり、対話状態を更新しない。

### 5.2 ゴール定義
- 目的: 差分と根本原因を構造レベルで特定し、目標設定の根拠を作る。
- 背景: 原因が表層のままだと同じパターンを繰り返し、再現性のある改善につながらない。
- 達成ゴール: 差分が数値で明示され、根本原因が 1 つ特定された状態。固定手順は書かない。

### 5.3 完了チェックリスト (ゴール到達の停止条件)
- [ ] 根本原因が 1 つ特定されている
- [ ] 目標と実績の差分が数値で明示され、原因が構造的に深掘りされている
- [ ] 種別が1年のときは、到達点アンカー 2 件 (`月間売上到達点` / `継続コンサル人数`) に対する現在地との差をそれぞれ確認している
- [ ] 種別が1年で前年の 1年目標が無いときは、現在地の出所 (直近の期報・月報の積み上げ) と到達点の出所 (挑戦宣言) をユーザーと確認し、`prev_sales_diff` を `null` にしている
- [ ] 出力契約 (2.4) の担当フィールドが interview_data に構造化されている

### 5.4 実行方式
- 固定手順を持たない。現状評価→手順を都度立案→実行→検証→全項目充足まで反復する。

## Layer 6: オーケストレーション層 (ゴールシーク制御)

### 6.1 上位スキルとの接続
- 呼び出し元: `run-ubm-goal-setting` Phase 3 の親コンテキスト (Step 2)。
- 前提 Step: R1-step1-current-review — 前回目標と実績の数値データがなければ差分分析ができない。
- 後続 Step: R3-step3-goal-setting — 受け渡し: 売上差分 (`prev_sales_diff`)、根本原因 (`root_cause`)、ボトルネック箇所 (`bottleneck`)、行動変化 (`behavior_change`)。

### 6.2 ハンドオフ / 並列性
- 直列: 完了チェックリスト充足後にのみ Step 3 へ遷移する。初回ユーザー (前回目標なし) は本 Step をスキップして Step 3 へ進む。
- 例外 (1年のみ): 種別が1年で前年の 1年目標ファイルが無い場合は、上の「初回スキップ」を適用せず本 Step を実施する。比較対象を直近の期報・月報の積み上げと挑戦宣言の到達点に差し替えれば差分が取れるため (2.2 の「1年層の初回」)。この場合も `root_cause` / `bottleneck` は Step 3 へ値として渡す (`null` にしない)。
- 並列: ユーザー回答待ちの間に差分計算・パターン分析・ナレッジ検索を先行実行してよい。

### ターンテンプレート (実行時発話の正本)

**ターン2A**:
> おめでとうございます！{{prev_sales_target}}に対して{{actual}}、{{diff}}ですね。
> 達成できた一番の要因は？その成功パターンを今回も再現するために、何を続けますか？

**ターン2B**:
> 売上目標{{prev_sales_target}}に対して{{actual}}、差分は{{diff}}ですね。
> この差分の一番大きな原因は何だと思いますか？（1つだけ）

**ターン2C**:
> こういう可能性を考えてみましょう:
> 1. 外交（人に会う・メッセージ送る）の量が足りなかった
> 2. 商品・サービスの準備に時間を使いすぎた
> 3. 既存対応で新規に手が回らなかった
> 4. 何から手をつけていいかわからなかった
>
> どれが一番近いですか？

**ターン2D**:
> 北原さんの言葉:「行動を管理する。成果や他人の評価はコントロールできない」
> 「頑張り」ではなく「仕組み」で考えましょう。
> 「仕組み」「手順」「環境」のどれを変えれば改善できそうですか？

**ターン2E-1年（1年・前年の1年目標あり・到達点アンカーに対する差）**:
> 前年（{{prev_period}}）の1年目標と今年の現在地を並べます。
> - 月間売上到達点: 到達点 {{yearly_monthly_sales_goal}} / 直近の月商 {{現在地}} → 差分 {{diff}}
> - 継続コンサル人数: 到達点 {{yearly_continuous_consult_count}} 人 / 現在 {{現在地}} 人 → 差分 {{diff}} 人
>
> 1年のギャップはこの2つで見ます（追うのは金額ではなく人数です）。
> 継続コンサル人数が到達点に届いていない一番大きな原因は何だと思いますか？（1つだけ）

**ターン2F-1年初回（1年・前年の1年目標なし・比較対象を差し替えて実施）**:
> 1年目標は今回が初回なので、前年の1年目標ファイルがありません。
> 比較する相手を次の2つに差し替えます。
> - 現在地: 直近の期報・月報の積み上げ（今年の累計売上実績 {{period_sales_cumulative}} / 継続コンサル {{現在の人数}} 人）
> - 到達点: 挑戦宣言の月間売上到達点 {{yearly_monthly_sales_goal}} / 継続コンサル人数 {{yearly_continuous_consult_count}} 人
>
> まず事実の確認です。この現在地の2つの数値は合っていますか？（違えば半角数字で直してください）
> その上で、到達点までの差 {{diff}} を埋めるために、今いちばん詰まっているのはどこですか？
> 「商品作り→外交→商談→成約→フォロー」のどこか1つで教えてください。
>
> ※ 前年目標が無いため売上差分（`prev_sales_diff`）は `null` のまま進めます。差分の数字を作らず、到達点との差として扱います。

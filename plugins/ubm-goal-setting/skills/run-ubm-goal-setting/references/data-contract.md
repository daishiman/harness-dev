# UBM目標設定 エージェント間データ契約

Phase間のデータ受け渡し仕様を定義するドキュメント。
各エージェントはこの契約に従ってデータを生成・消費する。

---

## Phase間データフロー図

```
Phase 0 ──[GoalConfig]──> Phase 1-2 ──[PastSummary]──> Phase 3 ──[InterviewData]──> Phase 4 ──[FormattedOutput]──> ファイル
(目標種別確認)          (info-collector)             (親コンテキストの対話)      (output-formatter)          (05_Project/UBM/目標設定/)
```

| 契約名 | 生産者 | 消費者 | データ形式 |
|--------|--------|--------|-----------|
| GoalConfig | Phase 0（メインフロー） | `info-collector` | 構造化テキスト |
| PastSummary | `info-collector` | `run-ubm-goal-setting` の親コンテキスト | マーク付き構造化サマリー（文脈フィールド継承を含む。§2.8） |
| InterviewData | `run-ubm-goal-setting` の親コンテキスト | `output-formatter` | 構造化テキスト（全37フィールド・#1-38、#15 は欠番） |
| FormattedOutput | `output-formatter` | ファイルシステム | Markdown ファイル |

## 1. GoalConfig（Phase 0 → Phase 1-2）

Phase 0 でユーザーから取得し、`info-collector` サブエージェントに渡すパラメータ。

### 1.0 4層の種別定義（正本）

目標は4層。設計・軌道修正の正本は `references/output-formats.md`「四層（1年目標・期報・月報・週報）の連携」。直属上位の成果・到達点を基準に計画し、参照アンカーの同値と月・週の実行値を区別する。

```
1年（yearly）→ 3ヶ月（quarterly）→ 1ヶ月（monthly）→ 1週間（weekly）
```

| 層 | `--type` / `goal_type` | 内部 kind | 期間語 | タイトル見出し | ファイル名 | 期間の決め方 |
|---|---|---|---|---|---|---|
| 1年 | `yearly` | `year` | 今年 / 前年 | `## 【1年の目標】{期間}` | `UBM - 4-年報（１年） - {期間}.md` | 暦の1年 |
| 3ヶ月 | `quarterly` | `period` | 今期 / 前期 | `## 【3ヶ月の目標】{期間}` | `UBM - 3-月報（３ヶ月） - {期間}.md` | 月報3件の期間の連結 |
| 1ヶ月 | `monthly` | `month` | 今月 / 前月 | `## 【1ヶ月の目標】{期間}` | `UBM - 2-月報（１ヶ月） - {期間}.md` | 月の最終月曜起点 |
| 1週間 | `weekly` | `week` | 今週 / 前週 | `## 【1週間の目標】{期間}` | `UBM - 1-週報 - {期間}.md` | 月曜起点 |

- `bimonthly` は `quarterly` の**後方互換の別名**（期報が2ヶ月だった頃の旧キー）。受理して `quarterly` に正規化する。新規では使わない。内部 kind はどちらも `period` になるため、種別の取り違えは kind ではなく**元の `--type` の値とタイトル見出しラベルの対応**で検出する（不一致は error）
- ファイル名プレフィックスの許容は `UBM - [1-4]-`
- **1年層の期間だけは暦の1年で切る**（下位3層の最終月曜起点に揃えない）。実例: `2026-10-01〜2027-09-30`。日付を機械的に割らず、参照文脈である到達点アンカーの同値と、各期の実行計画を別に照合する（§3.1.3）
- セクション構成の正本・テンプレート本文の正本は `references/output-formats.md`

| フィールド | 型 | 必須 | 説明 | 例 |
|-----------|-----|------|------|-----|
| goal_type | enum: `weekly` / `monthly` / `quarterly` / `yearly` | はい | 目標種別（`bimonthly` は `quarterly` の後方互換の別名。受理して `quarterly` に正規化する） | `weekly` |
| target_period | object: `{start: date, end: date}` | はい | 対象期間（`YYYY-MM-DD` 形式）。期報は3ヶ月分の月報期間の連結（開始=1ヶ月目の月報開始日／終了=3ヶ月目の月報終了日。例 `{start: 2026-06-29, end: 2026-09-27}`）。1年目標は暦の1年（例 `{start: 2026-10-01, end: 2027-09-30}`） | `{start: 2026-03-30, end: 2026-04-05}` |
| sections | enum: `detail_only` / `submission_and_detail` | いいえ（導出値・指定不要） | 出力ファイル内のセクション構成。`goal_type = monthly` は `submission_and_detail`（1ファイルの中に提出用セクションと管理用セクションを持つ）、`weekly` / `quarterly` / `yearly` は `detail_only` | `submission_and_detail` |

### バリデーション

- `goal_type` は4つの列挙値のいずれかであること（旧値 `bimonthly` を受け取った場合は `quarterly` として扱う）
- `target_period.start` < `target_period.end` であること
- 日付は `YYYY-MM-DD` 形式であること
- `sections` は `goal_type` から導出する（`monthly` → `submission_and_detail` / それ以外 → `detail_only`）。ユーザー指定は受け取らない
- **どの `goal_type` でも出力ファイルは1本。** 提出用の別ファイルを作らない。4層あわせて4本（層ごとの提出用の有無と、ファイルを分けない理由は `output-formats.md` の「共通部品F 層別差分表」）
- `goal_type = yearly` は `sections = detail_only`。提出用セクションを持たない
- `goal_type = monthly` の出力は1ファイルの中で `# 北原さん提出用（シンプル）` → `# 管理用（詳細）` の順に2セクションへ分け、提出用セクションの `## 【…】` には閉じ括弧の内側に「（提出）」を付ける。**管理用セクションの見出しには文字を足さない**（必須見出しを満たすのは管理用側）（正本: `references/output-formats.md`「月報は1ファイルの中で提出用セクションと管理用セクションに分ける」）

### 取得方法

- コマンド引数で指定されている場合: そのまま使用
- 未指定の場合: AskUserQuestion で1ターンで取得

## 2. PastSummary（Phase 1-2 → Phase 3）

### 2.8 inherited_context（継承文脈10種）

`info-collector` が「現在の月報/期報」から抽出し、週報の自動継承元となる今期文脈。週報は新規ヒアリングを行わず、この値を表示・確認して必要時のみ上書きする（所要時間5-8分維持）。月報・期報はフルヒアリングで確定する。全項目に `[自動取得]` / `[要ヒアリング]` マークを付与する。

各フィールドの型は `InterviewData` の文脈フィールド（#22-31）と一致させる。

| フィールド | 型 | マーク | 説明 | `InterviewData` 対応 |
|-----------|-----|--------|------|------------------|
| period_sales_target | number | [自動取得] / [要ヒアリング] | 今期の売上目標（期アンカー・全レベル同値） | #22 |
| period_sales_cumulative | number | [自動取得] / [要ヒアリング] | 今期の累計売上実績（期アンカー・週次更新） | #23 |
| business_partner_count | number | [自動取得] / [要ヒアリング] | 現在事業パートナー数（スナップショット） | #24 |
| grid_partner_count | number | [自動取得] / [要ヒアリング] | 現在のグリッドパートナー数（スナップショット） | #25 |
| grid_partner_goal | number / null | [自動取得] / [要ヒアリング] | グリッドパートナー目標数（スナップショット）。未設定時は `null` | #26 |
| last_academy_date | date / null | [自動取得] / [要ヒアリング] | 前回のアカデミーへの参加日（スナップショット） | #27 |
| next_academy_date | date / null | [自動取得] / [要ヒアリング] | 次回のアカデミーへの参加日（スナップショット） | #28 |
| next_sparring_date | date / null | [自動取得] / [要ヒアリング] | 次回の壁打ち予定日（スナップショット） | #29 |
| sparring_target_state | string | [自動取得] / [要ヒアリング] | 次回の壁打ち予定月までに目指している状態（スナップショット） | #30 |
| sparring_deliverables | string | [自動取得] / [要ヒアリング] | 次回の壁打ち予定日までに達成させること（スナップショット） | #31 |

- 継承供給源: `weekly` は『現在の月報』、`monthly`/`quarterly` は『現在の期報』から抽出する。取得不可は `[要ヒアリング]` を付与する。
- `grid_partner_goal` は `number` / `null`（#26 と一致）。専用出力セクションは持たず、文脈・行動目標へ反映する。
- `period_sales_cumulative` のみ週報でも必須で、当該週時点の累計実績に週次更新する（継承値の更新が前提）。
- 種別別の必須/任意/継承度は §3.1.3 マトリクスに従う。

### バリデーション（Phase 1-2 完了時）

- 全セクションに `[自動取得]` または `[要ヒアリング]` マークが付いていること
- `[自動取得]` の数値データが半角数字であること
- prev_goals が goal_type の取得スコープに合致する件数であること
- camp_data の freshness_mark が3つの列挙値のいずれかであること

## 3. InterviewData（Phase 3 → Phase 4）

`run-ubm-goal-setting` の親コンテキストが全5Stepのヒアリングで収集し、`output-formatter` に引き渡す構造化データ。`phase3-coordinator` は必要時に次問案を返すだけで、このデータの生産者ではない。

### 3.1 全37フィールド一覧（#1-38、#15 は欠番）

表の「集める問い」は、その値を利用者から聞くターンを書く（`R1`〜`R5` は `prompts/` の各責務プロンプトのターン、`iqt` は `assets/interview-quick-templates.md` の層別フローのターン。iqt は言い回し集で、ターン構成の正本は R 側）。聞かずに埋める値は `—（理由）` と書く（past_data＝前回正本からの転記、派生＝他のフィールドから算出）。「出力する層」は、`output-formats.md` のテンプレートに見出しか変数を持つ層を `週・月・期・年` の組合せで書き、持たないなら `—（理由）` と書く。期報は月報の、1年は期報の骨格を読み替えで継承するため、月報にあって期・年に無い項目は、期報・1年の読み替え規則に「出力しない」と書く。この2列とテンプレート・ターン見出しの対応は `tests/test_field_closure.py` が検査する。検査の範囲は、(b) テンプレートの変数と出力する層が週報・月報のテンプレートだけ、(c) 「出力しない」の記載が期報・1年の読み替え規則だけである。期報・1年だけに在る節の値（事業の柱・補助金戦略・地域戦略・事業計画の数字・確定スケジュール・合宿の学び・SNS 共有の確認）はこの表に行を持たず、(b) の範囲外になる。前回ブロックの売上・成果の挽回（【前回の売上に対して未達を挽回するための行動】【前回の売上以外の成果に対して未達を挽回するための行動】）もフィールドが無く、同テストの `KNOWN_GAPS` に置いている。フィールドや見出しを足したら、この2列と利用側（R プロンプト・iqt・`output-formats.md`）を同じ変更で直す。

#### 層間一致検査（validate-goal-output.py `--peer`）の対象一覧

「層間一致検査」列が **対象** の値だけが、週報・月報・期報の間で同じ値でなければならない。
`validate-goal-output.py --file <対象> --peer <他層>` がこの列に従って突き合わせ、
不一致を WARN で報告する（FAIL にはしない。継承は作成時の取り込みの一方向しかなく、
下位が先に作られる運用があるので、正しく運用しても最低1回はズレるため）。

- **対象**: `period_sales_target`（今期の売上目標）／`period_sales_cumulative`（今期の累計売上実績）
  — 週報でもこの2値は全レベル同値が正しい。
- **対象外**: 最重要数字。各層の【今(週/月/期/年)の最重要数字】は、**その層の売上目標と、その売上に至る
  人数・回数・件数**であって、層をまたいで同値になる値ではない（例: 1年「月間売上到達点」に対し月「今月の売上目標：600000」、
  週は今週の売上と、その売上に至る人数・件数）。どの組でも比較せず、分母からも落とす
  （検査スクリプトは `SKIP` 行で理由を印字する）。1年の到達点（#0a/#0b）の継承は、rc を持つ
  `validate-cross-level.py` が照合する。
- **対象外**: スナップショット8種（`business_partner_count` / `grid_partner_count` /
  `grid_partner_goal` / `last_academy_date` / `next_academy_date` / `next_sparring_date` /
  `sparring_target_state` / `sparring_deliverables`）。これらは各文書の作成時点の状態を写した値で、
  時点が違えば値が違うのが正常。**特に `last_academy_date` / `next_academy_date` /
  `next_sparring_date` は日付のスナップショットなので、層をまたいで一致させない。**
- **対象外**: `habit_check`（週報固有）、前期間行動レビュー4種（#32-35）と前期間の成果差分（#36）、前回のやらないことの確認（#37・週報・月報）。前期間の実績なので層ごとに範囲が違う。

新しい項目を層間一致の対象にする／外すときは、この表の「層間一致検査」列と
`validate-goal-output.py` の `PEER_ANCHORS` を同時に更新する。

#### 四層横断照合（validate-cross-level.py）の対象一覧

`validate-goal-output.py --peer` は**2ファイルの総当たり・WARN のみ・2アンカー（金額2値）**で、
不一致でも rc は上がらない。これとは別に、**上位層を正本とした継承が崩れていないか**を
rc を持って判定する検査スクリプトが `scripts/validate-cross-level.py`。

```
validate-cross-level.py (--yearly <1年目標> | --no-yearly <理由>) --quarterly <期報> --monthly <月報> [--weekly <週報>] [--month N]
```

`--quarterly` と `--monthly` が必須、`--weekly` は任意。`--yearly` と `--no-yearly` の扱いは `references/validation-gates.md` の「IN3 の1年層の引数」。

rc=0 全一致 / rc=1 不一致または抽出不可あり / rc=2 引数・入力不正 / rc=3 抽出0件。
**rc=1 と rc=3 を混ぜない。** rc=3 は「一致していた」ではなく「1件も抽出できず何も
判定していない」。出力は常に `照合対象 N 件中 不一致 M 件（抽出不可 K 件）` の形で分母を出し、
末尾に `MEASURED_AT` / `ARGS` を付ける。

継承の形は2種類あり、照合の当て方が違う。

- **同値継承**: 指定された上位の参照文脈をそのまま写す。年の最終到達点や今期売上等の参照値だけを同値にし、当月・当週の成果や実行数量と取り違えない。
- **内訳継承**: 期報が月別内訳として書いた値を、月報が自分の層の値として書く。
  期合計（例: 延べ回数120回）と月の値（56回）を直接比べると必ず不一致になるので、
  **期報が当月について書いた数**と**月報の当月計画**を比べる。差があれば誤記か実績に基づく軌道修正かを区別する。後者を同値継承の誤記として戻さない。
  対象月は月報の期間終了日の月（最終月曜起点のため 2026-09-28〜2026-10-25 の当月は10月）。

##### 4層ロールアップ契約（1年層の到達点アンカー2件）

1年層が持つ到達点を、期報・月報が**注記行で同値継承**する。正本はさらに上流の
`05_Project/UBM/挑戦宣言/UBM - 挑戦宣言 - YYYY-MM-DD.md`。
機械的に同値照合する年の到達点はこの2件で、各期・月の実行目標そのものではない。年間→期→月→週の成果対応は別に確認し、期の月別内訳は当月計画の基準として参照する。月・週の実績に基づく配分変更の記録は `output-formats.md` の「共通部品E 軌道修正記録」。

##### 月別配分を見直した場合の記録

記録の書式と記録先は `output-formats.md` の「共通部品E 軌道修正記録」。機械検査の範囲は内訳継承の4項目（#2-#5）で、期報の当月値＝上位計画、月報の現在値＝実行目標、理由・影響の記入を確認する。週報に月額参照根拠がある場合は修正後月額を参照する。条件を満たす差は `[調整確認]` として rc=0 にできる。記録なし・不備・未知の対象・現在値との不一致・抽出不可は失敗する。

抽出範囲から外す節（経緯の記述を現在値として拾わないため）:
【仮置き事項】【衝突】【来(週|月|期|年)以降に対応すること】【確定済み・解消済みの記録】
【追随させる箇所】【前(週|月|期|年)の…】。`##` 見出しに当たればその節全体、`###` 小見出しに
当たればその小見出しから次の小見出しまでを本文に入れない。アンカーの節の中に
「確定済み・解消済みの記録」が入っている形（記録の側の古い値が先に出てくる）を落とすのが目的。

数値はカンマ区切り（600,000）と素の数字（600000）を同値として扱う。全角数字で書かれていると
**抽出不可**（不一致ではない）として個別に列挙し rc=1 にする。抽出不可を「不一致0件」に
吸収しない（検査できていない状態を PASS にしない）。

受け入れテストはプラグイン直下の `../../tests/test_validate_cross_level.py`。

- 「任意（継承）」: 週報では値を新規ヒアリングせず、現在の月報/期報から継承した値を表示・確認する。継承値が取得できない場合のみヒアリングする。
- period_sales_cumulative のみ週報でも必須。週次で当該週時点の累計実績に更新する（継承値の更新が前提）。
- 前期間行動レビュー4種（prev_action_target/actual/diff/change・#32-35）は §1: 期間語化対象。全種別で初回は `null`、2回目以降は前期間データがあれば反映する。取得Stepは target/actual（#32-33）を Step 1 で表示・収集、diff/change（#34-35）を Step 2 で算出する。前期間の成果差分（#36 prev_other_diff）も同じく初回 `null`・Step 2 で算出する。

#### 逆算チェーン検査（売上→成果→行動。全種別共通・`check_goal_chain`）

| ID | チェック項目 | 判定 | 説明 |
|----|-------------|------|------|
| C1 | 貢献額の根拠の随伴 | FAIL | 成果目標の各項目の**2行目**に `  → 売上貢献：…` があり、**貢献額に「式（`<単価> × <件数> = <貢献額>`）」または「括弧の根拠（`<貢献額>（値引き後の一括見積）`）」のいずれかが随伴すること**（半角数字。裸の数字は FAIL）。要求しているのは式そのものではなく、貢献額が後から検算できる形になっていること。式は十分条件の一つであり、単価×件数に分解できない成果は括弧の根拠で満たす。貢献 0 は `output-formats.md` の「共通部品B 成果目標と売上貢献の根拠」の3つの括弧の形だけを通す（理由なしの裸の `0` と、3つの形以外の `0（…）` は FAIL） |
| C1c | 式の検算 | FAIL | 式で書いた場合、`<単価> × <件数>` の積が `<貢献額>` と一致すること。単価と件数を分けて書かせるのは、後から誰でも検算できる形にするため |
| C1d | 貢献 0 の偏り | WARN | 貢献額 0 の成果目標が全体の過半を占めないこと（今期間の売上にほとんど繋がらない目標設定になっている） |
| C1e | 計上期間の逸脱 | FAIL | 式の件数に期間単位（`ヶ月` / `ヵ月` / `か月` / `年`）が混入していないこと。貢献額はその期間に実際に売上として立つ分だけを計上する。月額5万の顧問を週報で成約するなら `50000 × 1 = 50000`（初月分）であり `50000 × 3ヶ月 = 150000` ではない。期間をまたぐ分は次の期間の成果目標として立て直すか、翌期に計上する直接成果の貢献0（`0（8月計上・顧問の2ヶ月目以降）`。共通部品B）として書く。※検査が捕まえるのは単位語が書かれた形のみで、「件数が期間の長さになっていないか」の意味判断は人が行う |
| C2 | 実行完了型の排除 | FAIL | 成果目標に実行完了型NG動詞10語（正本: `references/output-formats.md`「成果目標と行動目標の区別」＝`Validator.OUTCOME_NG_VERBS`）で終わる項目が無いこと |
| C3 | 売上目標との突合 | FAIL / WARN / OK / INFO | 売上貢献の合計と売上目標を `judge_sales_coverage()` で突合。合計 ≥ 目標 → OK／不足が目標の **5% 以内** → WARN（端数ズレ）／5% 超の不足 → FAIL／売上目標が 0 以下 → INFO（判定しない）。**完全一致は求めない** |
| C4 | 行動→成果の紐づけ | FAIL | 行動目標が `### → <成果目標名>：<要約>（<金額>円）` のグループ見出しの配下に置かれていること（1年・期報・月報・週報の全4種別）。見出しが無い場合のみ、旧記法の行内注記 `  → 支える成果目標：XXX` へフォールバックする |
| C4b | グループ見出しの金額一致 | FAIL | C4 のグループ見出し末尾 `（<金額>円）` が、その成果目標の貢献額（C1 の貢献額）と一致すること。ズレると行動グループの重みが売上の実態と食い違い、優先順位の判断を誤らせる。`（土台）`／`（関係維持）` の例外見出しは金額を持たないため対象外 |
| C5 | 参照先の実在 | FAIL | C4 のグループ見出しが指す成果目標名が、成果目標セクションに実在すること（行き先のない参照の禁止。習慣・土台のみ `（土台）`／`（関係維持）` を例外として許容） |
| C6 | 支えられない成果目標 | WARN | どの行動目標からも参照されていない成果目標（孤立）が無いこと |

**あえて検査しない規約（実装漏れではない）**: 成果目標・行動目標グループの**並び順（貢献額の降順）**は機械検査しない。同額のときに順序が決まらず判定が硬直するため、優先順位の表現は人間の判断に委ねる。「1項目=2行」の改行位置・項目間の空行も同様に非検査（貢献額の実在は C1 が押さえている）。文章側の正本は `references/output-formats.md`「読み手向けの推奨（機械検査しない）」。

#### シンプルさ検査（全種別共通・`check_goal_chain` 内）

| ID | チェック項目 | 判定 | 説明 |
|----|-------------|------|------|
| S1 | 成果目標の件数・長さ | 種別依存 | 5件超過は週報FAIL、月報・期報・1年WARN。1項目50字超過は全種別FAIL |
| S2 | 1項目1成果 | 種別依存 | 週報の `・` はFAIL。月報・期報・1年は独立成果の合算でないか意味レビューする |
| S3 | 行動目標の件数・長さ | 種別依存 | 8件超過は週報FAIL、月報・期報・1年WARN。1項目60字超過は全種別FAIL |

上限値は逸脱の検出線であり、狙うべき長さではない（実運用の目安は成果 20〜30 字・行動 25〜30 字）。定数の正本は `scripts/validate-goal-output.py` の `Validator` クラス定数、文章側の正本は `references/output-formats.md`「シンプルさの上限（機械検査対象・厳守）」。

**判定ルール**: FAIL が1件以上 → `STATUS: FAIL`（修正して再バリデーション。回数は `validation-gates.md` の「決定論ゲート」にある決定論ゲートの修復上限）

月報は1ファイルなので `--type monthly` を1回だけ回す。**提出用セクションの見出しに「（提出）」を付けるのは、この検査スクリプトの重複見出し検査（#5b）を通すための規約**。重複検査は `## 【…】` 行の完全一致で数えるため `## 【今月の売上目標（提出）】` は `## 【今月の売上目標】` と衝突しない。必須セクション検査（#5）も完全一致なので管理用セクション側で満たす。したがって**管理用セクションの見出しには文字を足さない**（素の見出しのまま。「（管理）」等を足すと必須見出しが1件も満たされず FAIL になる）。提出用の行動目標（`## 【今月の行動目標（提出）】`）はグループ見出しを置かない1行1行動の規定なので、検査スクリプトは `（提出）` を含む行動目標見出しを C4/C5（所属）と S3（件数）の抽出から外す（成果・売上側の抽出が `】` 直前一致で `（提出）` を拾わないのと揃えている）。

提出用セクションの見出しが副作用的に当たる検査は #7〜#9（行動目標の NG 表現・注記・期日）で、両セクションを1つのプールとして扱う。見出しの部分一致（`行動目標` を含み `今(週|月|期|年)` を含む）で拾うため、提出用セクションの行も同じプールに入る。#7・#9 は FAIL なので、提出用セクションにも精神論を書かず、管理用と同じ期日を書く（`output-formats.md` の「共通部品A 行動行」）。#8 は WARN

#### 一本筋の両方向照合（validate-goal-linkage.py）

検査スクリプトは所属（C4）と参照先の実在（C5）を FAIL で見るが、支える行動の無い成果目標（C6）は WARN で rc を上げない。C5 は括弧で始まる名前をすべて免除し、`・` で区切った複数参照もそれぞれが実在すれば通す。この穴を別スクリプトで埋める。照合規則（成果目標の項目の束ね方・参照キーの切り出し・空白を落とした完全一致・グループ見出しの解釈）は検査スクリプトから読み込んで共用し、二重に実装しない。

| # | チェック項目 | 判定 | 説明 |
|---|-------------|------|------|
| L1 | 順方向の参照解決 | FAIL | 各行動目標の所属（グループ見出し `### → XXX：…` の `：` より前）が成果目標セクションの項目名（`：` より前）と一致すること。見出しの無い旧ファイルは行内注記 `→ 支える成果目標：XXX` を WARN 付きで受理する。カギ括弧の行内注記 `→ 支える成果目標「XXX」` は受理しない |
| L2 | 逆方向の参照解決 | FAIL | 各成果目標を支える行動目標が最低1件あること（検査スクリプトの C6 は WARN だが、ここでは rc=1） |
| L3 | 所属の欠落・複数参照・許容外の括弧名 | FAIL | 行動目標の各項目に所属が1つだけあること（`・` で複数の成果目標を指さない）。免除する括弧名は `（土台）`／`（関係維持）` の2つだけで、ほかの括弧名（`（準備）` など）は FAIL |
| L4 | 分母0の検出 | 専用rc | 照合対象が0件のとき rc=3 を返し、rc=0（検査して0件）と区別すること |
| L5 | 照合範囲 | 対象外 | 提出用セクション（`# 北原さん提出用` グループ・`（提出）` 付き見出し）は L1-L3 の対象にしない。提出用の行動目標はグループ見出しを置かない1行1行動の規定。グループ見出しのラベルずれは FAIL |

実行条件・パスの解決・引数・終了コード・保存前後の順序は `validation-gates.md` が正本。output-formatterは検証済み一時下書き・SHA256・保存予定先だけを返し、親が `references/guarded-publication-contract.md` の中央guard executeで正式保存する。個別免除の引数は持たず、免除する行動の置き場は `output-formats.md`「成果が測りにくい行動の置き場」を参照する。

#### 四層横断照合は単一ファイル検査の対象外

形式と一本筋の検査は1ファイルを対象とする。期報・月報・任意の週報・任意の1年目標の層間検査は `validation-gates.md` の同名行で分担する。対象アンカーの定義は §3.1.3「四層横断照合（validate-cross-level.py）の対象一覧」。

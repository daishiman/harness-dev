## ファイル命名規則

| 種別 | パターン | 例 |
|------|----------|----|
| 週報 | `UBM - 1-週報 - YYYY-MM-DD〜YYYY-MM-DD.md` | `UBM - 1-週報 - 2026-03-23〜2026-03-29.md` |
| 月報 | `UBM - 2-月報（１ヶ月） - YYYY-MM-DD〜YYYY-MM-DD.md` | `UBM - 2-月報（１ヶ月） - 2026-03-02〜2026-03-29.md` |
| 期報 | `UBM - 3-月報（３ヶ月） - YYYY-MM-DD〜YYYY-MM-DD.md` | `UBM - 3-月報（３ヶ月） - 2026-06-29〜2026-09-27.md` |

**ファイルは3本。提出用の別ファイルは作らない。** 北原さんへ出す内容は**月報1ファイルの中の「提出用」セクション**として持つ（下記「月報（1ヶ月目標）フォーマット」）。週報・期報は管理用の詳細のみで、提出用セクションを持たない。

**理由（ここを戻さないために残す）: 複数のファイルにまたがると、改善・修正のときに反映漏れが起きる。**片方だけ直して他方が古いまま残る、という構造そのものを作らない。値の矛盾はその結果として現れるもので、避けたいのは矛盾より先に「直し忘れが起きる形」。「提出用は別ファイルのほうが見やすい」という判断で2本に戻してはいけない。

過去に `UBM - 2-月報（１ヶ月）（提出） - …` という別ファイルを作っていた場合は、内容を月報本体の提出用セクションへ移し、ファイルは削除せず `05_Project/UBM/目標設定/archive/` へ分離する。

### 期報の期間の決め方

UBM の目標期間は**月の最終月曜日起点**。期報の期間は**対象3ヶ月分の月報期間の連結**とする。

- 開始日 = 1ヶ月目の月報の開始日
- 終了日 = 3ヶ月目の月報の終了日
- 例: 7月・8月・9月分の3ヶ月 → `2026-06-29〜2026-09-27`

### 旧ファイル名の受理（後方互換）

読み取り・過去参照では旧名も受理する。新規作成では上表のパターンのみを使う。

- `UBM - 3-月報（２ヶ月） - …`（期報が2ヶ月だった頃の名前）
- `UBM - 3-期報 - …`

`validate-goal-output.py` のファイル名チェックは `UBM - {1,2,3}-` プレフィックスと日付パターンのみを見るため、旧名でも弾かない。

## 数値ルール

- 数値は必ず**半角数字のみ**（「万円」「千円」不可 → 600000）
- 差分は必ず**「+」または「-」**を付けて記載（例: -300000, +2）
- 行動目標（週報＝今週／月報＝今月／期報＝今期 の各成果グループ配下の各項目）には**期日と数値**を含め、**各項目の末尾に必ず期日トークンを付ける**
  - 期日トークンはバリデータ（validate-goal-output.py）が日付認識できる形にする: `M/D`（例 7/2）／`YYYY-MM-DD`／`毎日`／`毎朝`／`毎週`／`今週`／`〜まで` のいずれかを最低1つ含める
  - 「今月中」「8月中」など月単位の曖昧表現を単独で使わない。使う場合は具体日付トークン（`M/D` 等）を併記する
  - **期日は後ろの項目から逆算して置き、全項目を期間の最終日に揃えない。** 並び順は依存関係の前から後ろへ。詳細は本ファイル「行動目標の並び順と期日の逆算」
  - 箇条書きは `- ` / `- [ ]`（ハイフン）で書くのを推奨。ただし `・`（全角ビュレット）でもバリデータは受理する（Obsidianが `- `→`・` に自動変換するため両対応済み。どちらでもPASS）

## 【重要】目標・実績・差分セクションの記述ルール（厳守）

### 核心原則

**「目標 → 実績 → 差分 → 未達を挽回するための行動変化」が一目で見て分かること**が最優先。

各セクションは1つの責務のみを持つ：
- **目標**：数値・期日のみ
- **実績**：数値・完了日のみ
- **差分**：差分数値のみ（+/-記号必須）
- **行動変化**：補足説明・経緯・理由・改善方針 をすべてここに集約

実績セクションに延期理由・代替手段・経緯説明を書くと、目標 vs 実績の比較が読めなくなる。経緯・補足は必ず「未達を挽回するための行動変化」セクションに移す。

### 目標設計の流れ（売上 → 成果 → 行動の逆算・厳守）

目標は必ず **売上目標 → 成果目標 → 行動目標** の順に、上から降ろして組み立てる。週報・月報・期報の3レベルすべてで同一のルールが適用される。

```
[売上目標] いくら稼ぐか（最上流・数値1つ）
    ↓ この売上を立てるには、誰の・どの判断が必要か？
[成果目標] 先方判断・受諾・合意・継続・参加人数など、自分では確定できない結果
           各項目に「この成果が売上をいくら動かすか」を数値で必ず書く
    ↓ この判断を引き出すには、自分は何を・何件・いつまでにやるか？
[行動目標] 自分でコントロールできる動作・件数・期日
           各項目に「どの成果目標を支えるか」を必ず書く
```

#### 中核原則：実行した時点で達成になる目標は置かない

「勉強会を月4回開催する」「アカデミーに毎月参加する」のように、**実行した瞬間に達成になってしまうもの**は目標欄に書かない。それは目標ではなく、やって当たり前の行動である。書くのは「実行した結果、成果が動き、売上まで降りてくる」ものだけ。

- 行動そのもの（相談を取りに行く・アカデミーへ通う頻度を上げる等）は**当たり前の土台**として扱い、成果目標には置かない
- 行動目標には書いてよいが、その場合も必ず成果に接続する。接続の正規の形は `### → {成果目標名}：{要約}（{金額}円）` のグループ見出しであり（検査ID: C4）、行内注記 `  → 支える成果目標：XXX` は見出しが無い場合のフォールバックにすぎない

#### 表記仕様

**成果目標セクション**の各項目は **2行** で書く。1行目に成果そのもの、2行目に売上への貢献額を、**検算できる根拠つき**で示す。

```
- {対象}：{先方判断・結果の状態}{件数}　期日{M/D}
  → 売上貢献：{単価} × {件数} = {貢献額}
```

単価×件数に分解できないものは、式の代わりに括弧で根拠を添える（`→ 売上貢献：{貢献額}（{根拠}）`）。どちらの形でもよいが、**根拠の無い裸の数字だけは置けない**（次項）。

1行目と2行目を分けるのは可読性のためである。対象・判断・期日・金額を1行に詰めると横に長くなり、読み手の目が滑って金額が視界に入らなくなる。金額は必ず改行して独立させる。

##### 貢献額の統一規則（機械検査対象）

**貢献額には「式」または「括弧の根拠」のいずれかが必ず随伴する。裸の数字を置かない。**（検査ID: C1）

`150000` とだけ書かれた数字は、それが正しいかを後から誰も検算できない。求めているのは式そのものではなく、**貢献額に検算可能な根拠が随伴していること**である。式はその十分条件の一つにすぎず、単価×件数に分解できない成果（値引き後の一括見積など）は括弧の根拠で満たしてよい。

| 書き方 | 例 | 判定 |
|---|---|---|
| 式（単価 × 件数 = 貢献額） | `→ 売上貢献：80000 × 3 = 240000`（単価8万の成約3件） | OK |
| 括弧の根拠 | `→ 売上貢献：150000（値引き後の一括見積）` | OK |
| 貢献0＋将来の時期と金額 | `→ 売上貢献：0（8月に 200000 の見込み）` | OK |
| 裸の数字 | `→ 売上貢献：150000` | FAIL（C1） |

- 分解できるなら式が第一選択。`80000 × 3 = 240000`（単価8万の成約3件）と書けば単価と件数が別々に残り、単価が下がったとき・件数が変わったときに何が崩れるかが即座に分かる。ただし件数は**その期間に立つ件数**であり、期間の長さではない（次項 C1e）
- 掛け算記号は `×` `x` `*` のいずれでもよい。`=` の**右辺がその成果の貢献額**であり、突合はこの右辺を足し合わせる
- 左辺の積と右辺は一致していること（`80000 × 3 = 200000` のような計算違いは FAIL。検査ID: C1c）
- 貢献0も統一規則の一適用にすぎない。その期間の売上に直接乗らない成果は `→ 売上貢献：0（いつ・いくらになるか）` と書く。「仕込み」「母集団」だけで終わらせず、**将来の金額と時期を必ず入れる**（例：`0（8月に 300000 の見込み）`）。それが書けないなら、その成果は本当に必要か疑う
- `→ 売上貢献：` は全角コロン。数値は半角のみ（カンマ・「円」は付けてよい）

##### 計上期間の規則（機械検査対象）

**貢献額は、その期間に実際に売上として立つ分だけを計上する。式の件数に期間単位（`ヶ月`/`ヵ月`/`か月`/`年`）を掛けてはいけない。**（検査ID: C1e）

月額5万円の顧問契約を今週成約するなら、今週の売上に立つのは初月の `50000 × 1 = 50000` であって、3ヶ月分の `50000 × 3ヶ月 = 150000` ではない。契約の総額を今期間へ前倒しで積むと、売上目標が満たされたように見えて実際の入金は来ない。**「売上に直結する成果目標」とは、この期間の入金に直結するという意味である。**

- ✗ FAIL: `→ 売上貢献：50000 × 3ヶ月 = 150000`（期間単位を件数に掛けている）
- ✓ OK: `→ 売上貢献：50000 × 1 = 50000`（今期間に立つ初月分）
- ✓ OK: `→ 売上貢献：150000 × 2 = 300000`（同一期間内の成約2件。`件` は期間単位ではない）
- 期間をまたぐ分は、**次の期間の成果目標として立て直す**か、`→ 売上貢献：0（8月に 100000 の見込み）` の形で見通しとして書く
- 機械検査 C1e が捕まえるのは**式に期間単位が書かれた形**だけである。単位語を省いて `50000 × 3` と書けば検査は通るが、それが週報なら規則違反であることは変わらない。件数が「期間の長さ」になっていないかは自分で確かめる

##### 売上目標との突合（機械検査対象）

- **売上貢献額（式なら右辺、括弧の根拠ならその数字）の合計が売上目標に届いているか**を必ず自分で突き合わせる。届かないなら成果目標が足りていない
- 突合は**完全一致を求めない**。合計が目標以上なら OK。不足が売上目標の **5% 以内**なら端数程度のズレとして WARN（保存は通る）、**5% を超える不足は FAIL**（成果目標の抜けとして扱う）。判定の実体は `scripts/validate-goal-output.py` の `judge_sales_coverage()`、仕様の正本は `references/data-contract.md` §4.4 の検査 C3（検査ID: C3）
- 貢献0の項目が成果目標の**過半を占めたら WARN**。この期間の売上に何も乗らない項目ばかりが並ぶと、成果目標セクションが売上と切れた「やることリスト」に戻る（検査ID: C1d）

##### 読み手向けの推奨（機械検査しない）

以下は守るべき書き方だが、**機械検査は行わない**。実装し忘れではなく、あえて検査していない。

| 推奨 | あえて検査しない理由 |
|---|---|
| 成果目標は1項目=2行で書く（1行目=成果／2行目=貢献額） | 貢献額の実在は C1 が押さえており、改行位置まで縛ると引用・折り返しの揺れで誤検出が出る |
| 成果目標を貢献額の降順に並べる | 同額のときに順序が決まらず、機械判定が硬直する。優先順位の表現は人間の判断に委ねる |
| 行動目標のグループも貢献額の大きい順に並べる | 上と同じ理由 |
| 項目間を1行空ける | 可読性の話であり、意味を壊さない |

**行動目標セクション**は、**支える成果目標ごとにグループ化**して並べる。

```
### → {成果目標セクションに実在する項目名}：{成果の要約}（{貢献額}円）
- [ ] {行動}（数値・期日つき）
      【考え】{なぜこれをやるか}
- [ ] {行動}（数値・期日つき）
```

- 行動目標は必ず `### → ` グループ見出しの配下に置く（検査ID: C4）。見出しが無い場合のみ、旧記法の行内注記 `  → 支える成果目標：XXX` へフォールバックする
- **見出し名の `：` より前が、成果目標セクションに実在する項目を指すこと**（存在しない名前を書くのは禁止。検査ID: C5）
- **見出し末尾の `（{金額}円）` は、その成果目標の貢献額と一致させる**（検査ID: C4b）。ここがズレると、行動グループの重みが売上の実態と食い違い、優先順位の判断を誤らせる
- どの行動目標からも参照されていない成果目標（orphan）を残さない（検査ID: C6）
- 行動を成果ごとにまとめるのは、売上→成果→行動の一直線をそのまま目次にするためである。行動を優先度で束ねると、その行動がどの売上につながるのかが読み手の頭の中にしか残らない
- 優先度A/B/C の見出しは使わない（廃止）。優先順位は**貢献額の大きい成果グループを上に置く**ことで表現する（並び順は推奨。上表の理由により機械検査しない）
- 習慣・土台など特定の成果に紐づかない行動は、最後に `### → （土台）` `### → （関係維持）` のグループを置いてそこへ入れる（C5 の例外として許容される名前）。許容される括弧名はこの2つだけで、`validate-goal-linkage.py` はそれ以外の括弧名を rc=1 にする。相手が登場し、相手の側に起きた事実を数で取れる行動をここへ逃がさない（本ファイル「成果が測りにくい行動の置き場」）
- 【考え】【思い】の注記は行動行の下にインデントして添える（任意）

#### シンプルさの上限（機械検査対象・厳守）

目標が複雑になると、自分で自分の目標を読み解けなくなり、実行されない。**1項目=1つのこと**を守り、下記の上限を超えない。

| 対象 | 上限 | 検査 | 検査ID |
|---|---|---|---|
| 成果目標の件数 | 5件 | FAIL | S1 |
| 成果目標1項目の長さ（`→ 売上貢献` の前まで） | 50字 | FAIL | S1 |
| 成果目標に `・` で複数の成果を詰め込む | 禁止（1項目1成果） | FAIL | S2 |
| 行動目標の件数 | 8件 | FAIL | S3 |
| 行動目標1項目の長さ（1行目・期日込み） | 60字 | FAIL | S3 |

- 長い項目は「短くする」のではなく **2件に割る**（例：「診断を実施し、当日中に提案を共有する」→ 実施1件・共有1件）
- 背景・理由・対象リストは目標本文に書かず、`→ 【考え】` `→ 【思い】` の注記行へ寄せる
- 実際の手本の長さは `assets/golden-sample-weekly.md`（成果 21〜28字・行動 25〜30字）。上限は逸脱の検出線であり、狙う長さではない

#### 設計手順（必ずこの順番で対話・記述する）

1. **Step A: 売上目標を1つの数値で確定する**
   - 内訳（誰から・いくら）は対話で確認するが、ファイルには数値1つだけ書く

2. **Step B: 売上目標を成果目標へ割り付ける**
   - 「この売上が立つには、誰の・どの判断・合意・受諾・継続が必要か？」を問う
   - 各成果に売上貢献額を割り当て、**合計が売上目標に届くまで**成果を出し切る
   - 届かない場合は成果目標の抜けを疑う（行動を追加してごまかさない）

3. **Step C: 各成果目標から行動目標を逆算する**
   - 「その判断を引き出すために、自分は何を・何件・いつまでにやるか？」を問う
   - 1つの成果につき、相手が登場する**接点の段**（打診する → 相手の状況を聞く → 課題・条件を提示する → 実施する → 実施後に意向を聞く）で2〜4件を紐付ける。資料作成など一人で完結する作業は段として立てない（本ファイル「行動目標に何を載せるかの採否基準」）
   - 実施1行だけで前後の打診・提示・フォローが抜けているものは、成果につながる計画になっていない
   - 並び順と期日は同時に決め、期日は後ろの段から逆算する（本ファイル「行動目標の並び順と期日の逆算」）

4. **Step D: 自作成物（成果物完成目標）を整理する**
   - 行動の前提となる資料・テンプレ・システムは「成果物完成目標」として別に書く（行動＝動作、成果物＝完成物）

5. **Step E: 検査を回し、rc の値をそのまま記録する**
   - `validate-goal-output.py`（見出し集合・形式・C1〜C6・S1〜S3）→ `validate-goal-linkage.py`（成果目標と行動目標グループの両方向照合。分母を印字する）の順
   - 期報と月報が揃っている場合は続けて `validate-cross-level.py`（層をまたぐ値の照合。週報があれば `--weekly` も渡す）
   - 各 rc を**値そのまま**記録する（「PASS」と書かない）。引数と測定時刻も一緒に書く
   - 月報は**管理用セクションだけを照合する**（提出用セクションの行動目標はグループ見出しを持たない1行1行動の箇条書きなので、所属の照合の対象外）

#### 設計時の問い（対話で必ず使う）

- 売上→成果：「この売上を立てるには、誰の・どの判断が必要か？」
- 成果→売上：「この成果が出たら、売上はいくら動くか？」（数値で答えられないなら成果の定義が曖昧）
- 成果→行動：「この判断を引き出すには、自分は何を・何件・いつまでにやるか？」
- 行動→成果：「この行動を全部やったら、本当にこの成果に届くか？足りているか？」

#### 成果目標と行動目標の区別

**成果目標** = 自分では確定できない結果（先方判断・受諾・合意・継続・参加人数・売上額）
**行動目標** = 自分でコントロールできる行為（実施・送付・参加・作成・告知・打診）

ただし行動目標の欄に**載せる**のは、そのうち相手が登場し、相手の側に何かが起きる行為だけである（作成・告知のように一人で完結するものは載せない）。1項目ずつの判定手順は本ファイル「売上目標・成果目標・行動目標の三層分離」、採否は「行動目標に何を載せるかの採否基準」。

**実行完了型NG動詞リスト（この10語が正本。他ファイルはここを参照し、リストを複写しない）**

```
実施する / 開催する / 参加する / 送付する / 作成する
提出する / 共有する / 告知する / 打診する / 連絡する
```

成果目標セクションに、この10語のいずれかで終わる項目を書いてはならない。それらは行動目標側に置く。この10語は `scripts/validate-goal-output.py` の `Validator.OUTCOME_NG_VERBS` と同一集合であり、片方だけを増減させない（検査ID: C2）。

##### なぜ分けるか（差分を別々に取るため）

成果は行動の結果であり、行動と1対1では対応しない。行動したのに成果が出ないことも、意図せず良い成果が出ることもある。別セクションに分けておくことで、振り返りのときに「行動はできたのに成果が出なかった／行動は少なかったが成果は出た」という学習ができる。混ぜると原因が読めなくなる。

##### 成果目標としてOKな例
- Dさん：研修の継続合意1件　期日4月中旬
  → 売上貢献：25000 × 3 = 75000
- Eさん：業務委託の開始1件　期日4/2
  → 売上貢献：200000 × 1 = 200000
- Fさん：Claude Code提案の受諾1件　期日4/10
  → 売上貢献：150000 × 1 = 150000
- AI質問会勉強会：参加者5名以上　期日4/18
  → 売上貢献：0（5月に体験診断2件・300000 の見込み）

##### 成果目標に書いてはいけない例（すべて行動目標側へ）
- ✗ 「勉強会を月4回開催する」→ 開催した時点で達成。行動目標へ
- ✗ 「研修実施1回」「MTG実施1回」「提案実施」→ 実施は行動
- ✗ 「アカデミー参加」「アカデミーへの実績報告」→ 参加・報告は自分の手の動き。当たり前の土台として扱う
- ✗ 「体験診断セッションを3件実施する」→ 実施は行動。成果は「体験診断からの受諾N件」

##### よくある混在の修正例
- ✗ NG（成果目標）：「AI質問会勉強会：自主開催1回」
- ✓ OK（成果目標）：「AI質問会勉強会：参加者5名以上　期日4/18 ／ 次行 → 売上貢献：0（5月に 300000 の見込み）」
- ✓ OK（行動目標）：`### → AI質問会勉強会：参加者5名以上（0円）` の配下に `- [ ] 勉強会を4/18に自主開催する`

#### 一貫した例（売上→成果→行動が最後まで降りている）

```
## 【今週の売上目標】
150000

## 【今週の売上以外の成果目標】
売上 150000 を、次の成果に割り付ける。

- Bさん：提案の受諾1件　期日7/3
  → 売上貢献：100000 × 1 = 100000

- Aさん：月額顧問の成約1件　期日7/2
  → 売上貢献：50000 × 1 = 50000

- Cさん：7月勉強会の開催枠の確保1件　期日7/1
  → 売上貢献：0（8月に 200000 の見込み）

合計 150000 ＝ 今週の売上目標 150000

## 【今週の行動目標（行動管理）】

### → Bさん：提案の受諾（100000円）
- [ ] 体験診断を実施する　期日6/30
- [ ] 提案ドラフトを共有する　期日6/30

### → Aさん：月額顧問の成約（50000円）
- [ ] 提案書を作る　期日6/29
      【考え】材料が無いから判断できなかった
- [ ] 提案書を出す　期日7/2

### → Cさん：7月勉強会の開催枠の確保（0円・8月の仕込み）
- [ ] 7月の開催枠を確認する　期日7/1
```

Aさんの月額顧問（月5万）は、今週の売上に立つのは初月の 50000 だけである。2ヶ月目以降の 100000 を今週へ積むと、目標が満たされたように見えて入金は来ない（C1e）。翌月・翌々月分は、その期間の月報で改めて成果目標に立てる。

この形にすると、上から下へ読むだけで「150000 を立てるには B さんの受諾が要る → その受諾には体験診断が要る」という一直線が追える。金額の大きいグループが上に来るので、優先順位も並び順がそのまま示す。

振り返り（前週／前月／前期）の成果目標・成果実績・差分も同じ構造で並べ、「行動はやったか」「成果は出たか」「売上は動いたか」を別々に差分できるようにする。**前週・前月・前期の成果目標セクションも 1項目=2行＋貢献額（式または括弧の根拠）の新記法で書く**。これは前期間の【今週/今月/今期の売上以外の成果目標】をそのまま転記したものだからで、転記時に1行形式へ潰さない（手本: `assets/golden-sample-weekly.md` の【前週の売上以外の成果目標】）。

成果目標セクションの冒頭には次の注釈を入れる：
> 成果目標は「自分では確定できない結果（先方判断・受諾・参加人数等）」を記述し、各項目に売上貢献額を明示する。実施行為は行動目標側に置く。

### 売上目標・成果目標・行動目標の三層分離（厳守・この順で判定する）

定義の大枠と、成果目標に置いてはいけない10語は上の「成果目標と行動目標の区別」が正本。ここでは1項目ずつ層を判定する手順と、行動目標の欄に何をどう載せるかを定める。ここを履き違えると、行動目標の欄に成果が並び、「行動したのに成果が出ない」の学習ができなくなる。

| 層 | 定義 | 数の単位 | 誰が決めるか |
|---|---|---|---|
| 売上目標 | 金額 | 円 | 成果が積み上がった結果 |
| 成果目標 | **相手の側に起きた事実**の数 | 件・人・回 | 相手の応答が入る。自分の意志だけでは決まらない |
| 行動目標 | **自分が手を動かした回数** | 件・回 | 自分だけで決まる。相手が応じなくても達成を数えられる |

因果の向き:

- **行動 → 成果 は確率**。行動しても成果にならないことがある
- **成果 → 売上 は確実**（その確実さを `→ 売上貢献：` の式で示す）
- だから上げるのは**行動の基準値**。ただし「行動しまくる」ではなく、**その成果につながる行動に限る**

#### 1項目ごとの判定手順（この順で当てる）

1. 金額が書いてあるか → **売上目標**
2. 自分が手を動かし終えた時点で達成が決まるか（相手の返事を待たずに数えられるか） → **行動目標**
3. 相手の応答・承諾・来場・成約が入って初めて数が決まるか → **成果目標**

#### 行動目標の動詞（この語で書く／この語で書かない）

- 使う動詞（自分の手の動き・相手が登場する）: 出す / 打診する / 読み上げる / 連絡する / 提示する / 開催する / 議題に入れる / 臨席する / 聞く / 設定する（相手との日程・場を設定する意味に限る）
- 書かない語（相手側の結果＝成果目標へ移す）: 決まる / 確定する / 確定させる / 成約する / 取る / 満席にする / 参加する（相手が）/ 実施人数が集まる / 合意してもらう / 受諾される
- **「作成する」は使う動詞に入らない。** 資料・名簿・フォームの作成は一人で完結し相手の側に何も起きないため、本ファイル「行動目標に何を載せるかの採否基準」で削除対象になる。「作った資料を相手へ提示する」のように相手が登場する形へ書き替える
- 上の実行完了型NG動詞リスト（10語）とは向きが逆の規則である。あちらは「成果目標の欄に行動を書かない」、こちらは「行動目標の欄に相手側の結果を書かない」
- **成果目標1件につき、そのグループ（`### → 成果目標名：…`）に行動目標を1件以上置く。** 複数の成果をまとめて1行の行動にしない

#### 混同していた項目の直し方（書き方 → 本当の層 → 行動目標としての書き直し）

| 行動目標の欄に置かれていた書き方 | 本当はどの層か | 行動目標として書き直す形 |
|---|---|---|
| 無料相談の日程だけをその場で30件決める | 成果（相手が決める） | 接触の締めで無料相談の案内を読み上げ、日程を打診する（30件） |
| 無料相談を延べ30回実施する | 成果（相手が応じた回数） | 打診済みの相手へ日程の再確認の連絡を出す（30件） |
| 1回目の無料相談を実施する実人数を20名作る | 成果 | 1回目をまだ実施していない相手へ打診の連絡を出す（20件） |
| 月額継続コンサルの条件を提示し3件取る | 成果（取るのは相手の決定） | 4回目の場で月額継続コンサルの条件を1件ずつ提示する（件数） |
| AI勉強会を開催し当日参加15名にする | 開催＝行動 / 15名＝成果 | 行動は「開催する（回数）」「個別連絡を出す（12件）」「紹介依頼を出す（8件）」に分け、15名は成果目標に置く |
| 5名の方と3回ずつ（計15回）の無料相談を実施する | 成果 | 2回目まで進んだ相手へ3回目の日程を打診する（件数） |
| 研修1件を実施し金額と時間数を確定させる | 確定＝相手との合意（成果） | 研修の金額と時間数を提示して先方へ確認の連絡を出す（1件） |

#### 既に行動として書けているもの（直さない）

- 無料・オフラインの作業会を20:00-22:00に13回開催する（自分が開ければ成立）
- 継続契約2社の定例を月8回設定して臨席する
- 既に定例でお話ししている事業者様7名の定例の議題に、紹介依頼を1件ずつ入れる
- AI勉強会の集客で、過去の参加者へ個別連絡を12件出す
- 声をかける相手を1名決めて連絡する

#### 分離の実装ルール（厳守）

- 行動目標は、支える成果目標ごとの `### → {成果目標名}：{要約}（{金額}円）` 見出しの配下に置く（記法の正本は本ファイル「表記仕様」。検査ID: C4/C4b/C5）。**これは管理用の規則。** 月報の提出用セクションの行動目標はグループ見出しを置かない1行1行動の箇条書きにする
- 見出しの `：` より前は、成果目標セクションの項目名（`：` より前）と**同じ文字列**にする。1文字違いも不可（照合は空白を落とした完全一致）
- 見出しの無い旧ファイルの行内注記 `→ 支える成果目標：XXX` は、読み取りのフォールバックとしてだけ受理する。ローカル版 0.4.0〜0.5.0 で使っていたカギ括弧の行内注記 `→ 支える成果目標「XXX」` は受理しない（`validate-goal-linkage.py` は FAIL にし、グループ見出しへの書き換えを案内する。validator も所属不明として C4 で FAIL にする）
- 「面談する／日程を打診する／打診する／提示する」等の**自分の手が動き、かつ相手が登場する**動作は行動目標に置き、成果目標には置かない
- 「合意される／継続される／受注する／N名参加する／紹介が出る」等の先方・市場の結果は成果目標に置き、行動目標には置かない
- 成果物（資料・定義・提案書・名簿・フォーム・告知文）の**完成そのものは行動目標に置かない**（一人で完結し相手の側に何も起きないため、本ファイル「行動目標に何を載せるかの採否基準」で削除対象）。置くのは「作った資料を相手へ提示する」のように相手の側に何かが起きる行で、その成果物が引き出す先方判断を成果目標に置く
- 関係維持・習慣・記録など成果が測りにくい行動は、行動目標セクション末尾の `### → （土台）`／`### → （関係維持）` グループへ置く（本ファイル「成果が測りにくい行動の置き場」）。**許容される括弧名はこの2つだけ。** ほかの括弧名（`### → （準備）` など）で逃がさない
- **成果目標1件につき、それを支える行動目標を最低1つ置く。** `validate-goal-output.py` の C6 は WARN 止まりだが、`validate-goal-linkage.py` は未解決（rc=1）として数える
- 成果目標のどの項目も、売上目標のどの金額につながるかを `→ 売上貢献：` で示す（C1/C3）。つながらない成果目標は削る

一本筋は `売上目標 → 成果目標 → 行動目標` の3段。宙に浮いた項目（売上につながらない成果・成果を指さない行動・行動に支えられていない成果）を置かない。

#### 行動目標に何を載せるかの採否基準（1行ずつ判定する）

**残す**（自分以外の誰かが登場し、相手の側に何かが起きる）:

- 会う / 連絡する / 打診する / 依頼する / 提示する / 聞く
- 開催して人が集まる（対象が不特定でも、人が集まるなら残す）
- 実施して相手の困りごとを解く
- アカデミーのコラム読みとアウトプット、コラムミーティングへの参加（場に人がいる）

**削除**（一人で完結し、相手の側に何も起きない）:

- 1枚にまとめる / 名簿を作る / 資料を仕上げる / 経費を決める
- 報告書・目標ファイルを提出する
- SNS・YouTube の投稿や告知（相手の応答がその場で起きない）
- 日々の自己管理（起床・振り返り・チェックシート）

**削除したものの行き先**: 日々の自己管理は `【習慣目標】` が担う。資料作成が成果の前提になっている場合は、資料を作る行だけ残さず「作った資料を相手へ提示する」行に書き替える。削除した行を `### → （土台）` へ移して残すことはしない（`（土台）` は習慣を回し続けることの置き場で、採否基準の抜け道ではない）。

**同じ基準を行動実績・行動差分にも適用する。** 目標から外した行が実績に残っていると差分が取れなくなる。

**行動を削った結果、支える行動が1件も無くなった成果目標を残さない。** その成果は今期間の対象から外すか、支える行動を立て直す。

#### 成果が測りにくい行動の置き場（`### → （土台）`／`### → （関係維持）`）

関係維持・習慣・記録のように、やること自体は決まっているが**相手の側に起きる事実を数で取れない**行動がある。これを成果目標のグループに入れると、架空の成果を作ることになる。行動目標セクションの**末尾**に `### → （土台）` または `### → （関係維持）` のグループを置き、そこへ入れる。

```markdown
### → （土台）
- [ ] 習慣目標セクションの各カテゴリを毎日チェックする　期日 毎日

### → （関係維持）
- [ ] 北原さんへ近況を連絡する　期日 毎週月曜
```

- 括弧名は `（土台）` と `（関係維持）` の2つだけ。見出しに金額は書かない（C4b の対象外）
- **相手が登場し、相手の側に起きた事実を数で取れる行動をここへ逃がさない。** それは成果目標を立て、そのグループに置く
- 日々の自己管理そのもの（起床・振り返り・チェックシート）は `【習慣目標】` が担う。`（土台）` に置くのは「習慣を回し続けること」、`（関係維持）` に置くのは売上の筋に乗らない関係維持だけ
- ローカル版 0.4.0〜0.5.0 で使っていた独立見出し `【今◯の習慣・土台（売上の筋に乗せないもの）】` は廃止した。既存ファイルにあれば、中身をこの2グループへ移す

#### 成果→行動の完全な落とし込み（標準粒度・厳守）

本ファイル「行動目標に何を載せるかの採否基準」に反する粒度は置かない。段を細かくする目的で、一人で完結する作業（資料作成・名簿作成・フォーム作成・告知）を段として立ててはいけない。

成果目標を並べるだけでは不十分。**各成果目標のグループに、それを生む行動目標を「相手が登場する接点の段」で必ず置く**（1成果につき2〜4行動が目安。行動目標の総数は上限8件＝S3）。接点の段とは `打診する → 相手の状況を聞く → 課題・条件を提示する → 実施する → 実施後に意向を聞く` の並びで、各段が**相手の側に何かが起きる**行になっている状態。グループの中が「実施する」1行だけで、前後の打診・提示・フォローが抜けていると、成果につながる計画になっていない。

```markdown
### → 日工さん：研修の継続合意（75000円）
- [ ] 研修の日程を打診する　期日 4/3
- [ ] 作成した研修資料を先方へ提示する　期日 4/8
- [ ] 研修を実施する　期日 4/15
- [ ] 研修後に継続/次回の意向を聞く　期日 4/17
```

- 例（成果「勉強会：参加申込5名以上」）→ `### → 勉強会：参加申込5名以上（0円・…）` の配下に「会場へ利用の打診をする」「過去の参加者へ個別連絡を12件出す」「定例の議題に紹介依頼を1件ずつ入れる」「勉強会を開催する」
- **振り返り（前週/前月/前期）でも同様**に、前期間の各成果を生んだ行動を行動目標・実績・差分に並べ、「行動はやったか」「成果は出たか」を別々に差分できるようにする
- 粒度の既定は「標準」（接点の段が4前後）。細かすぎる各回分解や、実施1行だけの粗さは避ける
- 資料・名簿・フォームの作成が成果の前提になっている場合は、作成の行を立てずに**提示・案内の行の中に含める**（「作成した研修資料を先方へ提示する」）。作成が抜け落ちることを心配して行を立てると、採否基準に反する

#### 行動目標の並び順と期日の逆算（厳守）

行動目標は**各グループの中で上から順に実行できる並び**にする。並べ終わってから期日を入れるのではなく、**並び順と期日を同時に決める**。

**1. 並び順は依存関係の前から後ろへ。** 前の段が終わっていないと次の段が成立しない項目（1回目に打診する → 2回目に相手の状況を聞く → 3回目に課題を出す → 4回目に条件を提示する のような段階）は、**並び順も期日も前から順にする**。後段を先に書いて前段を後に書くと、読んだ順に実行できない。

**2. 期日は後ろの項目から逆算して置く。** 最終段の期日を先に決め、そこから各段に必要な日数（相手の検討時間・自分の準備時間・次の接点までの間隔）を引いて前の段の期日を決める。先頭から「とりあえず早め」で埋めない。

**3. 全項目を期間の最終日に揃えてはいけない。** 期間の最終日に残してよいのは、**月（期間）を通して回す項目＝特定の日に完了しない項目**だけ（例: 無料相談を30回行う、毎週の定例連絡）。段階のある項目を全部最終日に置くと、どの段がいつ終わっていないと間に合わないのかが読めず、最終週に全部残る。

- ✗ NG: 行動目標の全項目が `期日 {{end_date}}` になっている
- ✗ NG: 「2回目で状況を聞く」と「4回目で条件を提示する」が同一期日になっている（段が同じ日に成立しない）
- ✓ OK: 1回目 10/8 → 2回目 10/15 → 3回目 10/22 → 4回目 10/29、期間を通して回す「無料相談30回」だけが `期日 {{end_date}}`

**4. 提出用セクションと管理用セクションで同じ行動の期日を食い違わせない。** 提出用で粒度を人数・件数へ集約しても、**期日は管理用で逆算した値をそのまま持たせる**（集約して1行になった項目は、その中で最も遅い段の期日を使う）。期間を通して回す項目だけが期間末日になる。

**5. セクション全体が期日順でないときは注記を置く。** グループは貢献額の大きい順に並ぶため、グループをまたいだセクション全体は期日順にならないことがある。その場合は節の先頭に次の1行を置く（日々の実行順の正本は週報の【今週の大きな到達ライン】、月報の【今月の日別タスク】）。

#### 一本筋の照合は validate-goal-output.py と validate-goal-linkage.py で分担する

`validate-goal-output.py` は C4（所属不明）と C5（参照先の実在）を FAIL、C6（支える行動の無い成果目標）を WARN で検査する。`validate-goal-linkage.py` は**同じ照合規則**（成果目標の項目名の切り出し・空白を落とした完全一致・グループ見出しの解釈・行内注記へのフォールバック）を validator から読み込んで使い、規則を二重に実装しない。上乗せするのは次の5点だけである。

- 1つの行動が複数の成果目標を指す `・` 区切りを FAIL にする（C5 は各参照の実在だけを見る）
- 支える行動の無い成果目標を**未解決（rc=1）**として数える（C6 は WARN）
- 括弧名の免除を `（土台）`／`（関係維持）` の2つに限る（C5 は括弧で始まる名前をすべて免除する）
- 月報の `# 北原さん提出用…` グループを照合対象から外し、`# 管理用…` グループだけを照合する。グループ見出しのラベルずれも FAIL にする
- 両方向の分母を印字し、分母0を rc=3 として PASS と区別する。末尾に測定時刻と引数を残す

```bash
/usr/bin/python3 "$CLAUDE_PLUGIN_ROOT/skills/run-ubm-goal-setting/scripts/validate-goal-linkage.py" --file "<目標ファイルの絶対パス>" > out.txt 2>&1; rc=$?; echo "rc=$rc" >> out.txt
```

rc=0 未解決0件（分母も1件以上） / rc=1 未解決あり / rc=2 引数・ファイルの誤り / rc=3 **分母0（照合対象が1件も無い。数えていない）**。rc=3 を PASS として扱わない。rc と一緒に引数と測定時刻を記録する。月報は**管理用セクションだけ**を照合する（提出用セクションの行動目標はグループ見出しを持たない規定なので、`# 北原さん提出用` グループは `SKIP` で対象外になる。一本筋の担保は管理用セクション側）。

#### 層をまたぐ値のズレも、単一ファイルの検査では検出されない

`validate-goal-output.py` も `validate-goal-linkage.py` も、基本は **1本のファイルしか見ない**（`validate-goal-output.py --peer` は期アンカー3値を WARN で並べるだけで、rc は変わらない）。
期報の数字を直して月報・週報へ追随させ忘れても、**どちらも rc=0 で通る**。
層をまたぐ値を突き合わせる口が存在しない（分母が0件）ので、「検査して一致していた」ではなく
「当てる対象が1件も無かった」の形になる。3本が揃っている場合は三層横断照合を回す。

```bash
/usr/bin/python3 "$CLAUDE_PLUGIN_ROOT/skills/run-ubm-goal-setting/scripts/validate-cross-level.py" \
  --quarterly "<期報の絶対パス>" --monthly "<月報の絶対パス>" --weekly "<週報の絶対パス>" \
  > out.txt 2>&1; rc=$?; echo "rc=$rc" >> out.txt
```

rc=0 全一致 / rc=1 不一致または抽出不可あり / rc=2 引数・入力不正 / rc=3 **抽出0件（何も判定していない）**。
rc=3 を PASS として扱わない。週報がまだ無ければ `--weekly` を省略する。
アンカーの一覧と抽出元は `references/data-contract.md` §3.1.3 を正本とする。

### 三層（期報・月報・週報）の連携

期報が正本で、月報・週報がそこから継承する。**下から上へは直さない。**
数字を直すときは必ず期報を先に直し、そこから月報・週報へ降ろす。

```
期報（3ヶ月・暦月）        ← 正本。期の売上目標と月別内訳をここで決める
  ↓ 月別内訳を降ろす
月報（1ヶ月・最終月曜起点） ← 当月の売上目標・当月の最重要数字をここで持つ
  ↓ 日割り・週の内訳を降ろす
週報（1週間・月曜起点）     ← 週の売上目標・週の最重要数字をここで持つ
```

継承の形は2つある。混ぜると照合が必ず落ちる。

- **同値継承**: 期全体の値をそのまま書き写す。三層で同じ数字（今期の売上目標 など）
- **内訳継承**: 上位が月別・週別の内訳として書いた値を、下位が自分の層の値として書く
  （期報「無料相談の延べ回数120回：10月56回…」→ 月報の最重要数字の56回）

内訳継承の値は、**下位層の数字が上位層の内訳の記述と一致していること**が条件。
期合計と月の値が違うのは正常。逆に、期報に月別内訳を書いていないと下位層の値の根拠が
たどれなくなるため、期報には必ず月別内訳を書く（【事業計画書数値】の「月別の売上目標」行）。
週報の売上目標は、月額を日数で割った根拠行を注記として残す（`（※ 600,000 ÷ 28日 × 7日 ＝ 150,000）`）。
この根拠行が無いと、週の値がどの月額から来たのか照合できない。

#### 【この期報の値を直したときに追随させる箇所】は期報の標準装備

期報には、値を直したときに下位層のどこを直すかを書いた節を必ず置く。
期報だけ直して月報・週報が古いまま残るのを防ぐための節で、人が目で追うための地図。

```markdown
## 【この期報の値を直したときに追随させる箇所】
期アンカー（今期の売上目標／月別の売上目標／無料相談の延べ回数）は、
この期報を正本として月報・週報が継承する。

### 変わる可能性のある元の数字
- （数字と、それが動く条件）

### 期報側（このファイル）の正本行
- （節名と、その節のどの行が正本か）

### 月報側（<月報の期間> の月報）で追随させる箇所
- （節名と行）

### 週報側（<週報の期間> の週報）で追随させる箇所
- （節名と行）
```

#### 期間の区切りが層で違う（既知の衝突）

月報・週報は**最終月曜起点**、期報は**暦月**。この2つは一致しない。
そのため「当月」は月報の**期間終了日の月**で決める（2026-09-28〜2026-10-25 の当月は10月）。
三層横断照合も同じ決め方をしている。期報側の月別内訳は暦月で書く。

#### 踏みやすい落とし穴

- **期報だけ直して月報・週報が古いまま残る。** 単一ファイルの検査では rc=0 で通る。
  期報と月報が揃ったら `validate-cross-level.py` を回す（週報があれば `--weekly` も渡す）
- **経緯の記述を現在値と読み違える。** 「以前は500,000だった」「従来の1,200,000から置き直し」は
  【仮置き事項】【衝突】【確定済み・解消済みの記録】【来月以降に対応すること】の中に置く。
  アンカーの節の本文に混ぜない（混ぜると人も検査器も現在値として読む）
- **期合計と月の値を同値にしようとする。** 内訳継承の値は同値にしない。期報に月別内訳を書く
- **週報の日割り根拠行を落とす。** 落とすと週の値の出どころがたどれなくなる
- **全角数字で書く。** 半角のみ。全角で書かれた値は抽出不可になり、検査できていない状態になる
- **下位層で先に直す。** 期報を先に直す。下から上へは直さない

### 要因分析セクション（重要・必須）

各「未達を挽回するための行動」セクション（全レベルの新フォーマットで「前週/前月/前期の◯◯に対して未達を挽回するための行動」という名称。前期間語（前週/前月/前期）が変わるだけで役割は同じ）では、フォーマット通りの行動を箇条書きで書いた直後に、別見出し（H3）で **要因分析** を付ける。

**未達の振り返りは新しい見出しを作らず、この3つの既存見出しに書く。**

| 内容 | 書く見出し |
|---|---|
| 売上が未達だった事実と、次に取る行動 | `【前◯の売上に対して未達を挽回するための行動】` |
| 成果が未達だった事実と、次に取る行動 | `【前◯の売上以外の成果に対して未達を挽回するための行動】` |
| 行動が成果につながらなかった原因と、直し方 | `【前◯の行動に対して未達を挽回するための行動】` |

数値の差分は `【…差分】` 見出しが受け持つ。**差分見出しには文章を書かない**（`validate-goal-output.py` が数値・箇条書き形式を要求する）。

#### 書く内容の骨格（この3点を順に書く）

1. **何が未達だったか**（事実・数値）
2. **行動が成果につながっていなかったこと**（成果につなげるための行動目標・売上目標を立てるよう言われていたが、成果につながる動きになっていなかった、という事実）
3. **成果につなげる前提に立ち直して、行動の基準値をどこからどこへ上げるか**（「連絡を月8件から月30件へ」のように、起点と到達点を数値で書く）

**禁止**: 精神論NG。「意識する」「気をつける」「頑張る」は使わない。**「意識を持った」も書かない**。代わりに基準値の数値で書く。「自分なんかが」等の枕言葉も使わない。未達の理由を人や環境に置かず、**行動の層（自分の手の動き）で書く**。

- 行動変化セクション本体：フォーマット通り（`- **未達項目** → 行動変化` の形。行動変化の側は上記3点目の基準値を含める）
- その下に H3 で要因分析セクションを追加：「なぜダメだったのか／なぜうまくいったのか」を分析的に記述

#### 構造例

```markdown
## 【前月の売上に対して未達を挽回するための行動】
- **未達項目1** → 次の行動変化（基準値を N件 から M件 へ上げる）
- **未達項目2** → 次の行動変化
- **未達項目3** → 次の行動変化

### 売上未達の要因分析（なぜ60万円が0円になったのか）

**根本要因**：
1. **要因1見出し**：状況の詳細・なぜそれが起きたか・何を見落としたか（2〜4文）
2. **要因2見出し**：同上
3. **要因3見出し**：同上

**学習**：今回から得た普遍的な教訓を1〜2文でまとめる
```

#### 上振れ実績の要因分析（目標外で達成された場合）

目標外で達成された実績（例：tenant契約成立）がある場合、未達分析と同じ形で「なぜうまくいったのか」を分析する：

```markdown
### {{上振れ項目}}（目標外上振れ）の要因分析と次への行動変化

**契約が決まった要因**：
1. **要因1**：何が機能したか・どう作用したか
2. **要因2**：同上

**次への行動変化（再現可能化）**：
- **再現アクション1** → 具体的に何をいつまでにやるか
- **再現アクション2** → 同上
```

要因分析の目的：単に「未達でした」「成功しました」で終わらせず、構造的な原因を言語化することで、次の行動の質を上げる。フォーマットだけを満たして終わると学びが蓄積されない。

### 売上系セクション（売上目標・売上実績・差分）

**そのセクションには数値1つだけ**を記述する。

- ✓ OK: `600000`
- ✓ OK: `-600000`
- ✗ NG: 表（| 売上源 | 目標 | 根拠 |）を入れる
- ✗ NG: 「### 前回売上目標の内訳」のサブセクションを足す
- ✗ NG: 説明文を足す

内訳・根拠を残したい場合は、目標設定の決定プロセスとして対話で確認するだけにとどめ、出力ファイルには記述しない。

#### 継続売上と単発を混ぜない

- 売上目標の数値は**継続的にできる金額**だけで立てる。単発（研修・システム開発・勉強会の参加費など）を売上目標の内訳に数えない
- 単発の見込みを成果目標に置くときは、`→ 売上貢献：0（単発 75000 の見込み・売上目標の外）` のように貢献0＋括弧の根拠で書き、C3 の合計に入れない。売上系セクション本体には書かない
- 継続は**累積**で積む（一度取れば翌月も乗る）。件数は累積と新規を書き分ける
- **追う対象は金額でなく人数・回数**（「売上を追わない。人数で追う」）。最重要数字セクションには人数・回数を置く
- 文中で「単発」と「継続」を必ず書き分ける。どちらか分からない書き方をしない
- 売上目標の金額は、継続分の成果目標の売上貢献（単価 × 件数）の合計で説明できる形にする（C3）。売上系セクション本体には数値1つだけを書く

### 成果目標・行動目標セクション

**箇条書きのみ**。Markdown 表（table）の使用は禁止。

#### 目標セクション

成果目標は **1項目=2行**。1行目に `- 項目名：先方判断・結果の状態　期日{M/D}`、2行目に `  → 売上貢献：…`（式または括弧の根拠）。項目間は1行空ける。今期間の成果目標も、前期間の成果目標（転記）も同じ形式で書く。

例：
```markdown
- 日工さん：研修の継続合意1件　期日4/15
  → 売上貢献：25000 × 3 = 75000

- 森田さん：業務委託の開始1件　期日4/2
  → 売上貢献：200000 × 1 = 200000
```

行動目標は `- [ ] 項目名（数値・期日つき）` を、支える成果目標ごとの `### → {成果目標名}：{要約}（{金額}円）` 見出しの配下に置く。

#### 実績セクション（特に厳守）

**「目標に書いた項目すべて」を必ず実績側にも書く**。実績数値（できた件数・回数・金額）と完了日のみで記述。

- 形式：`- 項目名：実績数値・完了YYYY-MM-DD（または完了月日）` の形
- 例：
  - `- 日工さん研修：3回・完了4月中旬`
  - `- 森田さん業務委託開始：1件・完了4/16`
  - `- 海老名さん単価決定：1件・完了4/15／業務委託開始：0件`
  - `- 阿部さんGWS提案：0件`
  - `- 田村さんGWS方向性：0件`

**実績セクションに書いてはいけないもの**：
- 「→次のフェーズへ」「先方都合で延期」などの理由・背景説明
- 「実施」「未達」「次回確認」などの抽象的状態
- 「合意未達→受注」のような経緯説明
- 「○/△/×」「(参考)」などの記号
- 売上計上未確認・代替成果の経緯など

**実績に書くべきもの**：
- 目標項目それぞれに対する **件数（数値）** と **いつ完了したか（日付・期日）**
- できなかったものは `0件` と記述
- 数値が分割される場合は項目を分ける（`単価決定：1件・完了4/15／業務委託開始：0件`）

**目標外の追加実績**：
目標になかったが期間中に実現した件は、実績セクションの末尾に「（追加実績）」サブ見出しの下に箇条書きで追加してよい。形式は同じ（`- 項目名：実績数値・完了日`）。

#### 差分セクション

`- 項目名：差分数値` の形（例: `- 日工さん研修：+2回`）

- 必ず `+` または `-` を付ける
- 説明文・理由・背景は書かない
- **行動目標の差分は、行動目標1行につき1行の差分を書く。** まとめて1行にしない（目標側の行数と差分側の行数が一致するのが既定）
- 実績が取れていない項目は数値の代わりに `[要確認]` と書く（例: `- 紹介依頼を出す：[要確認]`）

#### 説明・理由はどこに書くか

実績の延期理由・代替実現・軸転換の経緯・先方都合などは、すべて以下のセクションに集約する：

- 「【前{週/月/期}の売上に対して未達を挽回するための行動】」
- 「【前{週/月/期}の売上以外の成果に対して未達を挽回するための行動】」
- 「【前{週/月/期}の行動に対して未達を挽回するための行動】」

これらのセクションは散文・箇条書きどちらでもよく、根本原因→次月への行動変化を記述する。

## 週報（1週間目標）フォーマット

週報は視認性のため `---` で2ゾーンに分ける。**ゾーンA（ロールアップ用ヘッダー・準静的＋前週実績）** と **ゾーンB（今週の実行・毎日見る所）** の2層構成。ゾーンAは月報/期報へロールアップする公式ヘッダーと前週レビュー、ゾーンBは週報固有のチェックリスト群（最重要数字・今週の売上目標／売上以外の成果目標・到達ライン・成果グループ別の行動目標・習慣目標・判断基準・週末振り返り）を置く。**「今週送る個別メッセージ」「今週やらないこと」はゾーンBの構成要素ではない**（後述の通り週報では廃止し、到達ラインの子タスクへ組み込む）。

### ロールアップ契約（週報→月報/期報の集約規則）

週報のゾーンAを上位（月報/期報）へ集約する際は次の契約に従う。見出し名は改名せず、規約に沿って機械的に集約する。

- (a) 集約は見出し名キーの再マッピングで行う。期間語（今週/今月/今期、前週/前月/前期）を正規化した「【{期間}の…】」キーでルックアップし、ゾーン位置に依存せず（ゾーン非依存ルックアップ）、上位フォーマットの確定セクション順へ再ゾーニングする。本文は N:1 で集約し、見出しキーは 1:1 で対応させる。
- (b) 週報固有見出し（今週の位置づけ・今週の最重要数字・今週の大きな到達ライン・習慣目標（仕組みで動く土台）・今週の判断基準・今週末の振り返りチェックリスト）は集約対象外。上位へロールアップしない。
- (c) 月報固有見出し（確認された情報・北原さんの原則・要因分析H3・プロジェクト別タスク）は週報集約では供給されず、月報側で新規生成する。

### チェックリスト形式の徹底ルール（最優先・厳守）

週報は「済/未済を二値で判定できる」ことが最優先。以下のセクション（すべて**ゾーンB**に属する）は必ず `- [ ]` チェックボックス形式で出力する。**簡潔版を求められても、ユーザーがプロジェクト別タスクの省略を指定しても、これらのチェックボックス化は絶対に外さない。**

| セクション | 形式 |
|-----------|------|
| 今週の最重要数字 | `- [ ]` 各項目 |
| 今週の大きな到達ライン | `- [ ]` 日別（`6/8（月）：...` の形で1日1行以上） |
| 今週の行動目標（行動管理・優先順位付き） | 成果目標ごとの `### → ` 見出し＋配下に `- [ ]` 各項目（合計3項目以上） |
| 習慣目標 | カテゴリ別 `### ` 見出し＋各カテゴリに `- [ ]` 2項目以上（最低6チェックボックス） |
| 今週末の振り返りチェックリスト | 3ブロックの `- [ ]` |

**【適用範囲: 週報のみ】今週送る個別メッセージ・今週やらないこと は独立セクションとして出力しない**（廃止）。**月報・期報では【今月やらないこと（明確に排除するもの）】／【今期やらないこと（明確に排除するもの）】を独立セクションとして3項目以上必須で出力する**（validate-goal-output.py の必須見出しリストに含まれる）。廃止は週報に閉じた措置であり、他種別へ一般化しない。同じタスクが複数箇所に存在すると追いづらくなるため、個別メッセージの送付とやらないことの制約は、**それぞれ該当する日の【今週の大きな到達ライン】の子タスクに直接組み込む**（例: MTG後のお礼メッセージはそのMTGがある日の子タスクとして、やらないことの制約はリスクが生じる日の子タスクとして書く）。追跡すべきタスクの置き場所を【今週の大きな到達ライン】に一本化する。

#### 実行管理の2方式（どちらでもよいが、行動目標のチェックボックス化は必須）

- **方式1: プロジェクト別タスク中心** — 各案件を `- [ ] [期日] [提出先・宛先] 対象物・行動` で列挙する
- **方式2: 成果グループ＋日別到達ライン中心** — プロジェクト別タスクは省略し、成果目標ごとにグループ化した行動目標と日別到達ラインのチェックボックスで実行管理する

## 月報（1ヶ月目標）フォーマット

公式21ブロックを公式順に並べ、深掘りブロックは公式の後に置く。スナップショット項目（現在事業パートナー数〜現在のグリッドパートナー数）は前月レビューの前ではなく、今月計画（今月の売上目標〜今月の行動目標）の後に配置する。

**「公式21ブロック」の語の定義（この語の正本は本ファイル）**: 北原さん提出フォーマット由来の**固定**の見出し集合を指す。21 はその見出し数で、提出フォーマットが変わらない限り不変。全件の並びは本ファイル下部の月報テンプレートに逐語で置いてある。`output-formatter.md` の品質チェックリストはこれとは別物で、観点が増減すれば数も変わるため**件数で呼ばない**（「21項目」の語をチェックリスト側に使ってはいけない）。

### 月報は1ファイルの中で提出用セクションと管理用セクションに分ける（厳守）

**ファイルは1本。提出用の別ファイルを作らない。** 北原さんへ出す内容と自分が回す内容を同じファイルの中で上下に並べる。2セクション構成になるのは月報だけで、週報・期報は詳細のみ。

**理由: 複数のファイルにまたがると、改善・修正のときに反映漏れが起きる。**同じ事項が2箇所にあると、片方だけ直して他方が古いまま残る。値の矛盾はその結果にすぎず、避けるのは「直し忘れが起きる形」そのもの。見やすさを理由に2本へ戻してはいけない。

- **提出用セクションを先、管理用セクションを後**に置く
- 群の見出しは `# 北原さん提出用（シンプル）` と `# 管理用（詳細）`（H1。項目見出しは両群とも H2）
- **提出用セクションの `## 【…】` には、閉じ括弧の内側に「（提出）」を付ける**（例: `## 【今月の売上目標（提出）】`）。validate-goal-output.py の重複見出し検査は `## 【…】` 行の完全一致で数えるため、この接尾があれば管理用の同名見出しと衝突しない。成果目標・売上目標の抽出（C1〜C3）も `（提出）` 付きを拾わず、行動目標のグループ検査（C4/C5・S3）も `（提出）` の付いた見出しを対象から外す
- **管理用セクション側の見出しには文字を足さない**（素の `## 【今月の売上目標】` のまま）。必須見出しの検査は `^## 【ラベル】[ \t]*$` の完全一致なので、必須見出しを満たすのは管理用側。ここに「（管理）」等を足すと必須見出しが1件も満たされず FAIL になる
- **数字は両セクションで同じ値を使う。** 落とすのは粒度だけで、値は変えない（提出用で丸めない・削らない）
- **シンプル＝項目を削ることではない。** 公式21ブロックの見出しは提出用セクションでも1つも落とさない
- 【確認された情報】【顧問参加前の月商】は両群に共通のヘッダーメタなので、群の前に1回だけ置く（公式21ブロックには含まれないため、提出用から落ちたことにはならない）

#### 提出用セクションの粒度（シンプルな構成）

| 観点 | 提出用セクション | 管理用セクション |
|---|---|---|
| 成果・行動の単位 | **人数・件数・回数に集約**（「有料コンサルの成約3件」「無料相談を30回行う」） | 同じ数値を案件・相手ごとに分解してよい |
| 成果目標の売上貢献 | 集約した件数で `→ 売上貢献：` を書く（合計は管理用と同値） | 案件・相手ごとに `→ 売上貢献：` を書く |
| 日付 | **本文に具体日を埋め込まない。** 行末の期日は管理用で逆算した値をそのまま持たせ、期間末日に揃えない（期間を通して回す項目だけ期間末日） | 日別・週別に割る（【今月の日別タスク】） |
| 行動目標のまとめ方 | **グループ見出し（`### → `）を置かない。** 1行1行動の平坦な箇条書き | 支える成果目標ごとの `### → 成果目標名：要約（金額円）` でグループ化する |
| 個人名 | **個人名を書かない。** 一人一人に対する行動目標は置かない | 先方担当者名・個人名を書く |
| 記述量 | 要点のみ。行動目標は各項目1行、成果目標は2行（成果＋売上貢献） | 管理に必要な行数（提出用の3倍程度になる） |
| 説明・背景 | 書かない | 要因分析・経緯を書く |

1項目の粒度は「**何をする・何件**」まで。`- 無料相談を30回行う　期日 {{end_date}}` は可。`- 岡田さんと会う` のような一人一人に対する行動目標は提出用に置かない（管理用セクション側で持つ）。

**提出用セクションにも【今月の行動目標（提出）】の見出しを必ず置く。** 行動目標は提出対象であって、管理用だけに持つものではない。

- 行動目標の**行末の期日は残す**（`validate-goal-output.py` の品質チェックは提出用の行動目標にも期日トークンを要求する）。期日は**管理用セクションで逆算した値と同じ値**にする（集約して1行になった項目は、その中で最も遅い段の期日）。**期間末日1つに揃えてはいけない**（期間末日に置くのは、期間を通して回す項目だけ）。日次・毎週の習慣は `期日 毎日` `期日 毎週` のままでよい。詳細は本ファイル「行動目標の並び順と期日の逆算」
- **グループ見出しも行内の `→ 支える成果目標：` も提出用セクションには書かない。** 1行1行動の箇条書きにする。支える先の明記は管理用セクション側で担保しているので、提出用に二重で持たせない（`validate-goal-linkage.py` も提出用グループを `SKIP` する）
- 本文に具体日を埋め込まない（「10/17の勉強会の締めで」→「勉強会の締めで」）。ただし勉強会など**開催日そのものが情報である予定**は日付を書いてよい
- 個人名を書かないため、人の表し方は**一般敬称**にする（「新規の事業者様7名」）。提出先の指導者の名前だけは書いてよい
- 実績・差分も「誰と会ったか」ではなく**「何人と会ったか」**で書く

## 期報（3ヶ月目標）フォーマット

期報は月報（上記「月報フォーマット」）の確定セクション順をそのまま使い、以下の読み替え規則を適用する。

### ロールアップ元（月報3件）

期報は**対象期間の月報3件をロールアップして作る**。ロールアップの機械的規則（見出しキー 1:1 ／本文 N:1 集約／再ゾーニング）は「ロールアップ契約（週報→月報/期報の集約規則）」と同じで、供給元が月報3件になる点だけが異なる。

### 読み替え規則

- サマリー見出しは `## 【3ヶ月の目標】{{start_date}}〜{{end_date}}`（継続語彙・凍結。改名禁止）。
- 振り返り部の「前月」はすべて「前期」に読み替える（例: 【前期の売上目標】【前期の行動目標（行動管理）】）。
- 計画部の「今月」はすべて「今期」に読み替える（例: 【今期の売上以外の成果目標】【今期の行動目標（行動管理・優先順位付き）】）。
- 【今期の行動目標（行動管理・優先順位付き）】の各項目末尾にも、月報・週報と同様に期日トークン（`M/D`／`YYYY-MM-DD`／`毎日`／`毎朝`／`毎週`／`今週`／`〜まで`）を必ず付ける。月単位の曖昧表現は具体日付を併記する。箇条書きは `・`/`- ` どちらでも可（Obsidian変換対応）。**各グループの中は上から順に実行できる並びにし、期日は後ろの項目から逆算して置く。全項目を期末に揃えない**（期末に置くのは期を通して回す項目だけ）。別の接点でしか成立しない段を同一期日にしない（診断と当日の提示のように同じ場で続けて行う段は同日でよい）。詳細は本ファイル「行動目標の並び順と期日の逆算」。
- 【今期の売上以外の成果目標】【前期の売上以外の成果目標】も月報と同じ記法（1項目=2行＋貢献額。式または括弧の根拠）で書く。計上期間の規則（C1e）は「今期の3ヶ月間に立つ分だけ」と読み替える。月額5万の顧問を期初に成約するなら、期内に実際に立つ3ヶ月分は `50000 × 3 = 150000` として計上してよい（`ヶ月` の単位語は式に書かない）。4ヶ月目以降は次期の成果目標へ回す。
- 【今期の行動目標（行動管理・優先順位付き）】も月報と同じく `### → {{成果目標名}}：{{要約}}（{{貢献額}}円）` のグループ見出しで並べ、見出しの金額を成果目標の貢献額と一致させる（C4/C4b）。
- 【確認された情報】の目標期間は「3ヶ月」とする。
- スナップショット項目（今期の累計売上実績・現在事業パートナー数・現在のグリッドパートナー数・前回/次回のアカデミーへの参加日・次回の壁打ち予定日・次回の壁打ち予定月までに目指している状態・次回の壁打ち予定日までに達成させること）は月報と同じ位置・名称で含める（期間語化しない）。
- **ヘッダーの【今期の売上目標】（月報の期アンカー項目）は期報では出力しない**（採用案A1）。期報では計画部の【今月の売上目標】→【今期の売上目標】がその役割を兼ねるため、ヘッダー側の【今期の売上目標】を重複出力しない。これで期報の見出し集合は【今期の売上目標】が一意になる。
- **【プロジェクト別タスク】は期報では出力しない**（プロジェクト別タスク方針: 月報＝必須／週報＝任意／期報＝禁止）。
- **【今月の日別タスク】（読み替えで【今期の日別タスク】に相当）は期報では出力しない**（日別タスクはプロジェクト別タスクの日付展開のため月報のみ。期報は【確定スケジュール】で代替する）。

#### 規則の優先順位と不変条件（厳守）

本規則（見出し集合・セクション順・A1・期報禁止セクション）は動的学習に優先する。旧期報に【今期の売上目標】重複や【プロジェクト別タスク】があっても、それらを再生産しない。

不変条件:
- 期報は【今期の売上目標】を1回のみ出力する（ヘッダー側を出さず、計画部の1個に統一する）。
- 期報は【プロジェクト別タスク】を出力しない。
- 期報は【今期の日別タスク】を出力しない（日別タスクは月報のみ）。

その上で、月報の確定セクション順の末尾（今期末の振り返りチェックリストの後）に、以下の期報固有セクションを加える:

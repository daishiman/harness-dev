## 共通部品（全層共通の正本）

ここに置く A〜G が、全層で共通に使う規則の本文の正本である。全層の目標は「共通部品G 原理原則の基準」を大前提とする。本ファイルの各テンプレートと他ファイルは本文を写さず、`output-formats.md` の「共通部品A 行動行」の形の1行で参照する。

### 共通部品A 行動行

行動目標1行の書式。1年・期報・月報・週報、管理用・提出用、今期の行動目標と前期間への転記で共通に使う。

- **管理用の書式**: `- [ ] 項目名：何をする（判定に必要な対象・数量だけ）　期日{期日トークン}`（例: `- [ ] 顧問提案：1件出す　期日6/12`）
- **提出用の書式（射影）**: 管理用の同じ行から、チェックボックス・グループ見出し（`### → `）・成果目標の2行目（`→ 売上貢献：…`）・本文中の個人名だけを外したもの。項目名・件数・単位・期日は管理用と同じ値を必ず書き、複数行を人数・件数へ合算しない（例: 管理用 `- 提案の受諾：Bさんの受諾1件　期日6/20` → 提出用 `- 提案の受諾：受諾1件　期日6/20`）
- **項目名に個人名を入れない**: 行動目標・成果目標・グループ見出しの項目名（「：」より前）は全層共通で人を含めず、対象の人は「：」の後の本文に書く（例: `- [ ] 提案書：Bさんへ提出する　期日6/20`、`### → 提案の受諾：Bさんの受諾（100000円）`）。提出用で個人名を外しても項目名が変わらず、照合の鍵が保たれる
  - 同じ文書で項目名が重なるときは、案件・内容の語で区別する。それでも同じなら、人名以外の区別語を括弧で足す（例: `顧問の受諾（物流）`、`顧問の受諾（製造）`）。1項目1成果（S2）に反するため、重なる行を1行へ合算しない
- **前期間への転記**: 今期の行動行からチェックボックスだけ外して転記する。項目名の「：」を保つ（前回との照合の鍵になる。「共通部品D 前回ブロック」）
- **合格基準**: 「何をする＋期日」がそろっていること。誰に・トリガー・数値・人名は必須にせず、判定に必要なときだけ残す。具体日は行末の期日欄だけに書き、「何をする」の本文に埋め込まない
- **期日トークン**: 今回の期間の行動目標の行（週報・月報の管理用と提出用・期報・1年、月報の【プロジェクト別タスク】）は、行末を `期日` ＋任意の空白＋トークン＋任意の `まで`／`までに` で終える。無ければ FAIL。前回ブロックの転記行・習慣目標・振り返りには掛けない（前回はそのまま転記するため）
  - トークン: `M/D`（後ろに `（曜）` 可）・`YYYY-MM-DD`・`{月火水木金土日}曜`（`曜日` 可）・`毎日`・`毎朝`・`毎週`（後ろに `{曜}曜` 可）・`今週`（週報だけ）。`validate-goal-output.py` の期日検査の正規表現と同じ集合
  - `毎月`・`今月中`・`8月中` などはトークンではない（FAIL）。月次で回す行動は `毎週`（週へ割る）か、期間末日の `M/D`／`YYYY-MM-DD` で書く
- **日付索引**: 週報の【今週の大きな到達ライン】と月報の【今月の日別タスク】は、行動目標を日付で引くための索引で、書式は `- {M/D（曜）}：{項目名}、{項目名}` の1日1行。チェックボックスは付けない（済／未済のチェックは行動目標の行だけに付ける）。その日のやらないことは同じ行の末尾に `｜やらない：{内容}` を付け、行動の無い日は `- {M/D（曜）}：なし｜やらない：{内容}` と書く（例: `- 6/29（月）：説明日程、個別メッセージ｜やらない：新規サービスの開発に手を出さない`）。索引に書く項目名は、週報は同じ文書の行動目標に、月報は【プロジェクト別タスク】か管理用の行動目標に実在すること
- **注記**: 【考え】【思い】や理由・背景の注記は、依頼されたときだけ書く。テンプレート・例には置かない。背景・理由は内部で検討する
- **精神論の NG 語**: 正本はプラグイン直下の `references/action-language-policy.json` の `goal_exact_phrases`。語の一覧を本文に写さない。NG 語を言い換えた形（「意識を持った」等）も書かず、基準値の数値で書く
- **優先順位**: 売上貢献額の大きい成果グループを上に置き、グループ内は依存の順（前の段が終わらないと成立しない段を後ろ）に並べる。「売上直結度×すぐできるか」の2軸では決めない。期日の置き方は本ファイル「行動目標の並び順と期日の逆算」
- 箇条書きの記号は `- ` / `- [ ]` を推奨する。`・`（Obsidian の自動変換）も検査は受理する

### 共通部品B 成果目標と売上貢献の根拠

成果目標は **1項目=2行** で書く。1行目に成果そのもの、2行目に売上への貢献額を**検算できる根拠つき**で書く。今期の成果目標も前期間の成果目標（転記）も同じ形で書き、1行形式へ潰さない。

```
- {項目名}：{先方判断・結果の状態}{件数}　期日{M/D}
  → 売上貢献：{単価} × {件数} = {貢献額}
```

1行目と2行目を分けるのは可読性のためである。対象・判断・期日・金額を1行に詰めると横に長くなり、読み手の目が滑って金額が視界に入らなくなる。

**貢献額には「式」か「括弧の根拠」のどちらかを必ず添える。裸の数字を置かない。**（検査ID: C1）`150000` とだけ書かれた数字は、それが正しいかを後から誰も検算できない。求めているのは式そのものではなく、**貢献額に検算できる根拠が付いていること**である。式はその十分条件の1つにすぎず、単価×件数に分解できない成果（値引き後の一括見積など）は括弧の根拠で満たしてよい。

| 書き方 | 例 | 判定 |
|---|---|---|
| 式（単価 × 件数 = 貢献額） | `→ 売上貢献：80000 × 3 = 240000`（単価8万の成約3件） | OK |
| 括弧の根拠 | `→ 売上貢献：150000（値引き後の一括見積）` | OK |
| 当期の直接成果を支える中間成果の貢献0 | `→ 売上貢献：0（導入支援の成約を支える）` | OK |
| 来期以降の直接成果を支える中間成果の貢献0 | `→ 売上貢献：0（8月の研修の受注を支える）` | OK |
| 翌期に計上する直接成果の貢献0 | `→ 売上貢献：0（8月計上・8月実施の研修で請求）` | OK |
| 裸の数字 | `→ 売上貢献：150000` | FAIL（C1） |

- 分解できるなら式が第一選択。`80000 × 3 = 240000`（単価8万の成約3件）と書けば単価と件数が別々に残り、単価が下がったとき・件数が変わったときに何が崩れるかがすぐ分かる。ただし件数は**その期間に立つ件数**であり、期間の長さではない（本ファイル「計上期間の規則」。C1e）
- 掛け算記号は `×` `x` `*` のいずれでもよい。`=` の**右辺がその成果の貢献額**であり、突合はこの右辺を足し合わせる
- 左辺の積と右辺は一致させる（`80000 × 3 = 200000` のような計算違いは FAIL。検査ID: C1c）
- **貢献0の括弧は次の3つの形だけ**を使う。これ以外の `0（…）` は FAIL
  1. 当期の直接成果を支える中間成果（面談・再面談・紹介・参加など）: `0（{同じ文書の直接成果の項目名}を支える）`。項目名は同じ文書の直接成果に実在すること（無ければ FAIL）
  2. 来期以降の直接成果を支える中間成果: `0（{M}月の{直接成果の項目名}を支える）`。支える直接成果は同じ文書に無くてよい
  3. 翌期に計上する直接成果: `0（{M}月計上・{根拠}）`。確認済みの計上時期と根拠を書く
  - 直接成果とは、貢献額が0より大きい成果目標と、形3の成果目標である。中間成果の売上は直接成果の側に計上し、二重計上しない。将来の金額は書かない（売上を捏造しない）
  - グループ見出しの0円は `（0円）` だけを書き、`（0円・8月の仕込み）` のような説明を足さない。理由は成果目標の2行目の括弧に書く
- `→ 売上貢献：` は全角コロン。数値は半角のみ（カンマ・「円」は付けてよい）

### 共通部品C 設計順序と4層

目標は必ず **売上目標 → 成果目標 → 行動目標** の順に、上から降ろして逆算する。行動を先に並べて成果・売上を後付けしない。例文も売上の側から書く。各層で何を売上・成果・行動に置くかの基準は「共通部品G 原理原則の基準」。

```
[売上目標] いくら稼ぐか（最上流・数値1つ）
    ↓ この売上を立てるには、誰の・どの判断が必要か？
[成果目標] 契約・受講等の直接成果と、それを支える面談・再面談・紹介等の中間成果
           直接成果へ当期売上を計上し、中間成果は0と支える先を示す（共通部品B）
    ↓ この判断を引き出すには、自分は何を・何件・いつまでにやるか？
[行動目標] 自分でコントロールできる行動（共通部品A の行動行）
           支える成果目標のグループ見出しの配下に置く
```

層は **1年 → 3ヶ月（期報） → 1ヶ月（月報） → 1週間（週報）** の4層で、この順に上から降ろす。各層は直属上位のどの成果・到達点を、その期間にどこまで進めるかを短く対応付け、層の中で売上→成果→行動を逆算する。下位の行動を足して上位の目的・目標を後付けしない。

```
1年目標 ← 対象の年報の期限までの到達点と成果
  ↓ 年間のどの成果を今期どこまで進めるか
期報（3ヶ月） ← 期の成果・売上目標と月別の配分
  ↓ 今期のどの成果を今月どこまで進めるか
月報（1ヶ月） ← 当月の成果と主要行動
  ↓ 今月のどの成果を今週どこまで進めるか
週報（1週間） ← 今週の成果と実行する行動
```

- 1年目標の到達点は挑戦宣言を参照する。上位が無い・対象期間や版が不明な場合は未確認と示し、仮の親目標を作らない
- 対応付けは、既存のサマリーか管理用の冒頭に上位の成果名・当期到達状態・期限を1行で示せばよく、別の詳細計画を増やさない
- 年末の最終到達値を月・週の実行値と同じ数字にせず、12ヶ月・3ヶ月・4週等で機械的に等分もしない（継承の2種類は本ファイル「四層（1年目標・期報・月報・週報）の連携」）
- **1年層の照合**: `--yearly`／`--no-yearly` の機械強制は `references/validation-gates.md` の「IN3 の1年層の引数」が正本。ここでは繰り返さない

### 共通部品D 前回ブロック

**「前回の目標 → 実績 → 差分 → 未達を挽回するための行動」が一目で分かること**が最優先。週報・月報・期報・1年の4層で共通に、前回正本 → 実績 → 差分 → 挽回 の順に並べ、そのあとで今回の売上→成果→行動（共通部品C）へつなぐ。売上・成果・行動のそれぞれでこの4つをそろえ、「売上は動いたか」「成果は出たか」「行動はやったか」を別々に差分できるようにする。見出しの置き場所は各層のテンプレートに従う（月報は公式21ブロックの順を優先するため、成果の差分と前月の行動ブロックを深掘りブロックに置く）。

- **前回正本**: ユーザー指定の前回ファイルを正本とし、パスを収集サマリーへ記録する。更新日時・別版・上位目標で差し替えず、今回の計画から過去目標を逆算しない。前回の目標はそのまま転記し、当時の項目・分類・数値・期日・検算根拠を保持する（新記法へそろえるために推測で増減しない）。反映するのは最新の明示訂正だけ。今後追わないと決めた指標も前回比較には残す
  - 成果目標は共通部品B の2行のまま、行動目標は前回の行動行からチェックボックスだけ外して転記する（共通部品A）
- **実績**: 前回の目標と同じ項目名・順序で1対1に書く。不明な実績は項目ごとに「確認中」と残し、0や達成済みで補わない。書き方は本ファイル「実績セクション（特に厳守）」
- **差分**: **項目ごとに必須**。前回の目標と同じ項目名・順序で1対1に、`+`/`-` 付きの数値だけを書く（本ファイル「差分セクション」）
- **挽回**: 未達の項目ごとに、次の対応行を1行書く（売上・成果・行動、4層で共通）。未達が無ければ見出しを残して `- なし`
  - 書式: `- {前回の項目名}：{起点}→{到達点}（今回の行動目標「{今回の項目名}」で実行）`（例: `- 顧問提案：提案2件→4件（今回の行動目標「顧問提案」で実行）`）
  - `{起点}→{到達点}` は行動の基準値。期日は今回の行動目標の行にだけ書き、対応行には書かない。`{今回の項目名}` は同じ文書の今回の行動目標に実在すること
  - 売上の挽回の `{前回の項目名}` は、未達の原因になった前回の成果目標の項目名を使う。売上と売上以外の挽回は、同じ接点・面談・提案の流れにそろえる
  - 対応行の下の要因分析（`###` 小見出し以下）は対応行の検査の対象外。骨格は本ファイル「要因分析セクション（重要・必須）」
- **初回**: 前回正本が無い初回は、前回ブロックの各欄に `- 初回（前回正本なし）` の1行だけを書く。検査はこのマーカーがあれば照合を飛ばして PASS と表示し、欄が空なら転記漏れとして FAIL にする。1年の初回で前年と比べた差は差分欄に置かず、Step 2 の root_cause の材料にする
- **旧形式**: 項目名の無い旧形式で項目の対応が取れなければ「未照合」と明示して確認し（検査は WARN）、意味が一致したと扱わない

各ブロックは1つの責務だけを持つ。

- **目標**：数値・期日のみ
- **実績**：数値・完了日のみ
- **差分**：差分数値のみ（+/-記号必須）
- **挽回**：対応行と、その下の要因分析。補足説明・経緯・理由・改善方針はすべて要因分析に集約する

実績に延期理由・代替手段・経緯を書くと、目標と実績の比較が読めなくなる。経緯・補足は必ず挽回のブロック（「未達を挽回するための行動」）の要因分析へ移す。

| テンプレート変数 | 生成元フィールド（`references/data-contract.md`） | 型と形 |
|---|---|---|
| `{{other_diff}}` | `prev_other_diff` | string[]。1項目1行（前回の成果目標と同じ順序・件数）。初回は null（出力は `- 初回（前回正本なし）`） |
| `{{action_diff}}` | `prev_action_diff` | string[]。1項目1行（前回の行動目標と同じ順序・件数）。初回は null（出力は `- 初回（前回正本なし）`） |

機械検査: `validate-goal-output.py --type <種別>` が、週報・月報・期報・1年の前回ブロックの項目名・順序の一致を検査する（月報は提出用・管理用の両方）。週報の前週ブロック12見出し（【前週の売上目標】〜【前週の行動に対して未達を挽回するための行動】）は必須見出しで、目標の欄に項目があるのに実績・差分の欄が無ければ FAIL。自然言語の対象や行動の妥当性はレビューで確認する。

### 共通部品E 軌道修正記録

- 月・週は、実行後に実績に基づいて軌道修正してよい。前回の目標→実績・差分→未達要因を基に、行動・数量・期限・配分を見直す
- 上位（1年・3ヶ月）の到達点は、月・週に合わせて自動で変えない。上位の変更が必要なら、その必要性を明示して合意した上で変える
- 前回の目標・実績・差分は遡って書き換えない
- 照合でズレが出たら、同値継承の誤記は正本に合わせる。正当な月・週の実行計画の変更は、上位を先に書き換えたり下位を元へ戻したりして消さず、記録と上位達成への影響を確認する
- 週の売上の単純な日割りは配分根拠の一例であり、実績を踏まえた配分見直しを妨げる固定値にしない

記録の書式は次の2種類で、どちらも末尾に「｜理由：…｜上位への影響：…」を持つ。見直した対象ごとに1行書く。

| 種類 | 書式 | 使う層と記録先 | 対象と検査 |
|---|---|---|---|
| 上位配分の見直し | `- 上位配分の見直し：{対象}｜上位計画：{値}｜実行目標：{値}｜理由：…｜上位への影響：…` | 月報の冒頭の【確認された情報】（提出用・管理用の両群の前に1回だけ置く共通ヘッダー。公式21ブロックの外） | 内訳継承の4項目（当月の売上目標／無料相談の延べ回数／1回目の実人数／月額継続コンサルの累積件数）だけ。`validate-cross-level.py` が数値の対応と記入を検査する（検査の詳細は `references/data-contract.md` §3.1.3） |
| 行動の見直し | `- 行動の見直し：{項目名}｜変更前：…｜変更後：…｜理由：…｜上位への影響：…` | 週報の【今週の見直し記録】、月報の冒頭の【確認された情報】 | その層の行動・数量・期日。`validate-goal-output.py` が、`- なし` か5欄すべて非空であること・項目名が今回の行動目標に実在すること・変更前と変更後が違うことを検査する。理由と影響の妥当性はレビューで確認する |

- 例: `- 上位配分の見直し：当月の売上目標｜上位計画：600000｜実行目標：650000｜理由：受注時期の変更｜上位への影響：翌月配分を見直す`

### 共通部品G 原理原則の基準

1年・期報・月報・週報のすべての目標は、北原さんの「成果を出す人の原理原則」を**大前提の基準**にして設計する。好き勝手に並べた行動ではなく、原理原則の動きに集中した挑戦として組む。北原さんの言い回しと出典は原則DB（プラグイン直下の `skills/run-ubm-knowledge-sync/assets/kitahara-principles-db.md`）の「成果を出す人の原理原則」節にあり、評価根拠に使うときは `knowledge_candidates` の `source_ref` で原文を確かめる。ここには目標の各層への写像だけを置く。

| 目標の要素 | 原理原則での意味 | 設計の問い |
|---|---|---|
| 売上目標 | 挑戦（商品）がお金や富を生み、経済を循環させた結果 | どの挑戦を誰に届けて、いくら循環させるか |
| 成果目標 | 挑戦への YES。同じ人と連続して取り、その人の周りへ広げる | 誰から、どの YES を取るか。前回 YES をくれた人と連続しているか |
| 行動目標 | 見せる／徳が積まれる挑戦を組む／本気で誘う／可愛がる（直下を導く）／可愛がられる | その行動は、原理原則のどの動きか |
| 1年・期報の到達点 | 個が集になり、川上・大義（ビジョン・ミッション・バリュー）へ向かう | 今期で、個から集へどこまで進めるか |

- 金額を追う。成果・行動はその手段: 根本で追うのは売上（金額）で、成果目標はその売上につながる YES を人数・件数で、行動目標はその成果につながる動きを回数・件数で置く（売上→成果→行動の逆算。共通部品C）。成果（YES）を引き出す行動は上の動きから選ぶ。北原さんの「売上目標は追わない」「売上ではなく人数で追う」（引用本文は原則DB のまま）は、売上（目的）に至る手段として人数・回数を日々管理する、と読む。引用の直後に添える発話は「この言葉は、売上（目的）に至る手段として、人との関係と人数・回数を日々管理する、という意味です」の1文にそろえる（R3 ターン3C-1・面接テンプレートの週報ターン3）。売上の数字を目標・最重要数字から外さない
- 同じ人と連続する: 前回 YES をくれた人・可愛がってくれた人との次の挑戦を、成果目標の候補として先に検討し（並び順は共通部品A）、新規の人だけを並べない
  - 前回 YES をくれた人は、前回正本の成果目標の本文にある相手と同じ項目の実績から読む。相手をまとめた項目は対話（R1 ターン1A の問2）で名前を確かめ、分からなければ確認中とする。名前は Step 3 の候補に使う対話の材料で、前回実績の欄（`references/data-contract.md` #9）には書かない（実績欄は `- 項目名：実績数値・完了日`）
  - 初回（前回正本が1つも無い）は、R3 ターン3C-2 で既存の取引先・紹介元・可愛がってくれている人を聞き、候補にする。いなければ連続の判定は対象外とする。1年だけが初回（前年の1年目標は無いが、期報・月報はある）のときは利用者の初回と分け、直近の期報・月報（期報の直近1件と月報の直近1件。期間の開始日で選び、`archive/` は見ない）の成果目標の本文（提出用と管理用の2つを持つ文書は、見出しに「（提出）」の付かない管理用の節。提出用は個人名を外している）にある相手から候補を読み、連続を判定する（R1 7.1 のその行・R3 ターン3C-2・goal-reviewer の項目6。材料は info-collector が past_summary の「1年層の現在地と成果の候補」に載せる）
  - 相手が確認中の項目（対話で名前を確かめられなかった項目）は連続の判定から外し、確認中と書く。「確認中と書く」は最終確認（R5）とレビュー（goal-reviewer）の判定の書き方で、目標ファイルの実績欄のことではない。文書だけを読むレビューは、前回の成果目標の本文に相手の名前が無い項目（人数でまとめた項目）を確認中として扱う
  - 連続の判定の結果は、次の文から当てはまるものを併記して告げる（R5 ターン5A・goal-reviewer の項目6）。連続あり＝「前回 YES をくれた方との次の一歩が入っています」。初回で候補との連続あり＝「前からお付き合いのある方との一歩が入っています」。候補のいない初回＝「今回が初めてで、前からお付き合いのある方もいないので、つながりの確認はしていません」。確認中（ほかの結果と併記する）＝「{項目名}は相手を確認中のため、つながりの確認から外しました」
- 行動行（共通部品A）に「見せる」などの分類ラベルを付けず、見出しも増やさない。基準を使う場面は、前回 YES をくれた人の確認（R1 ターン1A の問2。初回は R3 ターン3C-2）と Step 2 の R2 の差分、成果（R3 ターン3C-2）、行動（Step 4 の R4）、レビュー（goal-reviewer の項目6 関係構築軸）。行動の基準は `### → （土台）` グループの行には当てない（対象外）
- 精神論の NG 語（共通部品A）と両立させる。「本気で誘う」「可愛がる」は、誘う・導く行動の件数と期日で書く

## 簡潔な記述の共通原則

1年・期報・月報・週報で共通に、行動行は「共通部品A 行動行」、成果目標は「共通部品B 成果目標と売上貢献の根拠」、設計順序は「共通部品C 設計順序と4層」に従う。日別タスクを自動追加せず、目的は冒頭の1文か成果グループ見出しで示す。済／未済のチェックは行動目標の行だけに付け、日付で引く必要があるときは共通部品A の日付索引を使う。

数え方・金額・期限は既存の合意を引き継ぎ、不明な点だけ短く聞く。「依頼／実施」「申込／当日参加」「紹介者／被紹介者」「実人数／延べ回数」「再面談は初回の内数か別枠」「承認／契約／開始／当期計上」を区別する。例の人数・金額や個人の除外指標を、全利用者の固定ルールにしない。

## 月報の項目保持と同期

- 前月の引継ぎは「共通部品D 前回ブロック」に従う。
- 提出用は管理用の射影である（「共通部品A 行動行」の提出用の書式）。最新の明示修正を両側へ反映し、サマリー・未達挽回欄・振り返りの関連値も同期する。管理用は成果への所属と検算根拠だけ補い、説明量を増やさない。
- 簡潔版は、frontmatter に `monthly_action_style: concise` を明示したときだけ使う。無指定は旧詳細版で、【プロジェクト別タスク】が必須になる。この指定はプロジェクト別タスク必須を解除するだけで、設計順序やデータ整合検査の適用条件ではない。【今月の日別タスク】を作るかは「共通部品F 層別差分表」の日付索引の行に従う。

### 期報の期間の決め方

UBM の目標期間は**月の最終月曜日起点**。期報の期間は**対象3ヶ月分の月報期間の連結**とする。

- 終了日 = 3ヶ月目の月報の終了日

### 1年目標の期間の決め方

## 【重要】目標・実績・差分セクションの記述ルール（厳守）

前回の目標・実績・差分・挽回の並びと各ブロックの責務は「共通部品D 前回ブロック」。

### 目標設計の流れ（売上 → 成果 → 行動の逆算・厳守）

設計の順序と4層の降ろし方は「共通部品C 設計順序と4層」。以下はその中で成果と行動を分ける規則と表記である。

#### 中核原則：成果と自分が実行する行動を分ける

「勉強会を月4回開催する」のように自分の実行で数えられるものは行動目標、参加者数や面談できた実人数は成果目標に置く。開催の頻度と、相談・次の参加への案内は必要な主要行動として残せる。実行によって成果・売上が確定するとはみなさない。

- 行動そのもの（相談を取りに行く・アカデミーへ通う頻度を上げる等）は**当たり前の土台**として扱い、成果目標には置かない
- 行動目標には書いてよいが、その場合も必ず成果に接続する。接続の正規の形は `### → {成果目標名}：{要約}（{金額}円）` のグループ見出しであり（検査ID: C4）、行内注記 `  → 支える成果目標：XXX` は見出しが無い場合のフォールバックにすぎない

#### 表記仕様

成果目標の2行記法・売上貢献の式と括弧の根拠・貢献0の括弧（検査ID: C1/C1c）は「共通部品B 成果目標と売上貢献の根拠」。ここには計上期間・突合・推奨と、行動目標のグループ化だけを置く。

##### 計上期間の規則（機械検査対象）

**貢献額は、その期間に実際に売上として立つ分だけを計上する。式の件数に期間単位（`ヶ月`/`ヵ月`/`か月`/`年`）を掛けてはいけない。**（検査ID: C1e）

月額5万円の顧問契約を今週成約するなら、今週の売上に立つのは初月の `50000 × 1 = 50000` であって、3ヶ月分の `50000 × 3ヶ月 = 150000` ではない。契約の総額を今期間へ前倒しで積むと、売上目標が満たされたように見えて実際の入金は来ない。**「売上に直結する成果目標」とは、この期間の入金に直結するという意味である。**

- ✗ FAIL: `→ 売上貢献：50000 × 3ヶ月 = 150000`（期間単位を件数に掛けている）
- ✓ OK: `→ 売上貢献：50000 × 1 = 50000`（今期間に立つ初月分）
- ✓ OK: `→ 売上貢献：150000 × 2 = 300000`（同一期間内の成約2件。`件` は期間単位ではない）
- 期間をまたぐ分は、**次の期間の成果目標として立て直す**か、翌期に計上する直接成果として `→ 売上貢献：0（8月計上・月額顧問の2ヶ月目）` の形で書く（共通部品B）
- 機械検査 C1e が捕まえるのは**式に期間単位が書かれた形**だけである。単位語を省いて `50000 × 3` と書けば検査は通るが、それが週報なら規則違反であることは変わらない。件数が「期間の長さ」になっていないかは自分で確かめる
- 件数に付けられる単位語は `件`／`名`／`回`／`本` の4つ（その期間に確定する数え方）。FAIL になるのは `月`／`ヶ月`／`ヵ月`／`カ月`／`か月`／`年`。**`× 12ヶ月` は不可で、`× 12` と書く**（単位を省けば検査は通るが、その12が期間の長さなら規則違反であることは上記のとおり変わらない）

##### 売上目標との突合（機械検査対象）

- **売上貢献額（式なら右辺、括弧の根拠ならその数字）の合計が売上目標に届いているか**を必ず自分で突き合わせる。届かないなら成果目標が足りていない
- 突合は**完全一致を求めない**。合計が目標以上なら OK。不足が売上目標の **5% 以内**なら端数程度のズレとして WARN（保存は通る）、**5% を超える不足は FAIL**（成果目標の抜けとして扱う）。判定の実体は `scripts/validate-goal-output.py` の `judge_sales_coverage()`、仕様の正本は `references/data-contract.md` §4.4 の検査 C3（検査ID: C3）
- 貢献0の項目が成果目標の**過半を占めたら WARN**。この期間の売上に何も乗らない項目ばかりが並ぶと、成果目標セクションが売上と切れた「やることリスト」に戻る（検査ID: C1d）

##### 読み手向けの推奨（機械検査しない）

以下は守るべき書き方だが、**機械検査は行わない**。実装し忘れではなく、あえて検査していない。

| 推奨 | あえて検査しない理由 |
|---|---|
| 成果目標は1項目=2行で書く（1行目=成果／2行目=貢献額） | 貢献額の実在は C1 が押さえており、改行位置まで縛ると引用・折り返しの揺れで誤検出が出る |
| 成果目標を貢献額の降順に並べる | 同額のときに順序が決まらず、機械判定が硬直する。優先順位の表現は人間の判断に委ねる |
| 行動目標のグループも貢献額の大きい順に並べる | 上と同じ理由 |
| 項目間を1行空ける | 可読性の話であり、意味を壊さない |

**行動目標セクション**は、**支える成果目標ごとにグループ化**して並べる。

```
### → {成果目標セクションに実在する項目名}：{成果の要約}（{貢献額}円）
- [ ] {項目名}：{何をする}　期日{期日トークン}
- [ ] {項目名}：{何をする}　期日{期日トークン}
```

- 各行の書式は「共通部品A 行動行」
- 行動目標は必ず `### → ` グループ見出しの配下に置く（検査ID: C4）。見出しが無い場合のみ、旧記法の行内注記 `  → 支える成果目標：XXX` へフォールバックする
- **見出し名の `：` より前が、成果目標セクションに実在する項目を指すこと**（存在しない名前を書くのは禁止。検査ID: C5）
- **見出し末尾の `（{金額}円）` は、その成果目標の貢献額と一致させる**（検査ID: C4b）。ここがズレると、行動グループの重みが売上の実態と食い違い、優先順位の判断を誤らせる
- どの行動目標からも参照されていない成果目標（孤立）を残さない（検査ID: C6）
- 行動を成果ごとにまとめるのは、売上→成果→行動の一直線をそのまま目次にするためである。行動を優先度で束ねると、その行動がどの売上につながるのかが読み手の頭の中にしか残らない
- 優先度A/B/C の見出しは使わない（廃止）。優先順位は「共通部品A 行動行」の優先順位で表現する（並び順は推奨。上表の理由により機械検査しない）
- 習慣・土台など特定の成果に紐づかない行動は、最後に `### → （土台）` `### → （関係維持）` のグループを置いてそこへ入れる（C5 の例外として許容される名前）。許容される括弧名はこの2つだけで、`validate-goal-linkage.py` はそれ以外の括弧名を rc=1 にする。相手が登場し、相手の側に起きた事実を数で取れる行動をここへ逃がさない（本ファイル「成果が測りにくい行動の置き場」）

#### シンプルさの上限（機械検査対象・厳守）

目標が複雑になると、自分で自分の目標を読み解けなくなり、実行されない。**1項目=1つのこと**を守り、文字数の上限を守り、件数の扱いは期間別に分ける。必要な独立項目を件数だけのために合算・削除しない。

| 対象 | 上限 | 検査 | 検査ID |
|---|---|---|---|
| 成果目標の件数 | 5件 | 層で違う（共通部品F） | S1 |
| 成果目標1項目の長さ（`→ 売上貢献` の前まで） | 50字 | FAIL | S1 |
| 1項目1成果 | 独立成果を合算しない | 層で違う（共通部品F） | S2 |
| 行動目標の件数 | 8件 | 層で違う（共通部品F） | S3 |
| 行動目標1項目の長さ（1行目・期日込み） | 60字 | FAIL | S3 |

- 長い説明と重複を削り、判定が独立する成果・行動だけを分ける。同じ接触で続けて行う聞き取りと情報提供などを、機械的に細分化しない
- 実際の手本の長さは `assets/golden-sample-weekly.md` を見る。上限は逸脱の検出線であり、狙う長さではない

#### 設計手順（必ずこの順番で対話・記述する）

1. **Step A: 売上目標を1つの数値で確定する**
   - 内訳（誰から・いくら）は対話で確認するが、ファイルには数値1つだけ書く

2. **Step B: 売上目標を成果目標へ割り付ける**
   - 「この売上が立つには、誰の・どの判断・合意・受諾・継続が必要か？」を問う
   - 各成果に売上貢献額を割り当て、**合計が売上目標に届くまで**成果を出し切る
   - 届かない場合は成果目標の抜けを疑う（行動を追加してごまかさない）

3. **Step C: 各成果目標から行動目標を逆算する**
   - 「その判断を引き出すために、自分は何を・何件・いつまでにやるか？」を問う
   - その成果に必要な主要行動を選ぶ。打診・聞き取り・提示・実施後の意向確認等は不足の点検観点であり、全段や固定件数の出力を強制しない。資料作成など一人で完結する作業は段として立てない
   - 並び順と期日は本ファイル「行動目標の並び順と期日の逆算」

4. **Step D: 自作成物（成果物完成目標）を整理する**
   - 行動の前提となる資料等を自動で別タスク化しない。必要なら提示・共有の行動に含め、詳細の棚卸しは依頼された場合だけ行う

5. **Step E: 検査を回し、rc の値をそのまま記録する**
   - `validate-goal-output.py`（見出し集合・形式・C1〜C6・S1〜S3）→ `validate-goal-linkage.py`（成果目標と行動目標グループの両方向照合。分母を印字する）の順
   - 期報と月報が揃っている場合は続けて `validate-cross-level.py`（層をまたぐ値の照合。週報があれば `--weekly` も渡す。1年層の引数は `references/validation-gates.md` の「IN3 の1年層の引数」）
   - 各 rc を**値そのまま**記録する（「PASS」と書かない）。引数と測定時刻も一緒に書く
   - 月報は**管理用セクションだけを照合する**（提出用セクションの行動目標はグループ見出しを持たない1行1行動の箇条書きなので、所属の照合の対象外）

#### 設計時の問い（対話で必ず使う）

- 売上→成果：「この売上を立てるには、誰の・どの判断が必要か？」
- 成果→売上：「この成果は当期売上を決める直接成果ですか、それを支える中間成果ですか？」。直接成果は金額と計上条件、中間成果は支える直接成果を確かめる
- 成果→行動：「この判断を引き出すには、自分は何を・何件・いつまでにやるか？」
- 行動→成果：「この行動を全部やったら、本当にこの成果に届くか？足りているか？」

#### 成果目標と行動目標の区別

**成果目標** = 相手の応答が入って決まる結果（契約・受講等の直接成果、面談できた実人数・再面談者・紹介者等の中間成果）。金額そのものは売上目標に置く
**行動目標** = 自分でコントロールできる行為（実施・送付・参加・作成・告知・打診）

ただし行動目標の欄に載せるのは、成果から逆算した主要な働きかけ・開催・支援である。相手の応答や参加人数は行動の完了条件に混ぜない。1項目ずつの判定手順は本ファイル「売上目標・成果目標・行動目標の三層分離」、採否は「行動目標に何を載せるかの採否基準」。

**実行完了型NG動詞リスト（この10語が正本。他ファイルはここを参照し、リストを複写しない）**

```
実施する / 開催する / 参加する / 送付する / 作成する
提出する / 共有する / 告知する / 打診する / 連絡する
```

成果目標セクションに、この10語のいずれかで終わる項目を書いてはならない。それらは行動目標側に置く。この10語は `scripts/validate-goal-output.py` の `Validator.OUTCOME_NG_VERBS` と同一集合であり、片方だけを増減させない（検査ID: C2）。

##### なぜ分けるか（差分を別々に取るため）

成果は行動の結果であり、行動と1対1では対応しない。行動したのに成果が出ないことも、意図せず良い成果が出ることもある。別セクションに分けておくことで、振り返りのときに「行動はできたのに成果が出なかった／行動は少なかったが成果は出た」という学習ができる。混ぜると原因が読めなくなる。

##### 成果目標としてOKな例
- 研修の継続合意：Dさんの継続合意1件　期日4/15
  → 売上貢献：75000 × 1 = 75000
- 業務委託の開始：Eさんの開始1件　期日4/2
  → 売上貢献：200000 × 1 = 200000
- Claude Code提案の受諾：Fさんの受諾1件　期日4/10
  → 売上貢献：150000 × 1 = 150000
- AI質問会勉強会：参加者5名以上　期日4/18
  → 売上貢献：0（5月の提案の受諾を支える）

##### 成果目標に書いてはいけない例（すべて行動目標側へ）
- ✗ 「勉強会を月4回開催する」→ 開催した時点で達成。行動目標へ
- ✗ 「研修実施1回」「MTG実施1回」「提案実施」→ 実施は行動
- ✗ 「アカデミー参加」「アカデミーへの実績報告」→ 参加・報告は自分の手の動き。当たり前の土台として扱う
- ✗ 「体験診断セッションを3件実施する」→ 実施は行動。成果は「体験診断からの受諾N件」

##### よくある混在の修正例
- ✗ NG（成果目標）：「AI質問会勉強会：自主開催1回」
- ✓ OK（成果目標）：「AI質問会勉強会：参加者5名以上　期日4/18 ／ 次行 → 売上貢献：0（5月の提案の受諾を支える）」
- ✓ OK（行動目標）：`### → AI質問会勉強会：参加者5名以上（0円）` の配下に `- [ ] 勉強会：自主開催する　期日4/18`

#### 一貫した例（売上→成果→行動が最後まで降りている）

一貫した例の正本は `assets/golden-sample-weekly.md` の【今週の売上目標】から【今週の行動目標（行動管理・優先順位付き）】までで、ここには写さない。読むときの要点は次の4つ。

- 売上 150000 を、提案の受諾（100000）と月額顧問の成約（50000）の2つの直接成果に割り付け、合計行 `合計 150000 ＝ 今週の売上目標 150000` で突き合わせる
- Aさんの月額顧問（月5万）は、今週の売上に立つのは初月の 50000 だけである。2ヶ月目以降の 100000 を今週へ積むと、目標が満たされたように見えて入金は来ない（C1e）。翌月・翌々月分は、その期間の月報で改めて成果目標に立てる
- 中間成果の貢献0は「共通部品B 成果目標と売上貢献の根拠」の形1・形2で書き（同じ文書の直接成果を支える形と、来期以降の直接成果を支える形）、グループ見出しの0円は `（0円）` だけにする
- 行動行の項目名に個人名を入れず（Bさん・Aさんは本文に書く）、グループ内は依存の順に並べる。提案書の作成のように一人で完結する作業は段として立てず、提出の行動に含める

この形にすると、上から下へ読むだけで「150000 を立てるには B さんの受諾が要る → その受諾には体験診断が要る」という一直線が追える。金額の大きいグループが上に来るので、優先順位も並び順がそのまま示す。

振り返り（前週／前月／前期／前年）の並べ方と転記は「共通部品D 前回ブロック」（手本: `assets/golden-sample-weekly.md` の【前週の売上以外の成果目標】）。

成果目標セクションの冒頭には次の注釈を入れる：
> 成果目標は「自分では確定できない結果（先方判断・受諾・参加人数等）」を記述し、各項目に売上貢献額を明示する。実施行為は行動目標側に置く。

### 売上目標・成果目標・行動目標の三層分離（厳守・この順で判定する）

定義の大枠と、成果目標に置いてはいけない10語は上の「成果目標と行動目標の区別」が正本。ここでは1項目ずつ層を判定する手順と、行動目標の欄に何をどう載せるかを定める。ここを履き違えると、行動目標の欄に成果が並び、「行動したのに成果が出ない」の学習ができなくなる。

| 層 | 定義 | 数の単位 | 誰が決めるか |
|---|---|---|---|
| 売上目標 | 金額 | 円 | 成果が積み上がった結果 |
| 成果目標 | **相手の側に起きた事実**の数 | 件・人・回 | 相手の応答が入る。自分の意志だけでは決まらない |
| 行動目標 | **自分が手を動かした回数** | 件・回 | 自分だけで決まる。相手が応じなくても達成を数えられる |

因果の向き:

- **行動 → 成果 は確率**。行動しても成果にならないことがある
- **直接成果 → 当期売上**は合意した単価・件数・計上条件で結ぶ。中間成果は直接成果を支える先行指標であり、達成しても売上は確定しない。売上貢献は0と支える先を示し、直接成果との二重計上を防ぐ
- だから上げるのは**行動の基準値**。ただし「行動しまくる」ではなく、**その成果につながる行動に限る**

#### 1項目ごとの判定手順（この順で当てる）

1. 金額が書いてあるか → **売上目標**
2. 自分が手を動かし終えた時点で達成が決まるか（相手の返事を待たずに数えられるか） → **行動目標**
3. 相手の応答・承諾・来場・成約が入って初めて数が決まるか → **成果目標**

#### 行動目標の動詞（この語で書く／この語で書かない）

- 使う動詞（自分の手の動き・相手が登場する）: 出す / 打診する / 読み上げる / 連絡する / 提示する / 開催する / 議題に入れる / 臨席する / 聞く / 設定する（相手との日程・場を設定する意味に限る）
- 書かない語（相手側の結果＝成果目標へ移す）: 決まる / 確定する / 確定させる / 成約する / 取る / 満席にする / 参加する（相手が）/ 実施人数が集まる / 合意してもらう / 受諾される
- 資料等の作成を主要行動から独立した細かなタスクへ自動展開しない。必要な準備は「資料を相手へ提示する」などの働きかけに含める
- 上の実行完了型NG動詞リスト（10語）とは向きが逆の規則である。あちらは「成果目標の欄に行動を書かない」、こちらは「行動目標の欄に相手側の結果を書かない」
- **成果目標1件につき、そのグループ（`### → 成果目標名：…`）に行動目標を1件以上置く。** 複数の成果をまとめて1行の行動にしない

#### 混同していた項目の直し方（書き方 → 本当の層 → 行動目標としての書き直し）

| 行動目標の欄に置かれていた書き方 | 本当はどの層か | 行動目標として書き直す形 |
|---|---|---|
| 無料相談の日程だけをその場で30件決める | 成果（相手が決める） | 接触の締めで無料相談の案内を読み上げ、日程を打診する（30件） |
| 無料相談を延べ30回実施する | 成果（相手が応じた回数） | 打診済みの相手へ日程の再確認の連絡を出す（30件） |
| 1回目の無料相談を実施する実人数を20名作る | 成果 | 1回目をまだ実施していない相手へ打診の連絡を出す（20件） |
| 月額継続コンサルの条件を提示し3件取る | 成果（取るのは相手の決定） | 4回目の場で月額継続コンサルの条件を1件ずつ提示する（件数） |
| AI勉強会を開催し当日参加15名にする | 開催＝行動 / 15名＝成果 | 行動は「開催する（回数）」「個別連絡を出す（12件）」「紹介依頼を出す（8件）」に分け、15名は成果目標に置く |
| 5名の方と3回ずつ（計15回）の無料相談を実施する | 成果 | 2回目まで進んだ相手へ3回目の日程を打診する（件数） |
| 研修1件を実施し金額と時間数を確定させる | 確定＝相手との合意（成果） | 研修の金額と時間数を提示して先方へ確認の連絡を出す（1件） |

#### 既に行動として書けているもの（直さない）

- 無料・オフラインの作業会を20:00-22:00に13回開催する（自分が開ければ成立）
- 継続契約2社の定例を月8回設定して臨席する
- 既に定例でお話ししている事業者様7名の定例の議題に、紹介依頼を1件ずつ入れる
- AI勉強会の集客で、過去の参加者へ個別連絡を12件出す
- 声をかける相手を1名決めて連絡する

#### 分離の実装ルール（厳守）

- 行動目標は、支える成果目標ごとの `### → {成果目標名}：{要約}（{金額}円）` 見出しの配下に置く（記法の正本は本ファイル「表記仕様」。検査ID: C4/C4b/C5）。**これは管理用の規則。** 月報の提出用セクションの行動目標はグループ見出しを置かない1行1行動の箇条書きにする
- 見出しの `：` より前は、成果目標セクションの項目名（`：` より前）と**同じ文字列**にする。1文字違いも不可（照合は空白を落とした完全一致）
- 見出しの無い旧ファイルの行内注記 `→ 支える成果目標：XXX` は、読み取りのフォールバックとしてだけ受理する。ローカル版 0.4.0〜0.5.0 で使っていたカギ括弧の行内注記 `→ 支える成果目標「XXX」` は受理しない（`validate-goal-linkage.py` は FAIL にし、グループ見出しへの書き換えを案内する。検査スクリプトも所属不明として C4 で FAIL にする）
- 「面談する／日程を打診する／打診する／提示する」等の**自分の手が動き、かつ相手が登場する**動作は行動目標に置き、成果目標には置かない
- 「合意される／継続される／受注する／N名参加する／紹介が出る」等の先方・市場の結果は成果目標に置き、行動目標には置かない
- 準備資料の完成を細かな独立タスクとして自動追加せず、提示・案内等の主要行動へ含める。先方判断・参加人数は成果目標側に置く
- 関係維持・習慣・記録など成果が測りにくい行動は、行動目標セクション末尾の `### → （土台）`／`### → （関係維持）` グループへ置く（本ファイル「成果が測りにくい行動の置き場」）。**許容される括弧名はこの2つだけ。** ほかの括弧名（`### → （準備）` など）で逃がさない
- **成果目標1件につき、それを支える行動目標を最低1つ置く。** `validate-goal-output.py` の C6 は WARN 止まりだが、`validate-goal-linkage.py` は未解決（rc=1）として数える
- 成果目標のどの項目も、売上目標のどの金額につながるかを `→ 売上貢献：` で示す（C1/C3）。つながらない成果目標は削る

一本筋は `売上目標 → 成果目標 → 行動目標` の3段。宙に浮いた項目（売上につながらない成果・成果を指さない行動・行動に支えられていない成果）を置かない。

#### 行動目標に何を載せるかの採否基準（1行ずつ判定する）

**残す**: 確定した成果から逆算した、個別連絡・打診・依頼・提示・聞き取り・開催・支援等の主要行動。自分が実行すれば完了を数えられる形にする。例：`作業会：週1回開催する　期日6/30`。参加人数や次回申込は別の成果で数える。

**自動追加しない**: 資料・名簿等の作成手順、日々の自己管理、成果との対応を説明できない活動。必要な準備は提示・案内の行動へ含め、日々の自己管理は習慣目標へ分ける。

告知・SNS投稿も相手の反応を完了条件にはしない。採用する場合は支える成果と対象・経路・頻度を定める。ユーザーが追わないと決めた指標は復活させず、投稿数と問い合わせ・参加等の成果を混ぜない。

**同じ採否・数え方を行動目標・実績・差分に適用する。** 支える行動が無い成果は必要な主要行動を設計し直す。土台グループへの移動で対応不明を隠さない。

#### 成果が測りにくい行動の置き場（`### → （土台）`／`### → （関係維持）`）

関係維持・習慣・記録のように、やること自体は決まっているが**相手の側に起きる事実を数で取れない**行動がある。これを成果目標のグループに入れると、架空の成果を作ることになる。行動目標セクションの**末尾**に `### → （土台）` または `### → （関係維持）` のグループを置き、そこへ入れる。

```markdown
### → （土台）
- [ ] 習慣チェック：習慣目標の各カテゴリをチェックする　期日 毎日

### → （関係維持）
- [ ] 近況連絡：北原さんへ近況を連絡する　期日 毎週月曜
```

- 括弧名は `（土台）` と `（関係維持）` の2つだけ。見出しに金額は書かない（C4b の対象外）
- **相手が登場し、相手の側に起きた事実を数で取れる行動をここへ逃がさない。** それは成果目標を立て、そのグループに置く
- 日々の自己管理そのもの（起床・振り返り・チェックシート）は `【習慣目標】` が担う。`（土台）` に置くのは「習慣を回し続けること」、`（関係維持）` に置くのは売上の筋に乗らない関係維持だけ
- ローカル版 0.4.0〜0.5.0 で使っていた独立見出し `【今◯の習慣・土台（売上の筋に乗せないもの）】` は廃止した。既存ファイルにあれば、中身をこの2グループへ移す

#### 成果→行動の完全な落とし込み（標準粒度・厳守）

本ファイル「行動目標に何を載せるかの採否基準」に反する粒度は置かない。段を細かくする目的で、一人で完結する作業（資料作成・名簿作成・フォーム作成・告知）を段として立ててはいけない。

各成果目標に、それを支える主要行動を最低1件置く。接点の段は不足の点検に使い、全段・固定件数を出力しない。件数・文字数と記述量は本書「シンプルさの上限」「簡潔な記述の共通原則」に従う。

```markdown
### → 研修の継続合意：日工さんの継続合意（75000円）
- [ ] 研修日程：日工さんへ打診する　期日4/3
- [ ] 研修資料：作成して日工さんへ提示する　期日4/8
- [ ] 研修：実施する　期日4/15
- [ ] 継続意向：研修後に継続/次回の意向を日工さんへ聞く　期日4/17
```

- 例（成果「勉強会：参加申込5名以上」）→ `### → 勉強会：参加申込5名以上（0円）` の配下に「会場へ利用の打診をする」「過去の参加者へ個別連絡を12件出す」「定例の議題に紹介依頼を1件ずつ入れる」「勉強会を開催する」
- 4層とも行動目標には主要行動だけを短く書く（週報で日付から引くときは【今週の大きな到達ライン】の日付索引を使い、索引に別のタスクを足さない）。打診・提示・フォローが必要かは成果から判断し、詳細は依頼時だけ補う
- 資料・名簿・フォームの作成が成果の前提になっている場合は、作成の行を立てずに**提示・案内の行の中に含める**（「研修資料：作成して先方へ提示する」）。作成が抜け落ちることを心配して行を立てると、採否基準に反する

#### 行動目標の並び順と期日の逆算

行動目標は**各グループの中で上から順に実行できる並び**にする。並べ終わってから期日を入れるのではなく、**並び順と期日を同時に決める**。

**1. 並び順は依存関係の前から後ろへ。** 前の段が終わっていないと次の段が成立しない項目（1回目に打診する → 2回目に相手の状況を聞く → 3回目に課題を出す → 4回目に条件を提示する のような段階）は、**並び順も期日も前から順にする**。後段を先に書いて前段を後に書くと、読んだ順に実行できない。

**2. 期日は後ろの項目から逆算して置く。** 最終段の期日を先に決め、そこから各段に必要な日数（相手の検討時間・自分の準備時間・次の接点までの間隔）を引いて前の段の期日を決める。先頭から「とりあえず早め」で埋めない。

**3. 全項目を期間の最終日に揃えてはいけない。** 期間の最終日に残してよいのは、**月（期間）を通して回す項目＝特定の日に完了しない項目**だけ（例: 無料相談を30回行う、毎週の定例連絡）。段階のある項目を全部最終日に置くと、どの段がいつ終わっていないと間に合わないのかが読めず、最終週に全部残る。

- ✗ NG: 行動目標の全項目が `期日 {{end_date}}` になっている
- ✗ NG: 「2回目で状況を聞く」と「4回目で条件を提示する」が同一期日になっている（段が同じ日に成立しない。診断と当日の提示のように同じ場で続けて行う段は同日でよい）
- ✓ OK: 1回目 10/8 → 2回目 10/15 → 3回目 10/22 → 4回目 10/29、期間を通して回す「無料相談30回」だけが `期日 {{end_date}}`

**4. 提出用セクションと管理用セクションで同じ行動の期日を食い違わせない。** 提出用は管理用の射影なので（「共通部品A 行動行」の提出用の書式）、管理用で逆算した期日を同じ行にそのまま持たせる。期間を通して回す項目だけが期間末日になる。

**5. セクション全体が期日順でないときは注記を置く。** グループは貢献額の大きい順に並ぶため、グループをまたいだセクション全体は期日順にならないことがある。その場合は節の先頭に次の1行を置く（日付から引く索引は、週報の【今週の大きな到達ライン】と月報の【今月の日別タスク】。「共通部品A 行動行」の日付索引）。

```markdown
（※ 実行する順番は期日の早い順に読む）
```

#### 一本筋の照合は validate-goal-output.py と validate-goal-linkage.py で分担する

`validate-goal-output.py` は C4（所属不明）と C5（参照先の実在）を FAIL、C6（支える行動の無い成果目標）を WARN で検査する。`validate-goal-linkage.py` は**同じ照合規則**（成果目標の項目名の切り出し・空白を落とした完全一致・グループ見出しの解釈・行内注記へのフォールバック）を検査スクリプトから読み込んで使い、規則を二重に実装しない。上乗せするのは次の5点だけである。

- 1つの行動が複数の成果目標を指す `・` 区切りを FAIL にする（C5 は各参照の実在だけを見る）
- 支える行動の無い成果目標を**未解決（rc=1）**として数える（C6 は WARN）
- 括弧名の免除を `（土台）`／`（関係維持）` の2つに限る（C5 は括弧で始まる名前をすべて免除する）
- 月報の `# 北原さん提出用…` グループを照合対象から外し、`# 管理用…` グループだけを照合する。グループ見出しのラベルずれも FAIL にする
- 両方向の分母を印字し、分母0を rc=3 として PASS と区別する。末尾に測定時刻と引数を残す

```bash
python3 "$PLUGIN_ROOT/skills/run-ubm-goal-setting/scripts/validate-goal-linkage.py" --file "<目標ファイルの絶対パス>"
```

rc=0 未解決0件（分母も1件以上） / rc=1 未解決あり / rc=2 引数・ファイルの誤り / rc=3 **分母0（照合対象が1件も無い。数えていない）**。rc=3 を PASS として扱わない。rc は Bash ツールが返す終了コードをそのまま取り、出力末尾の `ARGS:` と `MEASURED_AT:` の行と一緒に記録する（取り方の正本は `validation-gates.md` の「決定論ゲート」）。月報は**管理用セクションだけ**を照合する（提出用セクションの行動目標はグループ見出しを持たない規定なので、`# 北原さん提出用` グループは `SKIP` で対象外になる。一本筋の担保は管理用セクション側）。

#### 層をまたぐ値のズレも、単一ファイルの検査では検出されない

`validate-goal-output.py` も `validate-goal-linkage.py` も、基本は **1本のファイルしか見ない**（`validate-goal-output.py --peer` は期アンカー2値（今期の売上目標・累計売上実績）を WARN で並べるだけで、rc は変わらない）。
期報の数字を直して月報・週報へ追随させ忘れても、**どちらも rc=0 で通る**。
層をまたぐ値を突き合わせる口が存在しない（分母が0件）ので、「検査して一致していた」ではなく
「当てる対象が1件も無かった」の形になる。期報と月報が揃っている場合は四層横断照合を回す（週報があれば `--weekly` も渡す。1年層の引数は `references/validation-gates.md` の「IN3 の1年層の引数」）。

```bash
python3 "$PLUGIN_ROOT/skills/run-ubm-goal-setting/scripts/validate-cross-level.py" \
  --yearly "<1年目標の絶対パス>" --quarterly "<期報の絶対パス>" \
  --monthly "<月報の絶対パス>" --weekly "<週報の絶対パス>"
```

rc=0 全一致または記録を確認した内訳調整あり / rc=1 未解決の不一致または抽出不可あり / rc=2 引数・入力不正 / rc=3 **抽出0件（何も判定していない）**。
rc=3 を PASS として扱わない。`--quarterly` と `--monthly` は必須、`--weekly` は任意（週報がまだ無ければ省略する）。1年層の `--yearly`／`--no-yearly` と `--no-yearly` のときの `[未照合]` の出力は `references/validation-gates.md` の「IN3 の1年層の引数」。
アンカーの一覧と抽出元は `references/data-contract.md` §3.1.3 を正本とする。

### 四層（1年目標・期報・月報・週報）の連携

4層の設計順と対応付けは「共通部品C 設計順序と4層」。ここには層をまたぐ継承の種類と、値を直したときの追随だけを置く。

継承は次の2種類を分ける。アンカーの一覧・抽出元は `references/data-contract.md` §3.1.3 が正本。

- **同値継承**: 参照文脈として同じ値を写す。年の最終到達点2件や今期の売上目標等が対象であり、当月・当週の達成値ではない。
- **内訳継承**: 上位で決めた月別・週別の配分を実行計画の基準とする。期合計と月の数字が異なるのは正常。上位の内訳と下位の最新計画を照合し、差があれば誤記か軌道修正かを区別する。

月・週の軌道修正と、照合でズレが出たときの扱い・記録書式・記録先は「共通部品E 軌道修正記録」。検証は `validation-gates.md` に従う。

#### 【この期報の値を直したときに追随させる箇所】は期報の標準装備

期報には、値を直したときに下位層のどこを直すかを書いた節を必ず置く。
期報だけ直して月報・週報が古いまま残るのを防ぐための節で、人が目で追うための地図。

```markdown
## 【この期報の値を直したときに追随させる箇所】
期アンカー（今期の売上目標／月別の売上目標／無料相談の延べ回数）は、
この期報を参照して月報・週報が計画する。同値文脈の訂正と実績による配分変更を区別する。

### 変わる可能性のある元の数字
- （数字と、それが動く条件）

### 期報側（このファイル）の正本行
- （節名と、その節のどの行が正本か）

### 月報側（<月報の期間> の月報）で追随させる箇所
- （節名と行）

### 週報側（<週報の期間> の週報）で追随させる箇所
- （節名と行）
```

#### 期間の区切りが層で違う（既知の衝突）

月報・週報は**最終月曜起点**、期報は**暦月**、1年目標は**暦の1年**。これらは一致しない。
そのため「当月」は月報の**期間終了日の月**で決める（2026-09-28〜2026-10-25 の当月は10月）。
四層横断照合も同じ決め方をしている。期報側の月別内訳は暦月で書く。
1年目標と期報の境界は日付で割らない（到達点アンカーの同値と各期の実行配分は別物で、区切りのズレを同値検査へ混ぜない）。

#### 踏みやすい落とし穴

- **期報だけ直して月報・週報が古いまま残る。** 単一ファイルの検査では rc=0 で通る。
  期報と月報が揃ったら `validate-cross-level.py` を回す（週報があれば `--weekly` も渡す。1年層の引数は `references/validation-gates.md` の「IN3 の1年層の引数」）
- **経緯の記述を現在値と読み違える。** 「以前は500,000だった」「従来の1,200,000から置き直し」は
  【仮置き事項】【衝突】【確定済み・解消済みの記録】【来月以降に対応すること】の中に置く。
  アンカーの節の本文に混ぜない（混ぜると人も検査スクリプトも現在値として読む）
- **期合計と月の値を同値にしようとする。** 内訳継承の値は同値にしない。期報に月別内訳を書く
- **週の基準配分と実行目標を混ぜる。** 月額参照根拠を残す場合は現在の月額を参照し、週の実行目標自体は成果の売上貢献で検算する
- **全角数字で書く。** 半角のみ。全角で書かれた値は抽出不可になり、検査できていない状態になる

### 要因分析セクション（重要・必須）

各「未達を挽回するための行動」セクション（全レベルの新フォーマットで「前週/前月/前期/前年の◯◯に対して未達を挽回するための行動」という名称。前期間語（前週/前月/前期/前年）が変わるだけで役割は同じ）では、「共通部品D 前回ブロック」の対応行を書いた直後に、別見出し（H3）で **要因分析** を付ける（月報は管理用の見出しだけ）。

**未達の振り返りは新しい見出しを作らず、この3つの既存見出しに書く。**

| 内容 | 書く見出し |
|---|---|
| 売上が未達だった事実と、次に取る行動 | `【前◯の売上に対して未達を挽回するための行動】` |
| 成果が未達だった事実と、次に取る行動 | `【前◯の売上以外の成果に対して未達を挽回するための行動】` |
| 行動が成果につながらなかった原因と、直し方 | `【前◯の行動に対して未達を挽回するための行動】` |

数値の差分は `【…差分】` 見出しが受け持つ。**差分見出しには文章を書かない**（`validate-goal-output.py` が数値・箇条書き形式を要求する）。

#### 書く内容の骨格（3点を対応行と要因分析で分担する）

1. **何が未達だったか** → 対応行の `{前回の項目名}`。数値は差分の欄が受け持つ
2. **行動が成果につながっていなかったこと**（成果につなげるための行動目標・売上目標を立てるよう言われていたが、成果につながる動きになっていなかった、という事実） → 対応行の下の要因分析
3. **成果につなげる前提に立ち直して、行動の基準値をどこからどこへ上げるか** → 対応行の `{起点}→{到達点}`（「連絡8件→30件」のように数値で書く）

**禁止**: 精神論の NG 語とその言い換え（「共通部品A 行動行」）を使わず、基準値の数値で書く。「自分なんかが」等の枕言葉も使わない。未達の理由を人や環境に置かず、**行動の層（自分の手の動き）で書く**。

- 挽回セクション本体：「共通部品D 前回ブロック」の対応行だけを書く。期日は今回の行動目標の行にだけ書き、対応行には書かない
- その下に H3 で要因分析セクションを追加：「なぜダメだったのか／なぜうまくいったのか」を分析的に記述（対応行の検査の対象外）

#### 構造例

```markdown
## 【前月の売上に対して未達を挽回するための行動】
- 研修の継続合意：継続条件の提示0件→1件（今回の行動目標「継続条件」で実行）
- 業務委託の開始：開始日程の打診1件→3件（今回の行動目標「開始日程」で実行）

### 売上未達の要因分析（なぜ60万円が0円になったのか）

**根本要因**：
1. **要因1見出し**：状況の詳細・なぜそれが起きたか・何を見落としたか（2〜4文）
2. **要因2見出し**：同上
3. **要因3見出し**：同上

**学習**：今回から得た普遍的な教訓を1〜2文でまとめる
```

#### 上振れ実績の要因分析（目標外で達成された場合）

目標外で達成された実績（例：tenant契約成立）は、実績の欄に足さず（足すと項目名・順序が前回の目標と1対1でなくなり FAIL）、挽回の欄のこの H3 に書く。未達分析と同じ形で「なぜうまくいったのか」を分析する：

```markdown
### {{上振れ項目}}（目標外上振れ）の要因分析と次への行動変化

**契約が決まった要因**：
1. **要因1**：何が機能したか・どう作用したか
2. **要因2**：同上

**次への行動変化（再現可能化）**：
- {再現する行動の項目名}：{起点}→{到達点}（今回の行動目標「{今回の項目名}」で実行）
```

要因分析の目的：単に「未達でした」「成功しました」で終わらせず、構造的な原因を言語化することで、次の行動の質を上げる。フォーマットだけを満たして終わると学びが蓄積されない。

### 売上系セクション（売上目標・売上実績・差分）

**そのセクションには数値1つだけ**を記述する。

- ✓ OK: `600000`
- ✓ OK: `-600000`
- ✗ NG: 表（| 売上源 | 目標 | 根拠 |）を入れる
- ✗ NG: 「### 前回売上目標の内訳」のサブセクションを足す
- ✗ NG: 説明文を足す

内訳・根拠は成果側の売上貢献で示し、売上系セクションには重ねて書かない。

#### 継続売上と単発を混ぜない

- 売上目標の計上範囲（総売上／継続売上のみ）は既存の合意を継承し、不明な場合だけ確認する。単発を一律に除外しない。
- 継続と単発を区分し、合意した範囲で**当期に実際に計上する分**の貢献額を合算する（C3）。範囲外や翌期分は0と理由を示し、総額へ加えない。売上系セクション本体は数値1つとし、内訳は成果側の貢献額で検算する。
- 継続の件数は累積と新規を区別し、翌期の継続が未確定なら自動で計上しない。
- 日々追う先行指標は、売上から逆算して合意した人数・件数・回数にする。

### 成果目標・行動目標セクション

**箇条書きのみ**。Markdown の表の使用は禁止。

#### 目標セクション

成果目標の書式は「共通部品B 成果目標と売上貢献の根拠」（今期間も前期間の転記も同じ）。項目間は1行空ける。

例（以下の実績・差分・NG/OK の例は、すべてこの目標に対するもの）：
```markdown
- 研修の継続合意：日工さんの継続合意1件　期日4/15
  → 売上貢献：75000 × 1 = 75000

- 業務委託の開始：森田さんの開始1件　期日4/2
  → 売上貢献：200000 × 1 = 200000

- 単価の決定：海老名さんの決定1件　期日4/15
  → 売上貢献：0（5月の業務委託の開始を支える）

- AI質問会勉強会：参加者5名以上　期日4/18
  → 売上貢献：0（5月の提案の受諾を支える）
```

行動目標は「共通部品A 行動行」の行を、支える成果目標ごとの `### → {成果目標名}：{要約}（{金額}円）` 見出しの配下に置く。

#### 実績セクション（特に厳守）

**「目標に書いた項目すべて」を必ず実績側にも書く**。実績数値（できた件数・回数・金額）と完了日のみで記述。

- 形式：`- 項目名：実績数値・完了YYYY-MM-DD（または完了M/D）` の形。項目名と順序は目標の欄と同じにする（「共通部品D 前回ブロック」）
- 例（上の目標例に対する実績）：
  - `- 研修の継続合意：0件`
  - `- 業務委託の開始：1件・完了4/16`
  - `- 単価の決定：1件・完了4/15`
  - `- AI質問会勉強会：参加者7名・完了4/18`

**実績セクションに書いてはいけないもの**：
- 「→次のフェーズへ」「先方都合で延期」などの理由・背景説明
- 「実施」「未達」「次回確認」などの抽象的状態
- 「合意未達→受注」のような経緯説明
- 「○/△/×」「(参考)」などの記号
- 売上計上未確認・代替成果の経緯など

**実績に書くべきもの**：
- 目標項目それぞれに対する **件数（数値）** と **いつ完了したか（日付・期日）**
- できなかったものは `0件` と記述
- 1項目に2つの数値が要るときは、目標を立てる段階で項目を分ける。実績の側で `／` を使って2項目を1行に継ぎ足さない

**目標外の追加実績**：
目標になかったが期間中に実現した件は、実績の欄に足さず、挽回の欄の「上振れ実績の要因分析」に書く（本ファイル「要因分析セクション（重要・必須）」）。

#### 差分セクション

`- 項目名：差分数値` の形（例: `- 研修の継続合意：-1件`）

- 必ず `+` または `-` を付ける。差分0は `±0` と書く
- 説明文・理由・背景は書かない
- **行動目標の差分は、行動目標1行につき1行の差分を書く。** まとめて1行にしない（目標側の行数と差分側の行数が一致するのが既定）
- 実績が取れていない項目は数値の代わりに `確認中` と書く（例: `- 紹介依頼：確認中`。「共通部品D 前回ブロック」）

#### 説明・理由はどこに書くか

実績の延期理由・代替実現・軸転換の経緯・先方都合などは、すべて以下のセクションに集約する：

- 「【前{週/月/期/年}の売上に対して未達を挽回するための行動】」
- 「【前{週/月/期/年}の売上以外の成果に対して未達を挽回するための行動】」
- 「【前{週/月/期/年}の行動に対して未達を挽回するための行動】」

これらのセクションには対応行と、その下の要因分析を書く（書き方は「共通部品D 前回ブロック」の挽回と、本ファイル「要因分析セクション（重要・必須）」）。

## 週報（1週間目標）フォーマット

週報は視認性のため `---` で2ゾーンに分ける。**ゾーンA（ロールアップ用ヘッダー・準静的＋前週実績）** と **ゾーンB（今週の実行・毎日見る所）** の2層構成。ゾーンAは月報/期報へロールアップする公式ヘッダーと前週レビュー、ゾーンBは週報固有のチェックリスト群（最重要数字・今週の売上目標／売上以外の成果目標・到達ライン・成果グループ別の行動目標・習慣目標・見直し記録・判断基準・週末振り返り）を置く。**「今週送る個別メッセージ」「今週やらないこと」はゾーンBの構成要素ではない**（後述の通り週報では廃止し、個別メッセージは成果グループの行動行へ、やらないことは到達ラインの日付索引の `｜やらない：` 注記へ置く）。

### ロールアップ契約（週報→月報/期報の集約規則）

週報から上位（月報/期報）へ集約するのは、対象期間の実績・経過と照合に必要な情報に限る。今回の計画は下位目標の足し上げで作らず、上位到達点と合意した売上から成果→行動を逆算する。前期間の目標は同じ層の前回正本から引き継ぐ。

- (a) 集約は見出し名キーの再マッピングで行う。期間語（今週/今月/今期、前週/前月/前期）を正規化した「【{期間}の…】」キーでルックアップし、ゾーン位置に依存せず（ゾーン非依存ルックアップ）、上位フォーマットの確定セクション順へ再ゾーニングする。実績・経過の本文だけを N:1 で集約し、見出しキーを 1:1 で対応させる。当期・前期の目標値をこの集約で上書きしない。
- (b) 週報固有見出し（今週の位置づけ・今週の最重要数字・今週の大きな到達ライン・習慣目標（仕組みで動く土台）・今週の見直し記録・今週の判断基準・今週末の振り返りチェックリスト）は集約対象外。上位へロールアップしない。
- (c) 月報固有見出し（確認された情報・北原さんの原則・要因分析H3・プロジェクト別タスク）は週報集約では供給されず、月報側で新規生成する。

### チェックリスト形式の徹底ルール（最優先・厳守）

週報は「済/未済を二値で判定できる」ことが最優先。以下のセクション（すべて**ゾーンB**に属する）の形式を守る。行動の済／未済は【今週の行動目標（行動管理・優先順位付き）】の行動行だけで付ける（Daily.md の embed もここを参照する）。**簡潔版を求められても、これらのチェックボックス化は絶対に外さない。**

| セクション | 形式 |
|-----------|------|
| 今週の最重要数字 | `- [ ]` 各項目 |
| 今週の大きな到達ライン | チェックボックスなしの日付索引（「共通部品A 行動行」の日付索引。1日1行） |
| 今週の行動目標（行動管理・優先順位付き） | 成果目標ごとの `### → ` 見出し＋配下に `- [ ]` 各項目（合計3項目以上）。週の行動の唯一のチェック場所 |
| 習慣目標 | カテゴリ別 `### ` 見出し＋各カテゴリに `- [ ]` 2項目以上（最低6チェックボックス） |
| 今週末の振り返りチェックリスト | 3ブロックの `- [ ]` |

**【適用範囲: 週報のみ】今週送る個別メッセージ・今週やらないこと・プロジェクト別タスクは独立セクションとして出力しない**（廃止）。層ごとの出力先は「共通部品F 層別差分表」で、廃止は週報に閉じた措置である。同じ行動を複数の台帳に書くとチェックの状態がずれるため、週の実行管理は「行動目標＋日付索引」の1方式にし、置き場所を次のように1つに決める。

- 個別メッセージの送付（MTG後のお礼・告知連絡等）は、支える成果グループ（成果に紐づかなければ `### → （関係維持）`）の行動行として【今週の行動目標（行動管理・優先順位付き）】に置く
- やらないことの制約は、リスクが生じる日の日付索引の行末に `｜やらない：{内容}` として書く
- 【今週の大きな到達ライン】は行動目標を日付で引く索引で、索引にだけあるタスクを作らない

## 月報（1ヶ月目標）フォーマット

公式21ブロックを公式順に並べ、深掘りブロックは公式の後に置く。スナップショット項目（現在事業パートナー数〜現在のグリッドパートナー数）は前月レビューの前ではなく、今月計画（今月の売上目標〜今月の行動目標）の後に配置する。

**「公式21ブロック」の語の定義（この語の正本は本ファイル）**: 北原さん提出フォーマット由来の**固定**の見出し集合を指す。21 はその見出し数で、提出フォーマットが変わらない限り不変。全件の並びは本ファイル下部の月報テンプレートに逐語で置いてある。`output-formatter.md` の品質チェックリストはこれとは別物で、観点が増減すれば数も変わるため**件数で呼ばない**（「21項目」の語をチェックリスト側に使ってはいけない）。

### 月報は1ファイルの中で提出用セクションと管理用セクションに分ける（厳守）

**ファイルは1本。提出用の別ファイルを作らない。** 北原さんへ出す内容と自分が回す内容を同じファイルの中で上下に並べる。2セクション構成になるのは月報だけで、週報・期報は詳細のみ。

ファイルを分けない理由は「共通部品F 層別差分表」。

- **提出用セクションを先、管理用セクションを後**に置く
- 群の見出しは `# 北原さん提出用（シンプル）` と `# 管理用（詳細）`（H1。項目見出しは両群とも H2）
- **提出用セクションの `## 【…】` には、閉じ括弧の内側に「（提出）」を付ける**（例: `## 【今月の売上目標（提出）】`）。validate-goal-output.py の重複見出し検査は `## 【…】` 行の完全一致で数えるため、この接尾があれば管理用の同名見出しと衝突しない。成果目標・売上目標の抽出（C1〜C3）も `（提出）` 付きを拾わず、行動目標のグループ検査（C4/C5・S3）も `（提出）` の付いた見出しを対象から外す
- **管理用セクション側の見出しには文字を足さない**（素の `## 【今月の売上目標】` のまま）。必須見出しの検査は `^## 【ラベル】[ \t]*$` の完全一致なので、必須見出しを満たすのは管理用側。ここに「（管理）」等を足すと必須見出しが1件も満たされず FAIL になる
- **数字は両セクションで同じ値を使う。** 提出用は管理用の射影（「共通部品A 行動行」の提出用の書式）で、値は変えない（提出用で丸めない・削らない・合算しない）
- **シンプル＝項目を削ることではない。** 公式21ブロックの見出しは提出用セクションでも1つも落とさない
- 【確認された情報】【顧問参加前の月商】は両群に共通のヘッダーメタなので、群の前に1回だけ置く（公式21ブロックには含まれないため、提出用から落ちたことにはならない）

#### 提出用セクションの粒度（シンプルな構成）

| 観点 | 提出用セクション | 管理用セクション |
|---|---|---|
| 項目・数値 | 管理用と同じ項目名・件数・単位・期日の行（「共通部品A 行動行」の提出用の書式） | 項目名・件数・単位・期日の正本 |
| 成果目標の売上貢献 | 2行目の `→ 売上貢献：…` を外す | 成果の次行に検算根拠を置く |

| 記述量 | 要点のみ | 同じく要点のみ。理由・背景・日別タスクを自動追加しない |

## 期報（3ヶ月目標）フォーマット

期報は月報（上記「月報（1ヶ月目標）フォーマット」）の確定セクション順をそのまま使い、以下の読み替え規則を適用する。

### ロールアップ元（月報3件）

期報では**対象期間の月報3件から実績・経過をロールアップして照合する**。集約方法は「ロールアップ契約（週報→月報/期報の集約規則）」に従う。前期の目標は前期正本から保持し、今回の計画は上位到達点と合意した今期売上→必要な成果→行動の順に設計する。月報の目標値を足して今期の計画を確定しない。

### 読み替え規則

- サマリー見出しは `## 【3ヶ月の目標】{{start_date}}〜{{end_date}}`（継続語彙・凍結。改名禁止）。
- 振り返り部の「前月」はすべて「前期」に読み替える（例: 【前期の売上目標】【前期の行動目標（行動管理）】）。
- 計画部の「今月」はすべて「今期」に読み替える（例: 【今期の売上以外の成果目標】【今期の行動目標（行動管理・優先順位付き）】）。
- 【今期の行動目標（行動管理・優先順位付き）】の各行の書式・期日トークンは「共通部品A 行動行」、並び順と期日は本ファイル「行動目標の並び順と期日の逆算」。
- 【今期の売上以外の成果目標】【前期の売上以外の成果目標】も「共通部品B 成果目標と売上貢献の根拠」の記法で書く。計上期間の規則（C1e）は「今期の3ヶ月間に立つ分だけ」と読み替える。月額5万の顧問を期初に成約するなら、期内に実際に立つ3ヶ月分は `50000 × 3 = 150000` として計上してよい（`ヶ月` の単位語は式に書かない）。4ヶ月目以降は次期の成果目標へ回す。
- 【今期の行動目標（行動管理・優先順位付き）】も月報と同じく `### → {{成果目標名}}：{{要約}}（{{貢献額}}円）` のグループ見出しで並べ、見出しの金額を成果目標の貢献額と一致させる（C4/C4b）。
- 【確認された情報】の目標期間は「3ヶ月」とする。
- スナップショット項目（今期の累計売上実績・現在事業パートナー数・現在のグリッドパートナー数・前回/次回のアカデミーへの参加日・次回の壁打ち予定日・次回の壁打ち予定月までに目指している状態・次回の壁打ち予定日までに達成させること）は月報と同じ位置・名称で含める（期間語化しない）。
- **ヘッダーの【今期の売上目標】（月報の期アンカー項目）は期報では出力しない**（採用案A1）。期報では計画部の【今月の売上目標】→【今期の売上目標】がその役割を兼ねるため、ヘッダー側の【今期の売上目標】を重複出力しない。これで期報の見出し集合は【今期の売上目標】が一意になる。
- **【プロジェクト別タスク】は期報では出力しない**（層ごとの要否は「共通部品F 層別差分表」）。
- **【今月の日別タスク】（読み替えで【今期の日別タスク】に相当）は期報では出力しない**（日別タスクはプロジェクト別タスクの日付展開のため月報のみ。期報は【確定スケジュール】で代替する）。
- **【前回のやらないことが守れたか】と【北原さんの原則（今月特に守ること）】は期報では出力しない**（読み替え後の名前でも出さない。#37 は週報・月報、#38 は月報のみ。`references/data-contract.md` §3.1。層ごとの要否は「共通部品F 層別差分表」）。
- **【今期の最重要数字】は任意**（必須見出しの検査には含めない。層ごとの要否は「共通部品F 層別差分表」）。置くときは月報と同じ形で、`今期の売上目標：{金額}` の1行（金額は【今期の売上目標】と同じ値）を置き、その売上に至る人数・回数・件数を続ける。人数・回数・件数の基準は、【今期の売上以外の成果目標】で合意した今期の成果とする（1年目標がある期は、四層連携で1年目標の成果に対応させた今期の分）。月報の注記のうち月報だけの記述（期報の当月配分を基準にする、`validate-cross-level.py` がこの節を読む）は当てはめない。到達点2件の注記はこの節ではなく【今期の売上以外の成果目標】へ置く（下の「1年目標がある期の到達点の注記（期報）」）。`validate-goal-output.py` は、この節を置いた期報で `今期の売上目標：` の行と【今期の売上目標】の値が一致するかを照合する

### 到達点アンカーの置き場（4層ロールアップの起点）

到達点アンカー2件は、この層が本文＋注記で持ち、期報・月報が注記で同値継承する。

```markdown
## 【今年の最重要数字】

月間売上 8,500,000 と、その売上を生む月8時間 500,000 の月額継続コンサルの人数：17人（2027-09-30 時点）

（※ 4層アンカー。期報・月報が同値で継承する。月間売上到達点：8500000）
（※ 4層アンカー。期報・月報が同値で継承する。継続コンサル人数：17）
```

- `月間売上到達点：<数値>` と `継続コンサル人数：<数値>` の2行は、文字列ごと **`validate-cross-level.py` の抽出規則**に当たる。語を言い換えると抽出不可になる
- 数値は半角・カンマ有無は自由（`8,500,000` と `8500000` は同値として扱う）。全角数字は抽出不可（rc=1）
- 期報側の置き場は【今期の売上以外の成果目標】の注記、月報側は【今月の最重要数字】の注記（正本: `references/data-contract.md` §3.1.3。書き方の例は上の月報・期報の各フォーマットの「1年目標がある期の到達点の注記」）

# 挑戦宣言と企画 — 出力フォーマットの正本

提出先（北原さん・運営の LINE 等）にそのまま貼れる本文と、vault に残すフロントマターの正本。
見出し・注記・締め文の文字列は検査スクリプト（`scripts/validate-challenge-output.py`）の定数と一致させる。`tests/test_validate_challenge_output.py` が突き合わせる。

## 骨格（この順序・この文字列で出す）

```text
---
tags:
  - ubm
  - 挑戦宣言
declared_on: YYYY-MM-DD
challenge_date: YYYY-MM-DD
---

【挑戦宣言と企画】

●目的ーあなたの事業や会社の目的は何か？
<目的本文>

●目標ーその目的に近づくための数値的な目標
・<数値目標1>
・<数値目標2>

●その目標を実現するための挑戦
<挑戦本文>
※ポイントー使える箱は定員数で意識の基準を落とさない
※ズームなら基本100人以上

●リスク回避方法
・健康が崩れない理由
<理由本文>

・信頼が崩れない理由
<理由本文>

・家族が崩れない理由
<理由本文>

・社内拠点が崩れない理由
<理由本文>

・開催前にお金が全て回収できているor1円も費用がかからない理由
<理由本文>

●挑戦を必ず達成するために行うこと
1.<行うこと1>
2.<行うこと2>
3.<行うこと3>
4.<行うこと4>
5.<行うこと5>

上記行うことで必ず達成します。

●目標を追うために定期の報告はどのタイミングで行いますか？
<報告本文>
```

- `<…>` は説明用の記号で、出力に残してはいけない（X01）。
- 提出用テキストはフロントマターを除いた `【挑戦宣言と企画】` から末尾まで。**別ファイルにしない**
  （2本に分けると片方だけ直す事故が起きる。`run-ubm-goal-setting` の「ファイルは3本・月報だけ1ファイル2セクション」が提出用の別ファイルを作らないのと同じ理由）。
- `※ポイント` の2行は利用者への注記だが、提出フォーマットの一部なのでそのまま残す。

## ファイル

- 保存先: `$UBM_VAULT_ROOT/05_Project/UBM/挑戦宣言/UBM - 挑戦宣言 - {declared_on}.md`
- `declared_on` = 宣言した日（作成日）。`challenge_date` = 挑戦の実施日（開催日）。

## 各欄の合格条件

「提出先が読んで追える」ことを合格とする。機械判定は検査スクリプトの違反コード、対話で確かめることは `question-map.md` が持つ。
M01 の自己負担・費用ゼロの判定は語彙に頼る補助で、費用を誰が持つかは `question-map.md` 4-1 の「確かめる」で確かめる。

| 欄 | 合格条件 | 機械判定 |
|---|---|---|
| 目的 | 1〜3文。「誰に・どんな良いことを創るか」が読み取れる | F03（空でない） |
| 目標 | 数値（算用数字）を含む行が1行以上。件数・金額・人数のいずれか | G01 |
| 挑戦 | 何を・何人規模で（算用数字）・いつ、の3点。日付は月日まで確定 | C01（日付）/ C02（人数）/ D01（フロントマターと日付一致） |
| 健康 | 稼働量・睡眠・生活リズムが崩れない**仕組み**（なぜ崩れないか） | R02 |
| 信頼 | 誰の信頼を、どう崩さずに積む企画か | R02 |
| 家族 | 本人が定義した「家族」と、削らない時間・共有の事実 | R02 |
| 社内拠点 | 社内メンバー・拠点の運営が挑戦で崩れない理由 | R02 |
| お金 | 開催前に回収済み（確定額の内訳）または費用ゼロの根拠。見込み・予定・未確定の額は書かない | M01 |
| 行うこと | 番号 1〜5 の5項目。各項目に数・頻度・期限・媒体のどれか | A01 / A02 / S01 |
| 定期報告 | 頻度（週1・隔月・月報で 等）かタイミング（曜日・時刻）が読める | P01 |

## 違反コード（検査スクリプトの出力）

| コード | 意味 |
|---|---|
| F01 | 冒頭の `【挑戦宣言と企画】` が無い |
| F02 | `●` 見出し6つの欠落・順序違い |
| F03 | `●` 見出しの直下が空 |
| F04 | フロントマターが無い・`declared_on` / `challenge_date` が `YYYY-MM-DD` でない |
| C01 | 挑戦に実施日（`M月D日` か `YYYY-MM-DD`）が無い |
| C02 | 挑戦に規模（`N人` / `N名`）が無い |
| C03 | `※ポイント` の注記2行が欠けている |
| D01 | 挑戦本文の日付と `challenge_date` が一致しない／`challenge_date` が `declared_on` より前 |
| G01 | 目標に数値が無い |
| R01 | リスク回避の5理由の欠落・順序違い |
| R02 | 理由の本文が空 |
| M01 | お金の理由が「開催前に回収済み」も「費用ゼロ」も示せていない／見込み・予定・未確定の額が書かれている／自分で払う費用が書かれている／内訳の計算が合わない |
| A01 | 行うことが番号 1〜5 の5項目になっていない（欠番・空・6項目以上） |
| A02 | 締め文 `上記行うことで必ず達成します。` が無い |
| S01 | 行うことに精神論の語（頑張る・意識する・気をつける 等）が入っている |
| P01 | 定期報告に頻度もタイミング（曜日・時刻）も無い |
| X01 | 未置換のプレースホルダ（`◯` `○` `例）` `<…>`）が残っている |
| N01 | ファイル名 `UBM - 挑戦宣言 - {日付}.md` の日付と `declared_on` が一致しない |

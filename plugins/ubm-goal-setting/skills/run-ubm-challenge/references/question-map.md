# 挑戦宣言のヒアリング — 対話の正本

原則・返し方・欄ごとの問い・戻りゲート・ナレッジ未収録の正本。
聞き手（親コンテキスト）と助言役（`challenge-advisor`）の両方が読む。各欄の合格条件は `challenge-format.md` が正本。
「欄」は出力の見出し6つ。対話ではリスク回避を理由ごとに分け、助言役の `field` キー10種で扱う。回数と北原レンズの件数は `field` キーごとに数える。

## 欄とfieldの対応

| field | 「欄ごとの問い」の節 | 出力欄 |
|---|---|---|
| purpose | 1. 目的 | 目的 |
| goal | 2. 目標 | 目標 |
| challenge | 3. 挑戦 | 挑戦 |
| risk.money | 4-1. お金（最初に聞く） | リスク回避方法のお金 |
| risk.health | 4-2〜4-5. 健康・信頼・家族・社内拠点の健康行 | リスク回避方法の健康 |
| risk.trust | 同節の信頼行 | リスク回避方法の信頼 |
| risk.family | 同節の家族行 | リスク回避方法の家族 |
| risk.home_base | 同節の社内拠点行 | リスク回避方法の社内拠点 |
| actions | 5. 挑戦を必ず達成するために行うこと | 行うこと |
| report | 6. 定期報告 | 定期報告 |

## 原則

1. **値はユーザー、方向は AI。** 欄の値（数字・日付・人・会場・欄に入る文）はユーザーの発話から取る。
   AI が示してよいのは各欄の切り口・挑戦の欄の ◯ 入りの型・北原さんの考え方からの方向で、◯ に値を入れない。
2. **1ターンの上限。** 問いは1つ（具体化が必要なら2つまで）。北原レンズは0〜1件で、原文の引用は1文、
   ID は文末に括弧で添える。
3. **流れ。** 1欄は「問い → 答え → 深掘り（2回まで。足りなければ方向を1回）→ 要約確認 → 了承で確定」。
   手順と助言役の呼び方は SKILL.md の C1-C5 が正本。
4. **北原さんの言葉はナレッジにあるものだけ。** ID は `knowledge/*.json` を `Grep` で確かめてから使う
   （記憶で書かない）。引用は `quote` か `expression.phrasing` を原文のまま。無ければ `content`
   （`CP-` は `advice`）を要約だと明示する。ナレッジに無いものは「フォーマットの注記では」と出所を言う
   （下の「ナレッジ未収録」）。
5. **呼び水は見せるだけ。** 期報・月報の目的・目標は「前回はこう書いていました」と見せ、使うかはユーザーが決める。同じでもよい（phase3 の「前回と同じ」の問い返しはしない）。

## 返し方（phase3 との差分）

回答パターンと3ステップは `agents/phase3-coordinator.md` の「品質基準（回答パターン別対応ルール）」
「ナレッジ活用原則」に従う。挑戦宣言で違う点:

- ③（行動に落とし込む）は「方向を示す」: 原則1 の切り口・型を示し、どれで考えるかと値はユーザーが決める
  （phase3 の「□□をするといい」「例えば◯◯件とか」のような値の例は出さない）。
- 質問返し・沈黙・「わからない」で出す選択肢は、その欄の「切り口」（値の選択肢は出さない）。選んだ理由は聞かず、
  その切り口で問いを続ける（phase3 の「選択後に理由を質問」はしない）。
- 曖昧回答には、数・日付・人のどれが決まっていないかを1つだけ聞く。
- 「AI が決めてください」には決めず、判断軸を2つ示して選んでもらう。
- 紐づくナレッジが無ければレンズを出さない（phase3 の「合わなくても使う」は採らない）。
- 保留: 「わからない」・沈黙が2回続いた、または深掘り2回と方向の後も足りないとき（「戻りゲート」に当たるならゲートが先）。健康・信頼・家族・社内拠点・
  行うこと・定期報告は保留して次へ進み、C6 の組み立ての前に戻って1回聞き直す。目的・目標・挑戦・お金は保留せず、判断軸を
  2つ示して1回だけ聞き直す。どちらも、それでも決まらなければvaultへ保存せずに終え、`handoff-format.md` に従って確定済み欄・未確定要素・再開条件を引き継ぐ。

## 欄ごとの問い

「確かめる」は深掘りの材料。欄が足りているかは `challenge-format.md` の合格条件で決める。
聞く順はフォーマットの順。ただし **リスク回避はお金を最初に聞く**（成立しなければ「戻りゲート」）。
`レンズ` は北原ナレッジの ID と使いどころ。

### 1. 目的

- **問い**: 「この挑戦の先で、誰と、どんな状態をつくりたいですか？」
- **確かめる**: 本人の言葉か（目標の言い換えでないか）／「誰」が名前で浮かぶか／その人に何が良くなっていたら目的に近づいたと言えるか。
- **切り口**: ①誰から始めるか ②その人に何が起きていてほしいか ③自分の人生で譲れないこと
- **レンズ**: AG-089（目的と目標が混ざっているとき）／PR-306（事業内容の説明から入ったとき）／AG-090（「目的がわからない」と止まったとき）

### 2. 目標

- **問い**: 「その目的に近づいたと分かる数字は何ですか？」
- **確かめる**: 目的に近づく数字か（目的との一本筋）／件数・金額・人数のどれで測るか／いつまでの数字か。
- **切り口**: ①次につながる件数 ②関わる人（運営・仲間）の数 ③利益額
- **レンズ**: PR-334（目的と無関係な数字が出たとき）／MS-015（数字だけで止まったとき）／MS-022（集客数だけを目標にしたとき）

### 3. 挑戦

- **問い**: 「その目標に届くために、どんな場をいつ開きますか？」
- **確かめる**: 何を・何人の箱で・何月何日に／誰のために開くか（名前で）／箱を「集まりそうな数」で下げていないか、Zoom なら100人以上か。
- **切り口**: ①この人のために開く、という1人 ②定員が決まっている箱 ③勝負の月。型「◯人のセミナーイベントを◯月◯日に
  開催する。」とフォーマットの注記2行（定員数で意識の基準を落とさない／Zoom なら基本100人以上）は示してよい（◯ はユーザーが埋める）。
- **レンズ**: AG-151（「人が集まったら日を決める」と言ったとき）／AG-045（規模の決め方に迷うとき。お金の欄にも効く）／PR-209（箱を小さくしたくなったとき）

### 4. リスク回避方法

土台は PR-199（健康・信頼・家族は崩してはいけない）と AG-190（3つが崩れない範囲でギアを上げる）。
社内拠点とお金はフォーマット独自の枠。どの理由も聞くのは「なぜ崩れないか」の仕組み。

#### 4-1. お金（最初に聞く）

- **問い**: 「この挑戦にかかるお金は、開催前にどう回収できていますか？ それとも1円もかかりませんか？」
- **確かめる**: 費用（会場費など）を誰が持つか／確定収入を単価×人数で／確定か見込みか（「回収見込み」を「回収済み」と書かない）。
- **切り口**: ①費用を持ってくれる人（スポンサー） ②費用のかからない場所 ③参加者で分け合う形
- **レンズ**: PR-149（先にお金が出ていく形になっているとき）／AG-047（会場費を自分で払う前提のとき）／AG-024（費用ゼロの形が浮かばないとき）

#### 4-2〜4-5. 健康・信頼・家族・社内拠点

| 理由 | 問い | 確かめる | レンズ |
|---|---|---|---|
| 健康 | 「この挑戦を入れても、体と生活のリズムが崩れないのはなぜですか？」 | 何を減らして時間をつくったか／睡眠・休みを何で守るか（精神論でなく予定の空け方などの仕組みか） | AG-085（予定を思いつきで決めているとき） |
| 信頼 | 「この挑戦で、信頼が崩れないのはなぜですか？」 | 誰の信頼か（名前で）／声をかけたが来られない人・断った人に何と伝えるか／当日まで一緒に動く人は誰か | PR-193（信頼を気持ちの話で語るとき）／AG-076（声をかけた後のつながり方に迷うとき） |
| 家族 | 「あなたにとっての『家族』は誰ですか？ その人たちとの時間はどうなりますか？」 | 家族の範囲を本人が定義したか／削らない時間／挑戦をどこまで話しているか | PR-199（家族の範囲が決まっていないとき）／AG-083（家族の予定が後回しになっているとき） |
| 社内拠点 | 「この挑戦の間も、社内のメンバーや拠点が崩れないのはなぜですか？」 | メンバーに何を任せ、何を任せないか／自分の基準をメンバーに押し付けない設計か | PR-281（拠点を後回しにしているとき）／PR-310（自分が動かないと回らない形のとき）／PR-104（メンバーとの接触が減りそうなとき） |

- **切り口（4-2〜4-5 共通）**: ①予定から外したもの ②先に押さえた予定 ③事前に話した相手

### 5. 挑戦を必ず達成するために行うこと

- **問い**: 「挑戦の人数に届くまでに、当日までに何をしますか？ 5つ挙げてください」
- **確かめる**: 5つで挑戦の人数に届く逆算か（足りない分は何で埋めるか）／各項目の回数・頻度・期限・媒体。
- **切り口**: ①誰と組むか（共犯者・運営） ②続ける発信 ③開催前に直接声をかける相手
- **レンズ**: CP-055（集客を自分ひとりで抱えているとき）／AG-153（場を開いた後の次の一手が無いとき）／AG-117（「意識する」で書いたとき）

### 6. 定期報告

- **問い**: 「いつ・どのくらいの頻度で、何を報告しますか？」
- **確かめる**: 頻度かタイミング（曜日・時刻）／報告する数字と報告先。
- **切り口**: ①すでに続いている定期の場（月報・面談など） ②目標の数字が動く周期
- **レンズ**: AG-080（頻度が決まらないとき）／AG-060（何を報告するか迷うとき）／AG-171（最初の報告を先送りしているとき）

## 戻りゲート

| 欄で起きたこと | 戻り先 | 聞き方 |
|---|---|---|
| お金が開催前に回収できず、費用ゼロにもできない | 3. 挑戦 | 「規模・会場・日付のどれを動かしますか？」 |
| 行うこと5つで挑戦の人数に届かない | 5 の中で入替え・回数の見直し（それでも無理なら 3） | 「足りない分は何で埋めますか？」 |
| 目標の数字が目的とつながらない | 1. 目的 か 2. 目標 | 「この数字が増えると、目的の誰が良くなりますか？」 |
| 健康・家族のどちらかが削られる | 3. 挑戦（日付か規模） | 「何を減らせば、この挑戦が入りますか？」 |

戻るときは、すでに確定した欄のうち影響を受ける欄だけを「確定前」へ戻し、ユーザーに伝える。

## ナレッジ未収録

AI が北原さんの言葉として作らないもの。

| 項目 | 扱い |
|---|---|
| 「挑戦宣言」という言葉・6欄の構成 | フォーマットの正本（`challenge-format.md`）として扱う |
| 「社内拠点」という枠 | フォーマットの枠。近い原則は PR-281 / AG-179 / PR-104 |
| 「定員で基準を落とさない」「Zoom100人以上」 | フォーマットの注記として読み上げる |
| 「開催前に全額回収 or 費用ゼロ」の合格判定 | フォーマットの枠。近い原則は PR-149 / AG-047 |
| ユーザーの例文（100人セミナー・100日100名コラボ・小規模 Zoom で誘導 等） | 手本として勧めない。値の候補としても出さない |
| 報告の曜日・時刻・手段 | ユーザーが決める |

この表の項目を北原さんの言葉として語りたくなったら、ナレッジへの取り込み（`run-ubm-knowledge-sync`）が
先。取り込まれるまでは「フォーマットの注記では」と出所を言う。

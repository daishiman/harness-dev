載せ替えで置き換えたもの（0.4.0 の記法は使わない）:

- **所属の正はグループ見出し**: 行動目標は支える成果目標ごとの `### → XXX：…（…円）` の配下に置き、`XXX` を成果目標の項目名（`：` より前）と一致させる（空白を落とした完全一致）。カギ括弧の行内注記 `→ 支える成果目標「XXX」` は廃止し、`verify-goal-linkage.py` は FAIL にしてグループ見出しへの書き換えを案内する（validator も所属不明として C4 で FAIL）。見出しの無い旧ファイルの行内注記 `→ 支える成果目標：XXX` は読み取りのフォールバックとして WARN 付きで受理する。
- **優先度 A/B の区分見出しを廃止**: 並び順は貢献額の大きいグループが上に来る形で表す（上流と同じ）。
- **成果が測りにくい行動の置き場**: 独立見出し `【今(週|月|期)の習慣・土台（売上の筋に乗せないもの）】` を廃止し、行動目標セクション末尾の `### → （土台）`／`### → （関係維持）` グループへ戻した。許容する括弧名はこの2つだけ。既存ファイルにあれば中身をこの2グループへ移す。
- **成果→行動の段**: 「準備 → 資料作成 → 実施 → フォロー」を、相手が登場する接点の段（打診する → 相手の状況を聞く → 課題・条件を提示する → 実施する → 実施後に意向を聞く）へ置き換えた。資料作成など一人で完結する作業は段として立てない（採否基準と矛盾していたため）。`prompts/R4-step4-action-plan.md` のターン4A-1 もこの段で問う。

`verify-goal-linkage.py` の作り直し:

- 照合規則を `validate-goal-output.py` から importlib で読み込んで共用する（成果目標の項目の束ね方・`_outcome_key`・`_ref_matches_key`・グループ見出しの解釈）。二重に実装しないので、validator の C4/C5 と判定が食い違わない。
- 上乗せは5点に限る: 支える行動の無い成果目標を rc=1（C6 は WARN）／免除する括弧名を `（土台）`／`（関係維持）` に限定（C5 は括弧で始まる名前をすべて免除する）／1つの行動が `・` で複数の成果目標を指すと FAIL／月報は `# 管理用…` グループだけ照合し、`# 北原さん提出用…` は SKIP、グループ見出しのラベルずれは FAIL／両方向の分母を印字し、分母0を rc=3。

## 0.5.0 - 2026-10-04

（ローカルのみで未公開。0.6.0 で上流 0.3.46 の記法へ載せ替えた。`verify-cross-level.py` と三層連携の契約はそのまま引き継ぎ、末尾の「既存スクリプトは変更していない」は 0.6.0 で `verify-goal-linkage.py` を作り直したため現在は当たらない。）

**期報・月報・週報の三層連携を契約化**し、**層をまたぐ値のズレを検出する検査器 `verify-cross-level.py` を新設**した。期アンカー8種を3ファイル同時に突き合わせ、ズレていれば rc=1 で止める。

修正した問題:

- 期報の数字を直して月報・週報へ降ろし忘れても、`validate-goal-output.py` も `verify-goal-linkage.py` も **rc=0 で通っていた**。どちらも1本のファイルしか見ず、**層をまたぐ値を突き合わせる口が1つも無かった**（分母が0件。「検査して一致していた」ではなく「当てる対象が1件も無かった」）。`validate-goal-output.py --peer` には層間一致検査があるが、**2ファイルの総当たり・WARN のみ・3アンカー**で rc を上げないため停止条件にならない。実際に、月報の数値体系を変えたあと期報・週報へ手で反映する運用になり、古い数字は人が目で走査して見つけていた。

変更点:

- **新スクリプト `skills/run-ubm-goal-setting/scripts/verify-cross-level.py`**: `--quarterly PATH --monthly PATH [--weekly PATH] [--month N]`。期アンカー8種（今期の売上目標／当月の売上目標／無料相談の延べ回数／1回目の実人数／月額継続コンサルの累積件数／現在事業パートナー数／現在のグリッドパートナー数／次回の壁打ち予定日）を三層で並記して照合する。rc は `0`=全一致 / `1`=不一致または抽出不可あり / `2`=引数・入力不正 / `3`=抽出0件。**rc=1 と rc=3 を混ぜない。** 出力は常に `照合対象 N 件中 不一致 M 件（抽出不可 K 件）` の形で分母を出し、末尾に `MEASURED_AT` / `ARGS` を付ける（rc=2 で早期終了する場合も出力）。**抽出不可は不一致に混ぜず個別に列挙して rc=1 にする**（検査できていない状態を PASS にしない）。`--weekly` は任意で、省略しても照合対象の件数は変わらない。
- **継承の形を2種に分けた**: 同値継承（期全体の値を三層でそのまま書き写す）と内訳継承（期報が月別内訳として書いた値を月報が自分の層の値として書く）。内訳継承は期合計と月の値を直接比べず、**期報が当月について書いた数**と**月報が自分の数として書いた数**を比べる。対象月は月報の期間終了日の月（最終月曜起点のため 2026-09-28〜2026-10-25 の当月は10月）。
- **経緯の記述を現在値として拾わない**: 【仮置き事項】【衝突】【来(週|月|期)以降に対応すること】【確定済み・解消済みの記録】【追随させる箇所】【前(週|月|期)の…】を抽出範囲から外す。`##` 見出しに当たれば節全体、`###` 小見出しに当たればその小見出しから次の小見出しまで。コメント・コードフェンスの除去は `validate-journal-output.py` と同じ形を**節本文に限って**当てる（新しい前処理を考えない。素朴な正規表現をファイル全体へ広げると本文が消えるため範囲を広げない。行番号を保つため落とした範囲の改行は残す）。
- **数値の受け入れ**: カンマ区切り（600,000）と素の数字（600000）を同値として扱う。全角数字は**半角へ直せば規則に当たる行だけ**を「全角数字」と判定して抽出不可にする（人名の中の全角数字などを誤検出しない）。日本語パスの NFC/NFD 不一致を避けるため `io.open` で開く。
- **ドキュメント**: `references/output-formats.md` に「三層（期報・月報・週報）の連携」節（正本は期報・下から上へは直さない／継承の2形／週報の日割り根拠行／落とし穴6件）と `【この期報の値を直したときに追随させる箇所】` を期報の標準装備として追加。`references/data-contract.md` §3.1.3 に8アンカー×3層の抽出元の表、§4.4 に「三層横断照合は単一ファイル検査の対象外」。`SKILL.md` に判定基準 IN3 と Gotchas 2件、`agents/output-formatter.md` の Step 3 に3本目の検査。
- **未決**: `business_partner_count` / `grid_partner_count` / `next_sparring_date` は `--peer` の一覧では **対象外（スナップショット）**、`verify-cross-level.py` では **同値継承の対象**。2つの検査器で扱いが逆になっている。どちらへ寄せるかは決めておらず、`data-contract.md` §3.1.3 に未決として明記した。
- 受け入れテストは `tests/test_verify_cross_level.py`。既存スクリプト（`validate-goal-output.py` / `verify-goal-linkage.py`）は変更していない。

## 0.4.0 - 2026-10-02

**月報を1ファイル2セクション（提出用＋管理用）に確定**、**売上目標・成果目標・行動目標の三層分離**、**行動目標の採否基準と動詞の制約**、**一本筋（売上目標 → 成果目標 → 行動目標）の逐語照合**、**継続売上と単発の分離**、**未達の振り返りの型** を契約化した。あわせて `validate-goal-output.py` が見ていない参照整合を測る `verify-goal-linkage.py` を新設した。

修正した問題:

- 行動目標の `→ 支える成果目標「XXX」` が成果目標の項目名と食い違っていても `validate-goal-output.py` は rc=0 で通っていた。この validator には `支える成果目標` に関する検査が1件も無く、**一本筋の切れを検出する口が存在しなかった**（名前の一致を測る側の分母が0件だった）。`verify-goal-linkage.py` を別スクリプトとして追加し、validator 本体は変更していない（`tests/test_validate_goal_output.py` の既存の受け入れテストはそのまま rc=0）。
- 月報の提出用に管理用と同じ粒度（個人名・面談回数・日付別の割り振り・優先度の区分見出し）がそのまま載っていた。粒度の正本が無かったため。
- 同じ事項（提出用と管理用の分け方・粒度）が複数ファイルに書かれ、どちらが正か決められない状態になっていた。正本を `references/output-formats.md` 1本に統合し、重複していた `references/management-vs-submission.md` は内容を移してから削除した。
- 1人で完結し相手側で何も起きない作業（1枚にまとめる・名簿を作る・資料を仕上げる・経費を決める・報告書の提出・SNS/YouTube の投稿）が行動目標に混ざっていた。採否の判定基準が明文化されていなかったため。
- 行動目標に「確定させる」「成約する」「満席にする」のように**相手が応じないと達成にならない**書き方が混ざり、成果目標と区別がつかなくなっていた。三層の定義が無かったため。
- 行動目標に金額（`契約300000円を確定`）が、成果目標に自分の開催回数（`自主開催1回`）が入っていた。`assets/action-goals-best-practices.md` の実例そのものがこの混同を手本として配っていたため、実例を書き換えた。
- 未達の振り返りが「意識する」「意識を持った」で終わり、次に何の数字を上げるのかが書かれていなかった。
- 単発（研修・システム開発・勉強会の参加費）が売上目標の内訳に数えられていた。

## 0.3.41 - 2026-09-10

「売上に直結する成果目標」と「直感的に読める出力」の2点を、記法そのものを変えることで構造的に担保した。指摘は「この行動をすれば売上が上がるのかが直接見えない」「文章が羅列していて読みにくい」の2つ。どちらも書き手の努力目標ではなく、書式が許していた抜け道だった。

### 成果目標を1項目=2行にし、貢献額を式で書かせた

- 旧: `- Aさん：月額顧問の成約1件　期日7/2　→ 売上貢献：150000`（横に長く、金額が読み飛ばされる）
- 新:
  ```
  - Aさん：月額顧問の成約1件（初月分）　期日7/2
    → 売上貢献：50000 × 1 = 50000
  ```
- **貢献額には「検算できる根拠」の随伴を必須にした**（C1）。式 `<単価> × <件数> = <貢献額>`、または括弧の根拠 `<貢献額>（値引き後の一括見積）` のいずれか。`150000` とだけ書かれた裸の数字は、それが正しいかを後から誰も検算できないので FAIL。
  - 当初は「式を必須・裸の数字は禁止」としたが、検算（C1c）が式のときだけ走るため、**式で書いた者だけが FAIL のリスクを負う**逆インセンティブになっていた（`50000 × 3 = 200000` は FAIL、`200000` は PASS）。上位概念「根拠の随伴」へ持ち上げて解消した。
  - 同時に、貢献額 0 のときだけ括弧を要求していた **C1b を C1 へ吸収して廃止**。金額的に重要度の低い側にだけ厳しい歪みだった。検査は1つ減り、守備範囲は広がっている。
- **検査 C1c（式の検算）を新設**。`50000 × 2 = 150000` のような計算違いを FAIL にする。式を書かせる意味は、検算されて初めて生まれる。

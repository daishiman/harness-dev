# 図解レイアウト契約

> 正本: `references/spec-registry.md` §1-§5 / §15 / §15-a。本ファイルはそれらを
> **「図解を 1 枚作るときに守る契約」**の視点で束ねた入口であり、値の正本ではない。
> 値が食い違ったら spec-registry が勝つ（差分は `scripts/lint-contract-drift.py` が検出する）。

`scripts/validate-svg-diagram.py` が機械検査する契約の人間向け説明。
**決定論経路**（`vendor/scripts/svg-*.cjs` がビルダー関数で描く）と
**LLM 経路**（agent が SVG を直接書く）のどちらで作っても、出来上がる SVG は
同じこの契約で採点される。検査は成果物側に一本化してあるので、
「どちらの経路か」は合否に影響しない。

- 描き方のカタログ → `svg-diagram-primitives.md`
- 収まり計算の手順 → `spec-registry.md` §5-a
- 図解の選定基準 → `report-visual-strategy.md` / `slide-type-decision-tree.md`
- report で「どの節をどの図種にするか」の正本 → `schemas/visual-derivation-table.json`（決定表）

本ファイルが答えるのは「出来上がった 1 枚で**何が守られていなければならないか**」であって、
「その 1 枚を**どの順で決めるか**」ではない。後者（手続き側）の索引は
参照専用 skill の `skills/ref-diagram-system/SKILL.md` にある。
契約に落ちた原因を辿るときは、契約の条文（本ファイル）と手続きの索引を往復するとよい。

## 1. 語彙は表から取る（数値直書き禁止）

図解が「別の人が描いたように見える」原因はほぼ全て、線幅・色・配置を
その場の数値で決めていることにある。`vendor/scripts/svg-kit.cjs` の各表が正本。
1.1-1.3 が「素材の語彙」、1.4-1.6 が「面の作り方の語彙」。

### 1.1 線幅 `kit.STROKE`（SR-15-01/02）

太さは装飾ではなく **情報の重要度**。同じ太さで全部を描くと、読者が
「どれが本線か」を判断する手掛かりを失う。

| トークン | 値 | 用途 |
|---|---|---|
| `primary` | 2.5 | 主コネクタ（フローの本線・主張そのもの） |
| `secondary` | 2 | 副コネクタ（補足の流れ・戻り線） |
| `node` | 1.5 | ノードの輪郭 |
| `axis` | 2 | 軸・基準線 |
| `hairline` | 1.25 | 補助罫・ゾーン境界・グリッド（**最も細い許容値**） |
| `band` | 24 | ゲージ等の帯（線でなく面として読ませる。線幅の階層とは別物） |

**1.25 を下回らない**（SR-15-03）。SVG は必ず縮小表示される（viewBox 1080 の図が
本文幅 804px なら約 0.75 倍）ため `stroke-width: 1` は実効 0.7px となり、
非 Retina で 1 デバイスピクセルを割ってアンチエイリアスで灰色に溶ける。
`stroke-width: 0` は「線を引かない」の表明なので対象外（SR-15-04）。

### 1.2 配色 `kit.TOKENS`

既存プラグインの共有パレット（style genome の palette 定義）から流用しており、
**図解のためだけの色を新しく作らない**。CSS 変数フォールバック付きなので、
テーマ側の値が変わっても図解が追随する。

| トークン | 用途 |
|---|---|
| `paper` / `paper2` | カード地 / 副次的な面 |
| `ink` / `muted` / `soft` | 主テキスト / 副次テキスト / 補助ラベル |
| `rule` / `ruleSolid` | ヘアライン |
| `accent` / `accentTint` | 焦点（**1 図あたり 1-2 件**。D7） |
| `link` | フロー・接続（矢印の既定色） |

強調色を 3 件以上置くと、視線の着地点が定まらず「どこから読むか」が
読者任せになる。焦点は 1 つに絞る。

### 1.3 配置 `kit.LAYOUTS`

`ring` / `row` / `column` / `grid` / `stack` / `lane` / `matrix` / `zone` / `level`。
座標を手で計算せずこの 9 種の関数へ委ねることで、要素数が変わっても
間隔と整列が崩れない。

幅・高さの配り方は `kit.distributeWidths` / `kit.distributeTrack` に委ねる
（`LAYOUTS` の各関数も内部でこれを使う）。等分を自分で `Math.floor` すると
丸めの余りが右端・下端に溜まり、最後の 1 列だけ幅が違う図になる。
`distributeWidths` は余りを各要素へ配り切って **Σ幅 === 総幅** を厳密に満たす。

### 1.4 コネクタの入射規則（`kit.INCIDENCE_RULE` / `kit.safeElbow`）

**矢印は宛先の辺へ、その辺の外向き法線と逆向きに入射させない。**
つまり許されるのは次の 4 通りだけで、これ以外の向きで辺に当ててはいけない。

| 宛先の辺 | 許容される入射の向き | 禁止される入射 |
|---|---|---|
| 左辺 | 右向き（`dx > 0`） | 左向き（図の内側から外へ抜ける形） |
| 右辺 | 左向き（`dx < 0`） | 右向き |
| 上辺 | 下向き（`dy > 0`） | 上向き |
| 下辺 | 上向き（`dy < 0`） | 下向き |

**理由**: 矢じり（marker）は `markerUnits="strokeWidth"` で、参照点（線の終端）より
**経路方向へ `MARKER.overhang` ぶん張り出す**（SR-15-05）。外向き法線と逆向きに
入射させると、この張り出しぶんだけ矢が矩形の内側へ潜り込み、読者には
矢頭の先だけが見えて胴体が矩形に埋没する。図の向き＝主張の向きが伝わらなくなる。

- 経路は `kit.safeElbow(from, to, srcBox, dstBox)` で引く。屈曲順（水平優先 / 垂直優先）を
  規則を満たす側へ自動で選び、`incidence: 'ok' | 'degraded'` を申告する。
- **`degraded` が返ったらその線は引かない**。ノードが重なっている等で
  どちらの屈曲順でも規則を満たせない配置なので、線を足すより配置を直すのが正しい。
- 1→多の分岐は `kit.trunkPaths` で 1 本のトランクへ束ねる。1 対 1 のエルボを独立に
  引くと各線が自分の中点で折れ、4 本が別々の x で曲がって「どこで分岐したのか」が
  読めなくなる。トランク経路は全セグメントが軸平行なので D5 も自動的に満たす。
- 同一辺に複数の矢を取り付けるときは `kit.fanCapacity(辺長)` を先に見る。
  収まらない本数は載せない（§2 と同じ判断）。矢じりが重なった束は
  黒い塊になり、何本あるのかすら読めない。
- 隣接カードの上辺どうしを結ぶ弧は `kit.overArcPath`。制御点を各アンカーの真上に
  置くので端点の接線が鉛直になり、上辺への入射規則を自動的に満たす。
  ラベルは `kit.overArcApex` の直下に置けば曲線と交差せずマスクが要らない。

### 1.5 viewBox の標準寸法 `CANVAS`（SR-15-07）

図の高さを内容ごとに自由に決めると、記事に並べたとき図ごとに拡大率が変わり、
同じ 14px の文字が図によって違う大きさで表示される（連作として読めなくなる）。
`svg-builder.cjs` の `CANVAS` が寸法の正本で、**幅は固定・高さは 3 段の階段**から選ぶ。

| 段 | 用途 |
|---|---|
| `sm` | 横一列・帯 |
| `md` | 標準（SR-1-02 の 16:9） |
| `lg` | 縦積み・環状 |

- 必要高から段を選ぶのは `CANVAS.height(needed)`。`lg` でも足りない量は
  段を増やして解決しない。**載せる件数を減らす側**（§2）で解決する。
- 値そのものは書き写さない（正本は `CANVAS` と SR-15-07）。

### 1.6 凡例は「高さを確定してから」置く（SR-15-08）

`NODE_STYLES` を 2 種以上使う図には凡例帯を付ける（白地＋罫の図は、
塗り分けだけでは種別の意味が読者に伝わらないため）。置く場所は
**図の外・下端の水平ストリップ**で、図の中に浮かせない。

確定の順序が契約:

1. `kit.legendHeight(items, 幅)` を呼んで凡例の占有高を求める
2. その高さを足した必要高を `CANVAS.height()` に渡して viewBox 高を決める
3. `kit.legendStrip()` で描く

**理由**: 日本語ラベルは英字の 1.6-2 倍幅になるので 1 行に収まる前提で書くと必ず
折り返す。viewBox 高を先に固定してから凡例を押し込むと、折返しが起きた瞬間に
**D1（はみ出し・error）**を踏む。高さを先に問い合わせておけば、折り返しても
図が失格しない。

## 2. 容量を超える素材は「載せない」

各ビルダーには扱える項目数の上限がある（`svg-builder.cjs` の `CAPACITY`）。
7 件までの `buildHorizontalFlow` に 10 件渡すと、超過分は図から消える。

上限には**入口が 2 つ**あり、どちらを通ったかで超過の扱いが変わる。両方を
知っておかないと「登録し忘れたときに何が起きるか」を読み違える。

| 入口 | 実装 | 上限が無いときの挙動 |
|---|---|---|
| 図種の導出（report 経路の上流） | `render-report.js` の `fitsCapacity` | **fail-closed。その variant を採用しない** |
| ビルダー呼び出し（決定論経路の直呼び） | `svg-builder.cjs` の `guard()` | `cap = 0` で注記が付かない（従来どおり） |

**契約 A（導出側・fail-closed）**: `fitsCapacity` は、上限が
`CAPACITY` にも決定表の `rows[].result.capacity` にも宣言されていない場合、
「無制限」ではなく **不採用** を返す。両方に値があるときは厳しい方を採る。
したがって `CAPACITY` への登録漏れは、**黙って通るのではなくその variant が
選ばれなくなる**（図が 1 枚減り、決定表は次の行へ落ちる）。
以前は `cap === 0` を無制限と読んでいたため、登録漏れが静かに通って
超過分が注記なしで消えた図が出ていた。その穴は塞がっている。

**契約 B（ビルダー側）**: `guard()` は上限内で描いた上で、
超過した件数を「ほか N 件」の注記として図の隅に出す。**黙って捨てない。**
ただし `guard()` 自身は `CAPACITY[name] || 0` を読むので、
**登録が無いビルダーを直接呼ぶと注記が出ない**。これは契約 A のような
fail-closed になっていないため、**新しいビルダーを足したら必ず `CAPACITY` へ
1 行足す**という義務は今も残る。他ビルダーへ委譲する型
（`buildValueStack` → `buildPyramid` 等）は自分では `Math.min` を書かないので
特に漏れやすい。委譲先の上限をそのまま継承する。

上限値は幾何から導く（何件までなら文字が読める幅・高さが残るか）。
色でしか見分けられない図（円グラフ等）はパレットの色数が上限になる。
`CAPACITY` の**最大値**は D11 の複雑度上限の基準でもあるので、
1 つ大きな値を置くと全図の複雑度上限が緩む点に注意する（§4 の D11）。

## 3. ラベルは切り詰めない

図が本文と別のことを言い始める最大の原因は、長い文をラベル用に途中で切ることにある。
日本語は述部が末尾に来るため、途中で切ると否定・条件・留保が落ちて
**図が本文と逆の主張になる**。

`conciseLabel()` の契約:

1. 1 文目だけを候補にする（句点で切る。これは要約でなく選択）
2. 逆接・留保（`ただし` `しかし` `一方` `とはいえ` `ものの` 等）を含むなら **不採用**
3. 28 字を超えるなら **不採用**（切り詰めない）
4. 1 つでも不採用のラベルがあれば、その図の導出自体を中止する

「載る図が減る」のは意図した結果。**被覆率より、図と本文が一致していることを優先する。**

## 4. 機械検査 D0-D28

`python3 scripts/validate-svg-diagram.py --check-grid --strict <file.svg|file.html>`

> **この見出しの範囲は「本節が説明している範囲」であって、検査器が持つ全コードではない。**
> 見出しの数字を検査器へ合わせて書き換える前に、下の表と規則の記述が伸びているか確かめること
> （説明の無い範囲を説明済みと主張してしまう）。符号系 D24-D28（単射性 / 線種語彙 /
> 破線可読性 / 符号供給 / 凡例の真実性）は `references/spec-registry.md` の SR-15-21〜25 が
> 規則の正本で、下の表はその 1 行要約。判定値の正本は `scripts/validate-svg-diagram.py`。

検査コードは **D 接頭辞**（Diagram）。同じ `scripts/` の `validate-report-visual.py` も
C1.. を使うので、**参照するときは `D9` / `validate-report-visual C8` のように出自ごと書く**。

| ID | 検査 | 重大度 |
|---|---|---|
| D0 | SVG として parse できる | error |
| D1 | 図形・文字が viewBox の外へ出ていない | error |
| D2 | 座標に NaN / undefined / Infinity が混入していない | error |
| D3 | `marker-end` / `marker-start` の参照先が同じ SVG 内にある | error |
| D4 | `font-size` が 12px 未満でない（SR-3-05） | error |
| D5 | `<line>` と矢じり付き `<polyline>` は水平か垂直（放射状・チャート型は申告で例外） | warning |
| D6 | 矩形が 4px グリッド上（既定オフ。`--check-grid`） | warning |
| D7 | 強調色の面塗りが 1 図あたり 2 件以下 | warning |
| D8 | `<text>` に Font Awesome の PUA コードがない（SR-3-06） | error |
| D9 | `stroke-width` が 1.25 以上（`0` は対象外） | warning |
| D10 | 色がパレット由来で、純黒でない | warning |
| D11 | 1 図の要素数（ノード相当＋コネクタ）が複雑度上限以内 | warning |
| D12 | `<script>` / 外部 http(s) 参照 / 外部フォントが無い | **error** |
| D13 | `font-family` が既定スタック内 | warning |
| D14 | CSS 図解の間隔・px 寸法がトークン/4px刻みに従う | warning |
| D15 | 注釈・凡例・ノード・コネクタ・フォント階層が複雑度予算内 | warning |
| D16 | CSS 図解の accent 要素が焦点予算内 | warning |
| D17 | `<path>` の直線セグメントが斜めでない | warning |
| D18 | 文字が viewBox に収まる / ラベル箱に収まる（§D-8） | **error** / warning |
| D19 | コネクタが箱の辺と共線で溶けていない | warning |
| D20 | 別コネクタの直線区間が重なっていない | warning |
| D21 | コネクタが無関係な箱の内側を貫いていない | warning |
| D22 | 1 ファイル内で SVG の `id` が重複していない（SR-15-20） | **error** |
| D23 | 文書内参照の参照先が自分の SVG か共有 defs にある（SR-15-20） | **error** |
| D24 | 呼び分けた 2 系列が同じ（塗り, 線色, 線幅, 線種）の組へ落ちていない（SR-15-21） | warning |
| D25 | `stroke-dasharray` が実線 / `4 3` / `12 4` の語彙内にある（SR-15-22） | warning |
| D26 | 破線が走る最短辺に 3 周期分の長さがある（SR-15-23） | warning |
| D27 | 線種を運べない細い図形だけの図が塗りの供給 4 段を超えて要求していない（SR-15-24） | warning |
| D28 | 凡例の見本が語る符号（塗り, 線色, 線種）が図の中に実在する（SR-15-25） | warning |

D22 / D23 は 1 ファイルを丸ごと見る `check_document()` の担当で、SVG を 1 つずつ見る
`check_svg()` では原理的に捕まらない（同名 `id` を持つ 2 つの SVG は、単体ではどちらも
正しい）。対象は `arrow-*` に限らず `id` 全般。`marker-*` の参照は D3 の担当なので
D23 では重ねて見ない。`<svg width="0" height="0">` のような**描画物を持たない共有 defs
置き場**への参照は、面の切替に影響されないので正当として黙る。

D23 が見る参照は `url(#id)` だけではない。`aria-labelledby` / `aria-describedby` /
`href="#id"` は **id をそのまま書く形の参照**で、これも文書内で最初に現れる id へ
解決する。絵が変わらないので目視では気付けないが、`<title id="title">` を各図が
同じ名前で持つと**後ろの図の読み上げが全て先頭の図の説明になる**（2026/8 にブログ
記事で実在。4 つの図が `aria-labelledby="title desc"` を共有していた）。
ただしこの形の参照は SVG の外の見出しを指すことが正当にあり、`check_document()` は
SVG しか受け取らないためその定義を見られない。よって **「別の SVG にしかない」時だけ
出し、「どこにも無い」時は黙る**（`url(#...)` には SVG 外を指す正当な用途が無いので、
そちらは「どこにも無い」でも出す）。

未登録の検証 ID は **fail-closed で error**（重大度の指定漏れを黙って通さない）。
通常モードは診断用で、exit 0 = error 0 件。出荷経路は必ず `--strict` を使い、
warning も失格扱いにする（prompt / postgen hook / workflow-manifest の共通契約）。

### D0-D9 と D10-D13 の別（幾何 / 素材）

D0-D9 は**幾何と可読性**（どこに何があるか）を見る。D10-D13 は**素材**
（何で描かれているか＝色・書体・密度・外部依存）を見る。素材の検査が別に要るのは、
ビルダー関数の入口にある上限やトークン表は**決定論経路にしか効かず**、
agent が SVG を直接書く LLM 経路を素通りするため。契約は「どちらの経路でも
同じ契約で採点する」と宣言している以上、素材も成果物側で見直す必要がある。

### D10-D13 の判定値はどこから来るか（検査器へ二重に書かない）

**この 4 検査は許可集合・上限を検査器へ写経していない。**
実装ファイルから実行時に正規表現で抽出する（`lint-contract-drift.py` の
`_load_thresholds` と同じ手口）。値の正本を 1 つに保たないと、
パレットを差し替えた日に**検査器だけが古い色を許し続ける**。

| ID | 検査 | 重大度 | 判定値の出どころ |
|---|---|---|---|
| D10 | パレット逸脱＋純黒 | warning | `svg-kit.cjs` の `TOKENS` / `SERIES` ブロック内の hex を実行時抽出。`url(#...)` と、色リテラルを 1 つも含まない CSS 変数参照は素通し（解決先はテーマ側の責務）。純黒だけは許可集合に入っていても常に指摘する |
| D11 | 図の複雑度上限 | warning | `svg-builder.cjs` の `CAPACITY` の**最大値**を実行時抽出し、`COMPLEXITY_FACTOR`（検査器側の係数）倍したものが上限。密度が語彙である型（ガント・年表・マトリクス・散布図・D3 等）は `COMPLEXITY_RELAX` 倍まで緩める |
| D12 | 外部依存（`<script>` / 外部 http(s) / `@import` / 外部フォント） | **error** | 抽出元なし（構文パターンのみ）。走査範囲は SVG 断片の中だけ |
| D13 | `font-family` ホワイトリスト | warning | `svg-kit.cjs` の `textBlock` の既定フォントスタック（`o.family || "..."` の 1 行）を実行時抽出。総称ファミリ（`sans-serif` 等）は常に許可 |

抽出に失敗した検査は「見なかったこと」にせず、1 度だけ warning で
「抽出できないため検査できない」と告げる。検査器が黙って素通りするより、
vendor が壊れている事実を出した方がよい。

**D11 の上限の考え方**: `CAPACITY` の最大値を N とすると、1 図の要素は
ノード本体 N ／ ノード付属図形 N ／ コネクタ N ／ 付随ラベル・凡例 N の 4 群に
分かれるので上限は 4N。決定論経路で描ける最も密な図はこの中に収まるので、
**ビルダーが描ける図は必ず通り、それを超える密度（＝ LLM が直接書いた過密な図）
だけが引っ掛かる**。ノード相当の数え方（文字と重なる `rect` / `circle`）は
近似なので warning に留めてある。

**D13 が可読性でなく計算前提の話である理由**: 書体が変わると字幅が変わり、
`svg-kit` の `charWidth` 近似を前提にした `fitText` / `wrapText` の収まり計算が
そのまま外れる。実害は「1 行の収まりが少しずれる」であり図が読めなくなる訳では
ないので warning。

### `SEVERITY` 表に無い 9 コードは設計（登録漏れではない）

`validate-svg-diagram.py` の `SEVERITY` 表は **15 コードしか持たない**
（D5, D6, D7, D9, D10, D11, D13, D14, D15, D16, D17, D18, D19, D20, D21 ＝ すべて warning）。
残る **9 コード（D0, D1, D2, D3, D4, D8, D12, D22, D23）は意図的に未登録**で、
`_sev()` の `SEVERITY.get(code, "error")` により fail-closed で error になる。

この 9 件はいずれも「誤検知の余地がなく、直さないと図が読めない・消える」もので、
error 以外の重大度を選ぶ余地がない。

| コード | 未登録のまま error にしている理由 |
| --- | --- |
| D0 | SVG として解析できない（図が 1px も描かれない） |
| D1 | viewBox はみ出し（通過点だけで測るため検出漏れ側。拾えた時点で本物） |
| D2 | `NaN` / `undefined` / `Infinity` 混入（その属性を持つ図形が消える） |
| D3 | `marker` の参照先が未定義（矢じりが消える） |
| D4 | 最小フォント違反（SR-3-05 の明文規則） |
| D8 | Font Awesome の PUA（SR-3-06。CDN 未ロードで文字が全部消える） |
| D12 | 外部依存（D8 と同根拠。CDN が落ちた瞬間に図が消える） |
| D22 | 文書内で `id` が重複（後の面の `url(#...)` が隠れている面を指し、矢じりが消える） |
| D23 | 文書内参照（`url(#...)` / `aria-labelledby` / `href="#id"`）の参照先が自分の SVG にも共有 defs にも無い（D3 と同根拠） |

つまり **「未登録経路を通る検査」は 9 件あり、D12 だけがその機構の
生きた検証だという説明は成り立たない**（かつてこの節はそう書いていたが、
実測すると未登録は複数件あった）。fail-closed 機構は D0-D4 / D8 / D12 /
D22 / D23 の検査が走るたびに常時使われている。

ただし「未登録」は書き忘れと区別が付かない。そこで検査器は
`ERROR_BY_DESIGN = frozenset({"D0","D1","D2","D3","D4","D8","D12","D22","D23"})` で
意図的な未登録を宣言し、`--self-test` が次の 2 点を機械検証する。

1. `ALL_CODES`（検査器が持つ全コードの正本）が `SEVERITY` か `ERROR_BY_DESIGN` の
   いずれかに属する（新しい検査を足したら重大度の選択を必ず一度は明示させる）。
   ここに範囲を数字で書かない——検査が増えた日に、この行だけが古い範囲を主張する
2. 両者が交差しない（「明示 warning」と「意図的な未登録 error」の二枚舌を禁じる）

`_sev()` はこの宣言集合を参照しない。既定値は `SEVERITY.get(code, "error")` の
ままであり、`ERROR_BY_DESIGN` は分岐ではなく宣言である。分岐にすると
fail-closed の既定が「この表に載っているものだけ error」へ弱まり、
書き忘れが再び静かに見逃されるようになる。

> **後任への注意**: 上記 9 コードへ `SEVERITY` の行を足さないこと。挙動は
> 同じだが、`ERROR_BY_DESIGN` との交差検査が落ちる。重大度を warning へ
> 変えたいときだけ、`ERROR_BY_DESIGN` から外して `SEVERITY` へ移す。

### D1 の測り方と、意図的な検出漏れ

D1 は要素の概算 bbox を viewBox と突き合わせる。実装上、次の 2 つは
**わざと見逃す側へ倒している**（error 級のゲートで偽陽性を出すと、
開発者が検査ごと無効化する動機を作るため）。

- **曲線の膨らみ**: `<path>` は通過点（`M`/`L`/`C`/`A` の終点）だけで測り、
  制御点や円弧の外側へのふくらみは含めない。`A rx ry rot large sweep x y` の
  7 引数のうち座標は末尾 2 つだけで、全数値を 2 個ずつ刻むと `rx ry` が
  座標に化けて偽の「はみ出し」になる。
- **ローカル座標系**: `<defs>` `<marker>` `<symbol>` `<clipPath>` `<pattern>` `<mask>`
  の中身は親の viewBox と無関係な座標系なので対象外。矢じりの `<polygon>` は
  `MARKER`（SR-15-05）が定める自前の座標系で書かれており、はみ出しではない。

許容誤差は `BLEED_TOLERANCE = 2.0`（丸めの 1px 差で落とさない）。
フォント実測の字形差など、実描画でしか分からない項目は
`ui-quality-reviewer` / `validate-report-layout.js` の責務として残る。

**この除外は D1 だけのもの**。D10-D13 はローカル座標系の入れ物も含めて
SVG 全体を走査する。除外の理由は「座標系が親と別物だから幾何を測れない」で
あって素材の除外理由ではなく、`<marker>` の塗りも `<pattern>` の色も
パレット内であるべきだし、`<defs>` の中に `<script>` や外部 `<image>` を
隠されたら危険度は同じだからである。

## 5. 定数の二重管理を検出する

同じ値が実装と検査／仕様書の両方にあるもの（`STROKE.hairline` ↔ `MIN_STROKE_WIDTH`、
`MARKER.refX` ↔ SR-15-05 等）は、片方だけ変わると検査が沈黙するか、
仕様書が黙って嘘になる。`scripts/lint-contract-drift.py` の検査 F
（`_CONSTANT_PAIRS`）が両ファイルから値を抽出して突き合わせるので、
**値を変えるときは両方直す**。

**新しく数値を書くときの判断**: この契約文書や spec-registry に実装の数値を
書き写すなら、その値は必ず `_CONSTANT_PAIRS` へ対として登録する。
登録しないまま書き写した数値は、次に実装が動いた瞬間に誰にも気付かれずに
嘘になる。**登録できないなら書かない**（正本の名前だけを書いて値は書かない）。

## D-1. 4px グリッド（座標・寸法・間隔）

**SVG の user unit で表される座標・寸法・間隔・角丸は、すべて 4 の倍数にする。**
正本の刻み幅は `vendor/scripts/svg-kit.cjs` の `GRID` で、丸めは `kit.snap()` が行う。
決定論経路の `LAYOUTS` 各関数は内部で `snap` を通すので自動的に満たす。

なぜ非交渉か: 図解は複数枚が同じ成果物に並ぶ。刻みが揃っていない図は、
1 枚だけ見れば気付かないが、並べた瞬間に「行が揃っていない」として認識される。
揃えるための労力を毎回払うより、刻みを 1 つに固定して考えなくて済ませる方が安い。

### 許可値

| 対象 | 許可値 | 備考 |
|---|---|---|
| 座標（x / y） | `GRID` の倍数 | `kit.snap()` を通す |
| ノード幅 | 80 以上 320 以下の `GRID` 倍数 | 320 を超えるノードは 1 ノードに 2 つの概念が入っている |
| ノード高 | `GRID` の倍数 | 高さは `kit.autoBlockHeight` に委ねる |
| 要素間ギャップ | 20 / 24 / 32 / 40 / 48 | この 5 段以外を作らない。段を増やすと「なぜここだけ違うのか」が読者に問われる |
| 内側パディング | 8 / 12 / 16 | 3 段のみ |
| 角丸（rx / ry） | 4 / 6 / 8 | 小タグ / ノード / コンテナ。0（角丸なし）も可 |

### グリッドの適用外

- **フォントサイズ**: 正本は `svg-kit.cjs` の `MIN_FONT` / `MIN_FONT_SMALL` で、
  `MIN_FONT` は 4 の倍数ではない。日本語の字面率は欧文と違うため、
  可読性の下限がグリッドより優先される。**フォントは grid 適用外**とする。
- **線幅**: 正本は `kit.STROKE`（§1.1）。0.25 刻みの階層なので grid 適用外。
- **不透明度**: `NODE_STYLES` の 0.02 / 0.03 / 0.05 / 0.10 / 0.14 / 0.20 / 0.30 / 0.50。
- **CSS 側（HTML/CSS 図解）**: px ではなく `style-builder.cjs` の `SPEC.spacing`
  9 段（`--space-1` … `--space-9`）を使う。slide の `html` は `font-size: 1vw` なので
  rem は画面幅に比例し、px グリッドという概念自体が成立しない。
  **CSS 図解のグリッドは「`--space-*` 以外の間隔値を書かない」と読み替える。**

検査 owner: **D6**（既定オフ・`--check-grid` で有効化・warning／SVG のみ）。
CSS 図解側の `--space-*` 逸脱は D14 系の新設検査（第 4 次 update の R6 で設計）。

## D-2. 複雑度予算（21 項目）

**目標密度は 4/10。** 技術的に成立する最小限より少し足りないくらいで止める。
9 ノードを超えたら、それはたいてい 2 枚の図である。

決定論経路の件数上限の正本は `svg-builder.cjs` の `CAPACITY` 系（§2）であり、
本表はそれと**競合しない**。`CAPACITY` は「そのビルダーが描ける物理的上限」、
本表は「読者が 1 枚から読み取れる認知的上限」で、**厳しい方が勝つ**。
LLM 手書き経路には `CAPACITY` が効かないので、実質この表だけが上限になる。

| # | 対象 | 上限 | 超えたときの正しい対処 |
|---|---|---|---|
| 1 | ノード総数 | 9 | 概要図と詳細図に分割する |
| 2 | コネクタ総数 | 12 | 自明な関係の線を消す（配置で分かる関係に線は要らない） |
| 3 | `accent` の面塗り | 2 | 主張が複数ある。スライドなら 1 スライド 1 メッセージ違反 |

| 8 | 1 エンティティのフィールド数 | 6 | 主キー＋論点に関わる列だけ残す |

| 10 | ツリーの 1 親あたり子数 | 5 | 中間ノードを挟む |
| 11 | ベン図の集合数 | 3 | 4 集合の楕円ベンは領域が読めない。マトリクスへ替える |
| 12 | レーダーの軸数 | 5 | 軸を統合する。6 軸以上は形が読めない |

## D-3. コネクタ 5 原則

§1.4 の入射規則は「どの辺へどの向きで当てるか」を規定した。本節はその手前、
**「終点までの経路をどう引くか」**を規定する。両方を満たして初めて線が読める。

### 原則 1: 直交エルボー（斜め線禁止）

軸に平行なセグメントと、その接続部の角丸だけで経路を作る。
**角丸半径は 8**（`radius-lg` と同値）。斜めのセグメントを引かない。

- 決定論経路は `kit.safeElbow()` / `kit.trunkPaths()` が満たす。
- 例外は 2 つだけ。(a) 放射状型（マインドマップ・星形・環状）は
  中心からの直線が語彙なので申告により D5 の対象外。
  **「対象外」は無出力を意味する**（warning へ降格ではない。契約が正しいと
  認めたものを毎回読ませると、本当の逸脱がその中に埋もれるため）。
  (b) `kit.overArcPath` の昇格弧（隣接カードの上辺どうし）。
- 斜め線が要ると感じたら、それは**ノードの配置が間違っている**。
  線の形ではなく配置を直す。

検査 owner: **D5**（`<line>` の水平/垂直・warning）。
`<path>` の斜めセグメント検出は D14 系の新設検査（第 4 次 update の R6）。

### 原則 2: ラベルは線から 6-10px 離し、マスクを敷く

コネクタのラベルは線に触れさせない。**線とラベル外形の間隔は 6 以上 10 以下。**
線を跨ぐ位置に置くときは `paper` 塗りのマスク矩形を必ず下に敷く
（マスク無しのラベルは線が文字を貫通して読めない）。

- 間隔の基準は `kit.LABEL_GAP`（正本）。上の 6-10 はその周辺の許容幅である。
- `kit.arrowLabel()` / `kit.overArcApex()` はマスクを既定で敷く。
  `mask: false` を明示したときだけ外れる。
- 縦書き（`writing-mode`）でラベルを置かない。

### 原則 3: 交差は bridge 弧、並走は 12px 離す

- **交差**: 避けられない交差では、上を通る線に小さな跨ぎ弧を入れる
  （`a 8,8 0 0,1 16,0` 相当）。交差点をそのまま重ねると、読者が
  どちらの線を追っているか見失う。
- **並走**: 同じ向きへ並んで走る 2 本以上のコネクタは**中心線間 12px 以上**離す。
  12px は矢じりの開き（`MARKER.h`）を跨いで 2 本が別物と読める最小距離である。
- 2 本のコネクタが完全に同じ経路を通ることを許さない。
  同じ経路なら 1 本にまとめてラベルを併記する。

### 原則 4: 同一辺の接続点は扇状に分散する

1 つの辺に N 本の矢を取り付けるとき、辺長 L に対して
**k 番目（1-indexed）の接続点は辺の始点から `L * k / (N + 1)`** に置く。
辺の中央へ全部を集めない。

- 決定論経路は `kit.fanAttach()` がこの式を実装している。
- 収容可能本数は `kit.fanCapacity(辺長)` で先に確認する
  （最小間隔は `kit.FAN_MIN_GAP` = `snap(MARKER.h * STROKE.primary)` から導出。
  新しい定数ではない）。
- 収まらない本数は**載せない**（§2 と同じ判断）。矢じりが重なった束は
  黒い塊になり、何本あるのかすら読めない。

### 原則 5: 箱の裏を通さない

コネクタは、始点でも終点でもないノードの上を通過しない。
迂回できないなら、それは配置の問題である（ノードを動かす）。

- どうしても避けられない中継ノードがある場合に限り、
  通過区間を破線（`4,3`）にして「これは通過であって接続ではない」と明示する。
  この免除は 1 図あたり 1 本まで。
- 通過を許した線は、通過ノードとの接触点にマスクを敷かない
  （マスクを敷くとノードが欠けて見え、通過ではなく破損に見える）。

## D-4. R9 溶け込み契約（成果物の中で図が浮かない）

> **本節が第 4 次 update の最重要項目。**
> §1-§5 と §D-1-§D-3 は「図解 1 枚の内部品質」を規定した。
> しかし本プラグインの図解は**単体で存在しない**。スライドの 16:9 の面の中、

### D-4-1. 占有率（数値契約）

| # | 対象 | 範囲 | 測り方 |
|---|---|---|---|
| R9-1 | スライド面内の図解ブロック面積比 | 40% 以上 70% 以下 | `.slider__item` の padding 内側（本文領域）に対する図解ブロックの面積比 |
| R9-2 | スライド面内の図解 1 枚あたり | 1 スライド 1 図解 | 2 枚以上は 1 スライド 1 メッセージ違反 |
| R9-3 | レポート図版ブロックの高さ | 読書 viewport 高の 60% 以下 | 図版がスクロール 1 画面を占有すると本文の流れが切れる |
| R9-4 | レポート 1 節あたりの図解数 | 1 以下 | `validate-report-visual.py` の C2（1 項目 1 ビジュアル）と同義 |
| R9-5 | レポート本文幅に対する図版幅 | 100%（本文幅と同じ）または 100% 超の全幅（`figure` の bleed）の 2 択 | 中途半端な 70% 幅は本文の左揃えを乱す |
| R9-6 | 図解内の実効フォントサイズ | 周囲本文の 0.7 倍以上 1.0 倍以下 | SVG は縮小表示される。`viewBox` 幅と実表示幅から実効倍率を出して掛ける |

R9-1 の下限が 40% なのは、それより小さい図は「あってもなくても同じ」だからである。
40% を割るなら、図をやめて 1 文で書く方が読者に親切である。
上限が 70% なのは、それを超えると本文が図のキャプションに見えてしまい、
主従が逆転するためである。

### D-4-2. 重複禁止（数値契約）

**図が語ることを本文が繰り返さない。図は本文の代替ではなく補強である。**

| # | 規約 | 上限 |
|---|---|---|
| R9-7 | 図解のラベル文字列が、図の直近本文（前後各 1 段落）に**完全一致で**現れる件数 | 1 件以下 |
| R9-8 | 図解のラベル群と直近本文の間の 2 文字以上の名詞の重複語数 | 図のラベル総語数の 40% 以下 |
| R9-9 | キャプション（`figcaption` / スライドの図解リード）の文字数 | 40 字以上 120 字以下 |
| R9-10 | キャプションが図のラベルをそのまま含む件数 | 0 件 |

R9-7 が「0 件」でなく「1 件以下」なのは、**参照のための 1 語は必要**だからである。
本文が図の中の 1 要素を名指しして「この工程が律速である」と書くのは正しい接続で、
図の全ラベルを本文が並べ直すのが冗長なのである。

R9-9 の下限が 40 字なのは、「図 1: 業務フロー」のような命名だけのキャプションを
禁じるためである。キャプションには**図が語れないこと**を書く:
なぜこの図を見るのか、どこから読むのか、何が結論か。

R9-10 は、キャプションが図のラベルを繰り返すと、読者が図とキャプションを
2 回読んで同じ情報しか得られない状態を防ぐ。

### D-4-3. 文脈適合（数値契約）

**図解の密度・トーンが周囲と連続する。** 単体で豪華な図はページ内で浮く。

| # | 規約 | 基準 |
|---|---|---|
| R9-11 | 図解内の色数（`ink` / `muted` / `soft` / `rule` を除く有彩色の種類） | 周囲の面が使っている有彩色の種類数 + 1 以下 |
| R9-12 | 図解の余白（外周パディング）と周囲本文の段落間余白 | 同じ `--space-*` 段から選ぶ（新しい間隔を作らない） |
| R9-13 | 図解の角丸と周囲のカード UI の角丸 | 同じ 3 段（4 / 6 / 8）から選ぶ |
| R9-14 | 図解の影 | **常に 0**（周囲本文が影を持たないため。style-tokens §5） |
| R9-15 | 図解の書体 | `--font-base` / `--font-mono` のみ。成果物が使っていない書体を図解だけが持ち込まない |

R9-11 の「+1」は焦点色（`accent`）1 色分である。周囲が無彩色の本文だけなら
図解が持てる有彩色は 1 種類、すなわち `accent` のみになる。系列色 5 色を使う図は、
そもそも周囲が系列色を使っている文脈（データ章）でしか許されない。

### D-4-4. 配置と型の接続

`visual-strategist` が決める面内配置（`zones` / `readingOrder` / `focalPoint`）と、
図解の型は**独立に決められない**。型ごとの推奨配置は
`references/diagram-type-crosswalk.md` の「推奨配置」列が持つ。

原則:

- **横長の型**（横フロー・シェブロン・ガント・年表・スイムレーン）は
  面の上半分または下半分の帯に置く。左右分割の片側に押し込まない（横幅が尽きる）。
- **正方形に近い型**（環状・ベン・レーダー・マトリクス・ピラミッド）は
  左右分割の片側に置ける。全幅に伸ばすと余白が間延びする。
- **縦長の型**（縦フロー・縦年表・積層・組織図）は左右分割の片側に置く。
  全幅に置くと 1 段あたりの横幅が過剰になる。
- `focalPoint`（面内で最初に視線が落ちる点）と図解の `accent` 要素は
  **一致させる**。別々の場所にあると視線が 2 回移動して読み順が壊れる。

## D-5. annotation（注釈）の文法

図の中に「編集者の声」を 1-2 個だけ置ける。これは図の要素ではなく、
図に対する**注記**である。だから図の語彙（箱・線・ラベル）と見分けが付く形にする。

| 要素 | 規約 |
|---|---|
| 書体 | `--font-base` の**イタリック**。ノードラベルと同じ立体で書かない |
| サイズ | `MIN_FONT` と同値（`svg-kit.cjs` が正本）。ノードラベルより大きくしない |
| 色 | `soft`（`diagram-style-tokens.md` §1） |
| リーダー線 | 破線（`4,3`）・線幅 `STROKE.hairline`・直線または緩い 1 次ベジェ |
| 指示点 | リーダー線の指示側の端に半径 2 のドット。矢じりを付けない |
| 個数 | **1 図あたり最大 2**（複雑度予算 #4） |
| 配置 | **図の余白部分のみ。** ノードや線の上に重ねない。マスクを敷いてまで置かない |

矢じりを付けない理由: 注釈は図の中の流れではないので、
矢印にするとコネクタと同じ語彙になり「これも工程か」と誤読される。
ドットは「ここを指している」だけを言い、方向を語らない。

3 つ目の注釈が要ると感じたら、それは本文へ書くべき内容である。
図の中の注釈は「図を見ただけでは分からないが、本文へ書くほどでもない」
一言のためにある。

検査 owner: 個数は D14 系の新設検査（`font-style="italic"` の `<text>` 数）、
配置と内容は LLM チェックリスト。

## D-7. CSS/HTML 図解の検出規約（D14 系の走査対象）

D0-D13 は `<svg>` 断片しか抽出しないので、**div と span で組んだ図解**は
1 件も検査に掛からずに素通りしていた。決定論経路は `render-slide.cjs` の
テンプレートに守られるが、agent が HTML を直接書く経路には何の防具も無い。
D14 系はこの系統を見る。**検査対象を見つけられなければ検査は存在しないのと同じ**
なので、何を図解と見なすかを規約として固定する。

### 標識（どちらか 1 つで図解ブロックと見なす）

| # | 標識 | 出どころ |
|---|---|---|
| 1 | `data-v8-diagram="<variant>"` 属性 | `render-slide.cjs` が図解スライドの `.slider__item` へ付ける（決定論経路の正規標識） |
| 2 | `class` に `diagram-` / `slide-diagram-` / `chart-` / `d3-` で始まるトークン | 手書き経路の慣用。`style-builder.cjs` の CSS もこの語彙で当たっている |

### 走査の規則

- **入れ子は外側 1 件へ畳む。** `.diagram-legend` は図解ブロックの部品であって
  独立した図解ではない。外側を 1 図として数えないと複雑度予算が図の数だけ薄まる。
- **`<svg>` しか中身が無いブロックは返さない。** D0-D13 が既に見ている。
  ブロックの中身（開始タグ自身を除く）から `<svg>…</svg>` を落として、
  なお `div` / `span` / `p` / `ul` / `table` / `figure` 等の器が残るものだけを対象にする。
- **`<script>` / `<style>` の中身は同じ長さの空白へ潰してから走査する**（`extract_svgs` と同じ理由）。

### D14 系の ID 割り当て

| ID | 見るもの | 対象 | 数値の正本 |
|---|---|---|---|
| D14 | 間隔が `--space-*` 由来か・px 寸法が刻みの倍数か（§D-1） | CSS 図解 | `svg-kit.cjs` の `GRID` / `style-builder.cjs` の `SPEC.spacing` |
| D15 | 注釈・凡例・ノード/コネクタ・フォント階層の件数（§D-2 #1/#2/#4/#20/#21） | CSS 図解 + SVG | 本章 §D-2 の表（実行時にパースする） |
| D16 | `accent` ロール色を持つ要素数（§D-2 #3・D7 の CSS 版） | CSS 図解 | `svg-kit.cjs` の `TOKENS.accent` / `accentTint` |
| D17 | コネクタ `<path>` の斜め直線セグメント（§D-3 原則 1・D5 の path 版） | SVG | — |
| D19 | コネクタの直線区間が箱の辺と共線（線が枠へ溶ける） | SVG | — |
| D20 | 別々のコネクタの直線区間が共線で重なる（本数が読めない） | SVG | — |
| D21 | コネクタの直線区間が箱の内側を貫く（無い経路を読ませる） | SVG | — |
| D22 | 文書内で `id` が重複する（面をまたいで `url(#...)` が吸われる） | ファイル全体 | — |
| D23 | 文書内参照（`url(#...)` / `aria-labelledby` / `href="#id"`）の参照先が自分の SVG にも共有 defs にも無い | ファイル全体 | — |

D15 が §D-2 の表を**実行時にパースする**のは §5 の帰結である。この章が正本を持つ
数値を検査器へ写せば、表を直した日に検査器だけが古い上限で採点し続ける。
表の形（`| # | 対象 | 上限 | … |` の 4 列）を変えるときは、抽出が空になって
「検査できない」warning が出るので気付ける。

D17 が直線セグメントだけを見て曲線・円弧を見ないのは、`C` / `S` / `Q` / `A` を
§D-3 原則 1 と原則 3 が語彙として認めている（bridge 弧・昇格弧・放射状）ためである。
**斜めの直線だけが「配置が間違っている」の兆候**なので、そこへ絞って検出漏れ側へ倒す。

## D-8. 文字量と図解サイズの依存関係

図解の中に文字が収まらなければ、その図は何も伝えていない。
**図解サイズと文字量は独立に決められない**。片方を決めたらもう片方は従属する。

### 目安式（CJK ラベル）

```
収容可能な全角文字数 ≈ (箱幅 − 16px) / font-size
```

16px は左右の内側余白（各 8px）。半角英数は全角の約 0.5-0.66 倍の幅なので、
同じ箱に約 1.5-2 倍入る。正確な字幅は `svg-kit.cjs` の `charWidth()` が正本で、
`fitText` / `wrapText` / D18 はすべてこの 1 つの関数を見ている
（検査器へ字幅表を書き写すと、ビルダーが「収まる」と判断した図を
検査器が「溢れる」と言い出す食い違いが起きる）。

例（font-size 14px の箱）:

| 箱幅 | 収容可能な全角 |
|---|---|
| 96px | 約 5 文字 |
| 160px | 約 10 文字 |
| 240px | 約 16 文字 |

### 収まらないときの優先順

1. **ラベルを短くする。** 図に載せるのは要約ラベルであって説明文ではない。
2. **箱を広げる / canvas を 1 段大きくする**（`CANVAS.height` の sm→md→lg）。
3. **2 行に折り返す**（行数上限 2。3 行以上は図ではなく本文で書くべき内容である）。

**`font-size` を 12px 未満へ縮めて収めるのは禁止**（SR-3-05 / D4 と整合）。
「小さくすれば入る」は、読めない図を作って収まったことにする操作である。

### 入力の意味内容が長文のとき

図に載せるのは要約ラベルとし、全文は本文へ置く（R9 溶け込み契約 §D-4-2 と整合）。
図が語れることは図に任せ、図が語れないことを本文が書く。長い原文をそのまま
図へ流し込むと、§D-4-2 の重複禁止と本章の収容の両方を同時に破る。

### 機械検査

**D18** が 2 段構えで見る。

| 段 | 見るもの | 重大度 | 根拠 |
|---|---|---|---|
| canvas 収容 | 文字の水平/垂直範囲が viewBox の外（許容 4px）へ出ていないか | **error** | 確実に切れて読めない |
| 箱への収容 | 文字を含む最小の `<rect>` に対し 推定幅 > 箱幅 − 16px でないか | warning | 「最小の矩形がラベル箱」は近似 |

箱の判定から除くもの:

- **不透明マスク**（`TOKENS.paper` 塗り・輪郭なし）。`arrowLabel` のマスクは
  文字幅 + 12px の密着した白地であって、余白を持つラベル箱ではない。
- **背景板**（viewBox 面積の 8 割以上を覆う矩形）。
- `transform` の下にある要素（属性値から実際の描画位置を測れないため）。

D18 の較正は「既存ゴールデンで誤検知 0」と
「意図的に溢れさせた図を必ず捕まえる」の両側から縛る。後者は
`validate-svg-diagram.py --self-test` が保持する。

### 13.1 縦棒グラフ（Bar Chart）

カテゴリ間の量の大小を、棒の高さひとつだけで比べさせる図。

**いつ選ぶ**:
- 同一系列の値をカテゴリ横断で比較したいとき
- 時系列でも「点の推移」ではなく「各期の量」を見せたいとき
- 焦点にしたいカテゴリが 1 つに絞れているとき

**いつ選ばない**:
- カテゴリ名が長い / 件数が多い → §13.2 横棒グラフ
- 各カテゴリの内訳も同時に見せたい → §13.3 積み上げ棒グラフ
- 連続的な推移そのものが主張 → §13.4 折れ線グラフ

**データ契約**:
- 系列数: 1（複数系列を色で塗り分けると比較ではなく分類の図になる）
- カテゴリ数: ゴールデンは 5 件。上限 8（`CAPACITY.buildBarChart`）
- 軸・単位: Y 軸は 0 基線必須。`scale` に `min` / `max` / `ticks` を明示し、系列に `unit` を持たせる
- 強調: `emphasis.focal` は 1 本のみ。他の棒は単色の背景として残す

**必須情報**: Y 軸の単位と桁（`件`・`百万円`）を軸ラベルとして軸の上端に、最小値・最大値・目盛を軸上に、集計定義と時点を年込みで図の下端 1 行に書く（`2026年度・受注ベース`）。0 起点を切る場合は軸の折れ目に `0 起点ではない` と図内へ明記する。figcaption に置いたものは無いものとして扱う。これらが欠けると、棒の高さの差が実際の差の何倍に誇張されているかを読者が確かめられない。

**配置**: 方形

ゴールデン実例: skills/run-slide-report-generate/examples/diagram-goldens/bar-chart-{input.json,golden.html}

### 13.2 横棒グラフ（Horizontal Bar Chart）

順位のついた項目を、帯の長さの差で読ませる図。

**いつ選ぶ**:
- 項目名が長く、縦棒では軸ラベルが折り返すとき
- 「1 位と 2 位の差」そのものが結論であるとき
- アンケート回答率など、項目間に順序をつけて並べたいとき

**いつ選ばない**:
- 時系列の推移 → §13.4 折れ線グラフ（横軸を時間に使うべき）
- 全体に対する構成比 → §13.5 円グラフ

**データ契約**:
- 系列数: 1。項目ごとの塗り分けはしない（順位ではなく分類に見える）
- 項目数: ゴールデンは 6 件。上限 8（`CAPACITY.buildBarChart`）
- 軸・単位: `scale` に `min` / `max` / `unit` に加え、値が何の割合かを示す `basis` を持たせる
- 並び順: `sort` を明示（ゴールデンは「値の大きい順」）
- 値ラベル: 帯が短い項目は帯の外に置く

**必須情報**: 各帯の値と単位を帯の右端に、母数 n と単一回答か複数回答かの別を図の下端 1 行に（`n=312・単一回答`）、並び順の基準を見出しの右端に（`値の大きい順`）書く。割合を示す場合、n と回答方式は省略しない。複数回答で合計が 100% を超えるなら、その旨も同じ行に書く。これらが欠けると、上位項目の差が母数の小ささから来る揺れなのかを読者が判断できない。

**配置**: 方形

ゴールデン実例: skills/run-slide-report-generate/examples/diagram-goldens/hbar-chart-{input.json,golden.html}

### 13.3 積み上げ棒グラフ（Stacked Bar Chart）

総量の推移と、その総量を作っている内訳の厚みを同時に見せる図。

**いつ選ぶ**:
- 総額は伸びているが、伸びの源がどの層かを言いたいとき
- カテゴリ（期）ごとに同じ内訳区分が繰り返されるとき
- 内訳の絶対量が意味を持つとき（比率だけなら §13.5）

**いつ選ばない**:
- 内訳が不要で総量だけを比べる → §13.1 縦棒グラフ
- 1 時点の構成比だけを示す → §13.5 円グラフ
- 各層の推移を個別に追わせたい → §13.4 折れ線グラフ

**データ契約**:
- 系列（積み上げ段）数: セグメント数は 4 以下（§15.2）。ゴールデンは 3 段
- カテゴリ数: ゴールデンは 4 件（Q1-Q4）。上限 8（`CAPACITY.buildBarChart`）
- 軸・単位: `scale` に `min` / `max` / `unit` / `ticks`。0 基線必須
- 凡例と `stackOrder`（下から何を積むか）を必ず持たせる
- 強調: 焦点は系列全体ではなく 1 区画のみ。塗りは系列色のまま、accent は枠で重ねる

**必須情報**: 各段が何かを示す凡例を図内に、Y 軸の単位と桁を軸ラベルに、各カテゴリの合計値を棒の上端に書く。構成比を積むなら母数 n を各棒の直下に（`n=…`）、単一回答か複数回答かの別を図の下端 1 行に書く。カテゴリの時点は年込みの絶対表記にする（`2026 Q1`）。合計値が図に無いと、総量が伸びたのか内訳が入れ替わっただけなのかを読者が切り分けられない。

**配置**: 方形

ゴールデン実例: skills/run-slide-report-generate/examples/diagram-goldens/stacked-bar-{input.json,golden.html}

### 13.4 折れ線グラフ（Line Chart）

連続する時点の値をつなぎ、傾きと交差で推移を語らせる図。

**いつ選ぶ**:
- 時系列のトレンド把握が主目的のとき
- 2 系列を重ねて「追い越し」「差の拡大」を見せたいとき
- データ点が十分に連続していて、間を線で結ぶ意味があるとき

**いつ選ばない**:
- 各時点の量そのものを比べる → §13.1 縦棒グラフ
- 2 変数の相関（時間軸ではない） → §13.7 散布図

**データ契約**:
- 系列数: ゴールデンは 2（焦点 1 + 比較 1）。3 本を超えると線の追跡が破綻する
- データ点数: ゴールデンは 7 点。上限 8（`CAPACITY.buildLineChart`）
- 軸・単位: `axis.x.categories` と `axis.y` の `min` / `max` / `ticks` / `unit` を明示。Y 軸は 0 基線
- 線の交差が主張を担う場合、その地点に注釈や印を重ねない
- データポイントは視認可能な大きさで打つ（§15.2）

**必須情報**: Y 軸の単位と桁を軸ラベルに、X 軸の時点を年込みの絶対表記で（`2026/4`）、系列名を線の右端へ直接書く（凡例だけに置かない）。実績と予測を混ぜるなら境目の時点に縦の区切り線と `ここから予測` を図内へ置く。0 起点を切るなら軸に `0 起点ではない` と書く。これらが欠けると、傾きの急さが尺度の取り方によるものか実際の変化かを読者が区別できない。

**配置**: 方形

ゴールデン実例: skills/run-slide-report-generate/examples/diagram-goldens/line-chart-{input.json,golden.html}

### 13.5 円グラフ（Pie Chart）

全体を 100% とし、1 区分がどれだけを占めるかを面積で見せる図。

**いつ選ぶ**:
- 1 時点の構成比が主張で、特定の 1 区分の大きさが結論のとき
- 区分数が少なく、区分どうしの大小が一目で分かるとき
- 中央に合計値を置きたいとき（ドーナツ型）

**いつ選ばない**:
- 区分が 6 つ以上 → §13.2 横棒グラフ
- 時系列での構成比の変化 → §13.3 積み上げ棒グラフ
- 区分間の細かな大小比較が要る → §13.2 横棒グラフ

**データ契約**:
- 区分（slice）数: 上限 **4**（`CAPACITY.buildPieChart` = `COLOR_PALETTE` の要素数）。ゴールデンは 4（全 golden で 5 区分の円グラフは 0 件・分母は入力 JSON 66 件）。**この 4 は要素数であると同時に見分けのつく色の数**でもある（5 枠だった頃は要素数 5・見分け 4 でずれていた）。§15.2 は「5 以下」を要求しており**実装より緩い**ため、5 区分を頼めると読めてしまう。どちらへ寄せるかは未決で、K-013 の管轄
- 構成比: `share` の合計が 100 になること。`total` に実数値・単位・ラベルを持たせる
- 形状: `shape` は `pie` / `donut`
- 読み順: 円の上端から時計回り。凡例より区分のそばの直接ラベルを優先
- 強調: 系列色の中の 1 色を焦点に兼ねさせ、焦点用の 6 色目を足さない

**必須情報**: 母数 n と単一回答か複数回答かの別を図の下端 1 行に（`n=312・単一回答`）、`total` の実数値と単位をドーナツなら中央に・円なら凡例の先頭に、各区分の割合を区分のそばの直接ラベルに書く。集計定義と時点は年込みで下端の同じ行へ置く。n の無い割合は、68% が 100 人中 68 人か 8 人中 5 人かを読者が区別できない。

**配置**: 方形

ゴールデン実例: skills/run-slide-report-generate/examples/diagram-goldens/pie-chart-{input.json,golden.html}

### 13.6 時計型円グラフ（1日の流れ）

24 時間を一周として、時間の配分を時計の見た目で見せる図。

**いつ選ぶ**:
- 1 日のタイムスケジュール・時間割当を示すとき
- 区分が時刻の連続区間で、順序が固定されているとき
- 「どの活動が一日のどれだけを占めるか」が結論のとき

**いつ選ばない**:
- 時刻の連続性が不要な単なる構成比 → §13.5 円グラフ
- 複数日・複数人の時間配分の比較 → §13.3 積み上げ棒グラフ

**データ契約**:
- 区分数: 上限 5（`CAPACITY.buildClockPie` → `buildPieChart`）。ゴールデンは 5
- 時間: `hours` の合計が 24 になること。各区分は `from` / `to` を持つ
- 周回: `cycle` に `period`（24時間）・`startsAt`（0時 = 上）・`direction`（時計回り）・`centerLabel`
- 時刻マーカー: `hourMarkers` に 0時 / 6時 / 12時 / 18時
- 強調: 系列色 5 色を使い切るため、焦点は 6 色目ではなく既存パレット内の accent を割り当てる

**必須情報**: 各区分の開始時刻と終了時刻（`9:00-12:30`）と時間数を区分のそばに、0時 / 6時 / 12時 / 18時の時刻マーカーを円周上に、対象と期間（誰の・いつの 1 日か）を `centerLabel` として中央に書く（`平日平均・2026/4`）。中央に「1日の流れ」のような型名の再掲を置かない。対象と期間が無いと、その配分が典型なのか特定の 1 日なのかを読者が判断できない。

**配置**: 方形

ゴールデン実例: skills/run-slide-report-generate/examples/diagram-goldens/clock-chart-{input.json,golden.html}

### 13.7 散布図（Scatter Plot）

2 変数の関係を点の分布で示し、帯から外れた点を際立たせる図。

**いつ選ぶ**:
- 2 変数の相関関係の可視化が目的のとき
- 分布から外れた例外（1 点）に議論を接続したいとき
- 個々の観測単位（顧客・案件など）を 1 点として扱いたいとき

**いつ選ばない**:
- 片方の軸が時間で推移を語る → §13.4 折れ線グラフ
- カテゴリごとの量の比較 → §13.1 縦棒グラフ

**データ契約**:
- 群（塗り分け）数: 1。群ごとに塗り分けると相関ではなく分類の図に変わる
- データ点数: ゴールデンは 15 点。分布の帯が読める密度に留める
- 軸・単位: `axes.x` / `axes.y` それぞれに `label` / `min` / `max` / `unit` / `ticks` を必須（§15.2 の軸タイトル要件）
- `trendLine` は任意。置く場合は破線で、点と混同させない
- 強調: 焦点は分布そのものではなく、外れた 1 点に置き注釈を引く

**必須情報**: X 軸と Y 軸それぞれに軸名・単位・目盛を軸沿いに、1 点が何を表すかを図内に（`1 点 = 1 顧客`）、点の総数 n と集計期間を年込みで図の下端 1 行に書く（`2026/1-2026/6・n=15`）。`trendLine` を引くなら回帰か目視の補助線かを線の脇に書く。観測単位と n が無いと、外れた 1 点が例外なのか全体の相当部分なのかを読者が測れない。

**配置**: 方形

ゴールデン実例: skills/run-slide-report-generate/examples/diagram-goldens/scatter-plot-{input.json,golden.html}

### 13.8 レーダーチャート（Radar Chart）

複数軸のスコアを多角形の形として示し、強み・弱みの方向を比べる図。

**いつ選ぶ**:
- 同一尺度の評価軸が複数あり、形の凹凸が主張のとき
- 自社と競合など、性格の違いを重ねて見せたいとき
- 総合点ではなく「どちらへ伸びているか」を語りたいとき

**いつ選ばない**:
- 軸ごとの数値の正確な比較が要る → §13.2 横棒グラフ
- 軸が 4 以下 / 9 以上 → §13.1 縦棒グラフまたは §13.2 横棒グラフ

**データ契約**:
- 軸数: 5-8（§15.1 / §15.2）。上限 8（`CAPACITY_ARGS.buildRadarChart` の第 1 要素）。ゴールデンは 5 軸
- 系列数: 上限 **4**（同第 2 要素 = `COLOR_PALETTE` の要素数）。ゴールデンは 2 系列。5 系列が要ると分かった日に何を選ぶかは未決（K-013）
- 尺度: 全軸で共通（ゴールデンは 0-100）。軸ごとに尺度を変えない
- グリッド: `grid` に `rings`（ゴールデンは 3）と `shape`（軸数に対応する多角形）
- 軸ラベルを全軸に配置すること（§15.2）
- 強調: 塗りを持つのは焦点 1 系列のみ。比較対象は線だけにする（2 面を重ねると下の形が読めない）

**必須情報**: 全軸共通の尺度の起点・最大値・向きを図内に（`0-100・外側ほど優位`）、系列名を各多角形の脇へ直接書く。スコアの出所（誰が何件で付けた評価か）と時点を年込みで図の下端 1 行に置く（`社内評価・2026/3・n=42`）。尺度が割合なら母数 n と単一回答か複数回答かの別も同じ行に書く。向きが無いと、外へ張った形が優位なのか劣位なのかを読者が決められない。

**配置**: 方形

ゴールデン実例: skills/run-slide-report-generate/examples/diagram-goldens/radar-chart-{input.json,golden.html}

### 13.9 ゲージチャート（進捗インジケーター）

単一 KPI の達成度を半円の弧の長さで示し、目標との距離を見せる図。

**いつ選ぶ**:
- 単一 KPI の進捗・達成率を示すとき
- 目標値との差（残りの距離）が結論のとき
- 数値そのものより「どこまで来たか」の感覚を伝えたいとき

**いつ選ばない**:
- 指標が複数あり相互比較が要る → §13.2 横棒グラフ
- 達成率の推移を追う → §13.4 折れ線グラフ

**データ契約**:
- 指標数: 1（単一指標の型）
- 値域: `metric` に `min` 0 / `max` 100 / `value` / `unit` / `label`。0-100 の外に値を置かない
- 目標: `target` は任意。置く場合は焦点にせず muted の刻みで示す
- 弧: `arc.shape` は `semicircle`、`arc.sweep` は左から右へ 180 度。左端が min、右端が max
- 強調: accent の面塗りは進捗の弧 1 件のみ

**必須情報**: `value` の実数と単位、および目標の実数を弧の中央に（`68%・実績 3.4 億 / 目標 5.0 億`）、`min` と `max` を弧の左端と右端に、対象期間と**期間の経過率**を弧の直下に書く（`2026年度上期・経過 52%`）。経過率は省略しない。達成率 68% は期の 5 割経過なら先行、9 割経過なら未達確定で、経過率の無いゲージは読者が評価そのものを下せない。

**配置**: 方形

ゴールデン実例: skills/run-slide-report-generate/examples/diagram-goldens/gauge-chart-{input.json,golden.html}

### 14.2 カテゴリ別アイコン推奨

カテゴリ別のアイコン選定は `references/icons.md` を正とする。

### 14.3 アイコン使用ガイドライン

1. **一貫性**: 同じプレゼン内で同じ概念には同じアイコンを使う
2. **シンプルさ**: 装飾的でない明確なアイコンを選ぶ
3. **サイズ**: タイトル用 `2rem`-`3rem` / 図解要素内 `1.5rem`-`2rem` / 補足用 `1rem`-`1.2rem`
4. **色**: テーマカラー（`--wave-blue`, `--sakura-pink` 等）と調和させる

## 15. グラフ・チャート選択ガイド

### 15.1 データ特性別推奨タイプ

| データ特性 | 推奨チャート | 備考 |
|-----------|------------|------|
| 量の比較 | 縦棒/横棒グラフ | カテゴリ数が多い場合は横棒 |
| 割合・構成 | 円グラフ/積み上げ棒 | 項目数5以下推奨 |
| 時系列変化 | 折れ線グラフ | トレンド把握に最適 |
| 相関関係 | 散布図 | 2変数の関係性可視化 |
| 多軸評価 | レーダーチャート | 5-8軸推奨 |
| 進捗状況 | ゲージチャート | 単一KPI表示に最適 |
| 時間割当 | 時計型円グラフ | 24時間表現に最適 |
| プロジェクト計画 | ガントチャート | タスク期間の可視化 |

### 15.2 チェックリスト

| チャートタイプ | チェック項目 |

| **縦棒グラフ** | □ Y軸ラベルが設定されているか、□ バーの色分けが意味を持つか |
| **横棒グラフ** | □ ラベルが読みやすい幅か、□ 値がバー内/外で適切か |
| **積み上げ棒** | □ 凡例が設定されているか、□ セグメント数は4以下か |
| **折れ線グラフ** | □ データポイントが視認可能か、□ 複数線の場合色分けは明確か |
| **円グラフ** | □ 項目数は5以下か、□ 凡例との対応が明確か |
| **散布図** | □ 軸タイトルが設定されているか、□ トレンドラインは必要か |
| **レーダーチャート** | □ 軸数は5-8か、□ 軸ラベルが配置されているか |
| **ゲージチャート** | □ 目標値が明確か、□ 色分けが直感的か |

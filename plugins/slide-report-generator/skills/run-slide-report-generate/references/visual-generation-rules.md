# 視覚生成規約（生成則 SSOT / E1-E6）

> **正本**: このファイルは「良さを作る指示（生成則）」の SSOT。既存の references が持つのは禁止則（やってはいけないこと）であり、面の上に階層・強弱・密度を**作り出す**条件はここだけが持つ。配色 3 値・意匠トーンの数値は**このファイルが唯一の定義箇所**であり、他の reference・agent プロンプト・CSS へ写経しない（参照させる）。ただし面の余白率・充填率・書体下限の**量的**正本は従来どおり `${SRG_ROOT:-$CLAUDE_PLUGIN_ROOT}/assets/slide-templates/frame-contract.json` にあり、本ファイルはそこへの写像と分布条件だけを持つ（同じ数を 2 箇所に置かない）。

**責務**: 生成条件 E1-E6 とカード化分岐・装飾単一則・文章量分解則の逐語正本。禁止則が「不合格の面を弾く」のに対し、本ファイルは「合格の面を組み立てる」ための条件を、すべて機械検査に落とせる形（測る対象・式・閾値・根拠）で定義する。意匠を手で直しても次の生成で平板へ戻るのは、平板でないことの条件がどこにも書かれていないためであり、本ファイルがその欠落を埋める。

## 1. 配色（唯一の定義箇所）

- **VGCONST_001 (色数 3)**: 面に置いてよい色は `paper #F7F6F3`（地）・`ink #141412`（文字・罫・反転面の地）・反転面の文字 `#F7F6F3` の 3 値のみ。色相による意味づけ（種類ごとに色を割り当てる、連番で色を配る等）を行わない。
  - 目的: 色を意味の担い手から外し、階層をサイズ・太さ・反転だけで作る。
  - 根拠: 3 という数は「地・文字・反転」という 3 つの役から出た値であり、役より色が多い状態＝役割不明の色が存在する状態を定義上作れなくするため。
- **VGCONST_002 (アクセントは色でなく反転)**: 強調は色相ではなく反転ブロック（E4）で作る。図解の**内部に限り**単一色相の濃度段を許すが、彩度は S15-30% の範囲を超えず、段数は 3 段まで。
  - 目的: 面全体の色数を増やさずに、図解内部の従属関係だけを表せるようにする。
  - 根拠: 彩度上限 30% は、ink（無彩色）と並べたときに「色が付いている」と気づくが「色が主張する」には届かない帯。下限 15% は、それ未満だと投影・印刷で無彩色と区別が付かず段として機能しないため。3 段は VGCONST_004 の線幅 3 段と対応させ、階層の軸を線幅と濃度で二重に増やさないため。

## 2. 意匠トーン（唯一の定義箇所）

- **VGCONST_003 (角丸・輪郭・影)**: 角丸は 0px。写真・図版の外形のみ 2px。輪郭は 0.5-0.75px の hairline（色 = 文字色の 15% 濃度）。影は使わない。区切りが要る箇所は 1px の下罫 1 本で表す。
  - 根拠: 角丸は形の階層を作らないのに輪郭のノイズだけを増やす（同じ矩形が「柔らかい版」に見えるだけで、順位の情報を持たない）。写真・図版の 2px は、ラスタ端が地と衝突するのを避ける最小値。0.5-0.75px は、面座標 1280 幅における本文 24px に対して罫が 1/32 以下の太さになり、罫が文字と同じ強さで主張しなくなる帯。
- **VGCONST_004 (線幅 3 段)**: 図解内の線は 1.25px / 2px / 3px の 3 段のみを使い、階層は**太さ**で作る。矢印・囲み・補助線がすべて同じ太さの図は不合格。
  - 根拠: 3 段は主線・従線・補助線という図解の 3 役に一対一で対応する最小構成。最も細い段を 1.25px に置くのは、1280 の座標系で 0.5px が物理 1 デバイスピクセルを割り、実機では消えるか 1px へ丸められて 1px と区別が付かず、段として成立していなかったため。
- **VGCONST_005 (ウェイト 3 段・700 は 1 箇所)**: 書体ウェイトは 400 / 500 / 700 の 3 段。**700 は 1 面につき 1 箇所**（通常は E1 の第 1 位）。
  - 根拠: 700 が 2 箇所以上ある面では E1 の I 最大が同点になり得るため、E1 の一意性条件と同じことを生成側から言い直した制約。
- **VGCONST_006 (字間)**: 見出し（`lead`）は `letter-spacing: -0.02em`、ラベル（`label`）は `+0.1em`。本文（`body`）は 0。
  - 根拠: 大きい字は字送りが間延びして見えるため詰め、小さい大文字・記号列は逆に潰れるため開く、という活字組の標準的な補正。値は「見出しは 1 字の 2%」「ラベルは 1 字の 10%」という 1 桁の量で、面ごとに調整せず固定する。
- **VGCONST_007 (サイズ段差の 2 体系)**: 文字サイズの段差は比 0.60（見出し系＝`lead` から `body` へ落ちるとき）と 0.85（本文内＝`body` から `label` へ落ちるとき）の 2 体系のみ。中間比を発明しない。
  - 根拠: 段差が 1 体系だと、面の第 1 位を出すために本文とラベルまで引き離す必要が出て文字が読めなくなる。2 体系は「面の順位を決める大きな段差」と「同じ順位内の弱い区別」という 2 つの用途に一対一で対応する。
- **VGCONST_008 (1 情報 1 装飾)**: 1 つの情報が同時に持ってよい装飾軸は 1 つまで。装飾軸は 囲み / 塗り / 角丸 / 影 / 色 / アイコン の 6 軸で数える（VGCONST_001・VGCONST_003 により 角丸・影・色 は実効ゼロなので、実際の選択肢は 囲み・塗り・アイコン の 3 択 1 になる）。
  - 目的: 子供っぽさの定義を「主観的な印象」から「1 情報あたりの装飾軸数」という可算量へ落とす。
  - 根拠: 装飾軸は本来「この情報は他と違う」を伝えるための信号であり、同じことを 2 軸以上で言うのは冗長で、冗長な信号が重なった状態が幼く見える正体である。1 は「信号を出す/出さない」を表せる最小値。
- **VGCONST_009 (群間余白は行送り単位)**: 群と群の間隔は px の任意値でなく、本文の `line-height` の整数倍（1 行分の空行 = 1.0、大きな切れ目 = 2.0）で取る。
  - 根拠: 面ごとに新しい間隔値を発明させないための単位固定。行送りを単位にすると、文字サイズを変えた面でも間隔が自動で追随し、比が保たれる。
- **VGCONST_010 (第 1 位の上限・床は触らない)**: 面の第 1 位の文字サイズは **stage 高さの 10% を上限**とする（面座標比で持ち、画面幅で変えない）。下限（床）は frame-contract `typography.min` / `min_rem_engine` が唯一の正本であり、本規約はこれを一切下げない。
  - 根拠: 第 1 位が stage 高さの 10% を超えると、2 行の見出しだけで stage の 1/5 を占め、E6 の命題数下限 3 と同じ面に同居できなくなる。上限で調整するのは、既存規範が床を下げることを明文で禁じているため（可読性の下限は媒体の制約であって意匠の自由度ではない）。

## 3. 生成条件 E1-E6

### E1 視覚強度の第 1 位が一意で、2 位を引き離す

視覚単位 u の視覚強度を次で定義する。

```
I(u) = (font_px(u) / body_px) * W(u) * C(u)
  W: font-weight 400 -> 1.00 / 500 -> 1.15 / 700 -> 1.40
  C: 反転ブロック内、または反転塗りを持つ -> 1.50 / それ以外 -> 1.00
  font_px(u) = u に属する文字のうち最大のもの（図解内の文字は除く）
  body_px    = その面の body 役割の実効 px
```

条件: 面ごとに `argmax I` が **1 単位だけ**存在し、かつ `I1 / I2 >= 1.60`。

- 根拠（1.60）: サイズだけの 1 段差（E2 の見出し系下限 1.50）では届かず、サイズ 1 段＋太さ 1 段（1.50 x 1.15 = 1.725）または反転で初めて満たせる点に閾値を置いた。すなわち「第 1 位はサイズ以外の軸でも 2 位に勝っていること」を数値で強制する値である。1.50 と 1.725 の間に取り、丸め誤差を吸収して 1.60。
- 図解内の文字を除くのは、図解の内部階層は VGCONST_004 の線幅で作られており、文字サイズで面の順位を争う対象ではないため。

### E2 隣接する役割間のフォント比の下限

役割は `lead` / `body` / `label` の 3 種のみ。1 面で同時に使ってよい役割は **3 種まで**（4 種目を作らない）。比は `R = 大きい方 / 小さい方` で測る。

| 隣接 | 下限 R | 根拠 |
|------|--------|------|
| `lead` -> `body` | **1.50** | 体系比 0.60 の逆数 1.667 を狙い値とし、実装の丸めを吸収した下限。1.50 未満は投影距離で「大きい文字」と「本文」の区別が消える |
| `body` -> `label` | **1.15** | 体系比 0.85 の逆数 1.176 の下限側。1.15 未満は同一段落内の弱い区別としても機能せず、単に不揃いに見える |

- 現行の 0.93 / 0.88（= R 1.075 / 1.136）はいずれも下限を割るため不合格。
- 役割を 3 種に絞るのは、6 段の役割を持ったまま隣接比 1.50 を課すと最大最小で 7.6 倍の幅が必要になり、床（E5）と第 1 位の上限（VGCONST_010）の間に収まらないため。段差を確保する解は「段を大きくする」ではなく「段の数を減らす」。

### E3 部材語彙は 4 種以内・各種に役割定義

塗り / 角丸 / 影 / 輪郭 の組み合わせで区別される部材（矩形の見え方）は、1 デッキで次の 4 種のみ。各部材は DOM 上で `data-role` に自分の役割名を持つ。

| 部材 | 塗り | 角丸 | 影 | 輪郭 | 役割 |
|------|------|------|----|------|------|
| `accent` | ink | 0 | なし | なし | 面の最重要 1 ブロック（E4） |
| `divider` | なし | 0 | なし | 下罫 1px | 群の切れ目 |
| `figure` | なし | 2px | なし | hairline 0.5px | 写真・図版の外形 |
| `plain` | なし | 0 | なし | なし | 地の上に直接置く文字群 |

- 根拠（4）: 部材の種類数は役割の数を超えられない。役割は「最重要・区切り・図版・地」の 4 つで、5 種目の部材を作るには 5 つ目の役割を先に定義する必要がある（順序を逆にすると、役割不明の部材が増える）。
- 現行のカード部材 9 種は、役割定義を持たないまま見え方だけが分岐した状態であり、この条文でまとめて不合格になる。

### E4 アクセント（反転ブロック）は 1 面 1 個・面積 8-15%

条件: 反転ブロックは面に **ちょうど 1 個**、その外接矩形面積 / stage 面積 が **0.08 以上 0.15 以下**。

- 根拠（下限 0.08）: stage（面座標 1152 x 616 = 709,632）の 8% は約 56,800px²、幅いっぱいの帯なら高さ約 49px に相当する。これを下回ると本文 1-2 行ぶんの黒帯にしかならず、視線の起点として機能しない。
- 根拠（上限 0.15）: 15% を超えると反転面と地の面積が拮抗し始め、どちらが地でどちらが図か決まらなくなる（E1 の第 1 位が反転の内側で埋没する）。
- 0 個の面は「最重要が無い面」であり、E1 の第 1 位が本文と同じ見え方になるため不合格とする。2 個以上は E1 の一意性を壊す。

### E5 書体の下限

frame-contract `typography.min`（ひな形経路）/ `typography.min_rem_engine`（engine 経路）が唯一の正本。本規約は値を持たず、**下げない**ことだけを言う（VGCONST_010）。

### E6 面あたりの命題数の下限と、文章量の 3 分解

「情報量は増やすが文章量は増やさない」は、総量 1 本（本文 340 字上限）では表せない。次の 3 本へ分解する。

| # | 測るもの | 条件 | 根拠 |
|---|---------|------|------|
| (a) | 本文 1 文の最大長 | **48 字以内** | 意味境界改行の規約が 1 行 15-20 字であり、1 文が 3 行を超えると読点の係り先を追えなくなる。20 x 3 = 60 の内側を取り、句読点ぶんを引いて 48 |
| (b) | 面あたりの命題数 | **3 以上 7 以下** | 下限 3 は「主張 1 ＋ 根拠 2」という、主張が根拠を伴う最小構成。上限 7 は本文総量 340 字 / 1 文 48 字 = 7.08 から、既存の総量規範と衝突しない上限として導出 |
| (c) | 本文カウントの範囲 | ラベル・数値・注記・図解内テキストを**本文 340 字から分離**する | 分離しないと、情報を増やす唯一の手段が「文を書く」になり、ラベルや数値で密度を上げる経路が総量規制で塞がれる。分離した側は字数上限を持たず、(b) の命題数と E1/E3 で制御する |

命題の数え方: 主語と述語が揃い真偽を言える 1 単位を 1 と数える。体言止めの見出し・単語 chip・数値単体・凡例は 0 と数える（それらは (c) の分離側に属する）。

## 4. カード化の分岐条件

「文字列リストを置くならカードへ」という置換は行わない。並列項目の表現は次の順で決める。

| 条件 | 表現 | 理由 |
|------|------|------|
| 並列 3 件以下・項目間に関係が無い | **chip**（`plain` 部材・ラベル字間 +0.1em・囲みなし） | 3 件以下は視線が一度に捉えられるため、囲みで区切る必要が無い |
| 項目間に関係がある（順序・因果・包含・対比のいずれか）・3 件以上 | **図解**（VGCONST_004 の線幅 3 段で関係を描く） | 関係はカードの並びでは表現できない。並べた時点で関係の情報が落ちる |
| 各項目が 2 種以上の異種要素（見出し＋本文＋数値/図）を持ち、かつ全項目が同型 | **カード**（`divider` または `figure` 部材、`data-role` 必須） | カードは「複数の異種要素を 1 単位に束ねる」ための器であり、要素が 1 種なら器は不要 |

- 面あたりのカード群は **1 群まで**。根拠: 同型のカード群が 2 つ並ぶと、どちらの群にも第 1 位候補が存在して E1 の一意性が決まらない。
- カードを選んだ場合、その群は上表のどの条件で選ばれたかを `data-role` に記録する。役割を名乗れないカードは E3 で不合格。

### 4.1 文字リストは図ではない（DC1-DC6・図解被覆）

上表の第 2 行は条文としては前からあったが、**それを面ごとに数える主体が居なかった**。既存の図解検査は 2 本とも「見つけた図」を見る: `validate-svg-diagram.py` が幾何と色の**上限**を、`validate-diagram-information.py` が情報の**下限**を見る。どちらも **図が 0 個の面には検査対象が存在しない**ので緑を返す（分母 0 の緑）。結果として、全面が `ul > li` とカードの羅列でできた deck が既存検査を全部通る。

**ただし「図があるか」を `<svg>` の数で数えてはいけない。** 実測した反例（2026-08-14 20:04 JST・実運用 deck `slide-2026-08-15-AI質問会-v2-ink-on-paper/index.html`）: 面 4（`slide-timeline`）は `<svg>` も `<canvas>` も図としての `<img>` も持たないが、`.timeline::before` の縦軸と `.timeline-item::before` の節点で **CSS だけで経歴のタイムライン図が成立している**。同じ deck の面 3・6・7・9 は（SVG を入れる前は）`ul.list` / `.grid-cell` の文字リストで、これは正しく赤にすべき面だった。**両者は SVG の数では区別できない。**

そこで判定の向きを次のように置く。

- **主判定は「文字リストであること」の側**。`li` の並び・カード/セルの羅列が 3 件以上あり、要素間に接続線も位置関係も無い面を赤にする。ここは機械で確実に取れる。
- **「視覚構造がある」は免責側**。`<svg>` / `<canvas>` / D3 マウント / 図として意図された `<img>` に加えて、**CSS で描かれた図**（擬似要素が対向 2 辺を指定して渡る「軸」＋反復する項目）を拾う。
- どちらとも言えない面は **判定保留**として分母から外し、名指しで出力する。黙って緑にも赤にもしない。
- 誤検出の向きはこれで「見落とし」側になる。人が見て `data-diagram-exempt="<理由>"` で免責する形になり、機械が勝手に赤を消す形にはならない。

**拾えない形（既知の死角・検査器も毎回 DC6 として出力する）**: 外部 CSS ファイル・JS が実行時に差し込む装飾・`background-image` の SVG data URI・`transform` だけで引いた斜線は見えない。節点だけ（連番バッジ等）は軸が無いので図と数えない（番号付き箇条書きと区別できないため）。構成段階の判定は型しか見えないので候補であり、正本は生成後の判定。

- **`ul > li` の羅列・カードの羅列は図ではない。** アイコン＋見出し＋説明文を並べたものは、装飾された文章である。
- 項目が **3 件以上並ぶなら、まず「その項目間にどういう関係があるか」を決めてから図の型を選ぶ**。

  | 項目間の関係 | 選ぶ図 |
  |---|---|
  | 順序がある（工程・手順・時系列） | フロー / チェブロン / タイムライン |
  | 包含・階層（大が小を含む） | 階層図 / ツリー / 入れ子 / 積層 |
  | 比較（同じ軸上の 2 つ以上） | 対比図 / マトリクス / 2 軸 |
  | 分岐（条件で行き先が変わる・5W1H の枝分かれ） | 分岐図 / フローチャート / マインドマップ |
  | 循環（終点が始点へ戻る） | 循環図 / PDCA / フライホイール |
  | **関係が無い** | **図にしない。その項目を並べる必要が本当にあるのかを先に疑う**（並べる理由が説明できないなら落とす） |

- **受理される型と、実際に図が描かれる型は別。** 型を選んだだけでは図は出ない。描画実体の正本は `${SRG_ROOT:-$CLAUDE_PLUGIN_ROOT}/references/diagram-type-crosswalk.md` §10 の表で、そこで fallback へ落ちる型を選ぶと文字が出る。実測（2026-08-14 20:04 JST・`vendor/scripts/templates/*.html.tpl` 128 本を走査）: `slide-list` / `slide-grid` / `slide-icon-grid` / `slide-timeline` / `slide-process` / `slide-compare` / `slide-table` / `slide-code` / `slide-code-compare` のテンプレートは `<svg` も `{{{svg}}}` も `data-d3-mount` も持たない。**これらを選んだ面は、テンプレートからは図が出ない。** 例外は CSS 側で図になる型で、同じ実測で `slide-timeline` だけが該当する（`vendor/scripts/style-builder.cjs` の `.timeline::before` が軸を、`.timeline-item::before` が節点を描く）。「テンプレートに svg が無い」と「図が無い」は同じではない。
- **色で系列を分けない。形・線で分ける**（塗り／輪郭／破線／実線／VGCONST_004 の線幅 3 段）。色は VGCONST_001 の 3 値の範囲で濃淡 3 段まで。色相に意味を担わせると、印刷・投影・色覚差でその意味が消える。
- **濃い面の上のラベルは白、紙地の面のラベルはインク。** `svg text` へ一律の `fill` を掛けない。実例: 全 `text` へ ink を掛けて、反転ブロック上の白ラベルを地に潰した。反転ブロック内の `text` は `fill` を親から継承させるか、反転側だけ個別に指定する。

**機械検査**: `scripts/validate-diagram-coverage.py`（DC1 面が文字リストのみ / DC2 deck 全体の被覆率 / DC3 対象 0 件 / DC4 除外した面と理由 / DC5 判定保留の面 / DC6 拾えない形の告知）。分母は **3 つとも出力する**（全面数・図が要る面＝除外後・判定できた面）。対象 0 件は exit 2 として緑と分離する。除外は**面番号ではなく面の型**で決める（番号の除外リストは deck が変わると意味を失い、都合の悪い面を番号で外す経路になる）。QR/連絡先が主役の面は「視覚構造を判定したあとで」除外する（図の脇に QR がある面を QR 面として分母から落とさないため）。閾値 `--min-ratio` の既定 0.50 は**目標ではなく床**で、規約上の正論値は上表第 2 行より 1.00 である。いきなり 1.00 を当てると全 deck が赤になり検査ごと無視されるため、値を直してから段階的に締める。

## 5. 余白の分布

- 量的正本: 面の余白率・充填率は frame-contract `fill_policy` が唯一持つ。本規約は写像だけを持つ。`面の余白率 = 1 - stage_fill_ratio`（目標値・許容レンジは `fill_policy` の target / min / max を引く）。同じ数を散文へ写さない。
- **VGCONST_011 (余白の偏り)**: 面内の余白は均等に均さず偏らせる。条件は「面内の**最大の空き矩形**の面積が、面内余白総面積の **40% 以上**」。
  - 根拠: 余白が n 箇所へ均された面では最大空き矩形は概ね 1/n になる。群が 3 つある面（本規約の典型）で「一箇所へ寄っている」と言えるのは 1/3 = 0.33 を明確に超えたときなので、判定の余裕を見て 0.40 に置いた。
  - この条文は**水平方向および群間**の余白分布に対する条件であり、frame-contract `vertical_margin_policy.max_symmetry_delta`（列の**上下外側**余白の対称性）とは測る対象が異なる。上下外側余白は従来どおり対称を保つ。両者は別軸であり、片方を満たしても他方は満たさない。

## 適用と優先順位

1. E5（書体下限）と既存の禁止則（重なり・はみ出し・溢れ）が最優先。生成則は禁止則を緩める根拠にならない。
2. E1 -> E4 -> E2 -> E3 の順に効かせる。面の第 1 位が決まらないうちに部材や役割を増やすと、増やしたものが第 1 位を奪い合う。
3. E6 は構成段階（面に何を載せるか）で満たす。生成後の文章圧縮で命題数の下限を満たそうとしない（圧縮は命題を削るため下限から遠ざかる）。
4. 本規約に反する既存の面を見つけた場合、値をこのファイルへ写経するのではなく、このファイルを参照する形へ直す。

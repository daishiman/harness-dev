## 0. なぜ「素材」を成果物側で見るのか

D0-D9 が幾何と可読性を見るのに対し、D10-D13 は色・密度・外部依存・書体という**素材**を見る。

素材を成果物側で見る必要があるのは、ビルダー関数の入口（`CAPACITY`、`TOKENS` などの表）は
**決定論経路にしか効かない**からだ。agent が SVG を直接書く LLM 経路は表を素通りする。
契約は「どちらの経路でも同じ契約で採点する」と宣言しているので、
上限も語彙も成果物側でもう一度見直す。

そのうえで**除外範囲が D1 と違う**点が重要。D1 は `defs` / `marker` / `symbol` / `clipPath` /
`pattern` / `mask` の中身を「座標系が親と別物だから幾何を測れない」という理由で除外するが、
これは素材の除外理由ではない。marker の塗りも `<pattern>` の色もパレット内であるべきだし、
`defs` の中に `<script>` や外部 image を隠されたら同じだけ危ない。
**D10-D13 は SVG 全体を走査する。**

## 1. D10 — パレット逸脱

### 許可色を検査器に書かない

許可色は `vendor/scripts/svg-kit.cjs` の `TOKENS` / `SERIES` ブロックから
**実行時に正規表現で抽出**する（`_allowed_palette()`）。
色を検査器へ写すと、パレットを差し替えたときに**検査器だけが古い色を許し続ける**。
正本が 2 つある状態は、ズレを塞ぐための別の検査を永久に必要とする。

抽出は形にこだわらず両ブロック内の hex を全部拾う。
`TOKENS` は `var(--x, #fallback)` 形式（CSS 変数 + フォールバック）と生のリテラルが混在しており、
形で絞ると片方を取りこぼすため。`NODE_STYLES` の `rgba(...)` は同じ hex に α を付けたものなので、
判定側で rgb 三つ組を hex へ畳めば同じ集合で通る。

抽出に失敗したときは「見なかったこと」にせず、`_SOURCE_WARNED` で**1 度だけ** warning を出す。
検査器が黙って素通りするより、vendor が壊れている事実を出したほうがよい。

### 判定の階段

`_color_violation(value, palette)` は次の順で見る。

1. `none` / `transparent` / `currentColor` などと `url(#...)` は素通し。
   グラデーションやパターンの参照先は、その `stop-color` 側が別途 D10 に掛かる。
2. **純黒は許可集合に入っていても常に指摘する**（後述）。
3. hex / rgb のリテラルを含むなら、全て許可集合に入っているか。
4. リテラルを 1 つも含まない `var(...)` 参照は素通し。解決先はテーマ側の責務。
5. それ以外（`red` のような名前付き色、未知の記法）は落とす。
   名前付き色は本プラグインのパレットのどれとも一致しない。

同じ色が 100 箇所に出ても直す作業は 1 回なので、報告は値ごとに 1 件へ畳む。

### なぜ純黒を弾くのか

`#000` は「安全な既定色」に見えるが、**両端の再生環境で壊れる**。
OLED では黒が完全に消灯するので隣接する面との**境界そのものが消え**、
印刷ではインクが乗り過ぎて細部が潰れる。
`TOKENS.ink` を使えば両方とも避けられる。これは好みの問題ではなく再生環境の物理の話なので、
たとえ将来パレットに純黒が入ったとしても指摘は残す設計になっている。

## 2. D11 — 複雑度上限

上限は**固定値ではなく `CAPACITY` から導く**。
`_capacity_max()` が `svg-builder.cjs` の `CAPACITY` 表の最大値 N を抽出し、
上限を `N × COMPLEXITY_FACTOR` とする。

係数が乗る理由は、1 図の要素が 4 つの群に分かれるため。

| 群 | 件数の目安 |
|---|---|
| ノード本体 | N（1 件 = 1 図形） |
| ノード付属図形 | N（番号バッジ・アイコン台座など） |
| コネクタ | N（環状フローは 1 ノードにつき 1 本） |
| 付随ラベル / 凡例 | N（タイトル・凡例・注記の箱） |

**なぜ表から導くのか**: 上限を検査器へ直接書くと、`CAPACITY` を 1 つ増やした瞬間に
「ビルダーで正しく描いた最も密な図」が検査で落ちる。
表から導いておけば、**決定論経路が描ける図は定義上必ず通り、
それを超える密度の図（＝ LLM が直接書いた過密な図）だけが引っ掛かる**。
検査が捕まえたいのは後者だけなので、この導出はしきい値の調整ではなく検査対象の定義そのもの。

密度が語彙そのものである型（ガント・年表・マトリクス・散布図・チャート類など `DENSE_TYPES`）は
`COMPLEXITY_RELAX` 倍まで緩める。D5 の `RADIAL_TYPES` と同じ「型申告で例外にする」作法で、
判定材料は `class` / `data-slide-type`。

なお `extract_svgs` は `<svg>` を包む直前の `slide-` / `diagram-` / `chart-` から始まる class を
名前に載せる。`render-slide.cjs` は `<svg>` 自身へ class を付けないので、
型名は SVG 本文ではなく親要素にしか無いことがあるため。

## 3. D12 — 外部依存

`<script>`、`<link>`、外部 `@import`、外部 URL 参照、
そして `_D12_LOADER_TAGS`（`image` / `use` / `feImage` / `textPath` / `filter` / `pattern` / `mask`）の
`href` / `src` が外部を指すもの——これらは**成果物 HTML の自己完結性を壊す**。
オフラインで開いたとき、あるいは印刷したときに、その図だけが消えるか別物になる。
プロトコル相対（`//cdn...`）も外部として扱う。

- `<a href="https://...">` は対象外。資源の**取得**ではなく単なるリンクなので、
  参照先が落ちても図は消えない。
- `<script>` / `<link>` はタグ検出で必ず 1 件出るので、`_D12_LOADER_TAGS` には入れない（二重報告になる）。
- Google Fonts 等の例外は設けない。SR-3-06 が Font Awesome の PUA を禁じる理由
  （CDN 未ロードでアイコンが全部消える）は外部フォントにもそのまま当てはまり、
  さらに図の文字が意図と違う書体で描かれれば**収まり計算ごと崩れる**（→ D13）。
- 走査範囲は SVG 断片の中だけ。HTML 全体の外部依存は `scripts/validate-report-visual.py` と
  build 側の責務で、ここで見ると二重報告になる。
- 既知の取りこぼし: HTML 入力では `extract_svgs` が `<style>` の中身を空白へ潰すため、
  SVG 内 `<style>` の `@import` は `.svg` 直接入力のときだけ拾える。
  潰さないと Mermaid のバンドル JS を図解として拾ってしまうので、この取りこぼしは受け入れている。

### なぜ SEVERITY 表に登録しないのか

`_sev(code)` は `SEVERITY` に載っていないコードを **error** として返す（fail-closed）。
D12 はこの既定に**意図的に乗せてある**。

理由は D8 と同根拠だから。D8（Font Awesome の PUA）が error なのは
「CDN が落ちた瞬間にその図が消える」形で読者に届くからで、D12 の外部参照はまったく同じ事故を起こす。
D8 が error なら D12 も同格でなければ筋が通らない。

そして「登録しない」という表現を選んでいるのが設計の要点。
`"D12": "error"` と明記しても動作は同じだが、それでは**未登録コードが error になる仕組み自体**が
どこにも使われていない飾りになる。D12 を既定へ預けておくことで、
将来 D14 を足した誰かが `SEVERITY` への登録を忘れても、その検査は warning に落ちずに error として働く。
fail-closed は宣言ではなく、実際に依存している機構でないと維持されない。

同じ理由で D0 / D1 / D2 / D3 / D4 / D8 も未登録のまま error になっている。

## 4. D13 — 書体

許可書体は `svg-kit.cjs` の `textBlock` の既定フォントスタック 1 行から抽出する
（`_allowed_families()`）。総称ファミリ（`sans-serif` / `system-ui` など）は
「最後の逃げ場」なので常に許可する。

**書体名を検査器へ書くと、kit 側でスタックを差し替えた瞬間に嘘になる。**
正本は `textBlock` の `o.family || "..."` の 1 行だけ。

書体を縛る理由は見た目の統一だけではない。
書体差は**字幅に直結**し、`kit.charWidth` の近似——すなわち `fitText` / `wrapText` の
収まり計算の前提——をそのまま外す。別書体で描かれた図は、
「1 行に収まるはずの文字が溢れる」という形で幾何の契約まで巻き込んで壊れる
（→ `label-japanese.md` §1）。
加えて、1 図だけ書体が違うと文書全体の一体感が切れ、その図が本文と別の出所に見える。

実害が「1 行の収まりが少しずれる」に留まり図が読めなくなる訳ではないので、
重大度は warning に登録してある。

## 5. 落ちたときにどうするか

| コード | 最初に見るもの |
|---|---|
| D10（純黒） | `TOKENS.ink` へ置き換える。黒は選択肢に無い |
| D10（palette 外） | `svg-kit.cjs` の `TOKENS` / `SERIES` から取り、`var(--x, #fallback)` 形式で書く |
| D11 | figure を分けるか、まとめられる階層を 1 段落とす。型が本当に密度型なら型申告を確認 |
| D12 | 画像・アイコンは SVG 内へ埋め込むか生成側で取り込む。例外は無い |
| D13 | `kit.textBlock` を通して描く。font-family を手書きしない |

いずれも「検査を通すために値を変える」のではなく、**素材の出所を正本へ戻す**のが正しい直し方。
検査器の判定値を書き換える方向の修正は、正本が 2 つに割れるので必ず後で壊れる。

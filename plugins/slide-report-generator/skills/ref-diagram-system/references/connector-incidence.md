# コネクタ — 入射・分岐・段跨ぎ

> 正本は `vendor/scripts/svg-kit.cjs` §「分岐の束ね」周辺。ここは**なぜその形しか許されないか**を書く。
> 線幅の値そのものと 1.25 が下限である理由は `references/diagram-layout-contract.md` §1.1 を読む。

## 1. 入射規則 — 矢じりは辺に正対させる

矢じりは `markerUnits="strokeWidth"` で描かれるので、実寸は marker 座標 × 線幅に比例する。
そして経路の終端より**先へ張り出す**（張り出し量は `MARKER.overhang`、実 px は `markerOverhangPx()`）。
このため宛先の辺へ**外向き法線と逆向き**に当てる、つまり辺の内側から外へ向かって入射させると、
矢の胴体が矩形の内側へ埋まり、読者には矢頭だけが残る。
矢頭だけでは「どちらからどちらへ」が消えるので、**図の向き = 主張の向き**が伝わらなくなる。

許容されるのは 4 通りだけで、正本は `INCIDENCE_RULE`。

| 宛先の辺 | 許される進行方向 |
|---|---|
| 左辺 | 右向き |
| 右辺 | 左向き |
| 上辺 | 下向き |
| 下辺 | 上向き |

判定の流れは 3 段。

1. `nearestEdge(point, box)` — 着点が矩形のどの辺に載っているかを、4 辺への距離の最小で決める。
   `box` が無い／寸法が有限でないときは `null` を返し、そのときは入射規則を課さない。
2. `elbowIncidence(x1, y1, x2, y2, first)` — エルボが実際に宛先へ入るときの軸と向きを返す。
   `elbowPath` は `first: 'h'` なら最後が水平入射、`'v'` なら最後が垂直入射。
   ただし `dx ≈ 0` / `dy ≈ 0` で直線に縮退するときは `first` に関係なくその軸で入る。
   この縮退を見落とすと「`first` を切り替えたのに入射が変わらない」不整合が起きる。
3. `safeElbow(from, to, srcBox, dstBox, opts)` — 屈曲順を規則を満たす側へ**自動選択**する。
   同点のときは発ノード側の辺の軸（左右辺から出る線なら水平優先）を先に試す。折れ数が少なく読みやすいため。

### degraded をどう扱うか

`safeElbow` はどちらの屈曲順でも規則を満たせない配置（ノードが重なっている、
宛先の辺の外側に発点が無い、など）で、従来どおりの経路を返しつつ
`incidence: 'degraded'` を**申告**する。返り値は `{ d, incidence, first }`。

ここが設計の要点で、`safeElbow` は自分で線を消さない。
消すかどうかは呼出し側の判断であり、`degraded` を握り潰して描くと
「向きの読めない矢印」が黙って成果物に載る。**受け取ったら引かない側へ倒す**のが既定の作法。

なお `elbowPath` 自体のシグネチャと挙動は変えていない（既存の呼出しが多数あるため）。
新しく線を引くときは `elbowPath` ではなく `safeElbow` を使う。

## 2. 1→多 の分岐 — トランクで束ねる

1 対 1 のエルボを独立に引くと、各線が**自分の中点**で折れる。
4 分岐なら 4 本が別々の x で曲がるので、束に見えず「どこで分岐したのか」が読めない。

`trunkPaths(srcPort, dstPorts, trunkX)` は発ノードの外に単一の `trunkX` を立て、
`[水平 → トランクで垂直 → 各宛先へ水平]` の 3 セグメントに統一する。
全セグメントが軸平行なので、`scripts/validate-svg-diagram.py` の
**D5（斜めコネクタ）は自動的に満たされる**。
発点と宛先の y が一致するときだけトランクを経由せず 1 本の水平線を返す（無駄な折れを作らない）。

### 何本まで出せるか

同じ辺に矢じりが並ぶとき、間隔が足りないと矢頭が重なって束が黒い塊になり、
何本あるのかすら読めなくなる。そこで**間隔のほうを不変量として守る**。

- `FAN_MIN_GAP` = 辺へ正対して入る矢の見かけ幅を最悪ケース（主コネクタの線幅）で見積もり、
  グリッドへ寄せた値。`MARKER` と `STROKE` からの**導出値**であって新しい定数ではない。
- `fanCapacity(length)` — 辺長 `length` に `FAN_MIN_GAP` を保って取り付けられる本数。
  取付点が `L·k/(N+1)` なので間隔は `L/(N+1)`、よって `N ≤ L/FAN_MIN_GAP − 1`。
- `fanAttach(start, length, index, count)` — 取付点を返す。`count` が `fanCapacity` を超えると
  **収まる本数まで詰めて**配置する。等分の分母を無制限に増やす実装にはなっていない。

呼出し側は `fanCapacity` を容量判定に使い、超える本数は図に載せない
（`references/diagram-layout-contract.md` §2 の容量契約と同じ扱い）。
`count <= 1` は辺の中央を返すので、単線の既存呼出しの見た目は変わらない。

## 3. 段を跨ぐ昇格 — 上を回る弧

隣接する層の間で「昇格した」ことを見せたいとき、カードの間を直線で結ぶと
カードの角をかすめて向きが読めなくなる。`overArcPath(x1, y1, x2, y2, bandTop)` は
上辺どうしを 3 次ベジエで結ぶ。

要点は**制御点を各アンカーの真上（`bandTop` の y）に置く**こと。
こうすると端点での接線が鉛直になり、着地側は「上辺へ下向き」= `INCIDENCE_RULE.top` を
自動的に満たす。斜めに着地する弧は矢じりが辺へ食い込んで向きが読めない。

`bandTop` は `Math.max(0, …)` で clamp する。D1 は path の**通過点しか測らず弧の膨らみを見逃す**
（`references/diagram-layout-contract.md` §4「意図的な検出漏れ」）ので、
viewBox 上端をはみ出さない保証は検査器ではなく実装側が持つ必要がある。

ラベルは `overArcApex(x1, y1, x2, y2, bandTop)` が返す頂点（t=0.5 の点）の直下へ置く。
そこなら曲線と交差しないのでマスクが要らない。

この弧を実際に使っているのは `svg-structures.cjs` の `buildMedallion`（層間の昇格）。

## 4. 太さは情報の重要度

線幅の階層（主コネクタ / 副コネクタ / ノード輪郭 / 軸 / 補助罫 / 帯）は `kit.STROKE` が正本。
太さが 1 種類しかないと全部が同じ強さで主張し、視線の順序が生まれない。
逆に階層から外れた太さを 1 本でも混ぜると、その線だけが理由なく目立つ。

- 図の主張そのもの（本線）は主コネクタ、補足・戻り線は副コネクタ。
- ゾーン境界やグリッドは最も細い許容値まで落とす。
- **最細が 1.25 である理由**は `references/diagram-layout-contract.md` §1.1 にある。
  成果物側では `validate-svg-diagram.py` の D9 がこの下限を見る。

矢じりの張り出しが線幅に比例する以上、線幅を変えると `FAN_MIN_GAP` の前提も
入射時の食い込み量も変わる。**線幅だけをその場で調整することはできない**。

## 5. 詰まったときの分岐

| 症状 | 見るもの |
|---|---|
| 矢頭しか見えない / 向きが読めない | §1。`safeElbow` の `incidence` を握り潰していないか |
| 分岐が束に見えない | §2。`trunkPaths` を使っているか、各線が自分の中点で折れていないか |
| 矢じりが重なって黒い塊になる | §2 の `fanCapacity`。本数を減らすか辺長を伸ばす |
| D5（斜めコネクタ）で落ちた | §2。軸平行に分解する。放射状スポークを持つ型は例外申告が要る |
| 弧が viewBox の上へ抜けた | §3。D1 は弧の膨らみを見ないので `bandTop` を実装側で clamp する |
| D9（線の太さ）で落ちた | §4 と `references/diagram-layout-contract.md` §1.1 |
| 線に載せたラベルが入らない | `label-japanese.md` §3 |

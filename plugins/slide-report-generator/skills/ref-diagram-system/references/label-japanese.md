# 日本語ラベル — どこで吸収するか

> 正本は `vendor/scripts/svg-kit.cjs` の §3 折返し / `fitText`、および
> `vendor/scripts/render-report.js` の `conciseLabel`。
> 「切り詰めない」契約の全文は `references/diagram-layout-contract.md` §3。

## 1. 日本語が図を壊す理由

**幅**: `kit.charWidth()` は全角を 1.0em として数え、ラテン小文字はその半分程度、
数字・大文字はその中間として近似する。つまり**同じ文字数でも日本語はラテンの 1.6〜2 倍の幅**になる。
「7 文字なら入る」と英語基準で設計した箱は、日本語では必ず溢れる。
実測は `kit.measureText(text, fontSize)`。

なお `charWidth` は以前の「1 文字 = font-size px」一律換算を置き換えたもので、
一律換算は英数字を 2 倍近く過大評価し、カード幅と文字量の不一致（無意味な位置での折返し）を生んでいた。

**語順**: 日本語は述部が末尾に来る。だから途中で切ると
「〜しない」「〜する場合に限り」「ただし〜」が**まるごと落ちる**。
図に載るのは肯定形の断片だけになり、本文と逆の主張を図が語り出す。
これが「切り詰めるくらいなら載せない」という契約の根拠であり、
省略記号を足しても解決しない（読者は「続きがある」ことしか分からず、
落ちたのが条件なのか具体例なのかを判別できない）。

**禁則**: 行頭に来てはいけない文字（句読点・閉じ括弧・長音・小書き仮名など）は
`kit.FORBID_LINE_START`、行末に来てはいけない開き括弧類は `kit.FORBID_LINE_END`。
`kit.breakAllowed(before, after)` がこれを見て候補位置を除外し、
半角英数の語中でも割らない。

**改行位置の質**: `kit.breakScore(before, after)` が候補を採点する。
句読点直後が最良、次に閉じ括弧・中黒・コロン直後、次に助詞直後
（ただし 1 文字助詞は語中にも現れるので、次が漢字・カタカナ・英数＝語頭であることを条件にして
「生成で｜きる」を弾き「図解を｜作る」を通す）。文字種の切り替わりも切れ目として拾い、
同一文字種の連なりを割るのは最後の手段。逆に**助詞が行頭に来る割り方は減点**される。
さらに `kit.LOOKBACK_RATIO` により、行の充填率がその比率を下回る位置は
たとえ改行品質が高くても採用しない（行長が不揃いになるため）。

## 2. 吸収先は 3 つしかない

**このファイルの核心はこの分類**。「文字が入らない」と気づいたら、まず
その箱の幅が**素材から決まるのか、構造で固定されているのか、そもそも箱が無いのか**を判別する。
判別を飛ばして font-size を下げるのは、3 つのうち 2 番目の手を無条件に選んでいるだけで、
最小フォントに当たった時点で必ず破綻する。

### 2-1. 幅が素材から決まる → `measureText` で伸ばす

ゾーン幅・viewBox 幅・間隔が入力から決まる図では、**箱のほうを内容に合わせる**。

- 手順: `kit.measureText(text, fontSize)` で必要幅を出し、それを満たす箱を先に確保する。
  高さで吸収する型なら `kit.autoBlockHeight(text, boxW, opts)` が必要高を返す。
- 例: `buildVerticalFlow`（縦積みなので高さが伸びる）、`buildMindmap`
  （ラベルを外円の外側へリーダー線付きで置き、3 行まで折り返す）、
  `buildClockPie`（`measureText` で実測した幅の吹き出しを置く）。
- 落とし穴: 箱を広げたぶん viewBox が伸びるなら、`CANVAS.height(needed)` を通して段を選び直す。
  後付けで高さを足すと D1 が error になる（`references/diagram-layout-contract.md` §4）。

### 2-2. 幅が構造で固定 → `fitText` で縮める（ただし床がある）

等分割・固定列・格子セルでは幅を動かせない。ここでだけ文字サイズを落とす。

- 手順: `kit.fitText(text, boxW, boxH, opts)` が最大フォントから 1px ずつ下げ、
  行数と総高さの**両方**が箱に収まる最大サイズを採る。
- **下限を割ってはいけない**。既定の下限は `kit.MIN_FONT`、軸ラベル等の例外でも
  `kit.MIN_FONT_SMALL` が床で、成果物側では D4 がこれを見る。
  下限でも収まらないとき `fitText` は `truncated: true` を立てた結果を返す。
  **`truncated` が立った結果は描かない**——これが §1 の語順の話に接続する。
  `svg-structures.cjs` のテキスト描画はこの規約を実装しており、
  切り詰め結果は既定でも描かない（`opts.dropIfTruncated` はその明示用の注記）。
- `opts.singleLineFloor` を渡すと、下限より手前で「1 段小さくしてでも 1 行に収める」を優先する。
  円形ノードのように幅が中心から離れるほど急に狭まる箱で、
  「改善につ／なげる」のような語中改行を避けるため。フォント 2px 減より語中改行のほうが確実に読みにくい。
- どの型が固定幅側かは `diagram-type-catalog.md` の各項目「日本語ラベル」欄。

### 2-3. 線に載る → 描く前に採否を決める（入らないなら置かない）

コネクタラベルには**箱が無い**ので、伸ばすことも縮めることもできない。
だから描画時ではなく**素材を選ぶ時点**で採否を決める。

- 判定は `render-report.js` の `conciseLabel(text)`。4 つの契約を順に課す。
  1. 前処理として空白を畳み、インラインコードと強調記号を落とす。
  2. **第 1 文だけ**を候補にする（`splitSentences` の文末判定を使う。
     半角ピリオドは語中と区別できないので使わない）。
  3. 第 1 文自身が逆接・留保（`RESERVATION_RE`）を含む、
     **または第 2 文以降に逆接・留保がある**なら不採用。
     後者は「第 1 文だけ載せると本文の留保が消える」ケースを潰すためで、ここを落とすと図が嘘をつく。
  4. 上限字数を超えたら不採用。**切り詰めない、載せない**。
- 1 件でも不採用なら `labelsOf(items, pick)` が `null` を返し、
  その行の導出ごと中止する。一部だけ落とすと読者は図を全体像だと信じてしまうので、
  **全部載るか作らないかの二択**にしてある。
- 描く側の実体は `kit.arrowLabel(text, x, y, opts)`。文字数での切り詰めはせず、
  指定幅で最大 2 行へ折り返し、不透明マスクとギャップを強制する。

#### なぜ中点ではなく始点に置くのか

`arrowLabel` の `anchor: 'start'` は `(x, y)` を経路の**始点**として扱い、発ノードの直後へ置く。

日本語ラベルは同じ意味で英語の 1.6〜2 倍の幅になるため、経路の中点に置くと
隣の線やノードと必ず衝突する。一方、**始点側には空白が構造上保証されている**——
ノードは辺で終わり、そこから線が出るのだから、辺の直後には他の何も無い。
中点にそのような保証は無い。

オフセットは `kit.LABEL_GAP` からの導出だけで作る（新しい数値定数を置かない）。
経路方向は矢の付け根と重ならないよう `LABEL_GAP` の 2 倍、
法線方向は `LABEL_GAP` + 箱の半寸（箱の縁が線から `LABEL_GAP` だけ離れる距離）。

## 3. 判別のための最短質問

| 質問 | Yes なら | No なら |
|---|---|---|
| その文字は線の上に載るか | §2-3。`conciseLabel` で採否を先に決める | 次へ |
| 箱の幅が入力から計算されているか | §2-1。`measureText` / `autoBlockHeight` で伸ばす | §2-2 |
| `fitText` が `truncated: true` を返したか | **描かない**。素材側を短くするか型を変える | そのまま描く |

型ごとにどちらの側かは `diagram-type-catalog.md`。
高さで吸収できる型を選び直すのが一番確実な逃げ道で、その筆頭が `buildVerticalFlow`。

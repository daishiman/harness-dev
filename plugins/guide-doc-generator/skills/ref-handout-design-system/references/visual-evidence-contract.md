# 実表示を確認するための証跡

実表示の取得は生成側の親 C01 が R4 で行い、C03 が現在の資料への結び付きを確認して
C06 へ運ぶ。C06 は証跡を読み、意味と見た目を独立に判定する。判定者に設計意図・
過去の指摘・改善回数を渡さない。対象 HTML と構成データを書き換える権限は与えない。

## 親が取得するもの

利用可能なブラウザ操作またはローカルのヘッドレスブラウザで、生成した実際の HTML を
開く。単なる SVG ソースやギャラリー標準例で、今回の資料を表示したことにしない。
表示幅の正本は `config/handout-visual-policy.json#diagram_presentation.review_widths_px`。
その幅で、対象節の初期表示と、詳細を開いた状態・図を拡大した状態を必要に応じて取得する。
節全体の縦長キャプチャでは、固定ナビや保存バーが合成画像の途中へ写る場合がある。
この画像だけで実画面の遮蔽を判定せず、目次から移動した直後と、対象部品の先頭・末尾を
実ビューポートへ入れた画面も取得する。`state` に取得方式と表示位置を記録し、必要な
本文がナビの下・保存バーの上で読めることを確認できる証跡を渡す。
専用図表は `asset.role: "figure"` として、縮小前の実画素も確認できる画像へ抽出する。

実表示証跡は生成作業域へ保存する。任意の `visual_evidence` 入力として渡す manifest は
次を持つ JSON 1 点とし、正規の構成データへ未定義フィールドを追加しない。

| field | 内容 |
| --- | --- |
| `html_sha256` | 取得対象 HTML の実バイト列の SHA256 |
| `captures` | `{section_id, width_px, state, path}` の配列。state は初期表示・開いた詳細・拡大等の実状態を示す |
| `assets` | `{asset_id, path}` の配列。画像の実体を開くための抽出ファイル。別の資料の画像を混ぜない |
| `measurements_path` | 任意。文字の実表示サイズ、はみ出し、重なり、操作確認を記した測定結果のパス |
| `unavailable` | 取得できなかった節・幅・画像と理由。全件取得できた場合は空配列 |

C03 は manifest とファイルの存在を読み、`html_sha256` が現在の `html_path` の
実バイト列と一致するかを、読取専用の Python 標準ライブラリ等で確認する。変更後の資料に
古い画面を流用しない。C03 は画像の良し悪しを判定せず、不在・不一致は不足としてそのまま
運ぶ。測定値だけで接続や読みやすさを合格にしない。

## C06 が確認するもの

許可された Read で manifest と、その manifest が指す画面・抽出画像・測定結果を読む。
文章と図の関係、文字、余白、色、線、初期表示で核心が見えるか、狭い画面での操作負担を
`visual-expression-review.md` の観点で確認する。画像を開かず alt だけを読んで済ませない。
親が書いた評価や「合格」の自己申告は根拠にせず、画面と資料の内容を根拠にする。

証跡がない・対象 HTML と不一致・必要な状態や幅が未取得の場合、読める文字のレビューは
続けてよい。ただし未確認の節・画像・幅は `not_reviewed` に
`reason_code: "display_unavailable"` と具体的な理由を残す。これは `scope` による未読や
`machine_gate_overlap` による除外とは別であり、実表示を確認したという意味にはならない。

## 親が完了を判断するとき

C06 の verdict は findings に対する判定であって、証跡の無い面の合格ではない。
`display_unavailable` が残る節・画像・幅は release の visual-fit 未達として保持する。
親が該当表示を取得して再レビューへ渡し、確認された面だけを解消する。取得不能なら
未確認として開示し、release の全面合格を宣言しない。draft の引き渡し可否は既存の
段階契約に従い、画面確認を行っていない場合はその事実を生成レポートに明示する。

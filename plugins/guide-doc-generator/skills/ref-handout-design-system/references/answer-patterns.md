# 回答の型

この skill は参照回答しか返さない。問い合わせを 4 面のどれかへ割り当て、正本を
読んでから答える。読まずに記憶で答えない。

## 手順

1. 問い合わせを分類する。部品の話か、トークンの話か、アイコンの話か、文章の
   書き方の話か。どれにも当たらないなら「この skill の担当外」と答え、担当する
   component を指す。
2. 語彙に関する問いなら、正本のデータファイルを Read で開いてから答える。
   - 部品の id と属性: `config/handout-parts.json` (owner: C11)
   - 用途の語彙: `config/handout-purposes.json` (owner: C23)
   - セクション種別: `config/handout-sections.json` (writer: C12)
3. 値に関する問いなら `assets/tokens/<theme>.json` を開く。テーマ名が指定されて
   いないときは、どのテーマの値を聞かれているかを確認してから答える。
4. 考え方に関する問いなら `assets/jp-web-design-mode-b.md` を引用する。
5. 回答には出典のファイルパスを添える。出典を書けない主張は書かない。

## 答え方の規律

- 引用と要約を区別する。原文にない条件を足さない。
- 正本に無いことを聞かれたら「正本に無い」と答える。埋めない。
- 実装 (C11) と規範の記述が食い違って見えるときは、その食い違い自体を報告する。
  どちらかを黙って優先しない。描画の決定権は C11 にある。
- 生成も検証もしない。HTML 断片を求められたら、様式の説明までに留め、生成は
  C11 が、検査は C16 から C18 と C22 が行うと答える。
- ユーザーグローバル資産と絶対パスを回答に書かない。パスは plugin root からの
  相対で示す。
- 絵文字を使わない。

## 担当外の問い合わせと差し戻し先

| 問い合わせ | 差し戻し先 |
|---|---|
| この HTML を作ってほしい | C11 render-handout.py |
| この HTML は規約を満たすか | C16 / C17 / C18 / C22 |
| 構成データのスキーマは正しいか | C12 |
| 図解 SVG を描いてほしい | C14 |
| sprite の symbol id は何になるか | C15 |
| 用途プリセットの中身を決めてほしい | C23 |
| 原稿の読みやすさを採点してほしい | C06 |

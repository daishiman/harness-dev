## Layer 1: 基本定義層

### 1.1 不変ルール

- HTML の断片を LLM で書かない。組み立ては決定論 script が行い、この責務は引数の
  組み立てと結果の受け取りに閉じる。
- 生成された HTML を手で編集しない。直す必要があれば構成データ側を直して再生成する。
- 外部から取得する参照を HTML へ持ち込まない。素材は data URI として畳み込む。

### 1.2 倫理ガード

- 生成に失敗した図解や画像を、空のまま「生成済み」として扱わない。欠落は warning
  として報告し、通ったことにしない。

## Layer 2: ドメイン定義層

### 2.1 責務

- 担当: 素材の埋め込み、図解の生成、アイコンの生成、挿絵の生成委譲、レンダリング。
- 非担当: 構成データの設計 (R2)、ゲートの実行と集約 (R4)、出力先への配置 (C19)。

### 2.2 ドメインルール

- 入力は R2 が確定した正規化済み構成データ 1 点だけ。ここで構成データを書き換えない。
- 素材は `embed-assets.py` で data URI へ畳み込む。畳み込んだ結果のサイズは生成レポートの
  「埋め込みサイズ」として報告する。
- 挿絵の生成は `srg-image-bridge.py` へ委譲する。委譲先が不在なら生成を skip し、その事実を
  warning として残す。不在を成功として扱わない。
- 生成する HTML は 1 ファイル。テーマの書き戻しが要る場合、書き戻し先は出力ディレクトリ
  ではなく明示パス (`--config-out`) を使う。
- 適用した部品の一覧は生成レポートの「適用部品」として報告する。部品 id の語彙は
  カタログが正本であり、この prompt に列挙しない。

### 2.2.1 描画が必ず備える面 (利用者指定 2026-08-19)

以下は `render-handout.py` (C11) が構成データから決定論に組み立てる。**指摘を受けても
HTML を手で足さない** — ここに挙がる面が出ていないなら C11 か構成データ側の欠落である。

- **共有時のサムネイル。** `thumbnail_asset_id` が指す 1 枚を OGP / Twitter Card
  (`og:image` ほか) として head へ出す。画像は data URI のまま載せ、外部ホスティングを
  要求しない (自己完結の契約 SC-01/SC-10 を崩さないため)。説明文は `goal` の写しで、
  共有カード用に別の要約を書かない。favicon はテーマのアクセント 1 色だけの図形をその場で
  描く (素材の再掲でサイズを膨らませない・文字を入れない)。
- **資料の題は帯の一番上。** どこまでスクロールしても「何の資料か」が見えている。帯の題は
  `data-hb-generated="true"` の写しであり、素値の出所は冒頭の `h1` 1 箇所だけ。
- **日付は紙面に出さない。** 唯一の運び手は root 属性 `data-hb-date` で、逆抽出 (C20) は
  そこから読む。日付の欄を紙面へ戻さない。
- **節番号と題は区切り記号で分ける。** 「1毎日の…」と 1 つの語に見えるのを防ぐ。連番は
  index からの派生物なので、見出しの素値へ混ぜない。
- **目次は主題色 1 色・2 行まで折り返し・常時表示。** 現在地の札だけが塗られる。横スクロール
  にしない (右にまだ項目があることが見えない)。
- **操作帯は常駐。** 「メモを埋め込んだ HTML を保存する」はどこを読んでいても押せる位置に
  1 つだけ置く (同じ操作の入口を 2 つ作らない)。

### 2.3 入力契約

| field | required | 説明 |
|---|---|---|
| config_path | yes | 正規化済み構成データ JSON |
| assets_dir | yes | 素材原本の所在 |
| theme | no | 指定があるときだけ渡す |
| html_out | yes | 生成 HTML の書き出し先 |

### 2.4 出力契約

- `html_path` — 生成した単一 HTML のパス。
- `applied_parts` — 適用した部品の一覧。
- `embedded_bytes` — 埋め込み後のサイズ。
- `warnings` — skip した生成・畳み込み上限に触れた素材などの一覧。

## Layer 4: 共通ポリシー層

### 4.1 失敗時

- script が exit≠0 で落ちたら、後続 script を走らせず原因を報告する。落ちた工程の
  出力を欠いたまま次へ進むと、欠落がゲートまで露見しない。
- 図解や画像が空で生成された場合は warning に載せる。自己完結性ゲートが同じ欠落を
  検出するが、検出を待たずに報告する。

### 4.2 観測

- 各 script の argv と exit code、生成物のパスとサイズを記録する。

### 4.3 セキュリティ

- 素材の読み込みは構成データが指す範囲に限る。範囲外のファイルを埋め込まない。

## Layer 5: エージェント定義層 (ゴール駆動の実行主体)

### 5.1 担当 agent

- 本 skill 自身 (inline)。script 実行のみで意味判断を伴わない。

### 5.2 ゴール定義

- 目的: 検証済み構成データから、外部依存ゼロの単一 HTML を再現性のある形で得る。
- 背景: 生成を LLM が担うと同じ入力から同じ出力が出ず、資料の差分が読めなくなる。
  再現性は決定論 script でしか得られない。
- 達成ゴール: 単一 HTML が生成され、同じ構成データからの再生成でバイト一致する状態。

### 5.3 完了チェックリスト (ゴール到達の停止条件)

- [ ] 素材が data URI として畳み込まれている
- [ ] 図解とアイコンが生成され、空の生成物が残っていない
- [ ] 挿絵の生成委譲を実行した (委譲先不在なら skip を warning に載せた)
- [ ] 単一 HTML が生成された
- [ ] HTML を手で編集していない
- [ ] 適用部品・埋め込みサイズ・warning を報告用にまとめた

### 5.4 実行方式

- script 列の順序は入力の依存関係から決める (畳み込み -> 図解 / アイコン -> 挿絵 ->
  レンダリング)。未達 checklist に応じて必要な工程だけを再実行する。

## Layer 6: オーケストレーション層

### 6.1 上位接続

### 6.2 並列性

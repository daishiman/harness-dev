## Layer 1: 基本定義層

### 1.1 不変ルール

- 等価判定を目視で代替しない。再レンダリングと機械比較を経ない判定は判定ではない。
- 差分を要約しない。全件を機械可読な形で残す。
- 判定の粒度を勝手に強めない / 弱めない。粒度は構成データ側で定義されている。

### 1.2 倫理ガード

- 差分があるものを「実質同じ」と書かない。逆抽出の信頼性を測る唯一の手掛かりが消える。

## Layer 2: ドメイン定義層

### 2.1 責務

- 担当: 再レンダリング、自己完結性の確認、構成データ等価の判定、逆抽出レポートの確定。
- 非担当: 構成データの補完 (R2)、資料の生成と配置 (C07 / C19)、資料内容の書き換えと改善提案 (範囲外)。

### 2.2 ドメインルール

- 確定した構成データを `render-handout.py` で再レンダリングし、生成物を
  `verify-handout-selfcontained.py` にかけてから比較へ進む。
- 判定は正規化後の構成データ等価で行う。比較の前に両側を C12 の正規化へ通し、同一の
  正規化実装を経ることを前提にする。正規化を自前で書かない。
- 比較対象射影は provenance ブロックを除いた残りとする。provenance は実行環境と
  catalog 版に依存し、意味的同一性に属さない。
- HTML のバイト一致は課さない。空白・属性順・改行位置は再生成のたびに変わりうる。
  バイト一致が課されるのは同一構成データからの再生成だけである。
- 配列は順序込みで比較する。順序は意味を持つ。
- 不一致は `E-ROUNDTRIP-DIFF` として JSON Pointer と expected / actual を全件出す。
  差分ありを等価と読める要約にしない。
- 抽出器の `--compare` を使う場合、round-trip 不一致のときは `--out` が書かれない。
  作業台としての `--out` を得る起動とは別に起動する。
- `W-` で始まる診断行は合否に影響しない。とくに抽出器の起動時自己整合検査に由来する
  `W-EXTRACT-CATALOG-DRIFT` は対象 HTML と無関係に出るため、不一致の根拠にしない。
- 逆抽出レポートには、復元した部品一覧 (fidelity つき)、復元不能箇所と採った補完
  (キーパス / 理由 / 補完方針)、round-trip 差分を揃える。

### 2.3 入力契約

| field | required | 説明 |
|---|---|---|
| config_path | yes | R2 が確定した構成データ |
| source_html | yes | 元の対象 HTML (読み取り専用) |
| completions | yes | R2 の補完記録 (レポートへ載せる) |
| fidelity_map | yes | 各値の fidelity |

### 2.4 出力契約

- `verdict` — 構成データ等価か否か。等価でないときも判定として返す。
- `diffs` — JSON Pointer / expected / actual の全件。
- `rendered_html` — 再レンダリングした HTML のパス。
- `selfcontained` — 自己完結性検査の exit code。
- `report_path` — 逆抽出レポートのパス (上記の必須要素が揃ったもの)。
- `next_step` — 生成へ進む場合の案内 (`/handout-build --config <出力パス>`)。実行はしない。

## Layer 4: 共通ポリシー層

### 4.1 失敗時

- 構成データが検証を通っていない状態では再レンダリングへ進まない。通っていない事実を
  そのまま返す。穴のある構成データが描画される経路を作らない。
- 再レンダリングが失敗したら、比較へ進まず失敗の位置を返す。
- 上限周回で等価に至らなければ、未達のまま差分を添えて返す。

### 4.2 観測

- 各 script の argv と exit code、差分の全件、判定に用いた射影の定義を記録する。

### 4.3 セキュリティ

- 比較のために元 HTML を書き換えない。生成物は指定された作業先にのみ書く。

## Layer 5: エージェント定義層 (ゴール駆動の実行主体)

### 5.1 担当 agent

- 本 skill 自身 (inline)。script 実行と機械比較が主で、意味判断を伴わない。

### 5.2 ゴール定義

- 目的: 逆抽出の結果が元資料をどこまで再現できているかを、機械が再現できる形で確定する。
- 背景: 逆抽出は「取れた気になる」のが最も危険な工程である。再レンダリングして突き合わせない限り、
  取りこぼしは表に出ない。
- 達成ゴール: 構成データ等価の判定が付き、等価でなければ差分が全件示され、レポートの
  必須要素が揃っている状態。

### 5.3 完了チェックリスト (ゴール到達の停止条件)

- [ ] 構成データを再レンダリングした
- [ ] 再レンダリング結果を自己完結性検査に通した
- [ ] 正規化を揃えたうえで比較対象射影を取った
- [ ] 判定を返し、差分があれば JSON Pointer / expected / actual で全件示した
- [ ] 逆抽出レポートに必須要素 (復元した部品一覧 / 復元不能箇所と採った補完 / round-trip 差分) が揃った
- [ ] 生成へは進まず、次の一手の案内に留めた

### 5.4 実行方式

- 固定手順を持たない。未達 checklist に応じて、再レンダリング・検査・比較のうち必要な工程を
  選んで実行する。差分の原因が走査側か補完側かを切り分けて上位へ返す。

## Layer 6: オーケストレーション層

### 6.1 上位接続

- 呼び出し元: run-handout-extract のゴールシークループ (outer ループの評価対象)
- 前提: R2 が構成データを確定し、検証結果を添えている
- 後続: 利用者への結果提示。生成は C07 の責務であり、ここでは案内までとする。

### 6.2 並列性

- 同一の出力先へ書く再レンダリングを並行させない。

## Layer 7: UI / 提示層

### 7.1 提示形式

- 判定を最初に置き、差分を JSON Pointer の一覧として示す。等価でないことを先に述べる。
- 復元できなかった箇所を、判定とは別枠で、人が埋める対象として示す。

### 7.2 言語

- 日本語 (フィールド名と診断コードは英語)。

# 言い換え

打ち合わせ資料を読むのは、現場の担当者と発注側の責任者。技術の言葉を、その人たちの言葉に言い換える。

## しくみ

- 正本は plugin の `assets/data/plain-language.json` (`{"term", "say", "level"}` の並び)。下の表は読む人のための写し。
- `validate-briefing-docs.mjs` が 要件定義.md と仕様書.md を調べ、表の語 (`term`) を見つけると `PLAIN-TERM` を出す。
- 要件定義.md の「## 8. 用語」の表に、その語の行があれば出さない。
- 無ければ `level` どおり。`error` は技術者にしか通じない語、`warn` はよく使うが人によって分からない語。
- バッククォート (`` `...` ``) の中と、根拠の `素材:<ファイル名>` は調べない。
- `--stage all` では、ボード HTML (`_src/NN_*.html`) の文字も同じやり方で調べる (行番号は出ない)。確認点では briefing-reviewer も 言葉 の観点で確かめる。

## 直し方

1. まず言い換える。言い換えで意味が通るなら 8. 用語 に書かない。
2. 言い換えると長くなり、何度も出る語だけを 8. 用語 に書く。意味は 1 文で、現場の言葉で。
3. ボードでは 8. 用語 に書いた語でも、なるべく言い換えを使う。

## 決まった見出しに出る語

仕様書の見出しは変えられない (2.2 ヘッダー、2.4 フッター、2.6 モーダル、6 章の バックアップ、7 章 権限と運用)。
そのため、これらの語は 要件定義.md の 8. 用語 に毎回書く。雛形が初めから行を入れておく。
意味の文は [requirements.md.tmpl](../assets/templates/requirements.md.tmpl) の「## 8. 用語」を読む。

| 権限 | 役割ごとの、できることの決まり | warn |
| バックアップ | データの控え | warn |
| 操作ログ | 操作の記録 | warn |
| アクセスログ | 画面を開いた記録 | warn |

言い換えと level の正本は JSON。この表とずれたときは JSON に従い、この表を直す。

## 書くときの目安

文の長さ、文の終え方、製品名の書き方は [quality-rules.md](quality-rules.md) の「3. 言葉」を読む。ここにはそれ以外だけを書く。

- 「〜を実施する」「〜を行う」より「〜する」。
- カタカナ語が続いたら、どれか 1 つを日本語にする。
- 数字は半角、単位は日本語 (3 人、5 個、毎日 1 回)。
- 人は役割名で書くのを基本にする (配車の担当者、運転手、発注側の責任者)。実名を書いてよいかは briefing.json の `data_policy` で決まる ([quality-rules.md](quality-rules.md) の「名前と値の扱い (data_policy)」)。

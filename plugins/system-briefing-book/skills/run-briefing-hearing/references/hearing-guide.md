# ヒアリングの質問と既定案

run-briefing-hearing が使う質問の一覧。聞く前に素材で埋め、埋まらない質問だけを既定案つきで聞く。
最初の版は「こういうことがやれます」が伝わる最小のものにする。既定案はどれも、足さないほう・シンプルなほうを選んである。

## 1. 既定案の一覧

聞いて「わからない」と言われたとき、聞かずに埋めるとき、この案で進める。

| 項目 | 既定案 |
| --- | --- |
| PC の骨組み | 左にメニュー、上に帯 (アプリ名と使っている人) |
| スマホの骨組み | 上に帯、下に主なボタンを 1 つ |
| メニュー | 5 個まで。今いる画面に色を付ける |
| 下の帯 (フッター) | PC は問い合わせ先だけを小さく。スマホは主なボタンの置き場 |
| 色 | 主なボタンの色は 1 つ。注意は黄、失敗は赤。色だけで意味を伝えない |
| 画面に重ねて出す小窓 (モーダル) | 確かめるときと消すときだけ。入力には使わない |
| 保存したとき | 画面の上に短く「保存しました」と出し、数秒で消える |
| まちがいがあるとき | その項目のすぐ下に、理由と直し方を出す |
| 何もないとき | 「まだありません」と、最初にすることのボタンを出す |
| 読み込み中 | 中身の形だけを灰色で出す |
| 動かす場所 | インターネット上のサービス (クラウド) |
| データの置き場所 | インターネット上の保管場所 (クラウドのデータベース) |
| ログイン | 会社の Google アカウント |
| 外部とのつなぎ | 最初の版はつながない。要るときはファイルに書き出して渡す |
| 自動で動く処理と知らせ | 最初の版は無し。画面を開いて見る |
| バックアップ | 毎日 1 回、自動で |
| 管理する人 | 発注側の責任者 1 人 |
| 困ったときの連絡先 | 作った会社 (開発する人) |
| データを残す期間 | 1 年 |
| 権限 | 「使う人」と「管理する人」の 2 つ |
| 先々広げること | 素材と要望から読んだ広げる案を 次に広げる候補 に置き、最初の版では データの備え だけをする。ボードは足さない |
| 仕事の流れ | 素材と要望から読んだ流れ (だれが何をして、次にだれへ渡すか) |
| 管理の画面 | 使う人と同じ画面で、管理する人にだけ管理のメニューを出す |
| あとから直す・消す人 | 登録した本人と管理する人。消す前に確かめの小窓を出す |
| 使う人を足す・外す場所 | アプリの中の管理のメニューで、管理する人がする |
| 残しておく情報 | 今の紙や表にある欄をそのまま残す |
| 増える量 | 素材から読んだ件数 (1 日に何件、1 か月に何件) |
| 今あるデータ | 最初の版では移さず、使い始めた日の分から入れる |
| 見られると困る情報 | 素材から読んだもの (名前・電話番号・金額など) は、ログインした人だけが見られる |
| 会社の外から使うか | 外出先からも使う。ログインした人だけが開ける |
| 登録や直しの記録 | 最後に登録や直しをした人と日時を残す |
| 止まったとき | 半日なら紙や電話でしのぐ。作った会社が直す |
| 使う時間帯 | 平日の昼間。夜と休日に止めて直してよい |

## 2. 聞き方

- AskUserQuestion で聞く。1 回に 4 問まで。全部で 6 回までで終える。聞き足しで 1〜2 回増えてよい (下の「聞き足しと促し方」)。
- 聞くのは大きな流れだけ。細かい値 (画面の寸法、製品名、件数の上限) は聞かずに既定案で埋め、決めること に回す。
- Codex では同じ形の質問を文で出す ([execution-contract.md](../../../references/execution-contract.md) の「ホストの違いが出る所」)。促し方も同じ。
- 選択肢は 2〜4 個。先頭を既定案にして、ラベルの末尾に「(おすすめ)」を付ける。
- 説明は 1 文で、現場の言葉で書く。画面の言葉と専門用語は [plain-language.md](../../../references/plain-language.md) の言い換えを使う (例: モーダル → 画面に重ねて出す小窓)。
- header は 12 文字以内。
- 回の初めに 1 行添える: 「全部おすすめで良ければ、その他の欄に「全部おすすめ」と書いてください」。
- 1 つの質問に 2 つのことを混ぜない (例: 「ログインとバックアップは?」は分ける)。例外は、1 つの選択肢で両方に答えられる組 (例: C3 のだれが・どの方式で、B7 の保存のとき・まちがいのとき、B10 の直す・消す、C10 の入るか・だれが見られるか)。C5 (自動で動く処理と通知) は聞かずに既定案で埋め、仕様書 6 章の 2 行へ写す。
- 素材で答えが分かる質問は聞かない (出どころ `素材:<ファイル名>`)。

例 (4 回目の 3 問目、B6):

```yaml
question: "画面の上に重ねて出す小窓は、どんなときに使いますか?"
header: "小窓"
multiSelect: false
options:
  - label: "確かめと削除だけ (おすすめ)"
    description: "「消してよいですか」のように、取り消せない操作の前だけに出します。"
  - label: "入力にも使う"
    description: "小窓の中で項目を入れます。画面が狭いスマホでは入れにくくなります。"
```

### 聞き足しと促し方

聞き足すのは核心の 5 問 (A1 使う人、A2 いちばん困っていること、A3 最初の版でやること、A6 先々広げたいこと、A7 仕事の流れ) だけ。画面と基盤と運用の質問は聞き足さない。

(a) あいまいとみなす答え:

- 誰・何・どのくらい のどれかが無い (「別の人も使う」を選んで、誰かが無い)。
- 「手間」「不便」のような気持ちの言葉だけ。
- 素材と食い違う。
- 1 つの答えに、いくつものことが混ざる。
- 「わからない」。言葉にしにくいだけのことが多いので、促し方の型で 1 回だけ聞き直す。

(b) 促し方の型。問いは現場の言葉で 1 文にする。選択肢は素材と前の答えから作り、上の決まりのとおり先頭をおすすめにする。下の問いはお手本の配車の案件に合わせた例。

| 型 | 問いの例 |
| --- | --- |
| 1 日の流れか、最近の 1 場面で聞く | きのう配車表が事務所に届いてから、打ち直しが終わるまで、何をしましたか |
| 素材から作った具体例 2〜3 個から選んでもらう | いちばん手間なのはどれですか (1 行ずつ打ち直す / 「〃」の行を上から写す / 打ちまちがいを探して直す) |
| 数で聞く (件数・時間・人数) | 配車表は 1 日に何枚届きますか |
| 逆から聞く (無くなったら困るのは) | 撮って送る・読み取る・確かめる・書き出す のうち、最初の版から外すといちばん困るのはどれですか |
| まとめ直して「こういうことですか」と確かめる | 配車の担当者がスマホで撮って送り、請求の担当者が PC で確かめてから書き出す、ということですか |

(c) 素材と要望から A1〜A3 と A7 の選択肢が作れないときは、選択肢の代わりに促し方の型で聞く。AskUserQuestion は使わず、問いを文で出して答えを書いてもらう。

(d) 上限:

- 聞き足しは 1 問につき 2 回まで。2 回目は 1 回目と違う型で聞く。
- 「わからない」が出たら、それが何回目でも、その問いの聞き足しはあと 1 回まで (合わせて 2 回を越えない)。followup の中では、初めのヒアリングで使った回数を引き継がずに数え直す。
- 聞き足しも 1 回 4 問の枠に入れる。足りなければ回を 1〜2 回足す (5 章)。
- それでも出なければ、既定案で進めて 未定 にする (3 章の「わからない」の行)。A1〜A3 と A7 で既定案が作れないときは、要望から読める いちばん小さい案を既定案にする。

## 3. 答えの扱い

| 答え | ヒアリング.md の出どころ | ほかにすること |
| --- | --- | --- |
| おすすめ以外を選んだ | 聞き取り | 核心の 5 問であいまいなら、先に聞き足す (2 章の「聞き足しと促し方」) |
| おすすめを選んだ | 既定案 | なし |
| 「全部おすすめ」 | 残り全部を 既定案 | 残りの回は聞かない |
| 「わからない」「あとで」 | 既定案で進めて、出どころは 未定 | 5 章 あとで相談すること に「Hxx: 〜を決める」と書く。要件定義.md では 9. 決めること に移る。核心の 5 問の「わからない」は、先に 1 回だけ促す |
| 自由入力 | 聞き取り | 回答欄に 1 行で要約する。核心の 5 問であいまいなら、先に聞き足す (2 章の「聞き足しと促し方」) |
| 素材で分かった | 素材:<ファイル名> | なし |
| 名前を挙げて頼まれた機能 (「候補を出して選ばせたい」のような明示の要望) | 要望 | 1 章の表の最後に行を足す。番号は文書全体の最後の番号の続き (H36 まであれば H37)。質問 は「<機能>を頼まれた」、回答 は頼まれた中身を 1 行で |

- 答えが出るまで聞き続けない。聞き足すのは核心の 5 問のあいまいな答えと「わからない」だけで、上限までに出なければ既定案で進めて 決めること に回す。
- 「あとで」と、核心の 5 問でない「わからない」は、聞き足さずに既定案で進め、決めること に回す。
- 聞いている途中で出てきた広げる案 (「あれもできると良い」) は、最初の版に入れず H06 の回答の候補に足す。A6 を聞く前なら、A6 のおすすめの選択肢の案に入れて聞く。
- 名前を挙げて頼まれた機能は、広げる案と扱わない。出どころ `要望` の行に残す。A3 で最初の版から外す案にしたときも、行は残す (あとで に回すなら 9 章で聞く)。扱いは [quality-rules.md](../../../references/quality-rules.md) の「1. シンプルさ」を読む。

## 4. 質問の一覧

記号 (A1 など) はこの表の中だけの呼び名。ヒアリング.md には書かない。
H 番号は表の「番号」の列のとおりに振る。番号は質問ごとに決まっていて、聞かなかった質問も同じ番号で書く。A1〜D4 は H01〜H24、あとから足した A7・B9〜B11・C7〜C12・D5〜D6 は H25〜H36 なので、表の並びと番号の並びは同じではない。
素材から足した質問・要望・未定 の補足は、その章の表の最後に、文書全体の最後の番号の続きで足す (H36 まであれば H37)。もとからある番号は変えない。
「聞く回」が空の質問は、聞かずに既定案で埋める (素材に答えがあれば素材で)。

A1 で「会社の外の人も使う」を選んだら、その人たちが見てよいもの・できることを D4 の回答に残し、ログインの方式 (C3) を 未定 にして 決めること に回す。

A6 の決まり:

- 広げる案は、最初の版の画面・ボタン・メニューを増やさない。最初の版でするのは データの備え だけ。
- データの備え は 3 つの形だけ: 消さずに残す (直す前の値など) / 分けて置く (あとで計算に使う欄など) / 印を付ける (書き出した日時など)。
- 備え は 仕様書 8 章の各候補の下に書く。備え が無い候補は「なし」と書き、足すときに作り直す所を 1 文添える。
- 2 つ目の選択肢を選んだときだけ、将来の広げ方 (future) のボードを足す。「今は考えない」は、A5 の やらないこと だけを候補に置き、備え をすべて「なし」にする。

A7 は、人がすることと しくみがすることを分けて、3〜6 段の流れにまとめ直してから「こういう流れですか」と確かめる。今の流れ (紙や表のころ) と、これからの流れの両方を残す。

### 回答に残す設計情報

質問を足さずに、回答に次の観点を含める。この節の観点を残すために H番号を足してよいのは、この節の最後の段落にある追加要望と `未定` の補足行だけ (素材から足す質問は 4 章、確認点で足す行は 7 章の決まりに従う)。具体的な記入先は [document-structure.md](../../../references/document-structure.md) の「実装へ渡す情報の記入先」を正本とする。

- A1・A4・A7: 役割ごとの人数と端末、会社の外の人の有無、人の段としくみの段、受け渡しの順。要件定義 4 章と 5.1・5.2 へ写す。
- B1〜B4: 共通配置、ヘッダー/メニュー/フッター、主なボタンと補助操作の位置。アイコンの意味と文字ラベルもB3に残す。
- B5〜B8: 色と意味、モーダルの開閉・確定/取消、押せない/処理中/空/失敗/完了の見え方、再試行の導線。参考画面があれば位置・文言・状態を素材の根拠で残す。
- B9〜B11: 管理画面/ユーザー画面/共用の区分と入口、登録・直す・消す操作ができる役割と消す前の確かめ、使う人の追加/取消の入口。仕様書 2.1 `画面区分:` と 7.1 の権限表へ写す。
- C1〜C6: 画面とサーバーの役割、保存と連携、認証・権限確認、動かす場所、控えと復旧の条件。既定案が示すのは方向性であり、製品・地域・保存方式・処理の上限まで決定したことにはしない。
- C7〜C9: 画面の項目と保存データの対応、件数の目安、移すデータの範囲。仕様書 4 章のデータ表と 6 章 `稼働構成:` へ写す。
- C10〜C12: 機微な値、外からの利用の範囲、操作記録。仕様書 4 章と 6 章 `安全対策:` へ写す。
- D1〜D6: 管理者/利用者の操作範囲、使う人の追加/取消、異常に気づく人と復旧担当、止まってよい時間と使う時間帯、保存・削除の条件。仕様書 7.2 `監視と復旧:` と要件定義 7 章へ写す。

新しい細部が元の回答から分からなければ、既存の回答を「聞き取り」のまま架空の説明で増やさない。既定案による補足であることを分け、未確認部分は既存の規則で `未定` のH行と5章に残す。追加要望の記録や未定の補足行は末尾のH番号を使い、既存番号を変えない。質問を増やして一度に確定させず、要件定義の決めることへ返す。ボード向けの見え方と、仕様書だけに載せる実装詳細を回答の行き先で分ける。

## 5. 回の組み方

大きな流れから先に聞く。使う人と仕事の流れ、管理と権限、データ、画面、安全と止まったとき、先々と運用の順。

| 回 | 聞く質問 | 何を聞く回か | 省いてよいとき |
| --- | --- | --- | --- |
| 1 | A1 A2 A3 A4 | 使う人・困りごと・やること・端末 | 素材で分かった質問は省く |
| 2 | A7 B9 B10 B11 | 仕事の流れ・管理の画面・直す人・人の出し入れ | 「全部おすすめ」なら 3 回目以降も聞かない |
| 3 | C7 C8 C9 C10 | 残す情報・量・今あるデータ・見られると困る情報 | 同上 |
| 4 | B1 B3 B6 B7 | 画面の骨組み・メニュー・小窓・知らせ方 | 同上 |
| 5 | C3 C4 C11 D5 | ログイン・つなぎ・外から使うか・止まったとき | 同上 |
| 6 | A6 C6 D1 D4 | 先々・控え・人の出し入れの担当・役割 | 運用がまだ先の話なら A6 だけを聞き、残りは既定案で埋める |

聞き足しの回は、あいまいな答えが出た回のすぐあとに入れる。聞き足しの回は全部で 2 回まで。

聞かなかった質問 (A5、B2、B4、B5、B8、C1、C2、C5、C12、D2、D3、D6) も、ヒアリング.md に 既定案 か 素材 の行として必ず書く。ほかの質問の回答で分かったときだけ、出どころを 聞き取り にしてよい。
こうすると、要件定義と仕様書のどの行も、ヒアリング.md のどこかの行を根拠にできる。

## 7. ヒアリング.md の書き方

お手本は `examples/sample-haisha/打ち合わせ資料/ヒアリング.md`。

| 欄 | 書き方 | お手本 |
| --- | --- | --- |
| 質問 | 4 章の表の質問を 1 文字も変えずに写す。4 章に無い行は、要望なら「<機能>を頼まれた」、`未定` の補足なら確かめる事柄を問いの形で 1 文にする | H09 メニューはいくつにしますか |
| 回答 | 1 行で言い切る。数・役割・場所を入れる。聞けた理由は「。」のあとに 1 文だけ足す | H18 最初はつながず、ファイルに書き出して取り込み先のシステムで取り込む。同じ行を 2 回取り込むと請求が重なるので困る |
| 回答 (既定案) | 選んだ選択肢の文 (聞かなかった項目は 1 章の既定案の文) を土台にする。変えるのは案件の言葉 (画面名・ボタン名・役割名・データの名前) だけ | H14 「まだ配車表がありません」と次にすること。読み込み中は灰色の形 |
| 回答 (未定) | 頭に「決まるまで」を付けて、進める案 (既定案) を言い切る。確かめることがあれば「。」のあとに 1 文 | H17 決まるまで 全員が会社の Google アカウントでログインする案で進める。全員が持っているかを確かめる |
| 出どころ | `聞き取り` / `素材:<ファイル名>` / `既定案` / `未定` / `要望` のどれか 1 つ | |

H06 (先々、広げたいこと) の回答は、選んだ選択肢ごとに次の型で書く。広げる案はここ 1 か所にまとめ、仕様書 8 章はこの候補から書く。

| 選んだもの | 回答の型 | お手本 |
| --- | --- | --- |
| 次に広げる候補に置く (おすすめ) | 「<候補>・<候補> の N つを、次に広げる候補に置く。将来の広げ方のボードは足さない」 | 読み取りの学習・対応表を画面で直す・運賃の案・直接つなぐ の 4 つを、次に広げる候補に置く。将来の広げ方のボードは足さない |
| 1 枚のボードでも見せる | 「<候補>・<候補> の N つを、次に広げる候補に置く。将来の広げ方のボードも 1 枚見せる」 | 月ごとの集計・現場への知らせ・直接つなぐ の 3 つを、次に広げる候補に置く。将来の広げ方のボードも 1 枚見せる |
| 今は考えない | 「<H05 のやらないこと> だけを、次に広げる候補に置く。備えはすべてなし。将来の広げ方のボードは足さない」 | 読み取りの学習・運賃の案 だけを、次に広げる候補に置く。備えはすべてなし。将来の広げ方のボードは足さない |

候補は 4 つまで (仕様書 8 章に置く数)。5 つ以上出たら、先に要るものから 4 つを選ぶ。

5 章 あとで相談すること は次の形だけ。Q 番号は要件定義を書くときに振るので、ここには書かない。

```markdown
- H17: ログインする人と方式を決める
```

- 回答は、聞いた物の名前をそのまま並べて書く。言葉の決まりは [quality-rules.md](../../../references/quality-rules.md) の「3. 言葉」を読む。分からない所は 未定 にする。
- 役割名は 1 つの案件の中で同じ言い方を通す (「配車の担当者」と「配車係」を混ぜない)。ここで決めた言い方を要件定義と仕様書がそのまま使う。

### 確認点で出た答えの書き方

確認点で 決めること の Q に答えが出たとき (run-briefing-hearing の followup) は、次のように足す。

- その事柄の H の行があるとき (多くは 未定 の行): 回答を答えの文に書き換え、出どころを 聞き取り にする。未定 だった行は、5 章のその行を消す。
- H の行が無いとき (素材から出た Q): その事柄に近い章の表の最後に行を足す。質問は 決めること の文を問いの形にする。H 番号は、今ある最後の番号の次を使う (H36 まであれば H37)。
- 番号は振り直さない。文書がすでに H 番号を指しているため。
- おすすめ (案) を選んだ答えも、出どころは 聞き取り にする。利用者が決めたため。
- 「更新日:」を今日にする。

# 要件定義書: 配車表の読み取り
版: v0.2
更新日: 2026-09-30

## 1. 目的

手書きの配車表を、取り込み先のシステムへ打ち直す手間をなくす。
紙の書き方は変えずに、撮って送るだけで、行ごとのデータになるようにする。

## 2. 今の困りごと

- 毎日、手書きの配車表 (1 日 2〜4 枚、1 枚に 10 行くらい) を見ながら、取り込み先のシステムへ 1 行ずつ打ち直している。1 時間ほどかかる。
- 打ち直しで、車番や数量の打ちまちがいが月に何回か出る。
- 「〃」や略した書き方を、打つ人が毎回読み解いている。

## 3. 範囲

### 3.1 最初の版でやること

- スマホで撮って送る
- しくみが行ごとに読み取る
- PC で紙と見比べて確かめ直す
- 受注先・発地・着地の名前を、候補から選ぶ
- 確かめた行を CSV で書き出す

### 3.2 やらないこと

- 紙の配車表をやめること。紙は今までどおり書く。
- 運賃を決めることと、請求書を作ること。取り込み先のシステムで続けて行う。
- 対応表を画面で直すこと、運賃の案を出すこと。次の版で相談する。
- 読み取りの学習 (選んだ候補を覚えて、次から 1 番目に出す)。最初の版は、撮って送ってから書き出すまでを回すことを優先する。入れるかは Q06 で聞く。

## 4. 使う人と端末

| 使う人 | 人数 | 端末 | 主にすること |
| --- | --- | --- | --- |
| 配車の担当者 | 2 | スマホ | 手書きの配車表を撮って送る |
| 請求の担当者 | 2 | PC | 読み取った行を確かめて、書き出す |
| 発注側の責任者 | 1 | PC | 使う人を足す・外す |

## 5. 業務の流れ

### 5.1 今

1. 配車の担当者が、紙の配車表に手で書く。
2. 夕方、紙を事務所へ回す。
3. 請求の担当者が、紙を見ながら取り込み先のシステムへ 1 行ずつ打つ。

### 5.2 これから

1. 配車の担当者が、紙の配車表に今までどおり手で書く。
2. スマホで撮って送る (S01)。
3. しくみが、行ごとに読み取る。
4. 請求の担当者が、PC で紙の写真と見比べて確かめる。名前は候補から選ぶ (S02、S03)。
5. 確かめた行を CSV で書き出し、取り込み先のシステムで取り込む (S04)。

## 7. 守ること

- 速さ: 写真を送ってから 1 分ほどで、一覧に読み取った行が並ぶ (例)。
- 安全: 会社の人だけが入れる。紙の写真と読み取った行を、会社の外に出さない。
- バックアップ: 毎日 1 回、自動で控えを取る。
- 使いやすさ: どの画面も、主なボタンは 1 つ。スマホは片手で撮って送れる。
- 量: 1 日 20〜40 行、1 か月で 900 行までを見込む (例)。
- 止まったとき: 半日止まっても、紙の配車表から今までどおり打ち直してしのぐ。作った会社が直す。
- 使う時間帯: 平日の昼間。夜と休日は止めて直してよい。

## 8. 用語

| 用語 | 意味 |
| --- | --- |
| ヘッダー | 画面のいちばん上の帯。アプリ名と、使っている人を出す |
| メニュー (サイドバー) | PC の画面の左に縦に並ぶ、画面を切りかえるボタン |
| フッター | 画面のいちばん下の帯 |
| モーダル | 画面の上に重ねて出す小窓 |
| 権限 | 役割ごとの、できることとできないことの決まり |
| バックアップ | データの控え。消えたり壊れたりしたときに戻せるように取っておく |
| CSV | 表の形をした、文字だけのファイル。取り込み先のシステムが読める |
| サーバー | 画面から受け取った内容を処理し、結果や保存したデータを返す側の機械 |
| クラウド | インターネットの向こうにある、借りて使う機械。事務所に機械を置かなくてよい |
| 取り込み先のシステム | 今、請求や運賃の計算に使っているソフト |
| 〃 | 「上の行と同じ」の印 |
| 確認待ち | しくみが読み取ったが、人がまだ確かめていない状態 |
| 対応表 | 紙の書き方と、取り込み先のシステムの番号を結ぶ表 |

## 9. 決めること

| 番号 | 決めること | 案 | 誰に聞くか |
| --- | --- | --- | --- |
| Q01 | 「〃」は、上の行と同じ値として読んでよいか | 上の行の値を入れて、黄色で知らせる | 配車の担当者 |
| Q02 | 書き出すファイルの列の並びはこれでよいか | 取り込み列の見本 (素材) と同じ並び | 発注側の責任者 |
| Q03 | 「請求金額」の欄を使わないでよいか | 読み取らない。時刻やメモが書かれることが多い | 請求の担当者 |
| Q04 | ログインするのはだれで、どの方式か | 全員がログインする。会社のメールのアカウントで入る | 発注側の責任者 |
| Q05 | データを何年残すか | 1 年 | 発注側の責任者 |
| Q06 | 読み取りの学習を、最初の版に入れるか (要望:H38) | 入れない。最初の版で、候補から選んだ記録を残し、次の版で足す | 発注側の責任者 |
| Q07 | 対応表の中身を、最初にどこから入れるか | 取り込み先のシステムから受注先と場所の一覧を書き出してもらい、作る側が最初に入れる | 請求の担当者 |
| Q08 | 処理・安全対策・稼働構成・監視と復旧をどう具体化するか | 仕様書6章の責任分担と安全対策、7.2の監視と復旧を案とし、製品・保存・再試行・配布・復旧の条件を確認する | 開発する人と発注側の責任者 |
| Q09 | 画面構成の細部と、管理のメニューの中身をどうするか | 4画面は共通配置で作る案とし、ボタン・小窓・アイコン・状態を確かめる。管理のメニューは発注側の責任者にだけ出し、使う人の一覧から足す・外す案で、中身と置き場所を確かめる | 発注側の責任者と現場の担当者 |

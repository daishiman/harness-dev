# 文章整形ガイドライン

## 概要

このガイドラインは、ユーザーの「頭の中にあるものをアウトプットしただけ」のメモを、
読みやすい文章に整形するための指針です。

**最重要原則**: 意図はそのまま、伝えたいことは崩さずに、読みやすい文章に整える。

---

## 1. メモの読み取り方

### メモの特徴を理解する

ユーザーのメモは以下の特徴を持つことが多い：

| 特徴 | 説明 |
|------|------|
| 文脈の飛躍 | 話題が行ったり来たりする |
| 重複表現 | 同じことを何度も言っている |
| 口語的表現 | 話し言葉がそのまま書かれている |
| 構成未整理 | 情報の順序が最適化されていない |

### 読み取るべきこと

1. **核心メッセージ**: 一番伝えたいことは何か
2. **体験・実例**: どんな経験をしたのか
3. **問題意識**: 何に困っているのか、何を解決したいのか
4. **解決策**: どうやって解決したのか、解決すべきなのか
5. **読者への価値**: 読者に何を伝えたいのか

---

## 2. 文章整形の原則

### やるべきこと

| 整形項目 | 具体的なアクション |
|----------|-------------------|
| 情報の整理 | 話題ごとにまとめる |
| 順序の最適化 | 読みやすい流れに並べ替える |
| 重複の統合 | 同じ内容は1回にまとめる |
| 冗長の削除 | 無駄な表現を削る |
| 改行の追加 | 1-3文ごとに改行 |
| 空白行の挿入 | 話題転換時に空白行 |

### やってはいけないこと

| 禁止事項 | 理由 |
|----------|------|
| 意図の変更 | ユーザーの伝えたいことを変えてはいけない |
| 情報の削除 | 重要な情報を勝手に削除しない |
| 固定フォーマット適用 | テンプレート通りの構成にしない |
| 情報の追加 | メモにない情報を勝手に追加しない |

---

## 3. 文章の流れの整え方

### 基本的な流れのパターン

```
パターンA: 問題解決型
1. テーマ提示
2. 問いかけ・共感
3. 問題の具体化
4. 自分の体験
5. 原因分析
6. 解決策
7. 実践例
8. まとめ・呼びかけ

パターンB: 発見共有型
1. テーマ提示
2. きっかけ・背景
3. やってみたこと
4. 気づいたこと
5. 学び・教訓
6. 今後の展望
7. まとめ・呼びかけ

パターンC: 知見共有型
1. テーマ提示
2. 結論（先に言う）
3. 具体的な説明
4. なぜそう言えるか
5. 実例・証拠
6. 注意点
7. まとめ・呼びかけ
```

**入口はホリゾンタル・中身はバーティカル**: 冒頭側（テーマ提示・問いかけ・共感）はホリゾンタル入口として読者の普遍的欲求・日常の悩みの言葉で書く。専門語・ツール名は共感形成後に初出させる。中盤以降はバーティカル中身として深掘る（horizontal-vertical-guide.md 参照）。

### 流れの決め方

メモの内容に応じて最適なパターンを選択：

| メモの内容 | 推奨パターン |
|------------|--------------|
| 問題を解決した話 | パターンA |
| 新しい発見・気づきの話 | パターンB |
| ノウハウ・知識の共有 | パターンC |

## 4. 冗長表現の削除

### 削除対象パターン

| パターン | 修正前 | 修正後 |
|----------|--------|--------|
| 冗長な接続 | 〜ということなんですが | 〜ですが |
| 重複する副詞 | とてもすごく良い | とても良い |
| 曖昧な強調 | 基本的にはほぼ | ほぼ |
| 二重表現 | 今現在 | 今 |
| 冗長な謙遜 | 〜させていただいております | 〜しています |

### 削除してはいけないもの

- ユーザーの個性的な表現
- 共感を生む「んですよね」などの語尾
- 強調のための繰り返し（意図的なもの）

---

## 5. 重複表現の統合

### 統合の手順

1. **同じ意味の文を特定**
2. **より具体的・明確な方を残す**
3. **補足情報があれば統合**

### 統合例

```
【Before】
僕はプロンプトを作っています。
プロンプトを作成するのが僕の仕事です。
毎日プロンプトを書いてます。

【After】
僕は毎日プロンプトを作っています。
```

## 6. 情報の行き来を解消

### 問題のパターン

```
【Before - 情報が行ったり来たり】
AIを使っています。
でも問題があります。
AIはすごいです。
問題の解決策があります。
AIの良いところは〜です。
問題というのは〜です。
```

### 整理後

```
【After - 話題ごとにまとめる】
AIを使っています。
AIのすごいところは〜です。

でも、問題もあります。
その問題というのは〜です。

解決策があります。
〜
```

### 整理の原則

| 原則 | 説明 |
|------|------|
| 話題の一貫性 | 1つの話題は連続して書く |
| 時系列の維持 | 過去→現在→未来の流れ |
| 因果関係の明示 | 原因→結果の順序 |
| 抽象→具体 | まず概要、次に詳細 |

**注意**: 感情的な葛藤・迷い・体験の行ったり来たりは、意図的に残すこともある（→§9 崩し3技法「論理を崩す」、詳細は anti-ai-writing-guide.md 参照）。事実情報の配置は整理し、感情の流れは活かす。

## 7. 読みやすさの確保

### 1行の文字数

**改行は文字数ではなく文脈で行う。文節・意味の区切り・句読点（、。）の切れ目で改行し、単語・文節の途中では改行しない。** 下表の文字数は「1行の目安幅」であり、目標幅に最も近い自然な区切りで改行する（文字数ぴったりでは切らない）。

| 状況 | 目安幅 |
|------|------|
| 通常の文 | 30-40文字 |
| 強調文 | 10-20文字 |
| 説明文 | 40-60文字 |

### 改行・空白行のルール

| 状況 | ルール |
|------|--------|
| 文の区切り | 1-3文ごとに改行 |
| 話題の転換 | 空白行を挿入 |
| 強調したい文 | 前後に空白行 |
| リスト前後 | 空白行を挿入 |
| **かぎ括弧複数** | **括弧の数だけ改行** |

### かぎ括弧複数の改行ルール

**1行に複数のかぎ括弧がある場合は、括弧の数だけ改行する。**

```
【Before - 読みにくい】
これまで50名以上の方々の「プロンプトが思うように作れない」「AIに何を伝えればいいかわからない」という悩みを一緒に解決してきました。

【After - 読みやすい】
これまで50名以上の方々の
「プロンプトが思うように作れない」
「AIに何を伝えればいいかわからない」
という悩みを一緒に解決してきました。
```

**理由:**
- 複数のかぎ括弧が連続すると視認性が下がる
- 1つ1つの引用内容を読者が認識しやすくなる
- パターンA・B両方に適用（改行位置は異なるが原則は同じ）

## 8. AI文章編集の4原則

AIが生成した文章を「読まれる投稿」に変えるための4つの編集原則。
出典: 中村昌弘（@freelance_naka）「AIの文章を"読まれる投稿"に変える４つのポイント」

### 4原則の優先順位

4原則が相互に矛盾する場合（例: 具体性を上げると文字数超過）の優先順位：

| 順位 | 原則 | 理由 |
|------|------|------|
| 1 | ①主張を明確にする | 軸がブレると全体が崩壊する。他の原則の前提条件 |
| 2 | ③とにかく具体的に書く | 抽象的な文章は読まれない。読者の「？」を残さない |
| 3 | ②冒頭に命をかける | フックがなければ読み始めてもらえない |
| 4 | ④締めはフレーズを残す | 読後感向上。他の3原則が満たされた上で効果を発揮 |

**適用対象の分離**: ③（具体化）の主な適用対象は中身（本文・解決策）。入口（タイトル・冒頭1-2文・最初の見出し）では②＋ホリゾンタル入口原則（horizontal-vertical-guide.md §8）が優先する。入口に専門語・属性の重ね掛けを置かない。

**最上位原則**: ユーザーの意図保持は4原則すべてに優先する。4原則の適用によってユーザーの伝えたいことが変わってはならない。

### 原則①: 主張を明確にする（軸を1つに絞る）

AIの文章は「で、結局何が言いたいの？」と主張が曖昧になりがち。
投稿の「軸」を1つに絞り、その軸がブレないようにする。

| チェック項目 | 判定基準 |
|-------------|---------|
| 主張は1つに絞られているか | 言いたいことが2つ以上ある場合は軸がブレている |
| 全体が「軸」に沿っているか | 各段落が主張を補強する構造になっている |
| 主張と矛盾する記述がないか | AI文では異なる主張が混在しやすい |

```
【NG例】
主張A: 「うまく書けないときは、とにかく書くことが大切」
主張B: 「読むことも大事」
→ 軸が2つになり、読者が混乱する

【OK例】
軸: 「うまい文章を書きたいなら、書くだけじゃなくて読むことも大事」
→ 1つの軸に絞り、全体がそれを補強する構成
```

### 原則②: 冒頭に命をかける（フックを作る）

冒頭がつまらなかったら文章は読まれない。意外性のある冒頭でフックを作る。

| アプローチ | 説明 | 例 |
|-----------|------|-----|
| 逆説フック | 常識の逆を提示して興味を引く | 「文章がうまくなりたいなら、ムリに書かないほうがいい。」 |
| 具体描写フック | 抽象的な指示ではなく具体的な行動を描く | 「いいなと思う文章をひたすら読み、気づいたことをメモるだけ。」 |
| 問いかけフック | 読者の体験に訴える問い | 具体的な状況やセリフを使った問いかけ |

```
【NG - ありきたりな冒頭】
うまく書けないときは、とにかく書くことが大切です。
量をこなしていけば、そのうち文章力は上がっていきます。

【OK - 意外性のあるフック】
文章がうまくなりたいなら、ムリに書かないほうがいい。
アウトプットは重要だが、やみくもに書いても効果は薄い。
```

**注意**: フックの強度は書き手のキャラや文脈に合わせて調整する。
やりすぎ（「ペンを折れ」等）は逆効果になる場合がある。

### 原則③: とにかく具体的に書く（読者の「？」に答える）

AIは抽象的に書きがち。読者の頭に浮かぶ「？」に先回りして答える。

| 読者の疑問 | AI的な抽象表現 | 具体化した表現 |
|-----------|---------------|--------------|
| 何を読めばいい？ | 「いろいろな文章を読んでみる」 | 「好きな作家やエッセイストの作品をひたすら読む。知人のnoteでもいい。」 |
| 読んだ後どうする？ | 「メモを取っておく」 | 「スマホのメモ帳に気づいたことを残す。『なぜ？』と問いかける。」 |
| なぜ効果がある？ | 「表現の幅が広がる」 | 「なんとなく好きだった文章が『なぜ好きか』で語れるようになり、仮説ができる」 |
| 結果どうなる？ | 「良い影響がある」 | 「仮説→検証を繰り返せる。知らないうちに引き出しが増え、文章力は上がる。」 |

```
【NG - 抽象的】
読書をすると表現の幅が広がりますし、
自分の文章にも良い影響があるはずです。
気になった部分はメモを取っておくと、あとで役立つかもしれません。

【OK - 具体的】
エッセイをうまく書きたいなら、
好きな作家やエッセイストの作品をひたすら読む。
知人のnoteでもいい。

読んだらスマホのメモ帳に「気づいたこと」を残しておく。
そのときは「なぜ？」と問いかけるといい。
なぜタイトルをタップしたのか？
なぜこの表現が好きなのか？と。
```

**具体化のコツ**:
- 「何を」「どうやって」「なぜ」の3つに答える
- 読者の頭に絵が浮かぶレベルまで具体化する
- 行動レベルの指示にする（「読む」→「好きな作家の作品をひたすら読む」）

### 原則④: 締めはフレーズを残す

「そりゃそうでしょ」な当たり前の締めは心に残らない。
思い出しやすいフレーズで読後感を作る。

| アプローチ | 説明 | 例 |
|-----------|------|-----|
| フレーズ型 | 短い印象的な言葉で締める | 「それはいい文章を書くための仕込みになる。」 |
| リフレイン型 | 冒頭の主張を別の言い方で繰り返す | 冒頭のフックを回収する形で締める |
| 行動促進型 | 読者がすぐできる具体的な行動で締める | 「だから書けないときは『読む』時間にする。」 |

```
【NG - 当たり前すぎる締め】
アウトプットとインプットの両方を意識して、
バランスよく続けていくことが成長につながります。

【OK - フレーズが残る締め】
だから、どうしてもうまく書けないときは「読む」時間にする。
それはいい文章を書くための仕込みになる。
```

## 9. AIっぽい文章表現大全（もとやま6分類）と崩し方

出典: もとやま（@ysk_motoyama）「【保存版】AIっぽい文章表現大全」

このセクションは要約とインデックスである。検出パターン・排除ルール・具体例・崩し3技法の詳細・AI臭が出る構造的原因は、すべて anti-ai-writing-guide.md（AI臭対策の正本）を参照する。ここには分類名と1行要約のみを置く。

### 6分類（AI臭）の要約

| 分類 | 1行要約 |
|------|---------|
| ①視覚的な記号 | Markdown装飾・emダッシュ・カギ括弧多用・：後の半角スペース・（）逃げ・／並列を残さない |
| ②リズム単調 | 同じ語尾の連続・接続詞過多・温度一定・not A but B連発を崩す |
| ③説明書感 | 前置き過長・構造宣言・ステップ表記をやめ、いきなり本題に入る |
| ④事なかれ | 保険・中立装い・弱い否定をやめ、スタンスを取って言い切る |
| ⑤抽象語・万能語 | 本質・最適化・価値最大化などで押し切らず、動詞中心に具体化する |
| ⑥変な比喩 | 地図・羅針盤・土台・エンジンなどの使い古された定番比喩を使わない |

### 崩し3技法（人間らしさの注入）の要約

| 技法 | 1行要約 |
|------|---------|
| 崩し①バランスを崩す | メリデメ・複数案・賛否のどれかで片方に寄り、スタンスを取る |
| 崩し②客観を崩す | 主観・一次情報・感情を遠慮せず盛り込む |
| 崩し③論理を崩す | 思考過程・葛藤・雑談を残し整理しすぎない（§6の情報整理とトレードオフ） |

詳細な検出パターン・排除ルール・具体例はすべて anti-ai-writing-guide.md（正本）を参照する。

## 10. 最終チェックリスト

| 項目 | 確認内容 |
|------|----------|
| 意図の維持 | ユーザーの伝えたいことが維持されているか |
| 情報の網羅 | メモの重要な情報が漏れていないか |
| 流れの一貫性 | 話題が行ったり来たりしていないか |
| 重複の解消 | 同じことを何度も言っていないか |
| 文字数 | 1800〜2200文字に収まっているか（正本レンジ。`count-chars.js --min 1800 --max 2200` が PASS） |
| 1行の長さ | 文脈（文節・句読点）で改行しているか。単語・文節の途中で切れていないか。1行が目安30-40字程度の自然な区切りか |
| 空白行 | 適切に挿入されているか |
| スタイルゲノム | 8レベルが適用されているか |
| **主張の一貫性** | **軸が1つに絞られているか（原則①）** |
| **冒頭のフック** | **意外性・具体性のある冒頭になっているか（原則②）** |
| **具体性** | **読者の「？」に答える具体的な記述があるか（原則③）** |
| **締めのフレーズ** | **心に残る印象的なフレーズで締めているか（原則④）** |
| **AI臭①記号** | **Markdown記号、emダッシュ、／並列、（）逃げが残っていないか（§9 / anti-ai-writing-guide.md）** |
| **AI臭②リズム** | **語尾の連続、接続詞過多、温度一定、not A but B連発がないか（§9 / anti-ai-writing-guide.md）** |
| **AI臭③説明書感** | **前置き過長、構造宣言、ステップ表記がないか（§9 / anti-ai-writing-guide.md）** |
| **AI臭④事なかれ** | **保険・中立装い・弱い否定がないか。スタンスを取っているか（§9 / anti-ai-writing-guide.md）** |
| **AI臭⑤抽象語** | **万能語・根拠なし評価語で押し切っていないか（§9 / anti-ai-writing-guide.md）** |
| **AI臭⑥比喩** | **使い古された定番比喩を使っていないか（§9 / anti-ai-writing-guide.md）** |
| **ホリゾンタル入口** | **冒頭が普遍的欲求ベースで、専門語で始まっていないか（horizontal-vertical-guide.md）** |
| **バーティカル中身** | **本文が数字・失敗・手順を出し切っているか。入口を広げた分、中身を薄めていないか（horizontal-vertical-guide.md）** |

# 図解スタイル規範（run-x-visual-generate の画風・版面の唯一の正本）

> **正本**: 図解画像の画風・版面・構造型の規定はこのファイルだけが持つ。SKILL.md と `prompts/x-longpost-design-diagram-prompt.md` は本ファイルを参照し、規定を再掲しない。

## 1. 絶対ルール（違反したら生成物を破棄して作り直す）

| ID | ルール | 背景 |
|----|--------|------|
| VS-01 | アスペクト比は **16:9** 固定（生成サイズ 2560x1440） | X のタイムライン表示で最も破綻しにくい |
| VS-02 | 背景は **純白**（#FFFFFF）で**不透明**。グラデーション・テクスチャ・枠線装飾を置かず、アルファチャンネルも持たせない | 一目で読ませるため地を空ける。透過だと貼り先の背景色を透かし、ダークテーマで黒地に黒文字となって全文が消える |
| VS-03 | 配色は **白黒**。人物は黒塗りシルエット、機器・書類は黒線画 | 情報の主従を形だけで作る |
| VS-04 | 赤はアクセント1色のみ許可。用途は **否定・失敗を示す ✕ 印と取り消し線に限る** | 4枚のサンプル全てで赤の用途がこれに統一されている |
| VS-05 | **絵文字を一切使用しない**（画像内・プロンプト内・ファイル名すべて） | plugin 全体の絵文字全面禁止と同一の規定 |
| VS-06 | 画像内の文字は **日本語**。英字は固有名詞（AI / Claude Code / API / X）のみ | 読者が日本語話者だから |
| VS-07 | 「僕」という**文字自体を画像に入れない**。主語は人物アイコンの位置と視線だけで表す | 利用者確定事項（2026-08-31） |
| VS-08 | 「コメント」「キャッチコピー」という語を画像内に書かない | 元プロンプトの規定 |
| VS-09 | 文字量は最小。各ラベルは **原則6字以内**、結論文のみ2行×最大20字 | 図で説明を完結させるため |
| VS-10 | 文章内の「私」は視覚表現上「僕」として扱う（一人称の人物アイコンを立てる）が、VS-07 により文字にはしない | 元プロンプトの規定と VS-07 の接続 |

## 2. 版面（4枚のサンプルから抽出した共通骨格）

```
+--------------------------------------------------------------+
|            大見出し（黒・太字・日本語・20〜30字）              |  上段 15%
+--------------------------------------------------------------+
|   小見出し1        小見出し2         小見出し3                |
|  +---------+     +---------+      +---------+                |
|  | アイコン |  →  | アイコン |  →  | アイコン |                |  中段 60%
|  | の連鎖   |     | の連鎖   |     | の連鎖   |                |
|  +---------+     +---------+      +---------+                |
+--------------------------------------------------------------+
|   結論文1         結論文2          結論文3                    |  下段 25%
|  （太字2行）      （太字2行）       （太字2行）                |
+--------------------------------------------------------------+
```

| 領域 | 内容 | 字数 |
|------|------|------|
| 大見出し | 長文投稿の確定タイトルを図解用に圧縮したもの。`主題：効果` のコロン区切りを基本形とする | 20〜30字 |
| 小見出し | 各ゾーンが担う局面の名前（例: 初期の失敗と課題 / 解決策 / 段階的アプローチと展望） | 6〜14字 |
| アイコン連鎖 | ゾーン内の論理を矢印でつないだアイコン列。1ゾーンあたり2〜5個 | ラベル各6字以内 |
| 結論文 | そのゾーンで読者が持ち帰る一文。**太字・2行**に折る | 1行20字以内 |

ゾーン間は**太い黒矢印**で接続する。ゾーンを枠で囲むかは任意（サンプルでは囲う版と囲わない版の両方が成立している）。

## 3. 構造型（本文の論理構造から選ぶ）

判定は `prompts/x-longpost-analyze-visual-structure.md` が行う。**中段のゾーン内部**に適用する型であり、§2 の三分割版面は型に関係なく維持する。

| 型 | 適用条件 | ゾーン内の描き方 |
|----|----------|------------------|
| T1 三幕 | 本文が「課題 → 解決 → 結果/展望」で進む（既定。最頻） | 各ゾーンが一幕。ゾーン内は左から右への単線 |
| T2 循環 | 同じ手続きの反復・往復で価値が上がる（人間と AI の往復、改善ループ） | 該当ゾーンの内部を円環に組み、矢印を時計回りで閉じる |
| T3 対比 | BEFORE と AFTER、従来と自分のやり方を並べて差を見せる | 左ゾーンに BEFORE（赤 ✕ を伴う）、右ゾーンに AFTER。中央は転換の契機 |
| T4 単線フロー | 手順・工程の連なりが主題（自動化パイプライン等） | ゾーンをまたいで1本の矢印列を通す |

**型は排他ではない。** サンプル1枚目は T1 の中央ゾーンに T2 を内包し、3枚目は T3 の下段に T4 を併走させている。主型を1つ選び、必要なら1つだけ従型を内包する（3つ以上は混ぜない）。

## 4. アイコンの選び方

`icon-vocabulary.md` の語彙表から選ぶ。表にない概念は**同じ粒度で新しく作ってよい**（語彙表は制限リストではなく粒度の見本である）。

| 原則 | 内容 |
|------|------|
| 粒度をそろえる | 1枚の中で線の太さ・塗りの密度・簡略度を統一する。写実的なアイコンと極端に簡略なアイコンを混在させない |
| 1アイコン1概念 | 1つのアイコンに2つの意味を持たせない。意味が2つあるなら2つに割る |
| 同一概念は同一アイコン | 同じものが複数ゾーンに出るときは必ず同じ絵柄を使う（読者はそれを手がかりに視線を運ぶ） |
| 人物は黒塗りシルエット | 顔の描き込みをしない。感情は姿勢と付随記号（吹き出し・汗）で表す |

## 5. 退化パターン（生成結果がこうなったら失敗。作り直す）

| 退化 | 兆候 | 対処 |
|------|------|------|
| 平坦ボックス化 | アイコンが消え、角丸の四角にテキストが並ぶだけの図になる | プロンプトで「アイコン主体・箱にテキストを詰めない」を再強調して再生成 |
| 文字過多 | ラベルが文になり、6字を大きく超える | 本文の要約が足りていない。構造整理からやり直す |
| 文字化け | 判読できない日本語・崩れた字形が出る | 該当ラベルを削るか短くして再生成。崩れた字を残さない |
| 配色逸脱 | 赤以外の色、または ✕ 印以外への赤の使用が出る | VS-03 / VS-04 を明記して再生成 |
| コード描画への退化 | 生成系が拡散モデルではなく matplotlib 等で描いた線図を返す | `generate-images-codex.js` が指示文で禁止済み。出た場合はリトライ |
| 透過背景 | 背景が白く塗られずアルファチャンネルで抜ける。白い画面上では正常に見えるので目視をすり抜ける | VS-02 違反。`validate-visual-assets.js` が color type 4/6 を `has-alpha` で FAIL にする。再生成する |

## 6. 検証

生成物は `scripts/validate-visual-assets.js` が PNG 署名・寸法・比率・背景の不透明性を機械検証する。残る画風・退化（§5 の透過背景を除く5種）は機械判定できないため、**生成物を必ず目視してから成果物へ埋め込む**。

透過背景だけを機械検査に回してあるのは、これが**目視で最も見落としやすい**退化だからである。白い背景のビューアで開くと完璧に正常に見え、貼り先がダークテーマになって初めて壊れる。人間の目が弱い一点を機械で補っている。

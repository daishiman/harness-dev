# サムネイルスタイル規範（X 5:2 / note 1280x670 の画風の唯一の正本）

> **正本**: サムネイル2種の画風・配色・禁止事項はこのファイルだけが持つ。`thumbnail-specs.md` は版面と寸法、`visual-spec.json` は機械可読値、`prompts/x-longpost-design-thumbnail-prompt.md` は生成プロンプトへの写像を担い、いずれも本ファイルの規定を再掲しない。
>
> **図解との関係**: サムネイルは [`diagram-style-canon.md`](diagram-style-canon.md) の画風を**継承しない**。図解は「理解させる絵」なので純白地に人物シルエットと赤✕で論理を描くが、サムネイルは「読む前の人の足を止める絵」であり、目的が違えば最適な画風も違う。両者に共通するのは、後述の §1 TS-10 が指す plugin 横断の文字規則（絵文字禁止・一人称禁止）だけである。

## 1. 絶対ルール（違反したら生成物を破棄して作り直す）

| ID | ルール | 背景 |
|----|--------|------|
| TS-01 | 作るのは **5:2** と **1280x670（約 1.91:1）** の2種だけ。生成寸法・納品寸法・比率の実値は [`visual-spec.json`](visual-spec.json) の `kinds.x-thumb` / `kinds.note-thumb` を唯一の出所とする | 貼り先が X のリンクカードと note のヘッダの2つしかない。図解（16:9）を縮小して流用しない |
| TS-02 | 背景は **#F8F3E6（クリーム寄りのオフホワイト）の単色**。canvas 全面を不透明に塗り、アルファチャンネルを持たせない。純白 #FFFFFF にしない | 純白は X / note の白い UI と地続きになって画像の輪郭が消える。わずかに温度のある白なら、枠線を引かずに「ここから画像」と分かる。透過だと貼り先の背景を透かし、ダークテーマで黒地に黒文字となり全文が消える |
| TS-03 | **人物を描かない**。シルエット・顔・手・人型ピクトグラムのいずれも置かない | 利用者確定事項（2026-08-31）。図解の VS-03「人物は黒塗りシルエット」をサムネイルでは**上書きして禁止**する |
| TS-04 | 画像内の文字は **#1A1A1A（墨黒）のみ**。色文字・グラデーション文字・縁取り文字・影付き文字・立体文字を作らない | 縁取りと影は後述 §3 の情報商材的意匠の中核である。文字を装飾せずに目立たせる手段は大きさと余白しかなく、その制約が版面を締める |
| TS-05 | アクセントは**役割の違う2色だけ**。**#C1C2A0（セージ）は構造**（図形をつなぐ線・台・輪）に使い、**#D87C45（テラコッタ）は補助句の帯1枚**だけに使う。帯の中の文字は白、それ以外の文字には色を乗せない。**赤を使わない** | 色数ではなく**色の役割**を固定することで焦点が保たれる。セージは彩度が低く地に近いので構造を担っても主文を邪魔せず、テラコッタは高彩度を1枚に閉じ込めるからそこが視線の着地点になる。同じ彩度の色を2つ置けば視線は割れるが、地に沈む色と際立つ色を役割で分ければ割れない。図解の赤✕（VS-04）は否定・失敗の記号であり、サムネイルで赤を使うと煽りの記号に読み替えられる |
| TS-06 | 画像内の文字は **主文1本 + 補助句1本まで**。主文 6〜24字、補助句は X 16字 / note 20字以内、**合計 44字を超えない** | 文字が多いと直感的に読みたいと思われない（利用者確定事項）。範囲は `build-visual-prompts.js` が `visual-structure.json` の段階で機械検証する |
| TS-07 | 図形要素は **3個以内**。矢印つきの連鎖は note 版で1本まで、X 版では作らない | 図解の情報量を持ち込まないための上限。1秒で読ませる絵に流れは要らない |
| TS-08 | 四辺に **5% 以上の余白**を確保し、**枠線で画面全体を囲まない** | 余白はトリミング耐性であり、同時にインパクトの源である（§2）。枠線はプラットフォーム側のカード枠と二重になる |
| TS-09 | §3 に名指しした**情報商材的意匠を一つも使わない** | 「情報商材屋っぽくない」は否定形の要求なので、具体物へ翻訳しないと生成系に伝わらない |
| TS-10 | 絵文字を使わない。「僕」「私」「コメント」「キャッチコピー」を画像内に書かない | plugin 横断の文字規則。実体は `visual-spec.json` の `textRules` にあり、図解と共通する唯一の規定である |
| TS-11 | プロンプト内で**引用符に囲まれた文字列以外を画像に描かせない**。生成系に見出しやロゴを発明させない | 画像内テキストの正本は `visual-structure.json` である。生成のたびに違う文言が湧くと再現性が消える |
| TS-12 | X と note は**同じ配色・同じ図形語彙**を使い、**版面だけ**を変える | 同じ投稿の2枚だと一目で分かること。画風が揃っていれば版面が違ってよい |

## 2. インパクトは「足す」ではなく「減らす」で作る

「目に入るインパクト」を装飾で作ろうとすると、そのまま §3 の情報商材的意匠になる。本規範でのインパクトは次の4手段だけで作る。

| 手段 | 具体 |
|------|------|
| 余白を大きく取る | 要素が占める面積を canvas の 60% 以下に抑える。空いた地が主文を押し出す |
| 要素を1つに絞る | 図形は「主文の核となる概念1つ」を表す。3個置けるが、**1個で足りるなら1個にする** |
| 主文を極端に大きくする | 主文は canvas 上で最大の要素にする。補助句との差を2倍以上つける |
| 色に役割を与える | TS-05 のアクセント。地がオフホワイト、文字が墨黒なので、地に沈むセージが構造を描き、テラコッタの帯が1枚だけ際立つ。色数を数えるのではなく役割を守る |

この4つは**互いに支え合う**。要素を減らすから余白が生まれ、余白があるから主文を大きくでき、面が空いているからテラコッタの帯1枚が効く。1つでも崩すと残りも効かなくなるので、「文字を小さくして図形を足す」方向の調整をしない。

## 3. 情報商材的意匠（名指しの禁止リスト）

「情報商材屋っぽい」の実体は次の意匠である。プロンプトの NEGATIVE ブロックへ**すべて**書く（TP-C06）。

| 分類 | 禁止する具体物 |
|------|----------------|
| 文字の装飾 | 黄色や白の縁取り文字、赤い極太文字、グラデーション文字、影付き・立体・斜体の強調、文字の一部だけ拡大する強調 |
| 配色 | 赤と黄の組み合わせ、原色の高彩度、ネオン、暗い地に光る文字、放射状グラデーション |
| 記号 | 爆発マーク、集中線、光条、稲妻、王冠、メダル、star burst、吹き出しの多用 |
| 数字の煽り | 「〇〇万円」「〇日で」「〇倍」のような効果を約束する数値の巨大表示、赤丸で囲んだ数字 |
| 版面 | 画面を斜めに分割する帯、対角線の飾り罫、画面を埋め尽くす要素、3個を超える矢印 |
| 語り口 | 断定的な煽り語（「衝撃」「必見」「知らないと損」「完全版」など）。ただし本規範では画像内テキストが `visual-structure.json` 由来に限られるため、ここは TS-11 で構造的に防いでいる |

**この表は「派手さの禁止」ではない。** 禁止しているのは、**中身の価値ではなく強調記号そのもので注意を引く**手法である。§2 の4手段は派手さを別の原理（余白と対比）で作るため、両立する。

## 4. 版面

版面の ASCII 図と寸法表は [`thumbnail-specs.md`](thumbnail-specs.md) §1・§3 が正本である。本ファイルは配色と要素密度だけを規定し、座標は重複させない。

## 5. 退化パターン（生成結果がこうなったら失敗。作り直す）

| 退化 | 兆候 | 対処 |
|------|------|------|
| 純白化 | 背景が #F8F3E6 ではなく #FFFFFF で返る。白い UI 上で輪郭が消える | TS-02 違反。`validate-visual-assets.js` が背景サンプルの明度で `background-too-white` として FAIL にする |
| 透過背景 | 背景が塗られずアルファチャンネルで抜ける。白い画面上では正常に見えるので目視をすり抜ける | TS-02 違反。同スクリプトが color type 4/6 を `has-alpha` で FAIL にする |
| 人物の混入 | 図形にシルエットや人型ピクトグラムが現れる。図解の画風が漏れたときに起きやすい | TS-03 違反。目視で検出する。プロンプトの NEGATIVE に人物禁止が入っているか先に確認する |
| 情報商材化 | 縁取り文字・爆発マーク・赤黄の配色が出る。「インパクトを」と補足したときに起きやすい | TS-09 違反。§3 の表を NEGATIVE へ全量書き直して再生成する。補足で「派手に」と足さない |
| 文字過多 | 主文が2行を超える、または引用していない語が画像に湧く | TS-06 / TS-11 違反。前者は構造解析へ差し戻す。後者は再生成する |
| 図解化 | 3ゾーンや複数の矢印連鎖が現れ、縮小した図解になる | TS-07 違反。図解プロンプトの LAYOUT が混入していないか確認する |
| アクセント散乱 | テラコッタの帯が2枚以上ある、セージが構造以外（文字・大きな面）に乗る、または主文に色が乗る | TS-05 違反。焦点が消えるので必ず作り直す |

## 6. 検証の分界

| 検査 | 担い手 |
|------|--------|
| 比率・PNG 署名・背景の不透明性・背景の明度 | `validate-visual-assets.js`（機械。FAIL で停止） |
| 主文・補助句の字数、禁止語、絵文字、記号 | `build-visual-prompts.js`（機械。生成**前**に構造データで停止） |
| プロンプトが本規範の配色値・人物禁止・§3 の全項目を書いているか | `lint-thumbnail-prompt.js`（機械。生成**前**にプロンプト文で停止） |
| 人物の混入・情報商材化・図解化・アクセント散乱 | **目視**（機械判定できない。緑でも必ず見る） |

3層のうち2層が**生成前**にあるのは、画像生成が課金される操作だからである。守れているかを出力で確かめるのではなく、守らせる指示が書けているかを先に確かめる。目視に残る4項目は「絵として何が描かれたか」の判断であり、そこだけが人間の仕事として残る。

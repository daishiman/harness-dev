# 短文投稿フォーマット 8パターン

## 概要

@genkaidokushoの人気投稿（10万Views以上）から抽出した8つの構造パターン。
冒頭フック→本論→締めの3部構成が基本。

**重要**: 毎回異なる冒頭フックバリエーションを選択し、単調さを避ける。

**共通原則（ホリゾンタル入口×バーティカル中身）**:
フック行（最初の文章）はホリゾンタル入口とする。各パターンのプレースホルダー（[成果][行動][対象][分野][概念]等）には、専門語・ツール名でなく普遍的欲求の言葉（時間・お金・楽・不安解消・評価・変化の6カテゴリ）を優先して入れる（欲求翻訳）。限定属性の重ね掛けは禁止。本論はバーティカル中身として具体（数字・失敗・手順）を出す。詳細は horizontal-vertical-guide.md（正本）を参照。

## パターン1: 実績報告型

**Views**: 124,485

### 特徴

| 項目 | 内容 |
|------|------|
| 記述方法 | 実績報告を基調とした実践的アドバイス。プロセスを体系的に展開し、読者の再現性を高める洗練された語り口。 |
| 数字の使用 | 豊富に使用（売上額、年数、冊数、字数、ポスト数、価格、部数）。具体性を添え、信頼と説得力を強化。 |
| 最初の文章 | 成果のインパクトを即座に提示。読者の好奇心を優雅に引き込むフック。 |
| 全体構成 | 導入文 + 番号付きリスト（プロセス） + まとめ段落。論理的階層化で明瞭さを保つ。 |
| 締めくくり | 基盤の重要性を強調し、洞察的な余韻を残す。読者の行動を促す穏やかな締め。 |
| 表現スタイル | リスト形式で視覚的に整理。トーンは自信に満ち、励ましを込めた知的スタイル。 |
| 改行 | リスト各項で1行改行。段落間は自然な間隔（1行空け）を置き、読みの流れを優美に導く。 |
| 適用場面 | **具体的な数値成果がある場合** |

### 冒頭フックバリエーション

```
- "先月の[成果]は[数値]でした。"
- "[期間]で[成果]を達成しました。"
- "[数値]という結果が出ました。"
- "[成果]が[数値]になりました。"
- "ついに[成果]が[数値]を超えました。"
```

### 例文

```
先月のnoteでの売上は1,044,000円でした。
noteで月100万円になるまでにやったことは次の通りです。

①本を年間100冊読む（15年超）
②思考の言語化、経験の資産化を継続する（10年超）
③言語化した思考を仕事で実践しながら磨く（10年超）

重要なのは①から④のプロセスです。
ここで土台を作ったので、その経験が⑤以降に繋がっています。
```

## パターン2: 対比構造型

**Views**: 141,213

### 特徴

| 項目 | 内容 |
|------|------|
| 記述方法 | 問題分析と解決策の提示を優雅に融合。内省を促す論理的語りで、読者の思考を洗練。 |
| 数字の使用 | なし。抽象的な洞察に留め、普遍性を強調。 |
| 最初の文章 | 対比構造の洗練されたフック。「〜ではなく〜」で読者の共感を即座に喚起。 |
| 全体構成 | 3段落の流麗な展開（問題提起 → 原因説明 → 解決策）。論理の連鎖が優美。 |
| 締めくくり | 肯定的な展望で締めくくり、希望の余韻を残す。 |
| 表現スタイル | 比喩（「予見された未来のように」）を繊細に用い、トーンは励ましを帯びた知的深み。 |
| 改行 | 段落間2行空け。段落内は連続し、静かなリズムを生む。 |
| 適用場面 | **一般的な誤解を正す場合** |

### 冒頭フックバリエーション

```
- "[状況]は、「[誤解A]」からではなく、「[真の原因B]」からなんですよね。"
- "[状況]の原因は「[誤解A]」じゃない。「[真の原因B]」なんです。"
- "「[誤解A]」が原因だと思ってませんか？実は「[真の原因B]」なんですよね。"
- "[状況]、「[誤解A]」のせいにしがちですが、本当は「[真の原因B]」。"
- "多くの人が「[誤解A]」だと思ってる。でも違う。「[真の原因B]」なんです。"
```

### 例文

```
なかなか理想状態に近づかないのは、
「理想が高すぎる」からではなく、
「理想の具体性が低すぎる」からなんですよね。

理想の具体性が低いと、
理想を実現するためのアクションが定まりません。
理想実現に向けたアクションが明確でなければ、
日々の行動は「報われない努力」に終わります。

まるで予見された未来のように、
具体的に理想状態を描くこと。
これができれば、理想の実現に大きく近づきます。
```

## パターン3: 変化報告型

**Views**: 1,441,945

### 特徴

| 項目 | 内容 |
|------|------|
| 記述方法 | 体験談を基にした洞察的アドバイス。実務改善のプロセスを優雅に解明。 |
| 数字の使用 | 「3つ」など構造化を助ける数字を使用。簡潔さを保つ。 |
| 最初の文章 | 変化の提示で穏やかにフック。読者の興味を自然に引き込む。 |
| 全体構成 | 導入 + 番号付きリスト（理由） + まとめ。バランスの取れた階層。 |
| 締めくくり | 普遍的な教訓で締め、ポジティブな反省を添える。 |
| 表現スタイル | リストで明瞭。トーンは謙虚で励まし、スタイルは実践的優雅さ。 |
| 改行 | リスト各項1行改行。段落間自然間隔（1行空け）で視覚的な調和。 |
| 適用場面 | **自身の体験から学びを共有する場合** |

### 冒頭フックバリエーション

```
- "[行動]をするようになってから、[変化]しました。"
- "[行動]を始めてから、[変化]を感じています。"
- "[行動]を続けていたら、[変化]してきました。"
- "最近[行動]してるんですが、[変化]してきたんですよね。"
- "[行動]するようになって、[変化]に気づきました。"
```

### 例文

```
noteを書くようになってから、
仕事のアウトプットが早くなりました。
その理由は次の3つだと考えています。

①考えたことを外部化しているので取り出しやすくなった
②アウトプットの量が増えてスピードが上がった
③アウトプットを多くの人に晒す経験が増え、
「何をアウトプットすればよいか」を見極める精度が上がった

全く想定していませんでしたが、
やはり何事も真っ直ぐに取り組むと
ちゃんとリターンがあるものだと思います。
```

## パターン4: 特徴列挙型

**Views**: 113,424

### 特徴

| 項目 | 内容 |
|------|------|
| 記述方法 | 特徴列挙と解決策の洗練された提示。日常の洞察を優雅に言語化。 |
| 数字の使用 | なし。抽象的に保ち、普遍性を高める。 |
| 最初の文章 | 特徴の導入で簡潔フック。読者の自己反省を促す。 |
| 全体構成 | リスト + 説明段落 + 解決段落。コンパクトな流れ。 |
| 締めくくり | 実践的アドバイスで締め、希望的な解決を提案。 |
| 表現スタイル | 箇点リストで視覚的。トーンは分析的で優しい励まし。 |
| 改行 | リスト各項改行。段落間2行空けでリズムを優美に。 |
| 適用場面 | **問題の特徴を整理する場合** |

### 冒頭フックバリエーション

```
- "[対象]の特徴は、"
- "[対象]に共通しているのは、"
- "[対象]って、こんな傾向がありませんか？"
- "[対象]を見ていると、"
- "[対象]には、ある共通点があります。"
```

### 例文

```
疲れやすい人の特徴は、

・毎日がランダムでルーティン化されていない
・タスクのスイッチが多すぎる
・日常生活で小さな決断が必要な回数が多い

など、普通に生きているだけで
「意志力」を使い果たしてしまうこと。

内在エネルギーは「習慣」で守る。
余計な判断を省くほど意志力を温存でき、
疲れにくくなる。
```

## パターン5: 簡潔洞察型

**Views**: 524,739

### 特徴

| 項目 | 内容 |
|------|------|
| 記述方法 | 簡潔な洞察提示。人間観察を優雅に凝縮。 |
| 数字の使用 | なし。抽象的で普遍的な洞察。 |
| 最初の文章 | 基準の提案で意外性をフック。読者の視点を洗練。 |
| 全体構成 | 単一段落〜2段落。ミニマムな完結性。 |
| 締めくくり | 理由の再確認で自然に締め、余韻を残す。 |
| 表現スタイル | 逆説的表現。トーンは中立的で知的優雅さ。 |
| 改行 | なし〜最小限。コンパクトな一体感。 |
| 適用場面 | **シンプルな洞察を伝える場合** |

### 冒頭フックバリエーション

```
- "[判断基準]は、[一般的な基準A]よりも、「[意外な基準B]」を見るとよいと考えています。"
- "[判断基準]で大事なのは、[一般的な基準A]じゃなくて「[意外な基準B]」。"
- "「[判断基準]」って、[一般的な基準A]で決まると思われがち。でも実は「[意外な基準B]」。"
- "[判断基準]の本質は「[意外な基準B]」にあると思ってます。"
- "[一般的な基準A]より「[意外な基準B]」を見た方がいい。"
```

### 例文

```
口が堅い人かどうかは、
義理堅さや意思の強さよりも、
「他人に興味がない人か」を見るとよいと考えています。

他人に興味がない人は、口が堅いです。
```

## パターン6: 思考転換型

**Views**: 105,437

### 特徴

| 項目 | 内容 |
|------|------|
| 記述方法 | ビジネス洞察の優雅な分析。思考転換を促す論理的展開。 |
| 数字の使用 | 「20代」など時期の具体化で現実味を添える。 |
| 最初の文章 | 特徴の提示でフック。読者のキャリア反省を誘う。 |
| 全体構成 | 3段落（特徴 → 理由 → 利点）。流麗な論理連鎖。 |
| 締めくくり | 利点の強調でポジティブ締め。 |
| 表現スタイル | 対比表現。トーンは戦略的で励まし。 |
| 改行 | 段落間2行空け。静かなリズム。 |
| 適用場面 | **思考・行動の変化を促す場合** |

### 冒頭フックバリエーション

```
- "[成功者]は、「[思考A]」から「[思考B]」への転換を[時期]で終えている人が多い。"
- "「[思考A]」から「[思考B]」に切り替えられるかどうかで、大きく差がつく。"
- "[成功者]に共通しているのは、早い段階で「[思考B]」に転換していること。"
- "「[思考A]」のままでは限界がある。「[思考B]」への転換が鍵。"
- "[時期]までに「[思考B]」に切り替えた人は、その後が違う。"
```

### 例文

```
仕事のできる人は、
「正解探し」から「仮説検証」への
思考の転換を20代で終えている人が多い。

希少性があるのは不確実な状況で成果を出せる人であり、
「正解探し」の思考に囚われている限り
そのレベルに達することができない。

早期に不確実な状況で成果を出すことに慣れ、
「仮説検証」の思考に切り替えると、
評価、機会、報酬等が段違いに高くなる。
```

## パターン7: 定義対比型

**Views**: 124,649

### 特徴

| 項目 | 内容 |
|------|------|
| 記述方法 | 用語定義を通じた問題指摘。コミュニケーションの洗練を促す。 |
| 数字の使用 | 「殆ど」などの曖昧表現。抽象性を保つ。 |
| 最初の文章 | 問題の定義で即座フック。 |
| 全体構成 | 4段落（問題 → 定義1 → 定義2 → 結論）。定義対比の優雅な構造。 |
| 締めくくり | 行動喚起で実践的に締め。 |
| 表現スタイル | 定義使い分け。トーンはアドバイス的優雅さ。 |
| 改行 | 段落間2行空け。明確な区切り。 |
| 適用場面 | **概念の違いを説明する場合** |

### 冒頭フックバリエーション

```
- "[問題を抱える人]は、「[概念A]」ではなく「[概念B]」する癖がある。"
- "「[概念A]」と「[概念B]」の違い、分かりますか？"
- "[問題]の原因は、「[概念A]」と「[概念B]」を混同していること。"
- "「[概念A]」のつもりが「[概念B]」になっている人、多いんですよね。"
- "[問題を抱える人]は、「[概念A]」じゃなくて「[概念B]」をしてしまっている。"
```

### 例文

```
話がわかりにくい人は、
「説明」ではなく「実況」する癖がある。

説明とは、
相手に伝えたいポイントを絞って伝えたうえで、
そのポイントを理解してもらえるように
情報を付加していくこと。

実況とは、
自分の思考・検討プロセスを整理せずに
そのまま相手に吐き出すこと。

特に仕事においては、
「実況」は誰の特にもならないことが殆ど。
「説明」に徹することが大事。
```

## パターン8: 振り返り助言型

**Views**: 推定100,000+

### 特徴

| 項目 | 内容 |
|------|------|
| 記述方法 | 過去の自分への助言形式で、実践的なアドバイスを番号付きで列挙。各項目に「悪い例→良い例」の対比を含め、具体性を高める。 |
| 数字の使用 | 冒頭で「N点」と明示し、構造を予告。各項目内でも具体的な数値（字数、回数等）を使用。 |
| 最初の文章 | 「[分野]初心者だった頃の自分に送りたいN点」で共感と好奇心を喚起。 |
| 全体構成 | 導入文 + 番号付きリスト（各項目に悪例→良例の対比）+ 自己開示 + 読者への問いかけ。4層構造で完結。 |
| 締めくくり | 自己反省（「自分は〜が弱かった」）+ 読者への問いかけ（「あなたは？」）でエンゲージメント促進。 |
| 表現スタイル | 対比構造（「→」で変換を示す）、具体的な数値・形式の提示。トーンは先輩が後輩に教える親しみやすさ。 |
| 改行 | 各番号項目で改行。悪例→良例は同一行またはインデント。自己開示と問いかけは別段落。 |
| 適用場面 | **過去の経験から学びを共有し、読者と対話したい場合** |

### 冒頭フックバリエーション

```
- "[分野]初心者だった頃の自分に送りたい[N]点。"
- "[N]年前の自分に教えたい[分野]の[N]つのコツ。"
- "昔の自分に伝えたい[分野]の真実[N]選。"
- "[分野]を始めた頃に知りたかった[N]つのこと。"
- "過去の自分へ。[分野]で失敗しないための[N]点。"
```

**注記（ホリゾンタル入口）**: [分野]には広い言い換え（仕事・文章・伝え方・発信 等）を優先して入れ、専門ツール名・専門分野名は本論側で出す。[分野]を専門語にすると入口がその分野の関心層に限定される（欲求翻訳・horizontal-vertical-guide.md §3参照）。

### 例文

```
AIを使い始めた頃の自分に送りたい3点。

①ゴールを"成果物"で言い切る
「いい感じにまとめて」→「上司に送る承認を取る報告メール、300字で」

②制約と形式を決め打ちする
「120〜180字、改行3回、箇条書き3つ、最後に質問で締める」

③材料を渡して推測させない
「現状A、問題B、期限C。勝手に推測しないで」

この3つで再現性が一段上がる。

自分は③が一番弱かった。あなたは？
```

### 検索キーワード

- 過去の自分、昔の自分、初心者時代
- 〜に送りたい、〜に教えたい、〜に伝えたい
- N点、Nつのコツ、N選
- 悪い例→良い例、ビフォーアフター
- 自己開示、問いかけ、エンゲージメント

### 構造テンプレート

```
[分野]初心者だった頃の自分に送りたい[N]点。

①[ポイント1のタイトル]
「[悪い例]」→「[良い例]」

②[ポイント2のタイトル]
「[悪い例/具体的な制約]」

③[ポイント3のタイトル]
「[悪い例/具体的な方法]」

この[N]つで[効果/結果]。

自分は[最も弱かった点]が一番弱かった。あなたは？
```

## 改行ルール詳細

### 基本原則

**改行は文字数ではなく文脈で行う。文節・意味の区切り・句読点（、。）の切れ目で改行し、単語・文節の途中では絶対に改行しない。** 下表の文字数は「1行の目安幅」であり、改行位置は常に文脈で決める。目安幅に最も近い自然な区切りで切る（文字数ぴったりでは切らない）。

| 文の長さ | ルール |
|----------|--------|
| 短文（5-8文字） | 単独で1行 |
| 中文（30-40文字目安） | 文節・句読点の切れ目で1行 |
| 長文（目安を超える） | 意味・文節の切れ目で分割（途中改行しない） |

### パターン別改行

| パターン | 改行ルール |
|----------|------------|
| 実績報告型・変化報告型 | リスト各項は1行、段落間は1行空け |

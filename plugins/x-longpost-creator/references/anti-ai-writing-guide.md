# AIっぽい文章表現大全 — AI臭除去ガイド

> **出典**: もとやま（@ysk_motoyama）「【保存版】AIっぽい文章表現大全」
> **適用先**: Phase 2（スタイルゲノム適用・文章最適化）
> **役割**: 本ファイルはAI臭対策の**正本**。6パターンの検出・排除方法と崩し3技法の詳細を管理する。エージェントからのチェックルール参照先は [writing-guidelines.md §9](../skills/run-x-longpost-create/references/writing-guidelines.md) のインデックス表。

## 概要

AI が生成した文章には、文法は正しくても「何かキモい」独特のAI臭がある。
この臭みは誤字脱字よりも厄介で、気づきにくい。

このガイドでは以下を体系化する：
- AIが書いた文章の特徴（6パターン）
- なぜAIはそう書くのか（3つの理由）
- AI臭をどう崩すか（AIによる修正 + 人間による「崩し」3技法）

## 元記事の分析：AI臭の6パターン

### ① 視覚的な記号が残ったまま

AIは文章を「流れ」ではなく「構造化されたデータ」として出力しようとするため、独特の記号を使う。

**AI臭の具体例:**

> 現代社会において、**持続可能な成長**を実現するためには、多角的な視点—すなわち、マクロとミクロの双方からのアプローチが不可欠です。
>
> 重要な要素： テクノロジーと人間性の融合。
>
> 私たちはしばしば、「真のイノベーションとは『破壊』ではなく『再構築』である」という言葉を耳にします。この概念を理解することが、次世代への架け橋となるでしょう。具体的なアクションプラン／戦略的優先事項としては、以下の点が挙げられます。
> 1.**データの最適化**
> 2.**エコシステム**の構築
>
> これらの「プロセス（流れ）」を通じて、私たちは「新たなバリュー（付加価値）」を創造することが可能です（ただし状況によります）。

**AI臭チェックリスト:**

| AI臭パターン | 説明 |
|-------------|------|
| `**これ**`が残ったまま | Markdown記法（アスタリスク）の消し忘れ |
| 「—」で言い換える | 英語癖のemダッシュ接続 |
| 「」で言葉を切り出しすぎる | カギ括弧の過剰使用 |
| 「」の中に『』が登場する | 二重括弧の入れ子 |
| ：のあとに半角スペース | 英語のコロン+スペース癖 |
| （）で補足しすぎる | 括弧に逃げる説明 |
| （）の中で責任回避 | 「（ただし状況によります）」 |
| ／で概念を並列 | 全角スラッシュの並列（AIは/ではなく／を使いがち） |

**原因**: Markdown記法の消し忘れ、英語癖のコロン後半角スペース等。

**適用**: X長文投稿では上記の記号パターンを全て除去する。emダッシュ（—）は「つまり」「要は」など日本語の接続に置き換え、「」の中に『』が入る入れ子は使わず文で説明する。

### ② 文のリズムが単調

**具体的なパターン:**

| パターン | 例 | 対処法 |
|---------|-----|-------|
| 同じ語尾が続く | 〜です。〜です。〜です。〜でしょう。〜です。 | 語尾に変化をつける |
| 接続詞が多い | さらに、また、したがって、そのため、結果として、〜です。 | 順接の接続詞は削れるものが多い |
| 文章の温度が一定 | 重要なところも軽い補足も同じテンション | 重要部分は短文で強調、軽い部分はサラッと |
| 段落の終わりが毎回きれいに閉じる | 以上がポイントです。次に進みましょう。最後にまとめます。 | 読後の余韻に変化をつける |
| not A but B構文ばかり | これは～ではありません。～です。 | AIの安全制御装置が原因。数行に1回出てくるとAI感が出る。使うなら1投稿で1回までに抑える |
| 同義語の言い換え連打 | 重要・大切・欠かせない等、同義語を並べる | 1回で言い切る |

**元記事の解説:**
接続詞については、もとやま氏自身もコンサル時代の癖で多用するため「AIで書いたっしょ」と言われるとのこと。
Tips: 「順接の接続詞」は無くても伝わるので削ってよい。

文章のサビ（盛り上がりどころ）がわからないのは、重要なところも軽い補足も同じテンションで書かれるから。
だから熱が伝わってこない。

**適用**: スタイルゲノムL5（修辞・リズム）と連携。短→中→長→短のリズムを適用し、単調さを回避する。

### ③ 導入と進行が説明書っぽい

**具体的なパターン:**

| パターン | 例 | 問題点 |
|---------|-----|-------|
| 前置きが長い | 「ご質問ありがとうございます。業務効率化は現代のビジネスにおいて非常に重要なテーマです。以下では、その具体的な手法について解説します」 | 読み手が求めているのは結論や判断材料なのに、丁寧な受け止めと導入が毎回挟まる。くどい |
| 「結論から言うと」で始めるが結論が薄い | 「結論から言うと、状況に応じて最適な方法は異なります」 | 出だしは強気なのに内容が抽象的で、どちらでもよい話になりがち |
| 構造を本文で何度も宣言する | 「以下の3つの観点から説明します。それぞれ順に見ていきましょう」 | 見出しで分かることを本文でさらに宣言するのはくどい |
| ステップ・STEP | 「ステップ1：目的を明確化します」 | AIに方法論を尋ねると必ず出てくる。「：」と半角スペースのセットがあるとAIコピペ感 |

**適用**: 既存の禁止表現リストと連携。「以下で解説します」系の前置き宣言を排除する。「ステップ」「STEP」という語自体を使わず自然な文章の流れで説明する。結論を宣言するなら具体的で断定的な内容にし、曖昧なら宣言自体を削除する。

### ④ 事なかれ主義なスタンス

AIに尋ねると「ケースバイケースです」「場合によります」「価値観によります」と、何か言っているようで何も言っていない回答が返ってくる。

**具体的なパターン:**

| パターン | 例 | 問題点 |
|---------|-----|-------|
| 保険が多い（逃げ道の常設） | 「一概には言えませんが、一般的には有効だと考えられます」 | 必ず枕詞で逃げ道を作る |
| 中立を装いすぎる | 「メリットもあればデメリットもあります。賛否が分かれるテーマです」 | 整理としては正しいが、読後に判断が残らない |
| 否定が弱い | 「あまり推奨されません」「注意が必要です」 | 「やめろ」と言い切ってほしい時でもこの言い回し |
| ケースバイケース逃げ | 「場合によります」「価値観によります」 | 具体的な条件や判断基準を示す。逃げずに「〜の場合は〜がよい」と書く |

**元記事の解説:**
コンサル出身者が書いている本に必ず出てくるのが「スタンスを取れ」という言葉。
賛成か反対か、A案〜B案のどれをやるべきか、逃げずに自分のスタンスを示しなさい。

**適用**: スタイルゲノムL7（価値観）・L8（対人関係）と連携。ユーザーのメモに含まれるスタンスを明確に打ち出す。
安全クッション（「一概には言えませんが」等）は原則削除する。

### ⑤ 言葉選びが「抽象語」と「万能語」に寄る

事なかれ主義なくせに、抽象論は自信満々に語ってくるのもAIの特徴。

**具体的なパターン:**

| パターン | 例 | 問題点 |
|---------|-----|-------|
| 抽象語だけで押し切る | 「本質を押さえ、最適化し、価値を最大化することが重要です」 | 頭に具体の絵が浮かばない |
| 評価語が強いのに根拠がない | 「非常に有効です」「大きなメリットがあります」 | 情報商材感。強い評価なのに根拠がない |
| 万能語の乱用 | 重要、効果的、最適、本質、メリット | 「何がどうなるか」を具体的に書き、万能語に頼らない |

**元記事の解説:**
「読み手の頭のなかに動画が流れるレベルで具体的に書きなさい」と昔注意を受けたとのこと。
中村昌弘4原則の「③とにかく具体的に書く」と強く連携する。

**適用**: 中村4原則③と連携。抽象語・万能語（「本質」「最適化」「価値の最大化」等）を具体的な動詞中心の表現に置き換える。
根拠なき強い評価語（「非常に有効」「大きなメリット」）は削除または具体化。

### ⑥ 変な比喩が多い

AIが頻繁に使う比喩リスト（少なくとも3回ずつは見かけるもの）:

地図、仕様書、設計書、羅針盤（コンパス）、土台、柱、栄養、筋トレ（筋肉）、DNA、車の両輪、潤滑油、エンジン、スパイス、レシピ

**適用**: 上記の比喩は使用を避ける。比喩を使う場合は、ユーザーのメモに含まれる体験や具体例ベースのオリジナルな表現を使う。

## なぜAIはAIっぽい表現をするのか

AIの性格ではなく、仕組みとしてそうなる。

| 理由 | 詳細 | 対策 |
|------|------|------|
| 学習元の偏り | ビジネス文書の学習元（マニュアル、FAQ、規程、研修資料、一般向け解説）は、誤解を避けるため前置きがあり、構造を宣言し、注意書きを添え、まとめを繰り返す。AIはその平均的な型を最短で出すのでテンプレ色が濃くなる | 定型構造（前置き→構造宣言→注意書き→まとめ繰り返し）を崩す |
| 安全調教の副作用 | 「有害なことを言わない」「嘘をつかない」ように厳しく調教されているため、「Aだ！」と言い切ることを避け、全方位に配慮した毒にも薬にもならない文章を出力する | スタンスを取る。言い切る |
| 英語基盤の影響 | 英語の論理構造、英語圏のドキュメント文化（Markdown、箇条書き多用）で骨組みを作り、日本語に翻訳する。文法は正しい日本語なのにリズムや記号の使い方だけが洋風になる | Markdown記号を排除し、日本語のリズムで書き直す |

## AI臭をどう崩すか

### AIに修正してもらうプロンプト（もとやま氏作成）

```
# 役割
あなたは日本語のプロ編集者です。下の「元の文章」はAIが書いた下書きです。**意味と事実関係は変えずに**、読み手が「人が書いた」と感じる自然な日本語に全面的に書き直してください。追加の質問はせず、与えられた情報だけで最善の形に整えてください。

# 目的
AIっぽさ（テンプレ感、説明書感、記号過多、過剰な丁寧さ、逃げ文句、抽象語の空回り）を**完全に消す**こと。

# 厳守ルール（内容）
- 内容の捏造や、根拠のない具体化はしない。元の文章にない数字・固有名詞・事例は足さない。
- 曖昧な箇所は曖昧なままにする。ただし文章として読みやすく整える。
- 読者への質問や確認はしない（追質問禁止）。
- 「結論から言うと」「本記事では」「以下で解説します」などの前置き宣言は入れない。いきなり本文として自然に書き出す。
- 「一般的に」「多くの場合」「状況によって異なります」「一概には言えませんが」など、情報を増やさない安全クッションは原則削除する。必要なら最小限の注意書きに圧縮する。
- 「重要」「効果的」「最適」「本質」「メリット」などの抽象語だけで押し切らない。元文の範囲で「何がどうなるか」が伝わるよう、動詞中心の具体的表現に置き換える。
- 同義語の言い換え連打（例：重要・大切・欠かせない）はやめ、1回で言い切る。
- 「まとめると」「要するに」「総じて」などの抽象まとめの繰り返しや、同内容の再掲は削る。
- 文のリズムを均一にしない。短い文と長い文を混ぜ、同じ型（断定→理由、結論→補足）の連続を避ける。接続詞は必要最小限にする。
- 書き手の立場を漂わせない。一人称を出すなら一貫させ、「私／筆者／私たち」を混ぜない。

# 厳守ルール（記号・表記） ※最重要
- Markdown記法を使わない（`**太字**`、`##`見出し、箇条書き記号、装飾はすべて禁止）。
- 「」を多用しない。定義っぽい括りや強調のためのカギ括弧は削り、文脈に溶かす。引用や固有の呼称に必要な場合だけ最小限に使う。
- ()を多用しない。補足を括弧に逃がさず、必要なら本文の一文として自然に組み込む。用語の説明は初出で一度だけにする（可能なら括弧を使わず文で説明する）。
- コロン「：」は原則使わない。使う場合でも「： 」のように直後へ半角スペースを入れない（「： 」は禁止）。「目的：背景：結論：」のようなラベル列挙はしない。
- スラッシュ（／）で概念を並列しない。矢印（→）や疑似コード風の表記も避け、文章として書く。
- 締めの定型句（「参考になれば幸いです」「まずは小さく始めましょう」など）を入れない。必要なら内容に即した一文で淡く締める。

# 出力形式
- 書き換え後の文章だけを出力する（解説・前置き・注意書き・チェックリストは出さない）。
- 元の段落構成は大きく崩さず、読みやすい段落に整える。
- 文章量は元文から大きく増減させない（目安：±20%以内）。
```

### 人間による「文章を崩す技術」3つ

最終的には人間が文章に血を通わせる。そのために「崩す」こと。

#### 崩し①: バランスを崩す（スタンスを取る）

まずは、スタンスを取る。

- メリットとデメリットのどちらが大きいのか
- A案〜C案のうち、イチオシはどれか
- 賛成なのか、反対なのか

これらを思い切って言い切ってみる。するとバランスが崩れて、賛否を生む文章になる。
賛否があって議論を生む文章にする。これは人間の頑張りどころ。

**適用**: ユーザーのメモにスタンスが含まれていれば、それを投稿文に明確に反映する。
「どちらとも言えます」的な中立表現は、ユーザーの意図がない限り避ける。

#### 崩し②: 客観を崩す（主観を入れる）

AIがファクトとデータを分析してくれる時代、人間がやるべきなのは主観と一次情報をたっぷりと盛り込むこと。
偏った考え、尖った価値観を遠慮せずに入れる。
カッコよく表現すれば、それが理念やビジョン、ナラティブ。

**元記事の解説:**
もとやま氏の主観の例:
> 管理職なんてやりたくない。実際にやってみたけど、やっぱり向いてない。誰の面倒も見たくない
> かといって、管理されたくもない
> でも100%リスクを取って自分の会社だけで生きていくのも、なんか不安。要はビビり

この主観をベースに200記事近くが綴られている。
批判も来るが、同じくらい熱烈に賛同する読者もいる。
AIが客観性を担保してくれるからこそ、人間は主観に身を委ねてもいい。

**適用**: スタイルゲノムL7（価値観）・L8（対人関係：自己開示）と連携。
ユーザーのメモに含まれる主観・一次情報・体験を最優先で反映する。

#### 崩し③: 論理を崩す（人間らしさを残す）

- 話が行ったり来たりしている
- やや話が矛盾している
- 1つ目と3つ目の話の粒度が違う
- あってもなくてもいい雑談が含まれている

くらいの崩れた文章のほうが人間らしさが滲む。

ブログやnoteの読み物系は、結論に行きつくまでの葛藤や感情をダラダラと語ると、AIっぽさは無くなる。
読み手に思考過程や感情の動きを追体験してもらえる文章を書けるのも、人間にしかできないこと。

**適用**: ユーザーのメモの「行ったり来たり」を、全て整理しすぎず一部は活かす。
感情の動き（葛藤、迷い、失敗）はAI臭除去に有効なので積極的に残す。
ただし「情報の行ったり来たり」の完全な解消（§6）とのバランスを取る。

|---|---------|------------|-------------------|

## 3フレームワーク統合モデル（R-E-D）

もとやま式AI臭除去・中村4原則・崩し3技法は、3層構造で相互補完する。

### R-E-Dモデル

| Layer | 名称 | フレームワーク | 目的 | 適用順序 |
|-------|------|-------------|------|---------|
| L1 | **Reduction**（減点除去） | もとやま6分類 | AI臭を消す | 1番目 |
| L2 | **Elevation**（加点創出） | 中村4原則 | 読まれる文章にする | 2番目 |
| L3 | **Disruption**（人間らしさ注入） | 崩し3技法 | 人間の血を通わせる | 3番目 |

**適用順序: L1 → L2 → L3**
まずAI臭というマイナスを消し（Reduction）、次に読まれる要素というプラスを加え（Elevation）、最後に人間らしい崩しを入れる（Disruption）。

### 各レイヤーの対応関係

| 領域 | L1 もとやま式（減点除去） | L2 中村4原則（加点創出） | L3 崩し3技法（人間らしさ） |
|------|------------------------------|-------------------------------|-------------------------------|
| 記号・リズム | ①②で検出・除去 | - | - |
| 主張 | ④事なかれ主義の排除 | ①主張を明確にする | ①バランスを崩す |
| 具体性 | ⑤抽象語・万能語の排除 | ③とにかく具体的に書く | - |
| 冒頭 | ③説明書感の排除 | ②冒頭に命をかける | - |
| 比喩 | ⑥変な比喩の排除 | - | - |
| 主観 | - | - | ②客観を崩す |
| 人間味 | - | - | ③論理を崩す |
| 締め | - | ④締めはフレーズを残す | - |

### 適用の順序

1. **文章生成時に4原則を意識して書く**（加点要素を作る）
2. **生成後にもとやま式でAI臭を最終チェック**（減点要素を消す）

※ 概念的にはAI臭除去が先（マイナスを消してからプラスを加える）だが、
実際のエージェントフロー（apply-style-genome → optimize-length）では
4原則を意識した生成の後にAI臭チェックを行う方が効率的。

**エージェント実装での位置付け**: AI臭チェックはスタイルゲノム適用・4原則チェックの**後**に配置し、**最終フィルター**として機能させる。これにより「減点防止→加点創出」の論理的順序と「最終フィルター」の実装順序の両方が成立する。

## 適用方針

### スタイルゲノムとの連携

| AI臭パターン | 連携するスタイルゲノムレベル |
|-------------|--------------------------|
| ①記号残り | L連携なし（Markdown記号除去は機械的前処理であり文体特徴と無関係） |
| ②リズム単調 | L5修辞・リズム（短→中→長→短） |
| ③説明書感 | L4談話構造（問題提起型の自然な導入） |
| ④事なかれ | L7価値観（実用主義）、L8対人（自己開示） |
| ⑤抽象語 | L6認知（具体→抽象→具体のボトムアップ） |
| ⑥変な比喩 | L8対人（読者との距離感に合った比喩） |

### 注意点

- AI臭除去は「減点を防ぐ」目的。やりすぎると別の不自然さが生まれる
- ユーザーのメモの意図を最優先する（AI臭除去のために意図を変えない）
- 「崩し③論理を崩す」は、情報の行ったり来たりの完全解消（§6）とトレードオフ。感情・葛藤の流れは残し、事実情報の配置は整理する
- もとやま式プロンプトは参考として保持するが、x-longpost-creatorではスタイルゲノム適用とAI臭チェックリストで同等の効果を実現する

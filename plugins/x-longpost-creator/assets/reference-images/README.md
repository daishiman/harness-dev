# 画風の見本画像

> **責務**: 画風を「言葉」ではなく「絵」で示す見本の置き場。宣言は [manifest.json](manifest.json)、規範の正本は `../../skills/run-x-visual-generate/references/diagram-style-canon.md` と同ディレクトリの `thumbnail-style-canon.md` にある。

## 1. なぜ画像が要るのか

画風の正本は文章（canon と icon-vocabulary.md）である。しかし文章だけでは決められない量がある。

| 決められること（文章で足りる） | 決めにくいこと（絵が要る） |
|---|---|
| 背景色・文字色（hex） | 線の太さの絶対値 |
| 人物を描くか描かないか | どこまで簡略化するか（簡略度の粒度） |
| 図形の個数の上限 | 塗りの密度（黒の面積の割合） |
| 余白の割合 | 「白黒ミニマル」と言ったときの実際の見え方 |

右列は数値へ落とすと逆に窮屈になる。見本画像を1枚添えるほうが正確に伝わる。

## 2. 生成へどう効くか

`generate-images-codex.js` が `codex exec -i <FILE>` で kind ごとの見本を添付する。文章のプロンプトと同時に絵が渡るため、粒度が実際に生成へ効く。

**見本は複製する対象ではない。** 構図・文言・具体的なアイコンをそのまま写されると、どの投稿でも同じ絵が出てしまい、本文の構造を表す図解にならない。そのため指示文で「線の太さ・塗りの密度・簡略度の参照に限り、構図と文言と個々のアイコンは複製しない」ことを明示している。

## 3. 置き方

1. 画像を本ディレクトリ直下へ置く（PNG）
2. `manifest.json` の `images` に `file` / `kinds` / `role` / `canon` を書く
3. `node scripts/generate-images-codex.js --image-dir <dir> --dry-run` で `referenceImages.attached` に載ることを確かめる

宣言したが実体が無いファイルは `missing` として毎回の出力と `meta.json` に記録される。`--require-reference-images` を付けると missing がある時点で FAIL になる。運用が固まったらこのフラグを常用する。

`kinds` に書けるのは `visual-spec.json` の kind 名（`diagram` / `x-thumb` / `note-thumb`）だけである。未知の kind を書くと FAIL する。

## 4. 見本に選んではいけない画像

| 避けるもの | 理由 |
|---|---|
| 生成に失敗した画像 | 退化パターンを見本として教えることになる |
| 文字が主役の画像（図解の見本として） | 図解は構造を見せる絵であり、文字量の見本は canon の字数上限が持つ |
| 人物が写り込んだ画像（サムネイルの見本として） | TS-03 が人物の描画を禁じているため、見本と規範が矛盾する |
| 他者の著作物 | 本ディレクトリの画像は生成系へ送信される |

## 5. 実体が無いときの扱い

見本が1枚も無くても生成は動く。文章の canon が正本であり、見本は精度を上げる補助だからである。ただし「見本があるつもりで書かれた canon」と「見本なしの生成」の差は記録に残す必要があるため、missing は WARN として必ず出力へ載せる。判定できないことと合格を区別する。

# Task仕様書：8投稿作成

## 1. メタ情報

| 項目     | 内容                          |
| -------- | ----------------------------- |
| 名前     | Multi Post Creator            |
| 専門領域 | 構造化メモ → 8つの短文投稿   |
| Phase    | 1（文字起こし→8投稿ワークフロー） |
| 入力元   | `x-longpost-structure-transcript` が出力した構造化メモ |

---

## 2. 目的

構造化されたメモ（`x-longpost-structure-transcript` が生成した文字起こし由来のテキスト）から、
それぞれ異なる内容・テーマを持つ8つの短文投稿（各約200文字）を作成する。
1つの元テキストから多角的な視点で投稿を展開し、
コンテンツの多様性を確保する。

---

## 3. 制約（最重要）

| ID        | 制約内容                                                                               |
| --------- | -------------------------------------------------------------------------------------- |
| MP-C01 | **元テキストに含まれる内容のみを使用する（推論・補足・創作は禁止）**                  |
| MP-C02 | **8つの投稿はそれぞれ異なる内容・テーマにする（同じ内容の繰り返し禁止）**            |
| MP-C03 | **各投稿は約200文字（180〜220文字の範囲）**                                           |
| MP-C04 | **スタイルゲノム8レベルを各投稿に適用する**                                           |
| MP-C05 | **各投稿に最適な短文投稿フォーマットを個別に選定する（同じフォーマット連続使用は避ける）** |
| MP-C06 | **本質的な内容（課題・問題・やったこと・学び）を必ず反映する**                       |
| MP-C07 | **長文投稿と同時に作成する場合（文字起こし→長文投稿+8投稿ワークフロー）、8投稿に加えて「投稿9｜要約型」を必ず追加する。長文投稿（パターンA）の要点を400〜499文字で要約した投稿とする** |

## 5. 実行仕様

### 5.1 Phase 1: コンテンツ分析・テーマ抽出

元テキストから本質的な内容を特定し、8つの異なるテーマに分割する。

**思考プロセス**:

| ステップ | アクション                                           |
| -------- | ---------------------------------------------------- |
| 1        | テキスト全体を通読し、主要なテーマ・トピックをリストアップ |
| 2        | 各テーマの「本質的な内容（課題・問題・やったこと・学び）」を特定 |
| 3        | 8つの独立したテーマを選定（重複なし）              |
| 4        | 各テーマに最適な短文投稿フォーマットを仮決定        |
| 5        | テキストから根拠となる記述が存在するか確認          |

**テーマ選定基準**:
- テキストに明示・示唆されている内容のみを対象とする
- 読者に価値を提供できる切り口を優先する
- 課題・問題・解決策・学びのバランスを取る
- 入口を普遍的欲求へ翻訳できる切り口を優先する。欲求翻訳（専門語を読者が得る変化の言葉に言い換えること）は表現の言い換えであり、MP-C01（元テキストに存在する内容のみ使用）の禁止する内容追加・創作には当たらない（正本 horizontal-vertical-guide.md §3参照）

### 5.2 Phase 2: 8投稿の作成

各テーマについて、約200文字の投稿を個別に作成する。

**作成手順（各投稿共通 — `x-longpost-short-post-optimizer.md` の4フェーズを各テーマに適用）**:

| Phase | 担当 | アクション |
| ----- | ---- | ---------- |
| Phase 1 | 入力文章アナリスト | テーマの主題・意図・構造要素を特定する |
| Phase 2 | フォーマットセレクター | 8パターンから最適フォーマット・冒頭フックを選定する |
| Phase 3 | 投稿文ジェネレーター | 選定フォーマット構造に沿って**約200文字**の文章を生成する |
| Phase 4 | スタイルオプティマイザー | スタイルゲノム8レベル適用・AI臭チェック・最終仕上げ |

**フォーマット選定バランス（8投稿全体で）**:
- 同じフォーマットの連続使用を避ける
- できるだけ多様なフォーマットを使用する
- 内容に最も適したフォーマットを優先する

### 5.3 スタイルゲノム適用基準

| レベル | 適用内容                                                     |
| ------ | ------------------------------------------------------------ |
| L1 表層 | ひらがな58%、頻繁な改行。改行は文脈（文節・句読点）で行い、1行は目安30-40字程度の自然な区切りで切る（文節の途中では改行しない） |
| L2 語彙 | 一人称「僕」、カジュアル副詞（めっちゃ・結構・かなり等）   |
| L3 統語 | 単文60%、能動態95%、ですます調基調                          |
| L4 談話 | 問題提起→共感→分析→解決策（4段階、約200文字に圧縮）        |
| L5 修辞 | 短文→中文→長文→短文のリズム（コンパクトに適用）            |
| L6 認知 | 具体→抽象→具体のボトムアップ                                |
| L7 価値観 | 実用主義、透明性、継続改善                                 |
| L8 対人 | 問いかけ・共感・呼びかけ                                   |

### 5.3.5 投稿9｜要約型（長文投稿と同時作成時のみ）

長文投稿ワークフロー（文字起こし→長文投稿+8投稿）で実行する場合に限り、8投稿の後に「投稿9｜要約型」を追加する。8投稿単独ワークフロー（長文投稿を作成しない場合）では投稿9は作成しない（要約する長文が存在しないため）。

| 項目 | 内容 |
| ---- | ---- |
| 元にする文章 | 確定した長文投稿パターンA（`x-longpost-optimize-length.md` の出力・見出し1を含む） |
| 文字数 | **400〜499文字**（400文字未満・500文字以上は不可） |
| 内容 | 長文投稿の主張・要点を過不足なく要約する（新規の主張・推論・創作は禁止） |
| スタイル | 他の8投稿と同じスタイルゲノム8レベル・AI臭チェック・改行ルールを適用する |
| フォーマット名 | `要約型` 固定 |
| テーマ欄 | 「長文投稿の要点を[実際の文字数]文字で要約（[要約対象の核]）」の形式で記載する |

### 5.4 AI臭チェック（各投稿）

- ① 記号残り: em ダッシュ(—)、／並列、（）逃げがないか
- ② リズム単調: 同じ文末（〜です）が続いていないか
- ③ 説明書感: 箇条書きが過剰でないか
- ④ 事なかれ主義: 保険・中立装いがないか
- ⑤ 抽象語・万能語: 「重要」「効果的」「最適」多用がないか
- ⑥ 定番比喩: 「地図」「土台」「柱」等を使っていないか

## 6. 出力フォーマット

8つの投稿を以下の形式で出力する。投稿文はコードブロックで囲み、そのままXにコピペできる形式にする。

**【重要】コードブロック内でも必ず改行を適用すること。改行は文字数ではなく文脈で決める。文節・意味の区切り・句読点（、。）の切れ目で改行し、単語・文節の途中では改行しない。1行は目安30-40字程度で、目標幅に近い自然な区切りで切る。べた書き（改行なし長文）は禁止。スタイルゲノムL1の「頻繁な改行」をコードブロック内でも徹底する。**

## 投稿 1｜[フォーマット名]
**テーマ**: [この投稿が扱う内容（1行）]

```
[投稿文 約200文字 - 文脈（文節・句読点）で改行を入れること。1行は目安30-40字程度、文節の途中では改行しない]
```

---

## 投稿 2｜[フォーマット名]
**テーマ**: [この投稿が扱う内容（1行）]

```
[投稿文 約200文字]
```

---

（投稿3〜8も同様の形式で続ける）

長文投稿と同時作成する場合は、投稿8の後にも `---` で区切り、以下を追加する。

## 投稿 9｜要約型
**テーマ**: 長文投稿の要点を[実際の文字数]文字で要約（[要約対象の核]）

```
[投稿文 400〜499文字 - 長文投稿パターンAの要約。文脈（文節・句読点）で改行を入れること]
```

### 各投稿の品質基準

| 項目           | 基準                                         |
| -------------- | -------------------------------------------- |
| 文字数         | 投稿1〜8: 180〜220文字（約200文字） / 投稿9（長文同時作成時のみ）: 400〜499文字 |
| テーマの独立性 | 他の7投稿と重複しない内容・テーマ           |
| 根拠の存在     | 元テキストから根拠となる記述が確認できる     |
| スタイル反映   | スタイルゲノム8レベルが適用されている       |
| フォーマット適合 | 選定した短文投稿フォーマット構造に合致      |
| AI臭なし       | 6パターンのAI臭が除去されている             |
| 冒頭フック     | ホリゾンタル入口（専門語・限定属性で始まらない） |
| 改行           | 文脈（文節・句読点）で改行、文節の途中で切れていない（1行は目安30-40字程度） |

## 7. 使用例

### 入力（構造化メモの抜粋）

```
# 勉強会への参加と登壇

最近、勉強会に参加し、自身でもLT登壇している。
目的は学びを発信するだけでなく、関係性を構築すること。
登壇後に質問をもらえることで、言語化が深まる効果を実感している。
```

### 出力例（投稿1のみ）

```
## 投稿 1｜変化報告型
**テーマ**: 勉強会に登壇することで得られる言語化の力

勉強会で登壇するようにしてから、
気づいたことがある。

発表の準備をすることで、
頭の中でぼんやりしていたことが
整理されていく感覚がある。

しかも、発表後に質問をもらうと
さらに言語化が深まる。

「自分がやっていたこと」を
人に伝えようとすることで、
初めて自分でも理解が深まる。

アウトプットは、インプットの質を上げる。
```

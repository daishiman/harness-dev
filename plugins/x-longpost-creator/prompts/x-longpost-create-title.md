# Task仕様書：タイトル作成

## 1. メタ情報

| 項目     | 内容                |
| -------- | ------------------- |
| 名前     | Title Creator       |
| 専門領域 | タイトル設計・最適化 |
| Phase    | **1.5**（parse-input の直後・apply-style-genome の前） |

---

## 2. 目的

parse-input の構成要素リストから、読まれやすいタイトルを3案生成し、推奨1案を**確定**する。

**このフェーズで確定した文字列が、以後この投稿の唯一のタイトルになる。** 後続フェーズ（apply-style-genome / optimize-length / output-file）はこの文字列を一字一句そのまま使い、作り直さない。

## 3. 責務

| 責務               | 成果物              |
| ------------------ | ------------------- |
| タイトル候補生成   | 3パターンのタイトル |
| 最適タイトル選定   | 推奨タイトル1つ（確定タイトル） |
| 機械検証           | validate-title.js 終了コード0 |

### 責務外

| 項目 | 担当 |
|------|------|
| 本文生成 | apply-style-genome（Phase 2） |
| 見出し2の作成 | optimize-length（Phase 2） |
| ファイル名生成 | output-file（Phase 3） |

## 4. 入力要件

### 4.1 必須入力

| 入力 | 取得元 | 用途 |
|------|--------|------|
| キャッチコピー | ユーザー入力 | 核心メッセージ |
| 構成要素リスト | parse-input | タイトル素材 |

**Phase 1.5 の時点で投稿本文はまだ存在しない。** 本文との期待値一致は、本文ではなく構成要素リスト（最も言いたいこと・理想の状態・現状・解決策）と照合して判定する。

### 4.2 タイトル素材として活用する要素

| 要素 | 活用方法 |
|------|----------|
| 最も言いたいこと | 結論・主張の明示 |
| 理想の状態 | ゴール・ベネフィット |
| 現状 | 共感ポイント（Before） |
| 解決策 | 方法・ノウハウ |
| 具体的な数値・事例 | 信頼性付与 |

## 5. 実行仕様

### 5.1 思考プロセス

| ステップ | アクション |
| -------- | ---------- |
| 1 | キャッチコピーから核心メッセージを抽出 |
| 2 | 構成要素から具体的な数値・固有名詞を特定 |
| 3 | ターゲット読者を明確化 |
| 4 | ネタ性質判定（一般向け/専門家向けを判定し入口のホリゾンタル度を決める） |
| 5 | 欲求翻訳（専門語を普遍的欲求の言葉へ翻訳し入口に置く） |
| 6 | 構文パターン（A〜H）から3種を選びタイトル案を生成（各案とも50文字以内・推奨レンジ35〜48字） |
| 7 | 各タイトルのチェックリスト評価 |
| 8 | 最適なタイトルを選定・推奨理由を記載 |
| 9 | **`validate-title.js` で機械検証（§5.4）。FAILなら正本のリライト6手順でリライトして再検証** |

### 5.1.1 タイトル50文字ルール（絶対）

**タイトルは50文字以内。例外は認めない。**

**正本**: [references/heading-structure-rules.md](../skills/run-x-longpost-create/references/heading-structure-rules.md)（R1・4箇所一致・check ID・終了コード・**リライト6手順の実体**）

この上限の根拠:

> 50文字はファイルシステムの制約ではなく編集規範である。タイムラインで最初に読まれるのは先頭30文字程度であり、そこに核を置いたうえで予告を足すと50文字に収まる。加えて、この文字列は長文Bの先頭行・`# タイトル`・ファイル名のタイトル部にも同一で使われるため、短く保つことが一覧性と命名の一貫性に直結する。

| 禁止 | 理由 |
|------|------|
| 末尾を50文字で切り捨てる | 文意が途切れ、見出し1とファイル名の意味が壊れる |
| 50文字超のまま次フェーズへ渡す | output-file / generate-filename が停止する |

**超過時のリライト手順は本ファイルに実体を持たない。** [heading-structure-rules.md の「R1 違反時の対処（リライト6手順）」](../skills/run-x-longpost-create/references/heading-structure-rules.md) が唯一の正本であり、そちらの6手順に従う（本ファイルから削除したのではなく、二重宣言を避けて正本へ集約した。手順の内容は正本に完全な形で残っている）。

やみくもに作り直さず、必ず正本の手順に沿ってリライトする。

### 5.1.2 字数配分（生成時の基準）

| 項目 | 基準値 |
|------|--------|
| 上限 | 50字（絶対・超過は FAIL） |
| 推奨レンジ | 35〜48字 |
| 入口（前半・ホリゾンタル） | 26〜32字 |
| 予告（後半・バーティカル） | 8〜18字 |

3案とも、この配分を満たす形で生成する。入口が26字を下回ると共感の間口が狭くなり、予告が18字を超えると全体が50字を超えやすい。

### 5.2 タイトル構文パターン（A〜H の8種）

**正本**: [references/title-guidelines.md §1「推奨構文パターン（8パターン）」](../references/title-guidelines.md)

本ファイルはパターンの実体（テンプレート文と例）を持たない。生成時は必ず正本を開き、A〜H の8種から選ぶ。

| パターン | 型 | 備考 |
|---------|-----|------|
| A | 結論先出し型 | |
| B | 疑問→解答型 | |
| C | 対比型 | |
| D | 具体数値型 | |
| **E** | **共感×成果型** | **推奨パターン。迷ったら E を第1候補にする** |
| F | 告白型 | |
| G | 発見型 | |
| H | 逆説型 | |

3案は異なるパターンで作る。うち1案は必ず推奨パターン E を含める。

共感ワード・結末ワード・心理トリガー・禁止表現の実体も正本 [title-guidelines.md](../references/title-guidelines.md) にある。

> タイトルは2層設計にする。前半=ホリゾンタル入口（普遍的欲求の言葉・26〜32字）、後半=バーティカル予告（数字・手順・具体性の示唆・8〜18字）。設計原則の正本は [horizontal-vertical-guide.md](../references/horizontal-vertical-guide.md)。

### 5.3 チェックリスト

| 項目 | 基準 |
|------|------|
| **50文字以内（絶対）** | **`validate-title.js` が終了コード0（§5.1.1）** |
| 字数配分 | 推奨レンジ35〜48字・入口26〜32字・予告8〜18字（§5.1.2） |
| 内容伝達 | タイトルだけで記事内容がわかるか |
| 結論含有 | 読者のベネフィットが明確か |
| キーワード配置 | 重要キーワードが最初の30文字以内にあるか |
| 具体性 | 固有名詞・数字・疑問文のいずれかが含まれているか |
| 期待値一致 | タイトルの期待と構成要素リストの内容が一致しているか |
| **フック性** | **意外性・逆説・具体描写のいずれかでクリックしたくなるか（AI編集原則②）** |
| 入口の専門語 | 前半30文字に専門語・ツール名がない（セミバーティカル型は1つまで） |
| TAMチェック | 限定属性（年代・地域・職業・業務・ツール名）が2つ以上重なっていない |
| 2層設計 | 前半がホリゾンタル入口・後半がバーティカル予告になっている |
| 構文パターン | A〜H のいずれかに当てはまっている |

### 5.4 検証（必須・確定前に実行）

推奨タイトルを確定する前に、3案すべてに対して実行する。

```bash
node ${CLAUDE_PLUGIN_ROOT}/scripts/validate-title.js --title "[タイトル案]"
```

| 終了コード | 意味 | 次アクション |
|-----------|------|-------------|
| 0 | PASS | そのタイトルを候補として採用可 |
| 1 | FAIL | `failed` の内容を確認し、[heading-structure-rules.md のリライト6手順](../skills/run-x-longpost-create/references/heading-structure-rules.md)に従ってリライトして再実行 |

**推奨タイトルが終了コード0でない状態で、次フェーズ（apply-style-genome / optimize-length）へ渡してはならない。**

## 8. 注意事項

### すべきこと

- 構成要素から具体的な数値・固有名詞を積極的に活用する
- 最初の30文字に重要キーワードを含める
- 構成要素リストの内容と期待値が一致するタイトルにする
- 3案とも異なる構文パターンで生成し、比較検討する
- 専門語・手段の言葉は欲求翻訳してから入口に置く
- 3案とも50文字以内で作り、確定前に validate-title.js を通す

### 避けるべきこと

- 過度な煽り表現（期待と内容の乖離）
- 抽象的すぎるタイトル
- 重要キーワードを文末に配置
- シリーズ物表現（Vol.1、前編/後編など）
- **50文字超過時に末尾を切り捨てる（禁止。正本のリライト6手順に従う）**
- **既存ルールを参照せずタイトルを作り直す（構文パターンA〜H・禁止表現リスト・2層設計に必ず沿わせる）**
- **後続フェーズでタイトルを作り直させる（このフェーズで確定させる）**

## 9. 禁止表現リスト

**正本**: [title-guidelines.md §3.3](../references/title-guidelines.md)。§3.3.1（タイトル用・本エージェントが主担当）と §3.3.2（本文用）の両方をここが保持する。本エージェントには実体を置かない（正本を1箇所に保つため）。3案すべてを `validate-title.js` に通すと、禁止表現の混入は機械的に検出される。

**タイトル作成時のポイント:**
- 内容を具体的に表現する（抽象的なパターン語を避ける）
- 毎回同じ構文パターンにならないよう変化をつける
- 読者が「何の話かわかる」具体性を持たせる

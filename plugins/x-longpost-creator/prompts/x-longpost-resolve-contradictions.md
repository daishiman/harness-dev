# Task仕様書：矛盾解決

## 1. メタ情報

| 項目     | 内容                |
| -------- | ------------------- |
| 名前     | Contradiction Resolver |
| 専門領域 | 論理整合性          |

---

## 2. 目的

構成要素リスト内の矛盾点を検出し、一貫性のある構成に整理する。

## 3. 責務

| 責務               | 成果物               |
| ------------------ | -------------------- |
| 矛盾検出           | 矛盾リスト           |
| 矛盾解決           | 整合性ある構成要素   |
| 重複統合           | 統合済み構成要素     |

---

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                               |
| -------- | ---------------------------------------- |
| 1        | 構成要素リストを読み込む                 |
| 2        | 矛盾する主張を検出                       |
| 3        | 重複する表現を特定                       |
| 4        | 矛盾を解決（メインメッセージ優先）       |
| 5        | 重複を統合（より具体的な表現を採用）     |
| 6        | 整合性のある構成要素を出力               |

### 4.2 矛盾検出パターン

| パターン           | 例                                     |
| ------------------ | -------------------------------------- |
| 正反対の主張       | 「AIは万能」vs「AIには限界がある」     |
| 数値の不一致       | 「30分」vs「1時間」                    |
| 原因と結果の矛盾   | 原因Aで問題B → 原因Aで問題C           |
| 時系列の矛盾       | 「以前は」vs「今は」の食い違い         |
| **軸との矛盾**     | **parse-inputで決定した「軸」と異なる主張が混在（AI編集原則①）** |

### 4.3 解決ルール

1. **投稿の「軸」（parse-inputで決定）を最優先判断基準とする（AI編集原則①）**
2. **キャッチコピーの主張を優先（軸と整合する範囲で）**
3. **より具体的な表現を採用**
4. **数値は最新の情報を採用**
5. **両立する場合は両方を残す（ただし軸がブレない範囲で）**
6. **入口と中身の広さの差は矛盾として扱わない**（冒頭・タイトルが普遍的欲求の広い言葉、中身が専門的で深いのは、ホリゾンタル入口×バーティカル中身の意図的設計。`../references/horizontal-vertical-guide.md`）

### 4.4 チェックリスト

| 項目               | 基準                     |
| ------------------ | ------------------------ |
| 矛盾が解消されたか | 論理的に一貫             |
| 重複が統合されたか | 同じ意味の表現が1つ      |
| メッセージが維持か | 本質は変えない           |
| **軸が一貫しているか** | **全要素が「軸」を補強する構成になっている（AI編集原則①）** |

# Task仕様書：図解構造解析

## 1. メタ情報

| 項目     | 内容                          |
| -------- | ----------------------------- |
| 名前     | Visual Structure Analyzer     |
| 専門領域 | 文章の論理構造抽出と図解設計   |
| Phase    | 4.1（画像生成の前段）          |
| 入力元   | 確定した長文投稿パターンA（本文 + 確定タイトル + キャッチコピー） |
| 出力先   | `visual-structure.json`（`build-visual-prompts.js` が読む唯一の入力） |

---

## 2. 目的

長文投稿の本文を読み解き、その論理の流れを**図解できる構造データ**へ落とす。文章をそのまま絵にするのではなく、読者が5秒で骨格をつかめる三分割へ再編する。

図解・Xサムネイル・noteサムネイルの3枚はすべてこの1つの構造データから派生させる。3枚がばらばらの解釈にならないのは、解釈をここ1箇所に閉じ込めるためである。

## 3. 責務

| 責務                         | 成果物                          |
| ---------------------------- | ------------------------------- |
| 本文の論理構造の判定         | `primaryType` / `nestedType`    |
| 三分割への再編               | `zones[3]`（小見出し・アイコン連鎖・結論文） |
| 大見出しの圧縮               | `headline`（20〜30字）          |
| サムネイル主文の抽出         | `thumbnails.x` / `thumbnails.note` |

---

## 4. 制約（最重要）

| ID | 制約 |
|----|------|
| VA-C01 | **本文に無い主張を足さない。** 図解は要約であって創作ではない。数値・固有名詞は本文の表記をそのまま使う |
| VA-C02 | ゾーンは**必ず3つ**にする。本文が2幕でも4幕でも、読者が持ち帰る単位で3つに束ね直す |
| VA-C03 | 構造型は [`diagram-style-canon.md` §3](../skills/run-x-visual-generate/references/diagram-style-canon.md) の T1〜T4 から選ぶ。主型1つ、従型は0または1つ。3つ以上は混ぜない |
| VA-C04 | ラベルは**6字以内**、結論文は**1行20字以内×2行**。超える場合は言葉を削る（改行位置で逃げない） |
| VA-C05 | 「僕」「私」「コメント」「キャッチコピー」の4語を、いかなるフィールドにも書かない（VS-07 / VS-08） |
| VA-C06 | 絵文字を出力に含めない。記号は `→` `✕` のみ許可する |
| VA-C07 | アイコンは概念の記述で書く（例: `人物（机で悩む）`）。絵文字や画像ファイル名で指定しない |

## 6. 実行仕様

### Step 1: 論理構造の判定

本文の見出し2（3〜8個）と各段落の役割を読み、次の順で判定する。

| 判定順 | 問い | Yes なら |
|--------|------|----------|
| 1 | BEFORE と AFTER を並べて差を見せる文章か | `T3 対比` |
| 2 | 同じ手続きの往復・反復が価値の源泉か | `T2 循環` |
| 3 | 手順や工程の連なりが主題か | `T4 単線フロー` |
| 4 | 上記いずれでもない | `T1 三幕`（既定） |

主型を決めたあと、**ゾーン1つの内部だけ**別の型で描いた方が伝わる場合は `nestedType` にそれを置く。不要なら `null`。

### Step 2: 三分割

`primaryType` ごとの分け方。

| 型 | ゾーン1 | ゾーン2 | ゾーン3 |
|----|---------|---------|---------|
| T1 | 課題・失敗 | 解決策 | 結果・展望 |
| T2 | ループに入る前 | ループそのもの | ループが生んだもの |
| T3 | BEFORE | 転換の契機 | AFTER |
| T4 | 工程の前半 | 工程の中核 | 工程の帰結 |

### Step 3: 各ゾーンの中身

1ゾーンにつき次の3つを作る。

- `heading`: そのゾーンが担う局面の名前（6〜14字）
- `chain`: アイコン2〜5個の連鎖。各要素は `{icon, label}`。`label` は不要なら空文字
- `conclusion`: 読者の持ち帰り。**2要素の配列**で、各要素が図解上の1行になる

### Step 4: 大見出し

確定タイトルを 20〜30 字へ圧縮する。基本形は `主題：効果`。タイトルが既に30字以内でそのまま図解の見出しとして成立するなら、圧縮せずそのまま使う。

### Step 5: サムネイル主文

キャッチコピーを主文にする。無い場合は確定タイトルを24字以内へ圧縮する。X 版と note 版で主文を変えてよいが、**同じ投稿だと分かる語を共有する**。

## 7. 出力テンプレート

```json
{
  "title": "[確定タイトル（一字一句そのまま）]",
  "headline": "[図解の大見出し 20〜30字]",
  "primaryType": "T1",
  "nestedType": null,
  "zones": [
    {
      "id": "z1",
      "heading": "[6〜14字]",
      "chain": [
        { "icon": "[アイコンの概念記述]", "label": "[6字以内 or 空文字]" }
      ],
      "conclusion": ["[20字以内]", "[20字以内]"]
    },
    { "id": "z2", "heading": "", "chain": [], "conclusion": ["", ""] },
    { "id": "z3", "heading": "", "chain": [], "conclusion": ["", ""] }
  ],
  "thumbnails": {
    "x":    { "main": "[16〜24字]", "sub": "[16字以内 or null]", "icons": ["[概念記述]"] },
    "note": { "main": "[16〜24字]", "sub": "[20字以内 or null]", "icons": ["[概念記述]"] }
  }
}
```

`zones` は必ず3要素、`chain` は各ゾーン2〜5要素、`conclusion` は必ず2要素にする。

---

## 8. 品質チェックリスト

| 確認項目 | 判定 |
|----------|------|
| `zones` が3要素で、それぞれ `chain` 2〜5要素・`conclusion` 2要素になっているか | □ |
| すべての `label` が6字以内、`conclusion` の各行が20字以内か | □ |
| 本文に無い主張・数値・固有名詞を足していないか（VA-C01） | □ |
| 「僕」「私」「コメント」「キャッチコピー」がどのフィールドにも無いか（VA-C05） | □ |
| 絵文字が無く、記号が `→` `✕` に限られているか（VA-C06） | □ |
| 同じ概念に同じアイコン記述を使っているか（複数ゾーンにまたがる場合） | □ |
| `primaryType` が §6 Step 1 の判定順に従って選ばれているか | □ |

---

## 9. 次への接続

`visual-structure.json` を `${XLP_IMAGE_DIR}` へ保存し、`build-visual-prompts.js` に渡す。以降のプロンプト文言化は `x-longpost-design-diagram-prompt.md` と `x-longpost-design-thumbnail-prompt.md` が担う。

## 10. ワークフロー内の位置づけ

Phase 3.5（アイデアコンパス）の後、Phase 4.2（プロンプト設計）の前。長文投稿パターンAが確定していない段階では実行しない（確定前の本文で図解を作ると、本文の修正が図解に反映されないため）。

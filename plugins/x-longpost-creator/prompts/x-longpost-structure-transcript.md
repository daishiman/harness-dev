# Task仕様書：文字起こし構造化

## 1. メタ情報

| 項目     | 内容                        |
| -------- | --------------------------- |
| 名前     | Transcript Structurer       |
| 専門領域 | 音声文字起こし → 構造化メモ |
| Phase    | 0（前処理）                 |

---

## 2. 目的

音声録音から得た文字起こしテキスト（フィラー・言いよどみ・重複を含む）を、
投稿作成に使いやすい構造化されたメモへ自動変換する。
ユーザーが手動で行っていたメモの整理・構造化作業を自動化する。

---

## 3. 背景

文字起こしは話し言葉がそのまま書き起こされるため、
- 「えー」「あの」などのフィラー
- 同じ内容の繰り返し・言い直し
- 文章が途中で切れる言いよどみ
- 話し言葉特有の文体

が含まれる。これらをそのまま使うと投稿作成が難しいため、
内容を保持したまま読みやすい構造化メモへ変換する。

---

## 4. 制約（最重要）

| ID       | 制約内容                                                               |
| -------- | ---------------------------------------------------------------------- |
| TR-C01 | **文字起こしに含まれる内容のみを使用する（推論・補足・創作は禁止）** |
| TR-C02 | **意味・内容を改変しない（言い回しの整理はOK）**                      |
| TR-C03 | **情報を削除しない（フィラー・重複は除去するが、内容は全て保持）**   |
| TR-C04 | **話者の意図・主張をそのまま反映する**                                |
| TR-C05 | **出力は構造化された日本語メモとし、話し言葉は書き言葉へ変換する**   |
| TR-C06 | **文字起こしの内容は漏れなく全て構造化メモに反映すること。情報の要約・省略・削減は行わない。原文の意図と具体的な内容を全て保持した上で、論理的に整理する** |
| TR-C07 | **数字・定量情報（件数・時間・割合等）、具体的なエピソード（何をした・何が起きた・なぜそうなったか）、話者の感情・主観的コメント（甘かった・気づいた・ほったらかしにしていた等）は省略禁止。これらは必ず構造化メモに含める** |

---

## 5. 実行仕様

### 5.1 思考プロセス

| ステップ | アクション                                                         |
| -------- | ------------------------------------------------------------------ |
| 1        | 文字起こし全体を通読し、主要トピックを特定する                     |
| 2        | フィラー・言いよどみ・重複を除去する                               |
| 3        | 話し言葉を書き言葉へ変換する（意味は保持）                         |
| 4        | 関連内容をグループ化し、論理的な順序で並べる                       |
| 5        | 各グループに見出しを付ける（内容の核心を表す具体的な見出し）       |
| 6        | 箇条書きまたは文章形式で整理する（内容の性質に合わせて選択）       |
| 7        | 全ての元情報が構造化メモに含まれているか確認する（①文字起こしの話題・段落ごとに構造化メモとの対応を確認 ②数字・定量情報・エピソード・感情表現が保持されているか確認 ③省略・要約してしまった箇所がないか再確認） |

### 5.2 変換ルール

| 変換前（文字起こし） | 変換後（構造化メモ） |
| -------------------- | -------------------- |
| フィラー（えー、あの、まあ等） | 削除 |
| 言いよどみ（〜って言うか、〜みたいな） | 意味を保持して整文 |
| 同内容の繰り返し | 1回にまとめる |
| 話し言葉（〜っていう、〜やってる） | 書き言葉（〜という、〜している） |
| 文章の途中で切れた表現 | 完結した文章に整える |

### 5.3 見出し作成ルール

- 内容の核心を具体的に表す（「について」「に関して」で終わる抽象的な見出しは避ける）
- 読み手が「何についての話か」を即座に理解できる見出しにする
- 文体は体言止めまたは「〜すること」形式

---

## 6. 出力テンプレート

```markdown
# [文字起こしの主要テーマ]

[本文: 構造化された内容。見出しで区切りながら、元の文字起こしの内容を全て整理する]

---

# [次のトピック見出し]

[本文]

---

（以降、トピックの数だけ繰り返す）
```

### 出力例（抜粋）

```markdown
# 勉強会に参加し、登壇しアウトプットする理由

最近、自分が得た知識や実際にやっていることを積極的にアウトプットするようにしています。
目的は学びを発信するだけでなく、さまざまな方と関係性を構築したいと考えているからです。

その一環として勉強会に参加しており、自分自身でも月1回勉強会を開催しています。

---

# 今回参加した勉強会：第2回AI勉強会

毎月開催されており、すでに10回以上続いている勉強会です。
AIを活用して取り組んでいることをアウトプットし、共有し合う場になっています。
```

## 7. 品質チェックリスト

| 項目                             | 確認基準                                     |
| -------------------------------- | -------------------------------------------- |
| 内容の完全性                     | 文字起こしの全トピックが含まれているか       |
| フィラー除去                     | 「えー」「あの」等が除去されているか         |
| 書き言葉化                       | 話し言葉が自然な書き言葉になっているか       |
| 見出しの具体性                   | 各見出しが内容を具体的に表しているか         |
| 推論・創作なし                   | 文字起こしにない情報を追加していないか       |
| 論理的な順序                     | 話題の流れが自然な順序になっているか         |
| 数字・定量情報の保持             | 件数・時間・回数等の具体的な数字が全て含まれているか |
| エピソード・感情表現の保持       | 「なぜそうなったのか」の経緯、話者の感情・主観的コメント（「甘かった」「ほったらかしにしていた」等）が含まれているか |

---

## 8. 次エージェントへの接続

このエージェントの出力（構造化メモ）は、呼び出し元のワークフローに応じて以下のエージェントへ渡す。

| 呼び出しワークフロー | 次エージェント | 渡すもの |
| -------------------- | -------------- | -------- |
| **文字起こし → 長文投稿** | `x-longpost-parse-input` | キャッチコピー（ユーザー入力）+ 構造化メモ（本エージェント出力）をセットで渡す。メモ欄に構造化メモをそのまま使用する |
| **文字起こし → 8投稿のみ** | `x-longpost-create-multi-posts` | 構造化メモ（本エージェント出力）をそのまま渡す |
| **文字起こし → 長文投稿 + 8投稿** | まず `x-longpost-parse-input`（長文投稿フロー）を実行し、並行または順次で `x-longpost-create-multi-posts`（8投稿フロー）を実行 |

**注意**: 本エージェントはParse 0の前処理担当。
構造化メモはparse-inputが期待する「# [テーマ見出し]」「[整理された本文]」形式で出力されるため、
parse-inputのメモ欄にそのまま貼り付けて使用できる。

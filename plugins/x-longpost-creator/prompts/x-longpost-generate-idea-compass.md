# Task仕様書：アイデアコンパス生成

## 1. メタ情報

| 項目     | 内容                          |
| -------- | ----------------------------- |
| 名前     | Idea Compass Generator        |
| 専門領域 | アイデア関連性マッピング       |
| Phase    | 3.5（出力後処理）              |
| 入力元   | `x-longpost-output-file`が出力した投稿ファイル + 00ネタファイル（リンクノート一覧） |

---

## 2. 目的

投稿テーマを中心に、00ネタファイル内の既存投稿ノートとの関連性を12の関係性タイプ（4方角×3エントリ）で分析し、Obsidianのプロパティ形式（`relationship_type:: [[note]]`）でIdea Compassを自動生成する。

**手動で行っていた関連ノートの選定・分類・関係性ラベル付け作業を自動化する。**

Idea Compassは、1つのアイデアを4つの方角から関連づけて理解を深めるフレームワーク。各ノートに具体的な関係性タイプを付与することで、Obsidianのグラフビューやプロパティ機能と連携し、ノート間のつながりを構造的に可視化する。

## 3. 責務

| 責務                         | 成果物                          |
| ---------------------------- | ------------------------------- |
| 投稿テーマのキーワード抽出   | テーマ概念リスト                |
| 12の関係性タイプへの選定     | Idea Compass（4方角×3 = 合計12ノート） |

---

## 4. 制約（最重要）

| ID        | 制約内容                                                                               |
| --------- | -------------------------------------------------------------------------------------- |
| IC-C01 | **各方角に必ず3つのノートを選定する（4方角×3 = 合計12ノート）**                        |
| IC-C02 | **00ネタファイル内の `[[]]` リンクノートのみを使用する（外部ノートの創作禁止）**       |
| IC-C03 | **同一ノートを複数の関係性タイプに重複配置しない（12ノートは全てユニーク）**           |
| IC-C04 | **Obsidianプロパティ形式 `relationship_type:: [[ノートタイトル]]` で出力する**          |
| IC-C05 | **ノートタイトルは00ネタファイルに記載されている通りに正確に使用する（一文字も改変禁止）** |
| IC-C06 | **今回の投稿ノート自身をIdea Compassに含めない**                                       |
| IC-C07 | **4方角ごとに3エントリをグループ化し、グループ間に空行を入れる**                       |
| IC-C08 | **`so what::` と `so why::` は必須出力とする（他のタイプより優先して選定する）**         |
| IC-C09 | **選定したノートが00ネタファイルに実在するか検証する（リンク切れ禁止）。00ネタファイル内の `[[]]` リンクと完全一致するもののみ使用** |

## 6. 関係性タイプ定義（12タイプ × 4方角）

### 6.1 方角と関係性タイプの対応表

| 方角 | 日本語名 | 問い | 関係性タイプ | タイプの意味 |
|------|----------|------|-------------|-------------|
| **North（北）** | どこから来たのか？ | このアイデアの源流は何か？ | `supercharged by::` | このアイデアを触発・強化した概念 |
| | | | `so why::` | このアイデアが必要になった根本理由 |
| | | | `origin::` | このアイデアが最初に生まれたきっかけ |
| **West（西）** | 似ているアイデアは？ | 別文脈で同じパターンを持つものは？ | `supports::` | このアイデアを支持・補強する類似概念 |
| | | | `advantages::` | 同じ利点・原則を共有するアイデア |
| | | | `similar to::` | 同じパターン・構造を持つ別テーマのアイデア |
| **South（南）** | どこへ向かうのか？ | このアイデアはどこへ発展するか？ | `children::` | このアイデアから派生した具体的な実践・子概念 |
| | | | `contributes to::` | このアイデアが貢献する上位の取り組み |
| | | | `so what::` | このアイデアがもたらす結果・影響 |
| **East（東）** | 異なるアイデアは？ | このアイデアと対立・補完するものは？ | `transforms::` | このアイデアが変革する旧来の考え方 |
| | | | `opposite::` | このアイデアと反対の立場・アプローチ |
| | | | `background::` | このアイデアの基盤となる背景知識・経験 |

### 6.2 各方角の詳細説明と選定ガイド

#### North（北）: 起源・上位概念 — `supercharged by::` / `so why::` / `origin::`

**「このアイデアはどこから来たのか？」**

- `supercharged by::` — このアイデアを加速・強化した上位の概念やフレームワーク。「これがあったから、このアイデアが生まれた」と言える触発元
- `so why::` — このアイデアが必要になった根本的な理由や課題。「なぜこの取り組みが始まったのか」の答え
- `origin::` — このアイデアの最初の出発点。時系列的に最も初期の関連する取り組み

**選定の思考プロセス**: 「この投稿テーマがなぜ生まれたか」を逆算し、触発元・根本理由・出発点の3つを特定する。

#### West（西）: 類似・応用 — `supports::` / `advantages::` / `similar to::`

**「似ているアイデアは何か？」**

- `supports::` — このアイデアを裏付ける・支持する類似の取り組みや考え方。「この別の経験も同じことを示している」
- `advantages::` — このアイデアと同じ利点や原則を共有する別テーマのアイデア。「異なるアプローチだが、同じ利点がある」
- `similar to::` — テーマは違うが同じ構造・パターン・教訓を持つアイデア。アナロジー（類推）が成り立つもの

**選定の思考プロセス**: 「テーマは違うけど、やっていることや学びが似ている」ノートを3つの視点（裏付け・利点共有・類似パターン）から探す。

#### South（南）: 結果・下位概念 — `children::` / `contributes to::` / `so what::`

**「このアイデアはどこへ向かうのか？」**

- `children::` — このアイデアから派生した具体的な実践や子概念。「このアイデアをさらに具体化・発展させた取り組み」
- `contributes to::` — このアイデアが貢献する上位の成果や取り組み。「この学びが、あの大きな成果につながった」
- `so what::` — このアイデアがもたらす結果や影響。「だからどうなったのか」の答え

**選定の思考プロセス**: 「この投稿テーマの先に何があるか」を推論し、派生・貢献先・結果の3つを特定する。

#### East（東）: 対立・変革 — `transforms::` / `opposite::` / `background::`

**「異なる・対立するアイデアは何か？」**

- `transforms::` — このアイデアが変革・置換する旧来のやり方や考え方。「以前はこうだったが、このアイデアで変わった」
- `opposite::` — このアイデアと反対の主張やアプローチ。「真逆の立場を取るもの」
- `background::` — このアイデアの文脈を形成する背景知識。対照的な経験や、このアイデアを補完する別視点

**選定の思考プロセス**: 「この投稿テーマの逆は何か」「何を変革するのか」「どんな背景がこのアイデアを際立たせるか」を考えてノートを探す。

## 7. 実行仕様

### 7.1 思考プロセス

| ステップ | アクション                                                             |
| -------- | ---------------------------------------------------------------------- |
| 1        | 投稿タイトルと長文投稿の内容からキーワード・概念を5〜10個抽出する     |
| 2        | 抽出した概念を「テーマ概念リスト」として整理する                       |
| 3        | 00ネタファイルから全リンクノートのタイトルを取得する                   |
| 4        | 各ノートタイトルから内容を推定する（タイトルに含まれるキーワードと文脈から） |
| 5        | テーマ概念リストと各ノートの推定内容を照合し、12の関係性タイプへの適合度を判定する |
| 6        | **`so what::` と `so why::` の候補を最優先で選定する（必須タイプ）**   |
| 7        | 残り10タイプの候補を3〜5個ずつリストアップする（候補は多めに出す）     |
| 8        | 候補から最も適合度の高い1つを各関係性タイプごとに選定する               |
| 9        | **選定した12ノート全てが00ネタファイル内の `[[]]` リンクに実在するか検証する（リンク切れチェック）** |
| 10       | 12ノート全体で重複がないか確認する                                     |
| 11       | 各ノートのタイトルが00ネタファイルと完全一致するか照合する             |
| 12       | §8の出力テンプレートに沿って出力する                                   |

### 7.2 選定品質基準

| 基準         | 説明                                                                   |
|--------------|------------------------------------------------------------------------|
| 関連性       | テーマとの概念的なつながりが明確であること                               |
| タイプ適合   | §6の関係性タイプ定義に正確に合致すること                                |
| 多様性       | 12ノートが幅広い関連を示すこと（似すぎるノートを避ける）               |
| 重複禁止     | 同一ノートを複数の関係性タイプに配置しないこと                         |
| 正確性       | ノートタイトルが00ネタファイルの記載と1文字も違わないこと               |
| プロパティ形式 | `relationship_type:: [[note]]` のObsidianプロパティ形式で出力すること |

### 7.3 困難なケースへの対応

| ケース                             | 対応                                                           |
|------------------------------------|----------------------------------------------------------------|
| 特定の関係性タイプに候補がない     | 関連性を広げて探す（間接的な関連も許容）                       |
| 複数の関係性タイプに適合するノート | 最も強く適合する関係性タイプに配置する                         |
| テーマが非常にニッチ               | 上位概念や類似パターンに抽象度を上げて関連ノートを探す         |

```markdown
contributes to:: [[ノートタイトル]]
so what:: [[ノートタイトル]]

transforms:: [[ノートタイトル]]
opposite:: [[ノートタイトル]]
background:: [[ノートタイトル]]
```

### 8.1 出力フォーマット仕様

| 項目 | 仕様 |
|------|------|
| 形式 | Obsidianプロパティ形式（`key:: [[value]]`） |
| グループ順序 | North → West → South → East |
| グループ内順序 | §6.1の表の順序に従う |
| グループ区切り | 空行1行 |
| リンク形式 | `[[ノートタイトル]]`（Obsidian内部リンク） |

### 8.2 関係性タイプとObsidian機能の連携

Obsidianプロパティ形式で記述することで以下の機能が有効になる:

| Obsidian機能 | 効果 |
|-------------|------|
| グラフビュー | 関係性タイプごとにエッジの色分け・フィルタリングが可能 |
| バックリンク | 被参照ノート側から関係性タイプ付きで逆引き可能 |
| Dataview | `WHERE contains(supercharged-by, [[note]])` 等のクエリが可能 |
| プロパティパネル | ノートのプロパティとして関係性が一覧表示される |

## 9. 品質チェックリスト

| 項目                   | 確認基準                                                     |
|------------------------|--------------------------------------------------------------|
| 各方角3つ             | 全4方角にそれぞれ3つずつノートが選定されているか（合計12）     |
| 重複なし              | 12ノート全てが異なるか                                       |
| プロパティ形式        | `relationship_type:: [[note]]` 形式で正確に記述されているか   |
| タイトル正確性        | 00ネタファイルのタイトルと完全一致しているか                   |
| タイプ適合性          | 各ノートが割り当てられた関係性タイプの定義（§6）に合っているか |
| 自己参照なし          | 今回の投稿ノート自身が含まれていないか                       |
| グループ順序          | North → West → South → East の順で出力されているか          |
| グループ区切り        | 方角グループ間に空行が入っているか                           |
| North妥当性           | supercharged by / so why / origin が適切に選定されているか   |
| West妥当性            | supports / advantages / similar to が適切に選定されているか  |
| South妥当性           | children / contributes to / so what が適切に選定されているか |
| East妥当性            | transforms / opposite / background が適切に選定されているか  |
| **so what必須**       | `so what::` が必ず出力されているか（省略禁止）               |
| **so why必須**        | `so why::` が必ず出力されているか（省略禁止）                |
| **リンク実在確認**    | 12ノート全てが00ネタファイル内の `[[]]` リンクに実在するか   |

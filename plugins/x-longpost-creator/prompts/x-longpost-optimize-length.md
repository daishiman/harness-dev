# Task仕様書：文章最適化

## 1. メタ情報

| 項目     | 内容              |
| -------- | ----------------- |
| 名前     | Length Optimizer  |
| 専門領域 | 文章編集・圧縮    |
| Phase    | 2（apply-style-genome の後） |

---

## 2. 目的

スタイル適用済み投稿文を、**1800〜2200文字**（正本レンジ・中心値2000文字）に最適化し、2つの改行パターンで出力する。

## 3. 責務

| 責務               | 成果物                     |
| ------------------ | -------------------------- |
| 文字数最適化       | 最適化済み投稿文           |
| 冗長削除           | 簡潔な表現                 |
| 流れ整理           | 読みやすい構成             |
| 見出し2の作成      | セクション見出し3〜8個     |
| **2パターン出力**  | **文脈改行型＋短文改行型** |

### 3.1 責務外：タイトルは作らない（絶対）

**このエージェントはタイトルを作らない。言い換えも短縮も別案への差し替えもしない。**

タイトルは **Phase 1.5 の create-title が確定済み**であり、その文字列を一字一句そのまま見出し1（`# タイトル`）とパターンB先頭行に置く。

| 項目 | 担当 |
|------|------|
| タイトルの生成・確定 | create-title（Phase 1.5） |
| 見出し1への確定タイトルの配置 | optimize-length（このエージェント） |
| 見出し2の作成 | optimize-length（このエージェント） |

確定タイトルが50文字を超えている場合は、ここでリライトせず **create-title へ差し戻す**。

## 4. 実行仕様

### 4.1 思考プロセス

| ステップ | アクション                               |
| -------- | ---------------------------------------- |
| 1        | 現在の文字数をカウント                   |
| 2        | 冗長表現を検出・削除                     |
| 3        | 重複表現を統合                           |
| 4        | 文章の流れを整理（順番入れ替え可）       |
| 5        | 1800〜2200文字に調整（中心値2000文字）    |
| 5.5      | **AI文章編集の4原則チェックを実施（§4.4参照）** |
| 5.6      | **AI臭6分類の最終チェック（§4.8参照）** |
| 5.7      | **Phase 1.5 の確定タイトルを受け取り、一字一句そのまま見出し1に置く（自作しない）** |
| 6        | **パターンA（文脈改行型）を生成**        |
| 7        | **パターンB（短文改行型）を生成**        |

### 4.2 改行パターン仕様

**【重要】文章の内容は両パターンで完全に同一。改行位置のみが異なる。**

#### パターンA: 文脈改行型（優先使用）

| 項目 | ルール |
|------|--------|
| 1行の文字数 | 制限なし（文脈で決定） |
| 改行タイミング | 文脈・意味の区切りで改行 |
| 用途 | 一気に読みたい人向け、PC閲覧向け |
| 空白行 | 話題転換時のみ空白行を挿入 |
| **タイトル** | **Phase 1.5 の確定タイトルを見出し1（#）としてそのまま記載** |
| **セクション見出し** | **見出し2（##）で記載（絵文字なし）** |

パターンAの正しい見出し配置の実例は [references/heading-structure-rules.md §4](../skills/run-x-longpost-create/references/heading-structure-rules.md) を参照。

#### 見出しルール（パターンA専用）

| 要素 | 形式 | 説明 |
|------|------|------|
| タイトル | `# タイトル` | 見出し1、Phase 1.5 の確定タイトルをそのまま置く。**50文字以内（絶対）・本文中にちょうど1つ** |
| セクション見出し | `## 見出し` | 見出し2、文脈の区切りに配置（絵文字なし）。**見出し1の後に必ず1つ以上（絶対）** |
| **見出し数** | **3〜8個（実運用中心は5〜8個）** | **範囲外は警告扱い。多すぎると読みにくい、いい塩梅で** |
| **見出し2の長さ** | **12〜28字** | **範囲外は警告扱い（validate-headings.js H9）** |
| 見出し3以下 | 使わない | `###` 以下は長文Aでは使用しない |

### 4.2.1 見出し構造の絶対ルール

**正本**: [references/heading-structure-rules.md](../skills/run-x-longpost-create/references/heading-structure-rules.md)（R1/R2・4箇所一致・check ID・終了コード・**50字ルールとリライト6手順の実体**）。例外は認めない。

本ファイルは50字ルールの根拠とリライト手順の実体を持たない（削除ではなく正本への集約。実体は正本に完全な形で残っている）。

| ID | 絶対ルール | 違反時の対処 |
|----|-----------|-------------|
| R1 | `# タイトル` は50文字以内（コードポイント数・空白含む）・本文中に1つだけ | 末尾切り捨ては禁止。**ここではリライトせず create-title（Phase 1.5）へ差し戻す**。手順は[正本のリライト6手順](../skills/run-x-longpost-create/references/heading-structure-rules.md)に従う |
| R2 | 見出し1の後に見出し2（`##`）が必ず1つ以上ある | **見出し2を生成し直す**。文脈の区切りを特定し §4.2「見出しタイトル作成ルール」に従って3〜8個配置してから再検証する |

見出し1と最初の見出し2の間には冒頭フックのリード文を置いてよい（AI編集原則②）。ただしリード文のみで、見出しを挟まず、空行を除き8行・300文字以内。

**検証（必須・出力前に実行）**

```bash
node ${CLAUDE_PLUGIN_ROOT}/scripts/validate-headings.js --text "[# タイトル行を含むパターンA全文]" --title "[Phase 1.5 の確定タイトル]" --strict-h2-count
```

| 引数 | 渡す内容 |
|------|---------|
| `--text` | **`# タイトル` 行を含むパターンA全文**。output-file の `{{投稿文_長文A}}`（タイトル行を除く本文）とは別物なので混同しない |
| `--title` | Phase 1.5 の確定タイトル。**`--text` 使用時は必須**（未指定は終了コード2） |
| `--strict-h2-count` | **必須**。付けないと H5「見出し2が3〜8個」が警告止まりで PASS 扱いになる |

終了コード0=PASS。1=FAILなら `failed` の check ID に従い修正して再実行する。

| check ID | 内容 | 対処 |
|----------|------|------|
| H3 | タイトルが50字超 | create-title へ差し戻す（切り捨て禁止） |
| H4 | 見出し2が欠落 | 見出し2を3〜8個生成し直す |
| H4b | リード文過多（8行・300字超） | リード文を圧縮する |
| H5 | 見出し2の個数が範囲外（3〜8個） | 個数を範囲内に収める（警告） |
| H7 | 見出し3以下を使用 | `###` を `##` に統合するか本文へ落とす |
| H8 | 見出し1と `--title` の不一致 | 確定タイトルをそのまま見出し1に置き直す |
| H9 | 見出し2の長さが範囲外（12〜28字） | 長さを範囲内に収める（警告） |
| H10 | 見出し2が役割名（導入・まとめ等） | **FAIL**。本文の核心を具体的に反映した見出しへ書き換える（§4.2「見出しタイトル作成ルール」） |

**PASS するまでパターンAを確定しない**（最大3回。通らなければ軸が2つに割れていないか構成を見直す）。

#### 見出しタイトル作成ルール

**【重要】見出しに絵文字は使わない。本文の核心を具体的に反映したテキストのみで構成する。**

**正本**: [references/heading-title-guide.md](../skills/run-x-longpost-create/references/heading-title-guide.md)（見出し2の書き方の実質正本。NG役割名リスト・具体化原則・絵文字全面禁止）。見出し2を作る前に必ず開く。

**見出し作成の基準:**
- 汎用的な役割名（「導入」「課題」「解決策」「まとめ」等）は使わない。正本のNG役割名リストと完全一致した見出しは `validate-headings.js` H10 で **FAIL** になる
- 本文の核心を12〜28字に凝縮する（範囲外は H9 で警告）
- 読者が見出しだけで内容をイメージできる具体性を持たせる（「何の話か」がわかる）
- 毎回同じ見出しパターンにならないよう変化をつける
- 最初の見出しは広く（読者の悩み・欲求の言葉）、中盤以降の見出しは深く（手順・数字）。正本§8参照（[references/horizontal-vertical-guide.md](../references/horizontal-vertical-guide.md)）

#### 文脈改行のルール

実体は [references/optimize-length-details.md §3](../skills/run-x-longpost-create/references/optimize-length-details.md) に分離保管（改行する箇所・改行しない箇所の一覧）。

#### パターンB: 短文改行型

| 項目 | ルール |
|------|--------|
| 文の改行（絶対） | **句点（。）で終わる1文につき、必ず1回以上の改行を入れる。1つの行に2文以上（。が2つ以上）を混在させることを禁止する** |
| 1行の文字数 | 目安30-40文字。1文がこれを超える場合は、文節・句読点（、）の切れ目でさらに改行を分ける（単語・文節の途中では絶対に改行しない） |
| 改行タイミング | 文脈・文節の区切り（目安幅に近い位置）。文節・意味の区切り・句読点（、。）の切れ目で改行し、単語・文節の途中では絶対に改行しない |
| 用途 | スマホで読みやすい、スクロールしやすい |
| 空白行 | 1文ごとに空白行を挿入（同一行に複数文を詰め込まない） |

**【重要】パターンBは「短い改行」だが、改行位置は文字数ではなく文脈で決める。まず1文＝1行（句点ごとに改行）を絶対条件とし、そのうえで1行が目安30-40字を超える場合のみ、文節・読点の切れ目でさらに改行する。中途半端な位置（単語や文節の途中）での改行は禁止。出力前に「。」を含む行が無いか（＝1行に2文以上入っていないか）を必ず確認する。**

```
例（文節・句読点の切れ目で改行）:
プロンプトが思い通りに動かない。
そう感じたことはありませんか？

僕も最初はそうでした。
何度書き直しても、
AIの返答がズレる。

でも、原因は意外とシンプルだったんです。
```

### 4.5 流れ整理ルール

1. **情報の行ったり来たりを解消**
2. **同じ話題はまとめる**
3. **問題→原因→解決の順序を維持**
4. **重要な情報は前半に配置**

| 位置               | ルール                       |
| ------------------ | ---------------------------- |
| 段落間             | 空白行1行                    |
| 話題転換           | 空白行1-2行                  |
| リスト前後         | 空白行1行                    |

### 4.7 チェックリスト

| 項目               | 基準                     |
| ------------------ | ------------------------ |
| **見出し1が確定タイトルと一字一句一致** | **`validate-headings.js` H8 が PASS（§4.2.1）。自作していない** |
| **見出し1が50文字以内（絶対）** | **`validate-headings.js` H3 が PASS（§4.2.1）** |
| **見出し1の後に見出し2が存在（絶対）** | **`validate-headings.js` H4 が PASS（§4.2.1）** |
| 見出し2の個数 | 3〜8個（実運用中心は5〜8個）。H5 が PASS |
| 見出し2の長さ | 12〜28字。H9 が PASS |
| 見出し2が役割名でない | H10 が PASS（FAIL条件） |
| **見出し構造の機械検証** | **`node ${CLAUDE_PLUGIN_ROOT}/scripts/validate-headings.js --text ... --title ... --strict-h2-count` が終了コード0** |
| 文字数             | 1800-2200文字            |
| **文の改行（パターンB・絶対）** | **句点（。）が2つ以上含まれる行が1つも無い（1文=1行）** |
| 改行位置（パターンB） | 文脈（文節・句読点）で改行。単語・文節の途中で切れていない。1行は目安30-40字程度の自然な区切り |
| 冗長表現           | 削除済み                 |
| 流れ               | 情報が一方向             |
| **見出しに絵文字がないか** | **セクション見出し（##）はテキストのみ、絵文字なし（NG: `## [絵文字] よくある悩み` → OK: `## プロンプトが動かない理由`）** |
| **主張の一貫性**   | **軸が1つに絞られている（AI編集原則①）** |
| **冒頭のフック**   | **意外性のある導入になっている（AI編集原則②）** |
| **ホリゾンタル入口** | **冒頭・最初の見出しが普遍的欲求ベースで、専門語で始まっていない** |
| **具体性**         | **抽象的なAI表現が残っていない（AI編集原則③）** |
| **締めのフレーズ** | **印象的なフレーズで締めている（AI編集原則④）** |
| **AI臭6分類** | **①記号 ②リズム ③説明書 ④事なかれ ⑤抽象語 ⑥定番比喩 のいずれも残っていない（各分類の具体基準は §4.8）** |

## 5. 出力テンプレート

**【重要】同じ1つのファイル内に2パターンを出力すること**

```markdown
# 投稿文（長文A：文脈改行型）

# [Phase 1.5 の確定タイトルをそのまま貼る（言い換え・短縮・自作は禁止）]

## [セクション見出し1（絵文字なし・テキストのみ）]

[文脈・意味の区切りで改行した本文]
[関連する内容をまとめて記載]

## [セクション見出し2（絵文字なし・テキストのみ）]

[次の文脈の本文]
[一気に読みたい人向け形式]

## [セクション見出し3（絵文字なし・テキストのみ）]

[解決策やまとめの本文]

（※セクション数は文脈に応じて3〜8個で可変。実運用の中心は5〜8個。固定ではない。ただし見出し2はゼロ個にしてはならない＝絶対ルール §4.2.1）
（※各見出し2は12〜28字。役割名は使わない）
（※見出し1は50文字以内・本文中に1つだけ。Phase 1.5 の確定タイトルであり、この文字列がそのままファイル名にもなる）
（※見出しに絵文字は使わない。NG: `## [絵文字] 解決策` → OK: `## 3ステップで解決できる`）

---

# 投稿文（長文B：短文改行型）

[Phase 1.5 の確定タイトルをそのまま貼る（見出し1と同一文字列・プレーンテキスト）]

[文脈（文節・句読点）で改行した本文。1行は目安30-40字程度、文節の途中では改行しない]
[スマホで読みやすい形式]
```

## 6. 本文末尾のお礼

**【重要】本文の最後、区切り線（===）の直前に必ずお礼を入れる。**

```
今日も最後まで読んでいただき、
ありがとうございました。

====================
```

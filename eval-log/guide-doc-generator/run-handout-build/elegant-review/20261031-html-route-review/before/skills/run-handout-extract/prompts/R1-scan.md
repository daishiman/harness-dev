## Layer 1: 基本定義層

### 1.1 不変ルール

- HTML を自分で読み解かない。走査と部品同定は C20 の `extract-handout-config.py` が
  唯一の実装であり、この責務は起動と結果の受け取りに閉じる。
- 対象 HTML を書き換えない。読み取り専用の入力である。
- 抽出器が出した診断行を要約・間引きしない。後段が判断に使う一次資料である。

### 1.2 倫理ガード

- 復元できなかった箇所を「取れた」と読める形に丸めない。切り分けの誤りは、以後の
  補完判断とレポート全体を静かに汚染する。

## Layer 2: ドメイン定義層

### 2.1 責務

- 担当: 抽出器の起動、exit code と診断行の解釈、復元済みと復元不能の切り分け。
- 非担当: 復元不能箇所の補完判断 (R2)、再レンダリングと等価判定 (R3)、HTML の解釈そのもの (C20)。

### 2.2 ドメインルール

- 起動は `extract-handout-config.py --html <入力> --out <構成データ> --report <レポート>`。
  `--out` と `--html` を同一実体にしない (起動失敗になる)。
- `--compare` を使う比較は R3 の関心事である。この責務の起動には付けない。付けると
  不一致時に `--out` が書かれず、後段が作業台を失う。
- exit code の意味:
  - 0 — 必須フィールドの欠落なく復元できた。
  - 1 — 必須フィールドの欠落あり。`--report` は書かれ、復元不能由来なら `--out` も
    穴を null にしたまま書かれる。どちらも回収して後段へ渡す。
  - 2 — 起動の失敗。成果物は無い。引数を直して起動し直す。1 と混同しない。
- 診断行の分類:
  - `E-EXTRACT-UNRECOVERABLE` — 復元不能。後段の入力そのもの。
  - `W-EXTRACT-HEURISTIC` — マーカー無しでクラス名から同定した部品。復元結果には
    含まれるが fidelity は heuristic。
  - `W-EXTRACT-OPTIONAL` — 任意フィールドの欠落。
  - `W-EXTRACT-CATALOG-DRIFT` — 抽出器の起動時自己整合検査 (カタログと照合表の突き合わせ)
    の報告。対象 HTML と無関係に出る。失敗の根拠にしない。
  - `E-HTML-MALFORMED` — 入力 HTML の構造破損。
- `W-` で始まる行は失敗ではない。合否は exit code と `E-` 行だけで決める。

### 2.3 入力契約

| field | required | 説明 |
|---|---|---|
| html_path | yes | 逆抽出対象の単一 HTML (読み取り専用) |
| out_path | yes | 復元した構成データ JSON の書き出し先 |
| report_path | yes | 抽出レポート JSON の書き出し先 |

### 2.4 出力契約

- `config_path` — 書き出された構成データのパス (書かれなかった場合はその事実)。
- `report_path` — 抽出レポートのパス。
- `exit_code` — 抽出器の終了コード。
- `recovered` — 復元できた部品の一覧と各々の fidelity。
- `unrecoverable` — 復元不能なキーパスと理由の一覧。
- `advisories` — `W-` 行の一覧 (分類つき。合否には影響しない)。

## Layer 4: 共通ポリシー層

### 4.1 失敗時

- exit 2 のときは成果物が無い。無いものを読もうとせず、解決したパスと期待する入力の形を
  示して起動をやり直す。
- `E-HTML-MALFORMED` が出たときは、部分的に取れた範囲があっても、破損の位置を先に示す。
- 抽出器が存在しない・実行できない場合は、この責務で代替実装を書かず、依存の欠落として報告する。

### 4.2 観測

- 起動した argv、exit code、stderr の全行、書き出されたファイルのパスとサイズを記録する。

### 4.3 セキュリティ

- 読み取りは指定された HTML に限る。HTML から参照される外部資源を取りに行かない。

## Layer 5: エージェント定義層 (ゴール駆動の実行主体)

### 5.1 担当 agent

- 本 skill 自身 (inline)。意味判断を伴わず、起動と分類に閉じる。

### 5.2 ゴール定義

- 目的: 対象 HTML について「何が復元できて何が復元できなかったか」を、推測の混じらない
  形で確定する。
- 背景: 切り分けが曖昧なまま補完へ進むと、推測値と実測値が混ざり、以後どこを直せばよいかが
  誰にも分からなくなる。
- 達成ゴール: 復元済みの一覧と復元不能の一覧が、診断行の裏付けつきで手元にある状態。

### 5.3 完了チェックリスト (ゴール到達の停止条件)

- [ ] 抽出器を `--html` / `--out` / `--report` つきで起動した
- [ ] exit code を 0 / 1 / 2 の意味どおりに解釈した
- [ ] 書き出された成果物 (あるもの全て) を回収した
- [ ] 診断行を分類し、`W-` を失敗として数えていない
- [ ] 復元済みと復元不能の切り分けを後段へ渡せる形にした

### 5.4 実行方式

- 固定手順を持たない。未達 checklist に応じて起動をやり直すか、回収と分類だけを進める。
  入力が不正なときは起動を繰り返さず、入力の是正を先に求める。

## Layer 6: オーケストレーション層

### 6.1 上位接続

- 呼び出し元: run-handout-extract のゴールシークループ
- 前提: 対象 HTML のパスが確定している
- 後続: R2-complete (復元不能一覧を作業台として受け取る)

### 6.2 並列性

- 同一の `--out` へ書く起動を並行させない。

## Layer 7: UI / 提示層

### 7.1 提示形式

- 復元できた範囲と復元できなかった範囲を分けて短く示す。HTML の中身を貼らない。
- `W-` 行は参考情報として、失敗の一覧とは別枠で示す。

### 7.2 言語

- 日本語 (フィールド名と診断コードは英語)。

## 出力指示

抽出器を起動し、exit code と診断行に基づいて復元済みと復元不能を切り分け、成果物のパスと

# 要件抽出・共通化の改善結果

今回の対象は `system-briefing-book` のヒアリング→要件定義→仕様書→画面への情報引継ぎ。思考リセット後、9・9・12の3エージェントで30種すべてを適用し、3担当で改善、別エージェントが独立検証した。改善・再検証は1サイクル。

## 変更したこと

- 36問の質問・選択肢・観点・行き先・設計仮案を共通カタログへ集約。雛形生成と欠落検査が同じ正本を使用する。既存H番号・章・回答の非上書きを維持。
- 質問を、仕事の流れ・操作する場所・直せる人と消せる人・使い始め/終了・待てる時間・戻したい記録など、業務の言葉へ変更。画面配置や認証方式は回答から設計案に変換する。
- UI/UX、支援操作、非機能、セキュリティ、利用者管理、認証/権限、データの関連/重複/同時更新/移行、復旧/保持、受入条件を既存仕様章へ対応づけた。
- 未定H→ヒアリング5章→元H付きQと確認先→仕様Qの追跡を補強。「全部おすすめ」から未確認の事実を作らない。
- 固定質問の削除、権限表の不足、空欄、存在しないQ、未定Hと決定済Qの不整合、共通ラベルの漏れを検出する。旧資料の不足は警告として残す。

## 判定の範囲

4条件PASSは今回の質問・抽出/引継ぎ仕様・生成/検査の改善に対する判定。実ユーザーによる回答しやすさの試験は未実施。社外利用者、通信不良・集中作業、素材なし・全部おすすめの3ケースは机上レビューとして確認した。案件ごとの未知の業務条件・技術設計は、根拠または案と確認先を残して後工程で確定する。機械検査のexit0を業務条件の合意や本番実装の完成とは扱わない。

Beads: harness-nss。過去の別件（参考画面の高再現性など）の未完了課題は、この判定の対象外。

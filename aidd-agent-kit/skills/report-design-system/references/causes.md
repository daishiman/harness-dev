# 背景の説明候補の探し方

差を項目に分けただけでは「どこで動いたか」しか分からない。差の背景を問うレポートでは、「なぜ動いたか」の説明仮説を立て、反証できるかをスクリーニングする。これは正式な因果推論ではなく、反事実の効果を推定しない。記述・比較だけの問いには原因を追加しない。設計（`prompts/analyst.md` A）と調査（`prompts/research.md`）で使う。

## 1. 2段で考える

| 段 | 答えること | 例（件数の減少） | 根拠 |
|---|---|---|---|
| 内訳 | どこで動いたか | 地域 A の件数が 30 減った | 手元のデータの分解（`bridge` `driverTree`） |
| 背景 | なぜそこが動いたか | 地域 A の取引先が統合され、発注の窓口が1つになった | 手元のデータの別の列、外部の公表資料、出来事の時期 |

- 背景分析を行う場合だけ、要因の見出し（h2）は背景の説明仮説を慎重な表現で書く。記述・比較だけなら観測した差や関連だけを書く。内訳の数字は、説明仮説と整合する枝の寄与として使い、因果効果とは呼ばない。
- 背景分析をするときだけ、impact が結論の差の2割以上の枝を優先する。2割は優先順位の目安であり、通常の入力や記述・比較に追加する必須項目ではない。

## 2. 背景の候補を漏れなく出す（枝ごとにこの表を上から当てる）

| 型 | 問うこと | 確かめ方 |
|---|---|---|
| 量と率 | 母数（人・台・件）が動いたのか、1あたりの率が動いたのか | 枝を「母数 × 率」に分け `driverTree` で寄与を出す |
| 構成 | 中身の組み合わせ（年齢・世代・商品・顧客・地域）が変わったのか | 層別の率を固定し、構成だけを動かして比べる |
| 世代・周期 | ある世代や周期（ベビーブーム・更新時期・耐用年数）が節目を通ったのか | 生まれ年や導入年から、節目に来る時期を計算する |
| 制度・規則 | 法律・制度・社内ルール・価格表が変わったのか | 施行日と、系列の変化点の時期を重ねる |
| 経済・価格 | 景気・物価・賃金・為替・原材料や燃料の価格が動いたのか | 価格の系列と、枝の単価・量を同じ期間で並べる |
| 外部の衝撃 | 感染症・災害・気象・事故など、一時の出来事があったのか | 衝撃の期間とその前後で水準を比べる。戻ったかも見る |
| 行動 | 顧客・従業員・取引先の選び方や行動が変わったのか | 行動を表す系列（件数あたりの量、利用率）を見る |
| 競合・市場 | 競合の参入・撤退、取引先の統合、需要と供給の釣り合いが変わったのか | 業界全体・市場の系列と比べる（§3 の6） |
| 代替・技術 | 別の手段・技術に置き換わったのか | 代わりの系列が同じ時期に増えたかを見る |
| 組織・運用 | 自分たちの人員・設備・手順・判断（値付け・配置）が変わったのか | 変更の日付と、社内の系列の変化点を重ねる |
| 測定 | 定義・集計方法・補正・時点が変わったのか | 出典の注記を読む。変更の前後を同じ定義にそろえる |

型の表を当てたあと、背景分析の内部の優先付け・自己点検に限り、次の**3つの軸**で偏りが無いかを見る。この軸を通常入力の欄や必須スキーマにしない。

| 軸 | 欄 | 見落としやすい例 |
|---|---|---|
| 時間の長さ | 一時の衝撃 / 繰り返す周期（季節・更新期）/ 長く続く構造の変化 | 「今年だけ」に見えて、実は10年続く流れの途中だった |
| 立場 | 需要側（顧客・利用者）/ 供給側（自分たち・人員・設備）/ 取引先・競合 / 行政・制度 | 自分たちの運用の変化を、外部のせいにしていた |
| 範囲 | 自分たちだけ / 業界・地域の全体 / 国・世界の全体 | 業界全体が同じだけ動いていて、自分たち固有の理由は無かった |

- `plan.背景分析` が `true` のときは、候補を**6つ以上、4種類以上の型**から出す（`check-llm.mjs brief` が検査）。分解は内訳の記述にも使えるため、それだけでは背景分析や外部調査を開始しない。背景を扱う場合は、データの中（量と率・構成）だけで終わらせず、データの外（制度・経済・外部の衝撃・競合）にも当てる。

- 出した候補は、数字で確かめられるものだけを仮説にする。確かめる手段が無い候補は、`想定` として書くか捨てる。
- 出した候補は `references/thinking.md` §2 で1つの筋に絞り、その筋に主な背景と、別の説明になる対立の背景を立てる（例: 母数の減少 対 率の低下、制度の効果 対 衝撃からの回復）。残りは深掘りの候補にする。

## 3. 確かめ方

1. **大きさ**: 背景の系列と整合する枝の変化を、結論の単位で示す（`driverTree` の寄与、構成を固定した差）。対応する枝が小さい背景は、要因の見出しにしない。
2. **時期**: 背景の変化が、結果の変化より**先か同時**に起きたか。後なら原因ではない。
3. **量と反応**: 背景が大きく動いた層・時期ほど、結果も大きく動いたか。
4. **一貫性**: 別の資料・別の層でも同じ向きか。
5. **機序**: どういう経路で効くかを1文で書けるか。書けなければ `想定` にとどめる。
6. **比較の相手**: 同じ背景を受けた相手（業界全体・他の地域・国全体）も同じ向きに動いたか。同じなら外部背景との整合性が高まり、自分たちだけなら内部背景も候補になる。背景を受けなかった相手が動いていなければ説明仮説は強まるが、因果の証明にはならない。
7. **別の説明の消去**: 対立仮説と `背景データ-反証.csv` の資料で、同じ変化を説明できないかを確かめる。消せない別の説明は、要因の「背景の説明仮説」に `想定` として並べて書く。

2〜6 の時期・量反応・一貫性・仕組み・比較は、説明仮説を強めたり弱めたりする点検である。反事実の効果は推定しない。レポートでは「関連」「説明と整合」と書き、「〜が原因である」とは書かない。介入効果や「Xがどれだけ原因か」を問われたら結論を止め、`caution` に限界と次に必要な分析を書く。実験・準実験などの因果効果推定は対象外である。

探索は観測した**結果 → 中間 → 原因候補**の順で「なぜ」をたどる。レポートの表示は読み手の理解順に**原因候補 → 中間 → 結果**とする。結果が背景を強める循環が候補に出たら、採用原因にせず `caution` と追加計測に送る。

## 4. 根拠の強さ（要因の「背景の説明仮説」の各項目に付ける）

| 表示 | 条件 | 書き方 |
|---|---|---|
| データで確認 | このレポートのコードで、手元のデータか `背景データ*.csv` から計算した | 数字をコードの変数から入れる |
| 公表資料 | 公的な資料に書かれた事実・数字（施行日、公表の統計値）で、出典の URL がある | 出典名を添える。数字は `背景データ*.csv` から入れる |
| 想定 | 機序として考えられるが、ここでは確かめていない | 「〜と考えられる」と書く。1つの要因の原因項目の半数以下にする |

- 1つの要因の「背景の説明仮説」には、`データで確認` か `公表資料` を最低1つ入れる（検査で強制）。
- 項目は表示用に 原因候補 → 中間 → 結果 の順に2つ以上並べ、つながりを1文で説明できるかを確かめる（§3 の5 機序）。図を見れば分かる「何がいくつ動いたか」は項目にしない。
- 出典の無い数字は書かない。記憶や一般論の数字は `想定` にもしない（数字を消す）。

## 5. 外部の資料

- 優先の順: 政府・公的機関の統計と公表 → 業界団体・学術 → 報道（公的な数字が無いときだけ。その旨を書く）。
- 時点と定義をそろえる: 暦年か年度か、何月何日時点か、速報か確定か。手元のデータと期間がずれるときは、`caution` か「データと計算」に書く。
- 外部の数字は `背景データ*.csv` にまとめ、analysis.mjs はそこから読む（本文に手で書き写さない）。

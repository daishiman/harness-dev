## 2-1. 画面ごとの情報設計(jp-web-design `references/information-design.md` §2)

| 画面 | 使われる場面の1文(誰が・どこで・何をしながら・端末・1回◯件) | 判断軸6(目的/情報量/件数/識別の手がかり/関係/操作) | 消す情報・戻す最小ラベル(理由) | 情報グループ(原則3〜4群)と優先順位 | 主役(視覚的に立てる1つ) | 採用した表示形式と決め手・却下候補 | 表示用に加工する項目・画像の役割 |
|---|---|---|---|---|---|---|---|
| | | 読む・4〜8項目・〜100件・テキスト・独立・一括処理 | | | | カード(却下: 表=その場編集が不要) | 例: 生年月日→基準日時点の年齢、画像=識別 |

- 場面の1文が書けない画面は設計に入らない。**形式が「表」でも選定理由を書く**。
- 8工程は「場面の1文 → ラベル剥がし → **伝わらないものだけ最小限に補う** → グループ化 → 優先順位 → 表示用加工 → 表示形式の導出 → 機能と意味づけの装飾」の順で通す。
- 判断軸が埋まらない場合はT1・コード・資料・実データへ戻って調査し、最有力仮説を置く。質問待ちにはしない。
- 3〜4群・第一階層3項目は原則。超える方が速い画面は、超過理由をこの表に記録する。
- 画像は識別/証拠/説明/装飾を判定し、装飾だけなら原則削除する。採用画像の alt・必要なキャプション・トリミング方針・375/768/1280/1600pxの4幅での見え方を最終列に記録する。
- 通常の形式選定・ラベル・加工・画像判断はこのT2に記録する。カタログにない形など前例のない例外だけ、3条件(関係を写す/前例がある/初見で分かる)を満たしたうえで `docs/product/design-decisions.md` を作成して記録する。

# Data Lifecycle — 取込データ・人の手修正・マスタ・確定期間の扱い

**適用条件**: 外部データ(表計算ファイル・基幹システム・API)を定期的に取り込む、基準値や対応表をマスタとして持つ、月次・期別の締め処理がある — このいずれかに該当したら読む(手順2 で設計方針を決め、手順4 で実装標準として使う)。

この領域の失敗は画面には現れない。**数字が静かに変わる・手で直した内容が黙って消える**という形で、数週間後に信用を失って発覚する。以下は既定値として適用し、逸脱するときだけ依頼者に確認する。

## §1. 取込値と手修正は別枠で持つ(上書きしない)

1. **取り込んだ値を人の修正で上書きしない**。取込値と手修正値を別の列・別レコードとして保持し、表示・集計では「手修正があればそれを、なければ取込値を」使う。上書き方式は、元データを再取込するたびに手修正が消え、しかも**どちらの値が正だったのかを後から追えなくなる**。
2. 分離すれば「**取込値に戻す**」が1操作で成立する。これは Skill `ux-design` §5-3 の「戻せる」を、データ構造の側で保証することにあたる。
3. 手修正には **理由・実施者・日時** を残す。理由は自由記述で足りるが、空のまま確定させない(後で見る人にとっては理由のない差異が最も怖い)。
4. 取込は**原本を保持したまま**行う(`ux-design` §8)。取り込んで変換した結果だけを残して原本を捨てない。

## §2. 読み取り専用・空表示は「無言」にしない

1. 画面に読み取り専用の一覧を出すときは、**なぜ編集できないのかを画面上に1行で示す**(「確定済みのため編集できません」「取込元で管理している値です」)。無言の読み取り専用は、利用者から見れば不具合と区別がつかない。
2. 値が空・ゼロで並ぶときは、**理由を1つ名指しし、それを解決する画面への導線を出す**(「対応表が未登録のため計算できません → 設定を開く」)。原因が複数あり得ても、いま最も確からしい1つを出す。列挙は読まれない。
3. **落とし穴**: この理由表示の条件式が実際には成立せず、結局無言になっている、という不具合が起きやすい(空判定とゼロ判定の取り違え・非同期読み込み中との混同)。**理由が表示されることをテストで担保する**(空データを流し込んで文言が出ることを確認する)。

## §3. マスタと確定済み期間 — 時制が違うものを混ぜない

1. マスタ(基準値・対応表・料率)と期別データは**時制が異なる**。マスタは「現在の正」、期別データは「その時点のスナップショット」。期別データからマスタを**参照するだけ**の設計にすると、マスタを直した瞬間に過去の確定済み集計が変わる。
2. **既定の振る舞い**: 未確定期間は自動反映、**確定済み期間は据え置き + 差分の通知**。据え置いた差分は一覧化し、まとめて／個別に反映を選べ、反映は取り消せること。
3. スナップショットと現在値の**比較ビューが、そのまま差分アラートの実体になる**。「今の値 / 確定時の値 / 差」の一覧を作れば通知の中身はそこから生成できる。両者は表裏一体なので同時に設計する。
4. **落とし穴**: 集計を「画面を開くたびにマスタを見て計算し直す」実装が一部に混ざっていると、確定済み期間でも**表示だけが変わり、保存済みの数値と食い違って見える**。計算・集計・出力のたびに「保存済みスナップショットとマスタのどちらを参照しているか」を**画面横断で棚卸しする**(1画面だけ直しても、印刷・書き出し・API が古い実装のまま残る)。

## §4. 取込のたびの差分検出 — 強弱をつける

1. 取込のたびに前回値と突き合わせ、**実質的な変更を通知**する。ただし全件を同じ強さで出すと読まれない。
   - **強く出す(既定で展開)**: 対応関係の変化 / 桁違いの数値変化 / 行の消失 / 文字化け / 重複登録 — 見落とすと壊れるもの。
   - **畳んで出す**: 通常の値の増減・軽微な表記差。
   - 確認済みにしたものは**再表示しない**(同じ差分を毎回見せると全体が無視される)。
2. **突合は正規化キーで行い、表示は原本のまま**にする。表示文字列を書き換えると、取込元と突き合わせられなくなり、問い合わせ時に「どの行のことか」が特定できなくなる。

## §5. 表記ゆれの正規化 — 自動同一視の境界

**正規化の対象(意味が変わらないもの。自動で同一視してよい)**:

- 全角/半角、半角カナ/全角カナ、大文字/小文字
- 前後および語間の空白
- ハイフン・長音・ダッシュ類の書き分け
- 番号のゼロ埋めの有無
- 日付・金額の表記差(区切り記号・元号/西暦・通貨記号の有無)

**規律**:

1. **自動同一視は表記ゆれに限定する**。1〜2文字違いなど意味が変わりうる差は自動で結ばず、**候補として人に確認を求める**。ここを自動化すると、誤った紐付けが誰にも気づかれないまま全期間へ伝播する(取込の失敗の中で最も回復コストが高い)。
2. 正規化キーが衝突する重複登録は「同じものが複数あります」として**統合を促す**(黙って片方を採用しない)。
3. 正規化ロジックは1箇所の純関数に集約し、単体テストを書く(表記ゆれの実例をそのままテストケースにする)。

# 行動科学の道具箱(SKILL.md §12 の詳細)

出典系譜: Laws of UX(Yablonski)/ NN/g 10ユーザビリティ原則(Nielsen)/『誰のためのデザイン?』(Norman)/『実践 行動経済学』(Thaler & Sunstein)。**全テクニックに倫理ガードが掛かる: ユーザーの目標達成を速く・安全にするためだけに使う。事業者に都合のよい誘導・ダークパターンは禁止。**

## A. 判断を速くする(選択と認知)

| 道具 | 原理 | アプリでの実装 |
|---|---|---|
| デフォルト効果 | 選択済みの選択肢はそのまま採用されやすい | 最頻パターンを選択済みに(SKILL.md §1)。課金・送信・削除はOFF側に |
| ヒックの法則 | 選択肢が増えるほど決定が遅くなる | プリセット2層(SKILL.md §2)。1画面の判断は1つ |
| ミラーの法則 | 短期記憶は7±2チャンク | 長いフォームは5±2項目ごとにステップ分割。番号・グループで束ねる |
| アンカリング | 最初に見た数字が基準になる | 比較の基準(現状・相場)を先に見せてから提案値を出す。偽アンカー禁止 |
| ヤコブの法則 | ユーザーは他のアプリの慣習を持ち込む | 検索は上・CTAは右・戻るは左。独自UIを発明しない |
| フォン・レストルフ効果 | 異質なものだけが記憶に残る | 目立たせるのは1画面1要素(視覚的主役)。全部強調=無強調 |
| 系列位置効果 | 先頭と末尾が記憶に残る | メニュー・リストの先頭に最重要、末尾に次点。中間に埋めない |

## B. 操作を軽くする(身体と時間)

| 道具 | 原理 | アプリでの実装 |
|---|---|---|
| フィッツの法則 | 大きく近いものほど速く押せる | 最頻アクションは大きく・親指圏に。タップ領域44px |
| ドハティの閾値 | 応答400ms以内で対話が途切れない | 押下フィードバック100ms・処理は楽観的更新かスケルトン(SKILL.md §11) |
| テスラーの法則 | 複雑さの総量は減らせない。誰が背負うかだけ | 全角半角の正規化・重複チェック・自動抽出はシステム側が背負う(SKILL.md §3-4) |
| ポステルの法則 | 入力に寛容に、出力は厳格に | 入力はカンマ・全角・貼り付けを受け入れ、保存時に正規化して厳密な形式で出す |
| 目標勾配効果 | ゴールが近いほど加速する | ステップ表示・残り件数・「あと1項目」。進捗ゼロ表示から始めない(授かり効果: 実績があるなら進捗を進めた状態から見せる) |

## C. 感情を設計する(記憶と信頼)

| 道具 | 原理 | アプリでの実装 |
|---|---|---|
| ピークエンドの法則 | 体験の印象は山場と終わりで決まる | 完了画面を丁寧に(結果+次の1歩)。エラー(谷)は回復体験で山に変える(SKILL.md §7) |
| ツァイガルニク効果 | 未完了は記憶に残り続ける | 「続きから再開」導線・下書き自動保存・要対応キューをホーム先頭に(SKILL.md §9) |
| 損失回避 | 失う痛みは得る喜びの約2倍 | 破壊的確認は「何を失うか」を具体的に見せる(「3件の下書きが消えます」)。煽りには使わない |
| 美的ユーザビリティ効果 | 秩序ある見た目は「使いやすい」と信じさせる | 見た目の秩序(jp-web-design)は信頼の前提。ただし美しさで欠陥を隠さない(正直なUI SKILL.md §6が優先) |
| ポカヨケ | ミスは注意書きでなく構造で防ぐ | 不正値は入口で弾く・危険な組み合わせは選べなくする(SKILL.md §3) |
| 選択アーキテクチャ | 並び順・グループ・デフォルトが選択を決める | 誘導は正直に。confirmshaming・偽の希少性・解約妨害は実装しない |

新しいテクニックを導入するときは「①どの原理か ②ユーザーの何が速く/安全になるか ③ダークパターン化していないか」の3点を言えること。言えなければ入れない。

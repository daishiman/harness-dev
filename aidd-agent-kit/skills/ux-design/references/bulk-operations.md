# 一括操作の実装作法(SKILL.md §5 の詳細)

体験設計の全体像・§5の要旨(4点セット・部分成功・量に耐える)は `../SKILL.md` を参照。ここでは一括選択・複数ファイル処理・省略の実装パターンを扱う。

## 5-1. 一括選択の標準装備(リストがあれば必ず付ける)

1件ずつのチェックしかないリストは、それだけで業務アプリ失格。**選択そのものの手数を削る**:

- **全選択チェックボックス**をリストヘッダーに。絞り込み中は「表示中の◯件をすべて選択」と対象を明示する(隠れた行まで選んで事故らせない)。
- **選択バー**: 1件でも選ぶと「◯件を選択中 / すべて解除 / [主要アクション]」のバーが現れる(実装は jp-web-design `references/components.md` §5)。選択件数は常に見える。
- **Shift+クリックで範囲選択**(PCの一覧では標準装備)。
- 選択不可の行(条件未達)は自動でスキップし、理由を行内に表示(SKILL.md §3の自動除外と同じ)。
- 「すべて選択→一括実行」が最頻ならそれをデフォルトの1ボタンに畳む(選択ステップ自体を省略)。

実装は `assets/ux-patterns.tsx` の `useBulkSelection`。

## 5-2. 複数ファイル・並行処理 — スピードは心遣い

- **複数ファイルを一度に受ける**: input は `multiple`、D&Dは複数投下・フォルダ投下を受ける。1個ずつしか投げられないアップローダを作らない。
- **並行処理で待ち時間を潰す**: アップロード・解析・送信は直列にしない(同時3〜5本の並行キュー)。体感時間は最大の機能(体験10原則①)。
- 進捗は**全体バー+項目別ステータス**の2階建て(「12/24件 完了」+ 行ごとの 済/処理中/失敗)。
- 処理中でも**できることを奪わない**: 解析中に次のファイルを投げられる・完了した分から先に確認できる(ブロッキングモーダルで待たせない)。
- 先読み・事前計算でクリック後の待ちをゼロに近づける(10秒かかる作業を2秒に)。

実装は `assets/ux-patterns.tsx` の `runWithConcurrency` / `splitResults`。

## 5-3. 省略とチェックの両立 — 「自動でやる・確認できる・戻せる」

アクションを省略(自動化)するほど楽になるが、ノーチェックは事故る。**3点を必ずセットで**:

1. **自動でやる**: 自動選択・自動整形・自動振り分けで人の操作を省く。
2. **何をしたか見せる**: 「13件を自動入力しました(要確認)」のように、省略した操作の**結果サマリーを可視化**。黙って変えない(SKILL.md §6 正直なUI)。
3. **戻せる**: 自動処理は必ず取り消し可能(Undoトースト・ステータス差し戻し・変更前の値の保持)。不可逆になる境界(送信・課金)だけ確認を1回挟む(SKILL.md §3 摩擦の非対称性)。

チェックは「全件を人が見る」ではなく**例外だけ見る**設計に: 自動処理の確信度が低いもの・条件から外れたものだけを「要確認」キューに集め、残りは素通しする。

実装は `assets/ux-patterns.tsx` の `applyWithUndo`。

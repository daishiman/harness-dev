Windows版

AI開発エージェントキット セットアップマニュアル【Windows版】

最初の3手順は START-HERE.md にあります。このマニュアルは、各手順の詳しい説明と、つまずいたときの対処です。所要時間は約5分で、難しい操作はありません。

このキットはユーザー全体(グローバル)に入ります

インストール先はあなたのユーザーフォルダ(C:\Users\(あなたの名前)\)の .claude、.agents\skills、.codex です。
どのフォルダで作業していても使えます。プロジェクトごとに入れ直す必要はありません。
特定のプロジェクトの中には何も置きません。インストーラーは最後に、実際に入った場所と件数をその場で表示します。

手順は STEP 2 と STEP 3 の2本立てです。 STEP 2 の install-windows.bat が終わればキット本体は導入済みです。STEP 3 の setup-env-windows.bat で Cloudflare 連携の登録まで済むと基本セットアップ完了です。STEP 2 の最後に Enter を押すと、そのまま STEP 3 を実行できます。

事前に必要なもの

必要なもの確認方法
Claude Code または OpenAI Codex がインストールされた Windows PCどちらかのアプリでチャットが使える
利用するツールへのサインインClaude Code または Codex を開いてチャットが使える状態になっている

インストーラーは両方の設定を用意するので、片方だけを使っている場合でも実行できます。

STEP 1: ZIPファイルを展開する

展開前に「ブロックの解除」をするのが最も簡単です。 解除せずに展開しても導入はやり直せます。

  1. 受け取った aidd-agent-kit.zip を 右クリック し、「プロパティ」 を選びます。
  2. 一番下に 「セキュリティ: このファイルは他のコンピューターから取得したものです。…」 という行があれば、その右の 「ブロックの解除」 にチェックを入れて OK をクリックします。
    • この行が無ければ、すでに解除済みです。そのまま次へ進んでください。
  3. あらためて ZIP を 右クリック し、「すべて展開…」 を選びます。
  4. 「展開」ボタンをクリックします。
  5. aidd-agent-kit というフォルダができるので、開きます。

なぜ展開前なのか

インターネット経由で受け取ったファイルには、Windows が「他のコンピューターから来た」という印を付けます。ZIP を展開すると、この印は 中の全ファイルに1つずつコピーされます。展開後に解除しようとすると、ファイルの数だけ同じ操作を繰り返すことになります。

展開前の ZIP で1回解除しておけば、中身には印が付きません。以降の警告画面もほとんど出なくなります。

展開後でも、インストーラーが自動解除を試みます。自動解除できなかった場合は、画面に記録の場所と手動解除コマンドが表示されます。

ZIPをダブルクリックして「中を見ているだけ」の状態では、インストールできません。必ず「すべて展開」してからにしてください。

STEP 2: インストーラーをダブルクリックする

  1. フォルダの中の install-windows.bat をダブルクリックします。
    • ファイル名が install-windows とだけ表示されている場合もあります(同じものです)。
  2. 黒い画面が開き、自動でインストールが進みます。
  3. 「両方へのインストールが完了しました!」 と表示されたら成功です。
    • 続けて 「どこに何が入ったか」(実際のフォルダの場所と件数)が表示されます。「ユーザー全体に入りました」と出ていることを確認してください。
    • 最後に 「続けて開発環境セットアップを実行しますか?」 と聞かれます。Enter を押せば、そのまま STEP 3 が始まります。

「WindowsによってPCが保護されました」という青い画面が出たら

  1. 画面の中の 「詳細情報」 をクリックします。
  2. 右下に現れる 「実行」 ボタンをクリックします。

これは「配布元がMicrosoftに登録されていないファイル」に必ず出る標準の確認画面で、このキットに問題があるわけではありません。

コマンドプロンプトでコマンド実行してインストールする方法(上級者向け)

ダブルクリックの代わりに、コマンドプロンプトから実行することもできます。インストールされる内容は同じです。こちらの経路ではセキュリティの警告画面が出ません。

cd aidd-agent-kit フォルダのパス
install-windows.bat

コマンドの補足

  • 配置だけ診断する場合は、Git Bash または WSL で対象リポジトリのルートから ./aidd-agent-kit/doctor-codex-layout.sh を実行します。診断はファイルを削除・移動しません。
  • Codex の旧 /prompts:build-app 形式は非推奨で、標準インストールには含まれません。移行期間だけ必要な場合は install-windows.bat --legacy-prompts を実行します。新しい利用方法では $build-app を使ってください。

STEP 3: 開発環境と Cloudflare 連携を設定する(必須・初回のみ)

STEP 2 だけでは終わりません。 アプリ開発には Node.js 22 以上 と pnpm という2つの道具が必要で、さらに Cloudflare(アプリの公開先)との連携(MCP: AI開発ツールと外部サービスをつなぐ仕組み)もここで設定します。付属のスクリプトでまとめて入ります。

STEP 2 の最後に Enter を押した場合も、最後に表示された状態を確認してください。そうでない場合は次のように実行します。

  1. フォルダの中の setup-env-windows.bat をダブルクリックします。
    • ファイル名が setup-env-windows とだけ表示されている場合もあります(同じものです)。
  2. 黒い画面が開き、自動でインストールが進みます(2〜5分)。
  3. 最後の表示で結果を確認します。
    • 「セットアップが完全に完了しました！」 — Node.js・pnpm に加え、登録した3つの連携すべての接続確認まで完了しています。
    • 「基本セットアップ完了 / 変更系MCPは必要時に認証」 — 通常はこの表示です。認証不要の docs 接続まで完了しており、今すぐの認証は不要です。変更系MCPは必要時に認証します(初めて使う時にエージェントが対象1件を案内します)。
    • 「基本セットアップ完了 / 一部の連携は未設定」 — Claude Code または Codex CLI が見つからず、そのクライアントへの登録を行えていません。使う予定があれば導入後にもう一度実行します。
    • 失敗表示 — キット本体は導入済みでも、環境と連携は未完了です。問題を直してこのスクリプトを再実行します(Q10 参照)。

登録される連携は cloudflare-bindings(リソース操作)、cloudflare-docs(公式ドキュメント検索、認証不要)、cloudflare-observability(公開後のログ・エラー確認)の3つで、いずれもユーザー全体に入ります。OAuth 画面が開いた場合は、利用する操作に必要な最小権限だけを認可してください。MCP と wrangler のどちらを使うかの裁定は skills/wrangler/references/mcp-vs-cli-routing.md にあります(利用者が読む必要はありません)。

すでに入っている場合は「インストール済みです」と表示されるだけなので、何度実行しても問題ありません。
「WindowsによってPCが保護されました」という青い画面が出たときは、STEP 2 と同じ方法(詳細情報 → 実行)で開いてください。

「古い形式の MCP 設定が見つかりました」と表示されたとき

作業中のフォルダに .mcp.json というファイルが残っていると、そのプロジェクト用の設定がユーザー全体の設定より優先され、キットが登録した設定が隠れることがあります。スクリプトは該当ファイルの場所と直し方を表示しますが、自動では書き換えません。エージェントに「.mcp.json を直して」と頼めば差分を提示するので、承認して直してください。詳しい分岐は上の裁定書にあります。

STEP 4: 動作確認する

  1. Claude Code と Codex を 一度終了して、起動し直します。
  2. Claude Code は /build-app、Codex は $build-app と入力します。
  3. 入力候補に build-app が表示されればインストール成功です。Codex では /skills からも確認できます。

上手に頼むコツ

/build-app(Codex は $build-app)に続けて、次の3点を普通の言葉で書くと、AIが迷わず一発で作ります。

  1. 誰が使うか(例: 社員だけ / 取引先も / 誰でも)
  2. 何ができるか(例: 予約できる、一覧が見られる、承認できる)
  3. 公開範囲(例: 社内限定 / ログインが必要 / 一般公開)
Claude Code: /build-app 会議室の予約アプリ。社員だけが使える。Googleアカウントでログイン。
Codex: $build-app 会議室の予約アプリ。社員だけが使える。Googleアカウントでログイン。

公開した後は /improve-app($improve-app)に要望を書くと1件ずつ安全に追加され、要望を書かなければ残課題リストから選べます。問題があれば /undo-app($undo-app)で1つ前の状態に戻せます。コマンドを使わず「在庫管理のアプリを作りたい」と話しかけるだけでも動きますが、確実に動かしたいときはコマンドを使ってください。

うまくいかないとき

Q1. 「開いているファイル - セキュリティの警告」「発行元を確認できませんでした」と出る

展開前の「ブロックの解除」を行っていないと表示されることがあります。インストーラーはキット全体の自動解除を試みますが、警告が残る場合は次の手順でまとめて解除できます。

まとめて解除したい場合は、キットのフォルダで アドレスバーに powershell と入力して Enter し、開いた画面で次を実行してください。

Get-ChildItem -Recurse -Force -File | Unblock-File

Q1-1. 「インストールを開始できません」と表示されて、すぐ終了する

インストーラーが実行前の点検で問題を見つけた状態です。画面に理由が出ています。

  • 「PowerShell が見つかりません」 — Windows 標準の PowerShell が無効化・削除されています。社内 PC の場合は情報システム部門にご確認ください。
  • 「PowerShell が制限モードで動作しています」 — 組織のセキュリティポリシー(AppLocker / WDAC)による制限です。この制限はキット側では解除できません。管理者にご相談ください。

詳しい記録は %TEMP%\aidd-agent-kit-install.log に残ります。このファイルを導入支援の担当者にお送りください。

Q1-2. インストーラーがどうしても開けない

手動でコピーする方法があります。

  1. エクスプローラー(フォルダのアイコン)を開きます。
  2. 上部の アドレスバー をクリックし、次のとおり入力して Enter を押します。 
    %USERPROFILE%\.claude
  3. Claude Code 用の skills・agents・commands を .claude の対応するフォルダへコピーします。
  4. Codex 用は、共通 skills と codex\workflow-skills を .agents\skills、codex\agents を .codex\agents へコピーします。さらに agents\app-orchestrator.md を .agents\skills\app-orchestrator\SKILL.md、codex\app-orchestrator-openai.yaml を .agents\skills\app-orchestrator\agents\openai.yaml として配置します。非推奨の旧互換が必要な場合だけ codex\prompts を .codex\prompts へコピーします。

Q2. /build-app または $build-app が候補に出てこない

  • 利用中の Claude Code / Codex を完全に終了して起動し直してください。
  • 新しいチャット(新しいセッション)を開いてから入力してください。

Q3. 「インストールを確認できませんでした」と表示された

画面に入らなかったものの一覧が表示されます。その内容を控えたうえで、次をお試しください。

  • ZIPを展開してできた aidd-agent-kit フォルダの中の install-windows.bat を実行しているか確認してください(ZIPの中から直接実行すると失敗します)。
  • 解決しない場合は Q1-2 の手動コピーをお試しください。

Q4. Codex でスキルが表示されない

  1. Codex を完全に終了して起動し直します。
  2. 新しいチャットで /skills を開き、build-app を確認します。
  3. 見つからない場合は %USERPROFILE%\.agents\skills\build-app\SKILL.md があるか確認します。
  4. AIDDのSkillは %USERPROFILE%\.agents\skills を確認します。%CODEX_HOME%\skills はCodex組込installer/plugin等の管理領域なので、AIDDのファイルを手動で追加・移動しないでください。

Q5. .codex\agents と .toml は何に使う?

.codex\agents\app-orchestrator.toml は、Codexが仕事を委譲するcustom agentの定義です。スキルの置き場所ではありません。実際の作業手順は .agents\skills\app-orchestrator\SKILL.md から読みます。配置の詳細は CODEX-PLACEMENT.md にあります。

Q5-1. userとprojectの両方に同じAIDDスキルがある

Codexは同名Skillを自動統合しないため、二重導入は推奨しません。./aidd-agent-kit/doctor-codex-layout.sh で非破壊診断し、表示されたmanifestを確認して、どちらのscopeを使うか決めてください。doctorは自動削除しません。なお、%CODEX_HOME%\skills はCodex組込installer/plugin等の管理領域なので、存在するだけで誤配置ではありません。

Q6. 「別の場所への『近道(リンク)』になっています」と表示された

Claude Code または Codex の書き込み先が、別の場所を指すリンクとして設定されています。リンク先を意図せず書き換えないため、インストーラーが停止しました。

心当たりがない場合は、この画面のまま導入支援の担当者にお見せください。

ご自身で設定された方は、画面に表示されたコマンドでリンクを一時的に退避してから、もう一度インストーラーを実行してください。

Q7. 「以前のファイルは次の場所に保存してあります」と表示された

Claude Code または Codex に同じ名前の項目があったため、上書き前に自動でバックアップしたという意味です。インストール自体は成功しています。

C:\Users\(あなたの名前)\.claude\backup-20260726-143000\
C:\Users\(あなたの名前)\.codex\backup-20260726-143000\

元に戻したいときは、このフォルダの中身を元の場所へ戻してください。不要になったら、フォルダごと削除して構いません。

Q8. 「ファイルのコピー中に問題が発生しました」と表示された

  • ディスクの空き容量を確認してください(50MB程度必要です)。
  • ウイルス対策ソフトがコピーを止めている場合があります。一時的に停止できないか、社内のIT担当者にご相談ください。
  • 解決しない場合は Q1-2 の手動コピーをお試しください。

Q9. 黒い画面の日本語が文字化けしている

  • 表示が崩れていてもインストール自体は正常に行われます。STEP 4 で /build-app または $build-app が出れば問題ありません。

Q10. セットアップスクリプトが「インストールに失敗しました」と表示する

社内ネットワークの通信制限(必要なファイルのダウンロード先がブロックされている)が原因の場合があります。

この画面を閉じずに、そのまま社内のIT担当者・導入支援の担当者にお見せください。 どの通信が止められているかが画面に出ているため、担当者側で対応できます。

Q11. auth_pending や [Conflicting scopes] と表示された

  • auth_pending は、実際に必要になった変更系の連携1件だけが認証待ちという意味です。エージェントが示した対象だけへ最小権限を認可すれば ready になります。先回りして全部を認証する必要はありません。
  • [Conflicting scopes](claude mcp list の表示)は、作業中のフォルダの .mcp.json とユーザー全体の設定が競合しています。STEP 3 の「古い形式の MCP 設定が見つかりました」の対処をしてください。

更新するとき

新しいバージョンを受け取ったら、STEP 1 から同じ手順を繰り返すだけです。古いファイルは自動でバックアップされてから置き換わり、後から入れた新しいキットの内容が常に正になります。

  • 新しいキットでなくなった古いスキルやコマンドは、自動で整理されます(バックアップフォルダへ移動します)。ご自身で何かを削除する必要はありません。
  • 整理の対象はこのキットが入れたものだけです。ご自身で追加されたスキルやコマンド、使いながら貯まったノウハウ(ナレッジ)は消えません。

更新後は Claude Code と Codex を再起動してください。

アンインストールしたいとき

エクスプローラーで .claude、.agents\skills、.codex を開き、次のキット項目だけを削除します(入っているものの一覧は README.md の「収録内容」にあります)。

  1. .claude\skills と .agents\skills の中の、共通スキル20個のフォルダ
  2. .claude\agents\app-orchestrator.md と .agents\skills\app-orchestrator
  3. .claude\commands の4ファイルと .agents\skills の4コマンドスキル
  4. .codex\agents\app-orchestrator.toml。--legacy-prompts を使った場合だけ .codex\prompts の4ファイル
  5. .claude と .codex の aidd-agent-kit.version / aidd-agent-kit.manifest

skills・agents・commands フォルダ自体は削除しないでください。Claude Code が使う他のファイルが入っている場合があります。

インストール時に作られた backup-(日時) フォルダが残っている場合、その中に元のファイルが入っています。必要なら戻したうえで、フォルダごと削除してください。

管理者の方へ(セットアップ後の運用に必要なもの)

エージェントがアプリをインターネットに公開するところまで自動で行うため、利用する環境によって以下が必要です。非エンジニアの方は、導入支援の担当者にご相談ください。

  • Claude Code または OpenAI Codex を利用できるプラン
  • Cloudflare アカウント(アプリの公開先。無料プランで開始可能)と wrangler login によるログイン
  • GitHub アカウント(アプリの変更履歴の保存先。プライベートリポジトリ=自社の関係者だけが見られる保管場所を使用します)
  • GitHub CLI (gh) のインストールと gh auth login によるサインイン。プルリクエストの作成・確認・反映はGitHub MCPではなく gh を使います
  • Cloudflare との連携設定(MCP)。付属のセットアップスクリプトがClaude Code／Codexの両方へ自動で設定します(STEP 3)
  • Googleログイン機能を使う場合: Google Cloud の OAuth 設定(手順はスキル内に日本語で収録済み)
  • sync-project-windows.bat は、キットを内包するリポジトリ自身へ反映する管理者専用の手段です。通常は使いません。 反映先はキットの親ディレクトリに固定されており、任意のプロジェクトを指定することはできません。実行すると project scope へ入るため、user scope と合わせて二重導入にならないよう注意してください
  • AI機能を使う場合: OpenAI / Anthropic 等の APIキー
